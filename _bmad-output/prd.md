# Product Requirements Document - Thematic Synthesizer

**Author:** Xiafe
**Date:** 2025-12-29

---

## Executive Summary

### 产品愿景

**主题合成器 (Thematic Synthesizer)** 是 AnyKeep 从"信息仓库"迈向"智慧大脑"的关键功能。它解决重度用户的核心痛点：**"看不过来"和"连不起来"**。

当用户收藏了 50 篇关于同一主题的文章时，他们面临的不是"找不到"的问题，而是无法将这些碎片化信息整合成系统性知识。主题合成器通过 AI 驱动的"对抗性合成"策略，将多源信息进行交叉验证和逻辑重构，帮助用户真正"理解"而非仅仅"记住"。

### 目标用户

知识密集型互联网用户：

- 知识博主、科技博主、内容博主
- 考试备考者（考研、职业资格）
- 自学提升者
- 希望建立个人知识库的专业人士

这些用户的共同特征是：**知识焦虑 + 行动意愿**。他们主动收藏优质内容，期望将其转化为自身能力，而非让收藏夹变成"数字坟场"。

### 核心价值主张

> **"专家秘书"级别的知识整合能力**

用户已经接触过大量 AI 助理和聊天机器人，对简单的问答不感兴趣。他们需要的是真正的知识汇集、整理、结构化能力——相当于一个专业的研究助理，能够：

- 去除重复和噪音
- 识别不同来源的观点冲突（但不做价值判断）
- 发现知识盲区并建议进一步探索方向
- 将碎片整合成可操作的结构化报告

### What Makes This Special

**1. "对抗性合成" Prompt 策略**

不同于传统 AI 摘要工具产出的平淡共识，主题合成器强制识别并展示观点冲突：

- 如果资料 A 说方案 X 好，资料 B 说方案 X 有缺陷，必须明确标注
- AI 仅做信息筛选和呈现，不做观点判断
- 对于冲突内容，提示用户做进一步研究和探索

**2. 四维结构化输出**

每份综述报告包含：

- **概述**：该主题的整体背景
- **核心共识**：不同来源都认同的观点
- **观点分歧**：最具价值的差异化视角
- **知识盲区**：收藏中尚未覆盖但相关的领域

**3. 三模态入口设计（AI 原生应用特征）**

| 模态        | 入口                                 | 适用场景                     |
| ----------- | ------------------------------------ | ---------------------------- |
| UI 触发     | 文件夹/标签/批量选中后的左键操作菜单 | 用户明确知道要合成哪些内容   |
| Agent 对话  | AI 聊天窗口自然语言输入              | 用户需求模糊，需 AI 帮助定位 |
| AI 主动推荐 | 检测到主题聚集时主动提示（可关闭）   | 发现用户可能忽略的整合机会   |

**4. 闭环价值**

综述报告本身成为新的知识资产：

- 可被 Brain Sync（主动回忆）系统调用
- 可被未来的语义搜索检索
- 形成"收藏 → 整合 → 复习 → 内化"的知识复利闭环

## Success Criteria

### User Success

**核心成功时刻：**

1. **生成时刻** ⭐ 必须实现

   > "我选了 20 篇文章，5 分钟后得到了一份结构清晰的综述报告"

2. **洞察时刻**

   > "报告告诉我，这 5 篇文章说 A 好，那 3 篇说 A 有问题——我之前完全没注意到这个冲突"

3. **发现时刻**

   > "知识盲区部分建议我去了解 X 话题，我确实没想到这一点"

4. **复用时刻**
   > "一个月后我在 Brain Sync 中复习时，又看到了这份综述的关键洞察"

**期望行为改变：**

用户从"收藏了就忘"转变为主动知识管理者：

- 主动触发综述报告生成
- 阅读生成的综述报告
- 在报告中标注重点内容

**用户成功指标：**

| 指标           | 定义                             | 目标  |
| -------------- | -------------------------------- | ----- |
| 首次使用完成率 | 首次触发并完整阅读综述的用户比例 | > 70% |
| 标注互动率     | 阅读后有标注行为的用户比例       | > 30% |
| 重复使用率     | 30天内使用2次以上的用户比例      | > 50% |

### Business Success

| 指标维度     | 指标                         | 3个月目标 | 12个月目标 |
| ------------ | ---------------------------- | --------- | ---------- |
| **功能采用** | 使用综述功能的用户占比       | 50%       | 80%        |
| **使用深度** | 每用户每月生成综述次数       | 10 次     | 20 次      |
| **完成率**   | 生成后 48h 内阅读完成率      | > 50%     | > 70%      |
| **留存影响** | 使用综述功能用户的留存率提升 | +70%      | +30%       |
| **付费转化** | 学术模式（付费）使用占比     | 20%       | 30%        |

**北极星指标：** 生成后 48h 内阅读完成率

> 这个指标直接反映功能是否真正解决了用户"看不过来"的问题。

### Technical Success

| 维度         | 指标                       | 目标             |
| ------------ | -------------------------- | ---------------- |
| **响应速度** | 10 篇文章综述生成时间      | < 150 秒         |
| **响应速度** | 20 篇文章综述生成时间      | < 300 秒         |
| **质量保证** | 综述结构完整率（四维输出） | > 95%            |
| **成本控制** | 标准模式单次 Token 消耗    | < 40,000 tokens  |
| **成本控制** | 学术模式单次 Token 消耗    | < 100,000 tokens |
| **可靠性**   | 生成成功率（无报错完成）   | > 99%            |

**用户等待容忍度：** 最长 5 分钟

**成本预算参考：**

- 快读模式：~¥0.02/次
- 标准模式：~¥0.05/次
- 学术模式：~¥0.15/次

### Measurable Outcomes

**Phase 1 发布后 30 天验证：**

- [ ] 至少 30% 活跃用户尝试过综述功能
- [ ] 平均生成时间 < 3 分钟（15 篇文章）
- [ ] 用户主动生成第二份综述的比例 > 40%

**Phase 1 发布后 90 天验证：**

- [ ] 综述功能用户的次月留存率比非使用者高 20%+
- [ ] 收到至少 10 条用户正面反馈（"这正是我需要的"类型）

## User Journeys

### Journey 1: 职场白领「张哥」— 行业分析综述 (Primary Success Path)

张哥是一家中型科技公司的产品经理，工作中需要持续跟踪行业动态。过去一年里，他在 AnyKeep 里收藏了近 200 篇关于「AI 产品化」的文章——包括公众号深度分析、36氪行业报告、知乎专栏观点，还有几篇英文博客。

问题是，每次要做季度规划时，他都面临一个尴尬：**这些文章他根本没时间重读，只能凭印象东拼西凑**。有时候他甚至忘了自己收藏过某篇重要分析。

周一早上，张哥打开 AnyKeep，在「AI 产品化」文件夹上点击左键，看到了一个新选项：「生成综述报告」。他选择「标准模式」，系统提示「正在分析 47 篇相关内容...」，进度条缓缓推进。

3 分钟后，一份结构化报告呈现在眼前：

- **概述**告诉他这 47 篇文章覆盖了 AI 产品化的技术、商业、伦理三个维度
- **核心共识**列出了所有文章都认同的观点——比如「AI 产品需要人机协作设计」
- **观点分歧**让他惊讶：原来有 12 篇文章认为「AI 原生应用是伪命题」，而另外 8 篇持相反观点——他完全没注意到这个冲突
- **知识盲区**提示他缺少关于「AI 产品定价策略」的收藏

张哥用高亮功能标注了 3 处关键洞察，把这份报告发给了团队。周会上，他成了「最懂行业的人」。

> **此旅程揭示的功能需求：**
>
> - 文件夹级综述入口
> - 进度显示与等待体验优化
> - 四维输出结构
> - 标注重点功能
> - 综述分享/导出能力

### Journey 2: 科研人员「王博士」— 学术深度综述 (Edge Case - Academic Mode)

王博士是一位研究自然语言处理的学者，她的收藏夹里有大量 arXiv 论文、学术公众号解读、以及 GitHub 项目文档。她需要为一篇综述论文做文献调研，但面临两个问题：

1. **信息过载**：关于「大模型微调」的收藏有 80+ 篇，人工梳理需要一周
2. **观点追踪**：同一作者在不同论文中的观点演变很难追踪

王博士选择了「学术模式」——系统提示这将使用更强的推理模型，可能需要 5-8 分钟，并且会消耗付费额度。她确认后，系统开始深度分析。

7 分钟后，报告生成。与标准模式不同，学术模式额外提供了：

- 按时间线的观点演变图谱
- 核心论文的相互引用关系
- 方法论差异的详细对比

报告的「观点分歧」部分特别详细，甚至标注了「论文 A 的结论与论文 B 存在方法论冲突，建议深入对比」。

王博士发现，这份综述帮她节省了 3 天的人工梳理时间。虽然付费了 ¥0.15，但她认为非常值得。

> **此旅程揭示的功能需求：**
>
> - 学术模式深度分析
> - 付费确认流程
> - 时间线/引用关系可视化（Phase 2）
> - 方法论对比能力
> - 成本透明展示

### Journey 3: 自媒体创作者「小薇」— AI 主动推荐 (Third Entry Point)

小薇是一位专注穿搭分享的小红书博主，她用 AnyKeep 收藏竞品分析、穿搭灵感、爆款拆解等内容。她不太会主动「整理」，但收藏得很勤——一个月能存 100+ 篇。

某天她打开 AnyKeep，右下角弹出一个轻提示：

> 🎯 发现「秋冬穿搭」主题下有 35 篇相似内容，要生成综述吗？

小薇点击「试试看」，选择「快读模式」。1 分钟后，一份简洁的综述出现了，核心内容一目了然：

- 今年秋冬流行的 5 个关键词
- 不同博主对「叠穿」的不同演绎
- 她还没收藏但可能感兴趣的方向（运动风混搭）

小薇觉得这比自己翻收藏夹强多了。她关闭了这个功能一周后，又主动打开了——因为确实有用。

> **此旅程揭示的功能需求：**
>
> - AI 主动推荐触发器
> - 非侵入式提示设计
> - 快读模式（低成本、快速）
> - 推荐功能开关
> - 相似内容聚类检测

### Journey 4: 考研党「小陈」— 错误恢复场景 (Error Recovery)

小陈是一名备考中的大三学生，他用 AnyKeep 收藏了大量考研资料——政治时事、英语阅读、专业课笔记。他尝试对「政治时事」标签下的 120 篇内容生成综述。

系统开始处理，但在 2 分钟后弹出提示：

> ⚠️ 内容量较大，处理时间可能超过 5 分钟。建议：
>
> 1. 缩小范围（选择近 3 个月的内容）
> 2. 使用快读模式（减少深度分析）
> 3. 继续等待（预计 7 分钟）

小陈选择「缩小范围」，系统自动筛选出近 3 个月的 45 篇内容，3 分钟后成功生成综述。

报告的「知识盲区」提示他：「近期国际关系变化的内容较少，建议补充」。小陈觉得这个提醒很及时。

> **此旅程揭示的功能需求：**
>
> - 超时预警与建议
> - 范围缩减助手
> - 优雅的错误恢复流程
> - 智能时间范围筛选
> - 知识盲区的学习引导价值

### Journey 5: 知识博主「Alex」— 系统化知识输出 (Content Creator Path)

Alex 是一位知识类 UP 主，专注于商业分析和职场成长内容。他的工作流程是：大量阅读 → 整理观点 → 输出视频。AnyKeep 是他的「素材库」，但他面临一个核心痛点：**从素材到输出的鸿沟太大**。

每次准备选题时，Alex 需要：

1. 翻阅几十篇收藏
2. 手动整理不同观点
3. 找出有争议的点（这是好内容的来源）
4. 发现自己的知识盲区

这个过程通常需要 2-3 天。

现在，Alex 尝试用主题合成器。他选中「职场晋升」相关的 60 篇收藏，选择「标准模式」。4 分钟后：

- **核心共识**给了他「安全」的观点——这些可以作为视频的基础论述
- **观点分歧**让他兴奋——「35 岁危机是不是伪命题」的正反观点，正是一期好视频的素材
- **知识盲区**提示「创业 vs 打工」的对比内容较少——这成了他下一期的选题

Alex 把综述导出为 Markdown，导入到 Obsidian 中作为创作大纲。他的内容产出效率提升了 40%。

> **此旅程揭示的功能需求：**
>
> - 综述作为创作素材的价值
> - 观点分歧的「冲突挖掘」能力
> - Markdown/Obsidian 导出
> - 批量选择综述入口
> - 知识盲区转化为选题建议

### Journey 6: 科技博主「Kevin」— 技术趋势追踪 (Tech Blogger Path)

Kevin 是一位科技领域的独立博主，专注于 AI 和开发者工具赛道。他每天都在 Twitter、Hacker News、技术博客上发现新内容，用 AnyKeep 收藏后，文件夹里堆积了海量信息。

他的痛点是：**技术领域变化太快，上个月的热点可能已经过时**。

Kevin 的使用场景是「增量分析」：他已经对「LLM 应用开发」生成过一份综述，但最近又收藏了 15 篇新文章。系统检测到这个变化，提示：

> 📝「LLM 应用开发」综述有 15 篇新内容可更新，要刷新吗？

Kevin 点击刷新，系统进行增量分析，2 分钟后更新了报告：

- **新增共识**：Agent 架构成为主流方向
- **新增分歧**：关于 RAG vs Fine-tuning 的争论加剧
- **知识盲区变化**：多模态 Agent 的内容仍然稀缺

Kevin 把这份「技术趋势快报」分享到他的 Newsletter，读者反馈：「这比我自己刷信息流强多了」。

> **此旅程揭示的功能需求：**
>
> - 增量刷新能力（Phase 2）
> - 新内容检测与提醒
> - 综述版本历史（可选）
> - 分享/发布能力
> - 技术趋势追踪场景优化

## Innovation & Novel Patterns

### 创新领域检测

主题合成器在以下维度展现出显著的产品创新：

| 创新维度    | 创新点                                 | 创新类型        | 差异化程度 |
| ----------- | -------------------------------------- | --------------- | ---------- |
| Prompt 策略 | 「对抗性合成」— 强制识别观点冲突       | 方法论创新      | 高         |
| 输出结构    | 四维结构化输出（概述/共识/分歧/盲区）  | 设计模式创新    | 高         |
| 交互模式    | 三模态入口（UI + Agent + AI 主动推荐） | AI 原生应用设计 | 中高       |
| 价值发现    | 知识盲区自动识别                       | 功能创新        | 高         |

### 核心创新详解

#### 1. 「对抗性合成」Prompt 策略

**问题**：传统 AI 摘要工具输出平淡的「共识」，隐藏观点差异，用户失去批判性思考机会。

**创新方案**：

- 强制标注冲突：如果 5 篇文章说 A 好，3 篇说 A 有问题，必须明确展示
- AI 仅做信息筛选和呈现，**不做观点判断**
- 冲突信息成为用户进一步研究的起点

**市场差异**：目前没有专注于「观点分歧」挖掘的知识整合工具。

#### 2. 四维结构化输出

| 维度     | 功能             | 用户价值         |
| -------- | ---------------- | ---------------- |
| 概述     | 主题背景全景     | 快速建立认知框架 |
| 核心共识 | 多源认同的观点   | 建立知识基础     |
| 观点分歧 | 差异化视角       | 触发批判性思考   |
| 知识盲区 | 未覆盖的相关领域 | 引导持续学习     |

**创新点**：这不是传统的「层级摘要」，而是**多维度透视**。

#### 3. AI 主动推荐（第三模态）

- **触发条件**：检测到主题聚集（如 35 篇相似收藏）
- **非侵入式**：右下角轻提示，可一键关闭
- **用户控制**：功能开关，尊重用户偏好

**创新点**：将 AI 从「被动工具」升级为「主动助手」，同时保持用户控制权。

#### 4. 知识盲区发现

- **传统工具**：仅整合已有内容
- **主题合成器**：识别用户「不知道自己不知道」的领域
- **价值升级**：从「知道什么」扩展到「应该知道什么」

### 验证方法

| 创新点      | 验证方式                | 成功指标              |
| ----------- | ----------------------- | --------------------- |
| 对抗性合成  | A/B 测试：有/无分歧展示 | 用户阅读深度提升 20%+ |
| 四维输出    | 用户反馈调研            | 结构满意度 > 80%      |
| AI 主动推荐 | 功能开关使用率          | 30 天后仍开启 > 60%   |
| 知识盲区    | 点击率追踪              | 盲区建议点击率 > 15%  |

### 风险缓释

| 风险                  | 缓释策略                      |
| --------------------- | ----------------------------- |
| 对抗性合成过于复杂    | 提供「快读模式」简化输出      |
| AI 主动推荐被认为打扰 | 默认关闭 + 首次体验引导       |
| 知识盲区建议不相关    | 基于语义相似度 + 用户反馈迭代 |
| 四维输出信息过载      | 渐进式展开 + 折叠交互         |

## Web App Specific Requirements

### 项目类型概述

主题合成器作为 AnyKeep 的**功能模块**集成到现有 Web 应用中，复用现有技术栈和架构模式。

| 维度         | 说明                               |
| ------------ | ---------------------------------- |
| **项目类型** | Web App（功能模块）                |
| **集成方式** | 扩展现有 Next.js App Router        |
| **架构复用** | UnifiedEngine + OrchestrationSkill |
| **数据层**   | Supabase PostgreSQL + pgvector     |

### 技术架构

#### 1. 流式生成策略

采用**渐进式流式输出**策略，四个维度依次生成并实时显示：

```
用户触发 → 概述（流式）→ 共识（流式）→ 分歧（流式）→ 盲区（流式）→ 完成
```

**优势**：

- 用户可立即看到部分结果，减少等待焦虑
- 符合 AI 原生应用的交互预期
- 支持中途取消（部分结果仍可保存）

#### 2. 数据存储架构

**综述报告主表 `synthesis_reports`**

| 字段               | 类型         | 说明                                                |
| ------------------ | ------------ | --------------------------------------------------- |
| id                 | UUID         | 主键                                                |
| user_id            | UUID         | 用户关联                                            |
| title              | TEXT         | 综述标题                                            |
| source_type        | TEXT         | 来源类型：folder / tag / selection / ai_recommend   |
| source_ids         | UUID[]       | 关联书签 IDs                                        |
| depth_mode         | TEXT         | 深度模式：quick / standard / academic               |
| overview           | TEXT         | 概述内容                                            |
| consensus          | JSONB        | 共识列表 [{point, sources}]                         |
| divergence         | JSONB        | 分歧列表 [{point_a, sources_a, point_b, sources_b}] |
| blind_spots        | JSONB        | 盲区列表 [{topic, suggestion}]                      |
| full_markdown      | TEXT         | 完整 Markdown（导出用）                             |
| embedding          | vector(1536) | 向量嵌入（语义搜索）                                |
| token_cost         | INTEGER      | Token 消耗                                          |

## Project Scoping & Phased Development

### MVP 策略与理念

**选定策略**：体验型 MVP (Experience MVP)

> **核心理念**：先交付「对抗性合成」的核心体验，验证用户是否真的需要「观点分歧」挖掘，而非仅仅是传统摘要。

**策略选择理由**：

| 考量因素 | 分析                                 |
| -------- | ------------------------------------ |
| 核心假设 | 用户需要「观点分歧」而非「共识摘要」 |
| 验证目标 | 48h 阅读完成率 > 50%                 |
| 最小可行 | 四维输出 + 单一入口即可验证          |
| 技术风险 | 主要在 Prompt 策略，需快速迭代       |

### 资源需求

| 阶段    | 开发周期 | 团队规模 | 关键技能                       |
| ------- | -------- | -------- | ------------------------------ |
| Phase 1 | 4-6 周   | 1-2 人   | Next.js + Supabase + AI Prompt |
| Phase 2 | 4-6 周   | 1-2 人   | 同上 + 消息系统集成            |
| Phase 3 | 视反馈   | 视反馈   | 视用户需求决定                 |

### MVP 功能集（Phase 1 详细）

**Phase 1 支持的用户旅程**：

- ✅ 旅程 1：张哥 — 行业分析综述（成功路径）
- ✅ 旅程 3：小薇 — AI 主动推荐
- ✅ 旅程 4：小陈 — 错误恢复场景

**必须实现的能力**：

| 功能                  | 优先级 | 验证目标          |
| --------------------- | ------ | ----------------- |
| 文件夹/标签综述入口   | P0     | 用户能找到入口    |
| 四维结构化输出        | P0     | 结构满意度 > 80%  |
| 标准模式（DeepSeek）  | P0     | 生成成功率 > 99%  |
| 流式生成 + 进度显示   | P0     | 减少等待焦虑      |
| 综述详情页            | P0     | 阅读体验          |
| 标注重点功能          | P0     | 标注互动率 > 30%  |
| AI 主动推荐（带开关） | P1     | 30 天开启率 > 60% |
| 快读模式              | P1     | 低成本选项        |
| 综述列表页            | P1     | 综述管理          |

### 后续阶段功能

**Phase 2（增强）**：

- 学术模式（付费）
- Agent 对话入口

- Brain Sync 整合
- 综述摘要推送

- 冲突探索器

- 综述订阅
- 学术引用格式
- 跨用户知识图谱

### 风险缓解策略

| 风险类型 | 具体风险                   | 缓解策略                         |
| -------- | -------------------------- | -------------------------------- |
| **技术** | 对抗性合成 Prompt 效果不佳 | 准备 3-5 个 Prompt 变体 A/B 测试 |
| **技术** | 大量书签导致超时           | 分批处理 + 范围缩减建议          |
| **市场** | 用户不阅读生成的综述       | 48h 推送提醒 + 摘要预览          |
| **市场** | AI 主动推荐被关闭          | 默认关闭 + 首次体验引导          |
| **资源** | 开发周期超预期             | 先砍 P1 功能，保 P0              |

### 关键验证问题

1. **用户是否阅读综述？** → 48h 阅读完成率
2. **观点分歧是否有价值？** → A/B 测试有/无分歧展示
3. **AI 主动推荐是否被接受？** → 功能开关使用率
4. **学术模式是否有付费意愿？** → 付费转化率

## Functional Requirements

### 综述生成能力 (Core Synthesis)

- FR1: 用户 can 基于文件夹内的书签生成主题综述报告
- FR2: 用户 can 基于标签关联的书签生成主题综述报告
- FR3: 用户 can 基于手动批量选中的书签生成主题综述报告
- FR4: 用户 can 选择综述深度模式（快读/标准/学术）
- FR5: 系统 can 生成四维结构化输出（概述/共识/分歧/盲区）
- FR6: 系统 can 在综述中识别并标注不同来源的观点冲突
- FR7: 系统 can 发现用户收藏中尚未覆盖的知识盲区
- FR8: 系统 can 在生成失败时保存已完成的部分结果

### 综述入口与触发 (Entry Points)

- FR9: 用户 can 通过文件夹右键菜单触发综述生成
- FR10: 用户 can 通过标签右键菜单触发综述生成
- FR11: 用户 can 通过批量选中后的操作栏触发综述生成
- FR12: 用户 can 通过 AI Agent 对话自然语言触发综述生成
- FR13: 系统 can 检测主题聚集并主动推荐综述生成
- FR14: 用户 can 开启或关闭 AI 主动推荐功能

### 生成过程体验 (Generation Experience)

- FR15: 用户 can 在生成过程中看到实时进度条和当前处理维度
- FR16: 用户 can 在生成过程中看到流式输出的部分结果
- FR17: 用户 can 在生成过程中取消任务
- FR18: 系统 can 在内容量过大时给出优化建议（缩小范围/切换模式）
- FR19: 系统 can 显示预估生成时间和 Token 成本
- FR20: 系统 can 在生成前展示将要处理的书签列表

### 综述管理能力 (Report Management)

- FR21: 用户 can 查看所有已生成的综述报告列表
- FR22: 用户 can 按来源类型筛选综述报告
- FR23: 用户 can 按生成时间排序综述报告
- FR24: 用户 can 搜索综述报告（标题和内容）
- FR25: 用户 can 删除不需要的综述报告

### 综述阅读与互动 (Reading & Interaction)

- FR26: 用户 can 在专属详情页阅读完整综述报告
- FR27: 用户 can 在报告中标注重点内容（高亮）
- FR28: 用户 can 为标注添加个人备注
- FR29: 用户 can 查看标注列表并快速定位
- FR30: 用户 can 点击共识/分歧中的来源链接跳转到原始书签
- FR31: 用户 can 折叠/展开四维输出的各个部分

### 导出与分享 (Export & Share)

- FR32: 用户 can 将综述报告导出为 Markdown 格式
- FR33: 用户 can 将综述报告导出为 Obsidian 格式（含双链语法）
- FR34: 用户 can 复制综述报告的分享链接
- FR35: 用户 can 将综述报告的关键洞察一键分享

### 通知与提醒 (Notifications)

- FR36: 用户 can 在综述生成完成后收到通知
- FR37: 用户 can 在综述生成 48h 后收到阅读提醒（如未阅读）
- FR38: 用户 can 配置综述相关的通知偏好
