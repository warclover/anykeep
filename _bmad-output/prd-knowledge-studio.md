# Product Requirements Document - Knowledge Studio (知识工坊)

**Author:** Xiafe

## Executive Summary

### 产品愿景

**Knowledge Studio (知识工坊)** 是 AnyKeep 的核心付费功能模块，将"被动收藏"转化为"主动创作"。它不是一个简单的多文档摘要器，而是一个**基于引用的生成式写作台**——用户的"第一稿生成器"。

> **核心价值主张**：你的收藏不再是信息坟墓，而是知识炼金炉。

Knowledge Studio 替换现有的 Thematic Synthesizer v1.0，通过智能蓝图系统和聊天式修改能力，帮助用户将收藏的 5-200 篇文章快速转化为可发布的内容初稿。

### 核心差异化定位

> **"基于个人知识库生成"——这是 Notion AI 和 Jasper 做不到的**

- **Notion AI**：只能基于当前文档生成内容
- **Jasper/Copy.ai**：基于通用模板生成营销文案
- **Knowledge Studio**：基于**用户长期积累的个人收藏库**进行知识炼金

用户收藏了 3 年的行业文章、研究报告、竞品分析，Knowledge Studio 能将这些沉睡的资产激活，生成具有**个人知识沉淀**的高质量初稿。

### 目标用户

**P0 核心用户：内容创作者**

| 用户类型                | 核心需求              | 付费驱动力            | 优先级    |
| ----------------------- | --------------------- | --------------------- | --------- |
| 内容创作者（博主/UP主） | 快速产出博客/视频大纲 | 聊天式修改 + 博客蓝图 | **P0** ⭐ |
| 知识博主                | 深度分析 + 观点对撞   | 观点对撞机 + 引用追踪 | P1        |
| 职场白领                | 行业报告 + 决策支持   | 专业输出质量          | P1        |
| 自学者                  | 知识内化 + 复习卡片   | Brain-Sync 整合       | P1        |

**P0 用户选择理由**：

- 内容创作者有明确的"产出"需求（文章/视频）
- 产出频率高（周更/日更），付费 ROI 清晰
- 对"效率工具"付费意愿最强

### What Makes This Special

**1. 聊天式修改能力 (Chat-to-Edit) — Pro 核心卖点**

用户选中生成内容的任意段落，通过自然语言指令进行修改：

- "扩写这一段，加入更多案例"
- "用书签 #3 的观点来反驳这里"
- "改写成小红书风格，控制在 200 字以内"

这不是传统的"重新生成"，而是**精准的局部手术**。

**成本控制**：Pro 订阅包含 **50 次/月** 聊天式修改，超出部分 **¥0.5/次**。

**2. 智能蓝图系统 (5 种预设模式)**

| 蓝图          | 用户意图    | 输出特点                   | 免费/Pro |
| ------------- | ----------- | -------------------------- | -------- |
| ⚔️ 观点对撞机 | 决策辅助    | 强制识别观点冲突，客观呈现 | 免费     |
| 📝 博客大纲   | 内容创作    | H1/H2/H3 结构 + SEO 关键词 | Pro      |
| 🐦 社交串烧   | 传播分享    | 10 条连贯文案 + Emoji      | Pro      |
| 📚 终极教程   | How-to 学习 | 去重合并步骤，最全指南     | Pro      |
| 🧠 费曼学习法 | 知识内化    | 用比喻解释复杂概念         | Pro      |

**智能推荐**：基于来源内容 AI 分析，**默认推荐最适合的蓝图**，减少用户选择焦虑。用户可随时切换。

**3. 引用锚点联动 — 建立信任**

每个观点后的 `[1]` 引用，悬停时左侧书签高亮，显示原文出处。解决 AI 时代最大的痛点：**幻觉焦虑**。

**技术前提**：引用数据（`quote_snippet`、位置信息）需持久化到 `synthesis_reports` 表，而非会话级存储。

**4. Brain-Sync 深度整合 — Pro 独享**

综述完成后，一键生成 SM-2 算法驱动的复习卡片，形成"收藏 → 综述 → 复习 → 内化"的知识复利闭环。

### 付费策略

**硬付费墙 + 首次试用 + 转化窗口**：

| 功能            | 免费用户       | Pro 用户                    |
| --------------- | -------------- | --------------------------- |
| 蓝图选择        | 仅"观点对撞机" | 全部 5 个（AI 智能推荐）    |
| 来源数量        | 最多 5 个书签  | 最多 200 个                 |
| 聊天式修改      | ❌             | ✅ (50 次/月，超出 ¥0.5/次) |
| 引用锚点联动    | 静态展示       | 悬停联动 + 原文定位         |
| Brain-Sync 整合 | ❌             | ✅                          |
| 每月综述次数    | 3 次           | 无限                        |
| 写作质量标准    | 基础           | SEO/字数规范                |

**转化策略**：

- **首次体验**：新用户首次可免费体验完整蓝图功能一次
- **付费窗口**：试用后 **7 天内** 付费享 **首月 8 折** 优惠
- **付费墙设计**：展示"完整版生成效果 vs 基础版效果"对比，让用户直观感受价值差异

## User Journeys

### 核心用户特质

Knowledge Studio 的目标用户具备以下「知识工匠型」特质：

1. **追求数据主权**：重视隐私保护，不希望数据被第三方平台掌控，倾向于本地存储解决方案
2. **喜欢深度定制**：乐于探索插件、主题和 CSS 片段，根据个人习惯打造专属工作流，享受「装修」知识空间的过程
3. **具备系统思维**：不满足于碎片化记录，注重知识间的关联，追求构建完整的知识网络
4. **愿意投入学习成本**：认可学习曲线，愿意花时间掌握高级功能和插件使用，追求长期效率提升
5. **跨领域思考者**：常涉及多个领域知识，需要工具帮助打通不同领域间的壁垒，促进交叉创新

### 旅程 1：李明 - 从「收藏家」到「创作者」的蜕变

**用户画像**：科技博主 / 28岁 / 每周产出 1-2 篇深度文章

李明是一位科技领域的独立博主，过去三年他在 AnyKeep 里积累了 800+ 篇收藏——从 AI 论文解读到产品设计方法论。他的 Obsidian 知识库里有完善的 MOC（Map of Content），但每次写文章时，仍然要花 3-4 小时在各处「翻找」素材。

某天深夜，他需要写一篇「AI Agent 技术趋势」的稿件，截稿时间只剩 48 小时。他打开 AnyKeep 的 Knowledge Studio，选中过去半年收藏的 23 篇相关文章，选择「📝 博客大纲」蓝图。

系统在 45 秒内生成了一份结构清晰的大纲，每个论点后面都有 `[1][2][3]` 引用标记。他把鼠标悬停在 `[7]` 上，左侧书签列表中「LangChain vs AutoGPT 对比」这篇文章高亮闪烁——原来这个观点来自他三个月前收藏的一篇英文博客。

他选中第三段，输入「用书签 #12 的案例来扩写这里，控制在 300 字」。3 秒后，段落被精准改写，新增的内容完美融入上下文。

两小时后，初稿完成。他点击「导出到 Obsidian」，文章连同所有双链引用一起导入他的知识库。这是他第一次感觉到：**收藏终于不再是信息坟墓。**

**旅程揭示的能力需求**：

- 多书签批量选择 + 蓝图智能推荐
- 引用锚点悬停联动
- 聊天式精准修改（指定书签引用）
- Obsidian 双链格式导出

## Innovation & Novel Patterns

### 检测到的创新领域

**核心创新：基于个人知识库的生成式写作**

| 维度       | Knowledge Studio          | YouMind       | Get笔记       | Notion AI |
| ---------- | ------------------------- | ------------- | ------------- | --------- |
| 知识来源   | 用户长期收藏库 (3年+积累) | 用户笔记      | 用户笔记      | 当前文档  |
| 生成上下文 | 跨文档、跨时间            | 单笔记/笔记组 | 单笔记/笔记组 | 单文档    |
| 引用追踪   | 悬停联动 + 原文定位       | 基础引用      | 基础引用      | 无        |
| 精准修改   | Chat-to-Edit 指定书签     | ❌            | ❌            | 通用改写  |

**差异化定位**：

- **YouMind/Get笔记**：侧重「笔记整理」→「知识卡片」
- **Knowledge Studio**：侧重「收藏激活」→「创作初稿」
- **核心差异**：我们处理的是**外部收藏内容**（文章、博客、论文），而非用户自己写的笔记

---

### 技术验证方案

**引用追踪准确性目标**：

| 指标       | 目标值 | 说明                 |
| ---------- | ------ | -------------------- |
| 引用召回率 | ≥ 95%  | 每个观点都能找到来源 |
| 引用精准率 | ≥ 90%  | 引用的来源与观点相关 |
| 定位准确率 | ≥ 85%  | 能定位到原文具体段落 |

**无法追溯来源的处理策略**：

生成内容分为两类标识：

1. `[1][2][3]` - 有明确来源，悬停显示原文
2. `[AI]` - AI 综合推理生成，无单一来源

示例：

> "AI Agent 的核心价值在于自主决策能力[1][2]，未来可能会演化出多模态交互形式[AI]。"

### 风险兜底策略

**场景：用户收藏内容质量差**

| 风险场景 | 检测机制        | 用户提示                                 | 系统行为       |
| -------- | --------------- | ---------------------------------------- | -------------- |
| 内容过短 | 平均字数 < 200  | "部分素材内容较短，建议补充更详细的文章" | 降低权重或排除 |
| 内容重复 | 相似度 > 80%    | "检测到 3 篇内容高度相似，已自动去重"    | 合并处理       |
| 主题分散 | 语义聚类 > 5 个 | "素材主题较分散，建议聚焦到 2-3 个主题"  | 显示主题分布   |
| 语言混杂 | 多语言检测      | "检测到中英混合内容，将分别处理"         | 分语言生成     |

**智能素材评分系统**：

生成前显示素材健康度评分：

```
📊 素材健康度：72/100
├─ 内容丰富度：★★★★☆ (平均 1,200 字)
├─ 主题聚焦度：★★★☆☆ (3 个主题簇)
├─ 来源多样性：★★★★★ (8 个不同平台)
└─ 时效性：★★★☆☆ (30% 内容超过 1 年)

💡 建议：补充 2-3 篇近期文章以提升时效性
```

## Web App Specific Requirements

Knowledge Studio 作为 AnyKeep 的核心 Pro 功能模块，技术上复用现有 Next.js 14+ 技术栈，属于 Brownfield 项目（替换现有 Thematic Synthesizer）。

### 实时通信架构

**SSE Streaming 设计**：

```typescript
interface StreamChunk {
  type: "text" | "progress" | "citation" | "error" | "done";
  data: {
    text?: string; // 生成的文本片段
    percent?: number; // 进度百分比
    step?: string; // 当前步骤描述
    citations?: Citation[]; // 引用信息
    message?: string; // 错误信息
  };
}
```

**断线重连策略**：

- 自动重连（3 次重试，指数退避）
- 断点续传（基于 `last_event_id`）
- 离线提示 + 缓存已生成内容

## Project Scoping & Phased Development

### MVP 策略与理念

**MVP 类型**：体验型 MVP (Experience MVP)

> 核心目标：让用户在首次使用时感受到「收藏被激活」的惊艳时刻

**关键决策点**：

- **Week 2 Checkpoint**：评估 Chat-to-Edit 技术验证结果，决定 MVP 是否包含完整版
- **转化目标**：初期 3%（种子用户），迭代后达 5%

**资源需求**：

- 研发：1 全栈 + 0.5 前端（4-5 周）
- 设计：0.5 人力（UI 复用现有组件）

---

### Phase 1: MVP 核心功能

**目标**：验证「蓝图生成 + 首次试用」转化漏斗

| 功能模块          | 范围              | 说明                                       |
| ----------------- | ----------------- | ------------------------------------------ |
| **蓝图系统**      | 5 个蓝图          | 观点对撞机（免费）+ 4 个 Pro 蓝图          |
| **AI 推荐**       | 基于书签数量+标签 | 推荐最合适的蓝图                           |
| **引用锚点**      | ⚡ Tooltip-Only   | 悬停显示引用来源，**不含**左侧面板高亮联动 |
| **Chat-to-Edit**  | ⚡ Week 2 决策    | 基础版（单段修改）或延期到 Phase 2         |
| **首次试用**      | ✅ 已提前         | 免费用户完整体验 1 次（Party Mode 建议）   |
| **硬付费墙**      | Feature Flag      | Pro 功能访问控制                           |
| **SSE 流式**      | 实时生成          | StreamChunk 接口                           |
| **配额管理**      | 基础版            | 显示剩余次数，超额提示                     |
| **Markdown 导出** | 完整              | 含引用标记                                 |

**Week 2 Checkpoint 决策矩阵**：

| 条件                    | Chat-to-Edit 决策                    |
| ----------------------- | ------------------------------------ |
| 技术验证通过 + 工期允许 | MVP 包含基础版                       |
| 技术验证通过 + 工期紧张 | MVP 精简版（仅改写），完整版 Phase 2 |
| 技术验证阻塞            | 延期到 Phase 2                       |

---

### Phase 2: Growth 增长功能

**目标**：提升留存与付费价值

| 功能模块                | 说明                            |
| ----------------------- | ------------------------------- |
| **引用锚点增强**        | 左侧面板高亮联动 + 原文段落定位 |
| **Chat-to-Edit 完整版** | 指定书签引用、多段批量修改      |
| **按量计费**            | ¥0.5/次超额，无缝衔接           |
| **Obsidian 导出**       | 双链格式 `[[书签标题]]`         |
| **Brain-Sync 整合**     | 一键生成复习卡片                |
| **素材健康评分**        | 生成前质量预估                  |

---

### Phase 3: Expansion 扩展功能

**目标**：规模化与自动化

| 功能模块               | 说明                    |
| ---------------------- | ----------------------- |
| **7 天转化窗口自动化** | 邮件提醒 + 折扣推送     |
| **账单明细**           | 使用统计 + 消费记录     |
| **模板自定义**         | 用户自建蓝图 Prompt     |
| **增量更新**           | 书签变更后局部重新生成  |
| **内化率追踪**         | Brain-Sync 学习效果统计 |

---

### 风险缓解策略

| 风险类型     | 风险描述                    | 缓解措施                                        |
| ------------ | --------------------------- | ----------------------------------------------- |
| **技术风险** | Chat-to-Edit 上下文管理复杂 | Week 2 Checkpoint 决策点；基础版先行            |
| **技术风险** | 引用定位准确率不达标        | Tooltip-only MVP 降低 UI 复杂度；Alpha 阶段验证 |
| **市场风险** | 用户不理解「蓝图」概念      | 首次试用引导 + AI 推荐降低学习成本              |
| **市场风险** | 转化率低于预期              | 初期目标 3%，迭代优化                           |
| **资源风险** | 工期超出 5 周               | 优先级砍 Phase 2 功能；Chat-to-Edit 可延期      |

## Functional Requirements

> **能力契约**：此列表定义产品的完整能力边界。UX 设计师只设计此处列出的能力，架构师只支持此处列出的能力，开发只实现此处列出的能力。

---

### 蓝图系统 (Blueprint System)

- **FR1**: 用户 can 从 5 种预设蓝图中选择一种进行内容生成
- **FR2**: 系统 can 基于用户选中的书签内容自动推荐最合适的蓝图
- **FR3**: 免费用户 can 使用「观点对撞机」蓝图生成内容
- **FR4**: Pro 用户 can 使用所有 5 种蓝图（观点对撞机、博客大纲、社交串烧、终极教程、费曼学习法）
- **FR5**: 系统 can 为每种蓝图使用不同的 Prompt 模板生成差异化输出

---

### 内容生成 (Content Generation)

- **FR6**: 用户 can 选择 5-200 个书签作为生成素材
- **FR7**: 系统 can 将多书签内容综合生成一份结构化文档
- **FR8**: 系统 can 通过 SSE 流式传输实时展示生成进度
- **FR9**: 用户 can 在生成过程中看到当前步骤和完成百分比
- **FR10**: 系统 can 在网络断线后自动重连并恢复生成
- **FR11**: 用户 can 取消正在进行的生成任务

---

### 引用追踪 (Citation Tracking)

- **FR12**: 系统 can 为生成内容中的每个观点标注引用来源（如 `[1][2]`）
- **FR13**: 用户 can 悬停引用标记查看来源书签信息（Tooltip）
- **FR14**: 系统 can 区分「有明确来源」和「AI 综合推理」两类内容（`[N]` vs `[AI]`）
- **FR15**: 系统 can 持久化引用数据到数据库以支持后续查看
- **FR16**: Pro 用户 can 通过引用悬停联动高亮左侧书签列表中的来源（Phase 2）

---

### 聊天式修改 (Chat-to-Edit)

- **FR17**: Pro 用户 can 选中生成内容的任意段落
- **FR18**: Pro 用户 can 通过自然语言指令修改选中内容
- **FR19**: 用户 can 在修改指令中引用特定书签（如「用书签 #3 的观点」）
- **FR20**: 系统 can 保持修改后内容与上下文的连贯性
- **FR21**: 系统 can 记录每次修改消耗的配额

---

### 付费与配额 (Payment & Quota)

- **FR22**: 系统 can 通过 Feature Flag 区分免费用户和 Pro 用户的功能权限
- **FR23**: 免费用户 can 获得首次完整功能试用机会（1 次）
- **FR24**: 系统 can 限制免费用户每月生成次数（3 次）
- **FR25**: 系统 can 限制免费用户单次选择书签数量（5 个）
- **FR26**: Pro 用户 can 使用 50 次/月 Chat-to-Edit 配额
- **FR27**: 系统 can 实时显示用户剩余配额
- **FR28**: 系统 can 在用户接近配额上限时发出温和提醒
- **FR29**: Pro 用户 can 超额使用 Chat-to-Edit（按量计费 ¥0.5/次）（Phase 2）
- **FR30**: 用户 can 查看账单明细和使用统计（Phase 3）

---

### 导出功能 (Export)

- **FR31**: 用户 can 将生成内容导出为 Markdown 格式
- **FR32**: Markdown 导出 can 保留引用标记
- **FR33**: Pro 用户 can 将内容导出为 Obsidian 双链格式（Phase 2）
- **FR34**: Obsidian 导出 can 自动生成 `[[书签标题]]` 格式的双向链接（Phase 2）

---

### Brain-Sync 整合 (Brain-Sync Integration)

- **FR35**: Pro 用户 can 将生成内容一键转化为 Brain-Sync 复习卡片（Phase 2）
- **FR36**: 系统 can 自动从综述内容中提取知识点生成卡片
- **FR37**: 复习卡片 can 链接回原始书签来源
- **FR38**: 用户 can 查看基于 Brain-Sync 的知识内化率统计（Phase 3）

---

### 素材管理 (Material Management)

- **FR39**: 系统 can 在生成前评估素材健康度（Phase 2）
- **FR40**: 系统 can 检测并提示内容过短、重复、主题分散等问题
- **FR41**: 系统 can 自动去重高度相似的书签内容
- **FR42**: 用户 can 查看素材健康度评分和改进建议

---

### 首次试用与转化 (Trial & Conversion)

- **FR43**: 新用户 can 免费体验一次完整的 Pro 功能
- **FR44**: 系统 can 向试用后用户展示 Pro 版效果对比预览
- **FR45**: 系统 can 在试用后 7 天内向用户发送转化提醒（Phase 3）
- **FR46**: 系统 can 向符合条件的用户提供首月折扣（Phase 3）
