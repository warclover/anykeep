# AnyKeep 开发者工具页面移除方案

> **版本**: v1.0  
> **日期**: 2026-01-30  
> **目标**: 移除已完成调试目的的三个开发者工具页面

---

## 一、概述

### 1.1 背景

以下三个开发者工具页面已完成其调试任务，现计划从项目中移除：

1. **智能分类页面** (`/classification-debugger`) - V3.0 算法参数调优与准确性测试工具
2. **分类对比页面** (`/dev/classification-compare`) - V4.2 与 Lite V2 分类算法对比测试
3. **摘要调试页面** (`/debug/ai-summary`) - AI 摘要参数配置和实时测试

### 1.2 移除原则

- **完全清理**: 删除所有相关代码文件、组件、API 路由
- **保持稳定**: 确保移除不影响生产功能
- **可回滚**: 通过 Git 可轻松回滚
- **文档记录**: 保留必要的调试经验文档

## 三、执行步骤

### 阶段 1: 准备工作 (5 分钟)

**1. 创建备份分支**

```bash
git checkout -b backup/dev-tools-removal-$(date +%Y%m%d)
git push origin backup/dev-tools-removal-$(date +%Y%m%d)
```

**2. 创建工作分支**

```bash
git checkout main
git pull origin main
git checkout -b feat/remove-debug-tools
```

**3. 确认当前状态**

```bash
# 确认这些页面存在且可以访问
# 在浏览器中测试：
# - http://localhost:3000/classification-debugger
# - http://localhost:3000/dev/classification-compare
# - http://localhost:3000/debug/ai-summary
```

---

### 阶段 2: 删除文件 (10 分钟)

**按顺序执行以下命令**:

```bash
# 1. 删除智能分类页面
rm -f src/app/(main)/classification-debugger/page.tsx
rmdir src/app/(main)/classification-debugger

# 2. 删除分类对比页面
rm -f src/app/(main)/dev/classification-compare/page.tsx
rmdir src/app/(main)/dev/classification-compare

# 3. 删除摘要调试页面
rm -f src/app/(main)/debug/ai-summary/page.tsx
rmdir src/app/(main)/debug/ai-summary
# 如果 debug 目录为空，也删除它
rmdir src/app/(main)/debug 2>/dev/null || true

# 4. 删除 API 路由
rm -f src/app/api/classification/debug/route.ts
# 如果 debug 目录为空，删除它
rmdir src/app/api/classification/debug 2>/dev/null || true

rm -f src/app/api/dev/classification-compare/route.ts
# 如果 classification-compare 目录为空，删除它
rmdir src/app/api/dev/classification-compare 2>/dev/null || true

rm -f src/app/api/internal/debug/ai-summary/route.ts
# 如果 ai-summary 目录为空，删除它
rmdir src/app/api/internal/debug/ai-summary 2>/dev/null || true
# 如果 debug 目录为空，删除它
rmdir src/app/api/internal/debug 2>/dev/null || true

# 5. 删除调试组件
rm -f src/components/debug/ai-summary-debug-page.tsx
# 如果 debug 目录为空，删除它
rmdir src/components/debug 2>/dev/null || true

# 6. 删除调试配置文件
rm -f src/lib/classification/config/debug-config-store.ts
rm -f src/hooks/core/use-debug-config.ts
```

## 四、回滚方案

如果移除后发现问题，可以通过以下方式回滚：

### 方式一：回滚到备份分支

```bash
git checkout backup/dev-tools-removal-YYYYMMDD
git checkout -b recover/debug-tools
# 恢复所需文件
git cherry-pick <commit-hash>
```

### 方式二：还原特定提交

```bash
git revert <commit-hash>
```

### 方式三：从备份分支恢复特定文件

```bash
git checkout backup/dev-tools-removal-YYYYMMDD -- src/app/(main)/classification-debugger/page.tsx
# ... 恢复其他需要的文件
```

## 五、潜在风险与缓解

| 风险 | 影响 | 缓解措施 | 优先级 |
|------|------|----------|--------|
| AI 摘要配置依赖 | AI 摘要可能使用了 debug-config-store | 测试创建收藏功能，确保 AI 摘要正常 | 高 |
| 测试代码依赖 | 测试套件可能引用了调试工具 | 运行完整测试套件验证 | 中 |
| 其他页面链接 | 其他页面可能有链接到调试工具 | 全局搜索硬编码的链接 | 低 |
| API 路由依赖 | 其他服务可能调用调试 API | 检查 API 调用记录和日志 | 中 |

## 七、后续建议

### 7.1 保留调试经验

建议保留以下文档作为历史记录：

```
docs/archive/
  ├─ 智能分类调试工具使用总结.md
  ├─ 分类对比测试结果分析.md
  └─ AI摘要参数优化经验.md
```

### 7.2 开发新调试工具的建议

未来如需创建类似的调试工具，建议遵循以下原则：

1. **独立目录**: 将调试工具放在 `src/features/debug/` 下
2. **环境变量控制**: 通过环境变量控制功能开关
3. **完全解耦**: 不依赖生产代码，生产代码也不依赖调试工具
4. **清晰标记**: 在代码中明确标记"临时调试代码"
5. **文档先行**: 在创建时就规划好移除方案

### 7.3 替代方案

移除这些工具后，如果需要类似功能，可以考虑：

1. **分类调试**: 使用日志系统 + Grafana 监控
2. **算法对比**: 创建独立的基准测试脚本（不在 Web UI 中）
3. **摘要测试**: 使用 Postman/curl 直接测试 API
