### 4.2 Command Bar

```tsx
// 文件：src/components/knowledge-studio/command-bar.tsx

export function CommandBar({ onSubmit, isProcessing }: CommandBarProps) {
  const [input, setInput] = useState('');

  return (
    <div className="border-t bg-background p-4">
      <div className="flex items-center gap-2 bg-muted rounded-full px-4 py-2">
        <MessageSquare className="w-5 h-5 text-muted-foreground" />
        <input
          type="text"
          value={input}
          onChange={(e) => setInput(e.target.value)}
          onKeyDown={(e) => e.key === 'Enter' && handleSubmit()}
          placeholder="输入指令...（如：润色第二段、把开头改得更吸引人）"
          className="flex-1 bg-transparent outline-none text-sm"
          disabled={isProcessing}
        />
        <Button size="sm" onClick={handleSubmit} disabled={!input.trim() || isProcessing}>
          {isProcessing ? <Loader2 className="w-4 h-4 animate-spin" /> : <Send className="w-4 h-4" />}
        </Button>
      </div>
    </div>
  );
}
```

**支持的指令示例**：
- "润色第二段"
- "扩写引言部分"
- "把结尾改成号召行动的语气"
- "缩短到 500 字以内"

## 十一、风险评估

### 11.1 风险矩阵

| 风险项 | 等级 | 影响 | 缓解措施 |
|--------|------|------|----------|
| 书签列表缺少批量选择组件 | 🟠 中 | ���新建组件，增加工作量 | Phase 2 预留额外 1 天 |
| 路由 `/result` 与 `[id]` 冲突 | 🟠 中 | 动态路由可能误匹配 | 改用 `/generating` 路径 |
| Synthesis 与 KS 双向依赖 | 🟠 中 | 改造可能破坏集成 | 只改 UI，不动业务逻辑 |
| AI Skills 依赖 Synthesis API | 🔴 高 | 修改 API 格式会导致 Skills 失效 | 保持 API 响应格式不变 |
| 数据库表结构兼容性 | 🟢 低 | 新功能需兼容现有字段 | 复用现有字段，不新增迁移 |
