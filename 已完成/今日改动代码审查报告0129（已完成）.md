## 二、按模块审查

### 1. Folders API (`src/app/api/v1/folders/`)

**改动**：查询参数从 `.optional().transform().default(x)` 改为 `.default("...").transform(...)`。

- **评价**：合理。Zod 中先 `default` 再 `transform`，能保证输入始终是字符串再转成布尔，避免 `undefined` 与 `transform` 的交互问题。
- **建议**：无。

---

### 2. AI Agent / AI Skills 类型

**改动**：  
`ToolDefinition.parameters`、`BaseSkill.inputSchema`、`ISkill.inputSchema` 从 `z.ZodSchema<T>` 改为 `z.ZodType<T, z.ZodTypeDef, unknown>`，并补充注释。

- **评价**：正确支持带 `.optional().default()` 的 schema，注释说明了为何用 `ZodType`。
- **建议**：无。

---

### 3. Unified Engine (`unified-engine.ts`)

**改动**：  
- 本地定义 `WorkflowExecuteResult`（替代已移除的 workflow 模块）。  
- `result.executionId ?? ""` 避免 `undefined`。

- **评价**：兼容性处理合理。
- **建议**：若多处使用该类型，可考虑抽到 `@/lib/workflow-lite` 或共享 types 文件，避免重复定义。

---

### 4. Browser Bookmark 导入 (`import-session-manager.ts`)

**改动**：  
移除对 `emitBrowserBookmarkImportCompleted` 的调用，改为注释说明已迁移到 workflow-lite；保留 `_isFirstImport` 计算。

- **评价**：迁移说明清晰，事件触发移除得当。
- **建议**：  
  - `_isFirstImport` 当前未被使用，属死代码。若短期内不会用于 workflow-lite，建议**直接删除**该变量及计算，减少干扰。  
  - 若确定会在 workflow-lite 里用「是否首次导入」，可在注释里写明「预留供 workflow-lite 使用」，并考虑在 workflow-lite 接好后立刻用上，避免长期未用。

---

### 5. Email 服务与周报模板

**改动**：  
- `email.service.ts`：`digest.metadata?.persona` 改为 `(digest.metadata?.persona as string) || "default"`。  
- `weekly-digest.tsx`：Preview 使用 `aiSummary?.slice(0, 50) ?? "本周知识回顾"`。

- **评价**：  
  - 解决了 `persona` 类型与默认值问题。  
  - 周报预览在无摘要时有合理兜底。
- **建议**：  
  - 若 `metadata.persona` 在类型定义里是可辨识的联合类型，可优先用类型收窄或更精确类型，减少 `as string`；若当前类型较宽，现状可接受。  
  - 保持「UI 文案走常量/配置」的规范，若 "本周知识回顾" 会复用，可提到常量里。

---

### 6. Ledger 模块

**financial-ledger.generator.ts**

- `id: String(b.id)`、`time: this.formatTime(b.created_at ?? ...)`、`originalTime: b.created_at ?? undefined`：空值处理合理，与 `LedgerItem` 一致。
- `.insert(entriesToInsert as any)` 并加 `eslint-disable`：能跑，但丢失类型安全。

**knowledge-ledger.generator.ts**

- 同样使用 `.insert(entriesToInsert as any)`。  
- 文案修复：「你好，知识探索者！」正确显示。

**ledger.types.ts**

- 为 `LedgerItem` 增加 `originalTime?: string` 及注释，与 generator 使用方式一致。

- **建议（重要）**：  
  - 尽量避免长期使用 `as any`。  
  - 若 Supabase 生成的 `ledger_entries` 插入类型与 `entriesToInsert` 结构一致，可尝试：  
    - 用 `satisfies` 或显式类型标注 `entriesToInsert`，使其符合 `Database["public"]["Tables"]["ledger_entries"]["Insert"]`（或等价类型）；  
    - 或写一个窄一点的类型断言函数，例如 `as LedgerEntryInsert[]`，在函数内做必要校验。  
  - 这样既保留类型检查，又避免 `no-explicit-any` 的长期豁免。

### 7. Workflow-Lite Runner (`runner.ts`)

**改动**：  
- 每 5 分钟清理 `executionHistory` 中过期 key，避免长期泄漏。  
- 去重跳过时用 `createLogger(taskName, "skip").info(...)` 替代 `console.info`。

- **评价**：  
  - 定期清理逻辑清晰，能有效限制 Map 体积。  
  - 与项目「统一 logger」的规范一致。
- **建议**：  
  - `createLogger(taskName, "skip")` 中第二个参数本意是 traceId，这里用 `"skip"` 语义上更像「场景标识」。若团队约定第二参可为场景标签，可保持；否则可考虑：  
    - 使用固定 traceId，例如 `createLogger(taskName, "dedup-skip")`，或  
    - 在 logger 封装层增加「无 trace 的 info」用法（若后续有类似需求再抽象）。  
  当前实现功能上没问题。
