## 2. 使用场景分析

### 2.1 知识萃取的典型场景

```
场景1: 学术研究
用户：研究生，收藏了15篇关于"元宇宙"的论文
需求：找到学术界的共识和争议点，发现研究空白
使用：选择「学术模式」+「批判式」输出
输出：概述 + 5个共识点 + 3个分歧点 + 4个盲区建议

场景2: 投资决策
用户：投资人，收藏了10篇关于"新能源汽车"的分析
需求：对比不同机构的观点，找到投资盲区
使用：选择「标准模式」+「对比式」输出
输出：多角度对比 + 共识与分歧 + 市场盲区

场景3: 快速学习
用户：职场人士，收藏了8篇"时间管理"文章
需求：快速提取核心观点和方法论
使用：选择「快读模式」+「概要式」输出
输出：3-5句核心要点 + 方法论总结
```

**适用人群**：学习者、研究者、分析师、需要批判性思维的用户

### 2.2 知识工坊的典型场景

```
场景1: 公众号创作
用户：自媒体作者，收藏了5篇"AI绘画"相关内容
需求：快速写一篇1500字的公众号文章
使用：选择「博主」蓝图 + 文章风格
输出：完整可发布的文章（标题+开篇+正文+结尾）

场景2: 产品需求文档
用户：产品经理，收藏了3篇"AI助手"产品分析
需求：写一份PRD文档
使用：选择「PRD文档」蓝图
输出：结构化的PRD（背景+需求+功能+验收）

场景3: 工作周报
用户：项目经理，整理本周工作笔记
需求：生成周报汇报材料
使用：选择「周报月报」蓝图
输出：工作总结 + 成果展示 + 下周计划

场景4: 竞品分析
用户：运营人员，收藏了6个竞品信息
需求：输出SWOT分析报告
使用：选择「SWOT分析」蓝图
输出：Strengths/Weaknesses/Opportunities/Threats 四象限分析
```

**适用人群**：内容创作者、产品经理、运营人员、职场人士

## 3. 技术架构对比

### 3.1 数据层

**共用表**：`synthesis_reports`
- 知识萃取使用字段：`overview`, `consensus`, `divergence`, `blind_spots`, `source_type`, `depth_mode`
- 知识工坊使用字段：`content`, `blueprint_type`, `citations`, `generation_metadata`
- 标识字段：通过 `blueprint_type` 是否为 null 区分

**结论**：✅ 已在数据库层面实现共存（2026-01-05迁移）

### 3.2 AI实现

| 层面 | 知识萃取 | 知识工坊 |
|------|---------|---------|
| **Skill** | ✅ `thematic-synthesis.skill.ts`<br>+ `knowledge-extract.skill.ts` | ❌ 无独立Skill（直接调用AI） |
| **编排** | OrchestrationSkill | 蓝图 Prompt 系统 |
| **流式输出** | SSE（5种事件） | SSE（进度事件） |
| **模型选择** | 按深度模式选择 | 按蓝图复杂度选择 |

**结论**：🟡 技术实现相似但独立，知识萃取更工程化

### 3.3 代码模块

```
知识萃取：
├── src/lib/synthesis/                    # 核心逻辑
│   ├── types.ts                         # 类型定义
│   ├── constants.ts
│   └── generator.ts                     # 生成器
├── src/components/synthesis/             # UI组件（22个）
├── src/app/(main)/synthesis/            # 页面路由
└── src/app/api/synthesis/               # API路由

知识工坊：
├── src/lib/knowledge-studio/             # 核心逻辑
│   ├── v2/                              # V2架构
│   ├── incremental/                     # 增量生成
│   ├── analytics/                       # 学习统计
│   └── mastery/                         # 掌握度评估
├── src/components/knowledge-studio/      # UI组件
├── src/app/(main)/knowledge-studio/     # 页面路由
└── src/app/api/knowledge-studio/        # API路由
```

**结论**：❌ 完全独立的代码模块，合并成本高

## 4. 用户价值分析

- "我收藏了很多文章，但不知道哪些是共识，哪些有争议"

| 价值点 | 说明 | 替代性 |
|--------|------|--------|

**核心用户痛点**：
- "我需要快速出一篇公众号文章/周报/PRD"
- "我想要一稿多发，适配不同平台风格"
- "我想保存常用的写作模板"

## 5. 产品定位冲突分析

### 5.1 菜单层面的混淆

**问题**：两者都在「学习中心」，且都涉及"知识"处理

```
学习中心
├── 知识回顾 (Brain-Sync)
├── 知识萃取 (Synthesis)      ← "从书签中提取知识"
├── 知识工坊 (Knowledge Studio) ← "生成知识报告"
└── 学习助手 (Learning Hub)
```

**用户困惑点**：
- "萃取"和"工坊"有什么区别？
- 我该用哪个？
- 是不是功能重复？

### 5.2 命名冲突

**内部命名冲突**：
- **知识萃取功能**：`/synthesis`（主题合成器）
- **知识萃取Skill**：`knowledge-extract.skill.ts`（AI助手能力，与synthesis不同）
- **知识工坊**：`/knowledge-studio`

**建议重命名**：
```
现在：知识萃取 + 知识工坊
方案1：主题综述 + 内容工坊
方案2：知识整合 + 创作工坊
方案3：多源对比 + 场景创作
```

## 6. 整合可行性评估

### 6.1 方案A：完全合并（❌ 不推荐）

**合并路径**：将知识萃取作为知识工坊的一种蓝图

```
知识工坊统一入口
├── Step 1: 选择素材
├── Step 2: 选择输出类型
│   ├── 【默认4种】文章/摘要/总结/方案
│   ├── 【高级蓝图】PRD/周报/SWOT/OKR...
│   └── 【学术蓝图】主题综述（原知识萃取）  ← 新增
│        ├── 输出：四维结构
│        ├── 深度：快读/标准/学术
│        └── 风格：概要/叙事/对比/批判
└── Step 3: 获取结果
```

**优点**：
- ✅ 统一入口，降低用户选择成本
- ✅ 代码复用，减少维护成本
- ✅ V3规划正好是简化架构

**缺点**：
- ❌ 知识萃取的四维结构与其他蓝图差异太大，强行合并会破坏体验
- ❌ "盲区发现"、"QA问答"等功能难以融入蓝图体系
- ❌ 丢失知识萃取的学术/研究定位
- ❌ 开发工作量大（需重构知识萃取）

**结论**：❌ 不推荐完全合并

### 6.3 方案C：轻量化知识萃取 + 强化知识工坊（🟡 折中）

**策略**：简化知识萃取为轻量级工具，保留核心价值

#### 调整方向

```
主题综述（轻量化）
├── 输入：选择素材（简化流程）
├── 输出：只保留核心
│   ├── 📊 核心观点（合并原共识+分歧）
│   └── 🔍 知识盲区（保留）
└── 移除：深度模式、输出风格选择（固定为标准+叙事）

内容工坊（强化）
├── 新增「对比分析」蓝图（吸收知识萃取的对比能力）
├── 保留14种场景蓝图
└── 继续V3极简化改造
```

#### 技术实现

**将知识萃取改造为一个快捷入口**：
- 去掉配置页面，只保留素材选择
- 一键生成固定格式（核心观点 + 知识盲区）
- 生成后引导用户到内容工坊进一步创作

**优点**：
- ✅ 降低知识萃取的学习成本
- ✅ 保留"盲区发现"核心价值
- ✅ 减少维护负担

**缺点**：
- ❌ 丢失深度用户（学术研究者）的高级能力
- ❌ 四维结构是核心卖点，简化后价值降低

### 6.4 方案D：移除知识萃取（❌ 不推荐）

**假设**：知识工坊可以完全替代知识萃取

**分析**：
- ❌ "盲区发现"是知识萃取的独特价值，知识工坊无此能力
- ❌ 四维结构（共识/分歧/盲区）是批判性思维的体现，不应丢失
- ❌ 学术研究场景用户会流失
- ❌ QA问答功能会丢失

**结论**：❌ 不推荐移除

---

### 6.5 方案E：移除知识工坊（❌ 不推荐）

**假设**：知识萃取可以通过增加模板替代知识工坊

**分析**：
- ❌ 知识工坊的14种蓝图是场景化设计，知识萃取不适合
- ❌ 素材评分、聊天编辑、模板管理是知识工坊的核心价值
- ❌ 内容创作者、职场用户会流失
- ❌ V3规划投入会浪费

**结论**：❌ 不推荐移除

## 8. 风险与缓解

### 8.1 用户混淆风险

**风险**：改名后，老用户可能找不到功能

**缓解**：
- 在旧位置显示3个月的"迁移提示"
- 帮助文档中添加"功能已更名"说明
- 发布更新公告

### 8.2 技术债务风险

**风险**：保留两套代码增加维护成本

**缓解**：
- 识别可共用的模块（素材选择器、导出功能等）
- 逐步重构公共逻辑到 `src/lib/content-generation/`
- 建立统一的AI调用层

### 8.3 产品定位风险

**风险**：市场上竞品如何定位这两类功能？

**竞品分析**：
- Notion AI：只有场景化模板（类似内容工坊）
- Perplexity：只有问答和搜索（无综述能力）
- ChatGPT：通用AI，无结构化输出
- 飞书文档AI：场景化模板（类似内容工坊）

**结论**：
- ✅ "主题综述"的四维结构是差异化优势（市场罕见）
- ✅ "内容工坊"的14种蓝图也是竞争力（但竞品多）
- 🎯 建议：**主推"主题综述"作为差异化卖点**
