# 用户体验反馈系统 - 落地实现方案 (v2.0 解耦版)

基于项目现有架构，本方案采用 **Context Provider + Hook** 模式进行重构，旨在实现核心逻辑与业务组件的完全解耦，支持即插即用的无缝集成。

---

## 一、系统架构：解耦与集成

### 1.1 设计理念

- **全局单例 (Singleton UI)**: 反馈弹窗在全局 `Layout` 中只渲染一次，通过状态控制显示。
- **动态上下文 (Dynamic Context)**: 允许调用方在触发时注入特定的业务上下文（如当前收藏 ID、错误堆栈），而无需修改反馈系统核心代码。
- **Hook 驱动 (Hook Driven)**: 任何组件只需一行代码 `useFeedback().open(...)` 即可唤起反馈。

### 1.2 模块依赖图

```mermaid
graph TD
    App[应用根组件] --> Provider[FeedbackProvider]
    Provider --> Dialog[FeedbackDialog (UI)]
    Provider --> Service[FeedbackService (Logic)]

    ComponentA[任意业务组件] --> Hook[useFeedback]
    ComponentB[错误边界] --> Hook
    ComponentC[悬浮按钮] --> Hook

    Hook -.->|Dispatch| Provider
```

## 二、数据库设计 (保持通用性)

数据库设计保持通用，利用 JSONB 存储所有业务相关的动态信息，避免硬编码业务字段。

```sql
-- 文件: supabase/migrations/YYYYMMDD000001_add_user_feedback.sql

CREATE TABLE user_feedbacks (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,

  -- 基础分类
  type TEXT NOT NULL CHECK (type IN ('bug', 'complaint', 'suggestion')),
  category TEXT,

  -- 核心内容
  title TEXT NOT NULL,
  description TEXT NOT NULL,

  -- 动态上下文 (解耦的关键：不预定义业务字段)
  -- 示例: { "route": "/bookmarks", "bookmark_id": "xxx", "error_code": "500" }
  context JSONB DEFAULT '{}',

  -- 附件与状态
  attachments TEXT[] DEFAULT '{}',
  status TEXT NOT NULL DEFAULT 'pending',
  priority TEXT DEFAULT 'normal',

  -- 系统字段
  admin_notes TEXT,
  resolution TEXT,
  resolved_at TIMESTAMPTZ,
  is_anonymous BOOLEAN DEFAULT false,
  created_at TIMESTAMPTZ DEFAULT now(),
  updated_at TIMESTAMPTZ DEFAULT now()
);

-- RLS 策略 (略，同原方案)
```

## 三、类型定义 (抽象化)

移除具体的业务字段（如 `related_bookmark_id`），改为通用键值对。

```typescript
// 文件: src/types/user-feedback.ts

export type FeedbackType = "bug" | "complaint" | "suggestion";

// 通用上下文接口
export interface FeedbackContext extends Record<string, unknown> {
  page_path?: string;
  user_agent?: string;
  app_version?: string;
  // 允许任意业务字段注入
  [key: string]: unknown;
}

export interface OpenFeedbackOptions {
  type?: FeedbackType;
  title?: string; // 预填充标题
  description?: string; // 预填充描述
  context?: FeedbackContext; // 注入业务上下文
  screenshot?: string; // 自动截图(Base64)
}

export interface FeedbackStore {
  isOpen: boolean;
  options: OpenFeedbackOptions;
  open: (options?: OpenFeedbackOptions) => void;
  close: () => void;
}
```

## 四、核心集成方案 (Provider + Hook)

### 4.1 全局 Provider (集成点)

在 `src/components/feedback/feedback-provider.tsx` 中实现：

```tsx
"use client";

import { createContext, useContext, useState, useCallback } from "react";
import { UserFeedbackDialog } from "./user-feedback-dialog";
import { FeedbackStore, OpenFeedbackOptions } from "@/types/user-feedback";

const FeedbackContext = createContext<FeedbackStore | undefined>(undefined);

export function FeedbackProvider({ children }: { children: React.ReactNode }) {
  const [isOpen, setIsOpen] = useState(false);
  const [options, setOptions] = useState<OpenFeedbackOptions>({});

  const open = useCallback((opts: OpenFeedbackOptions = {}) => {
    setOptions(opts);
    setIsOpen(true);
  }, []);

  const close = useCallback(() => {
    setIsOpen(false);
    // 延迟清除选项，避免 UI 闪烁
    setTimeout(() => setOptions({}), 300);
  }, []);

  return (
    <FeedbackContext.Provider value={{ isOpen, options, open, close }}>
      {children}
      {/* 全局唯一的反馈弹窗实例 */}
      <UserFeedbackDialog
        open={isOpen}
        onOpenChange={setIsOpen}
        defaultOptions={options}
      />
    </FeedbackContext.Provider>
  );
}

// 暴露 Hook
export function useFeedback() {
  const context = useContext(FeedbackContext);
  if (!context) {
    throw new Error("useFeedback must be used within a FeedbackProvider");
  }
  return context;
}
```

### 4.2 根布局集成 (Root Layout)

在 `src/app/layout.tsx` 中只需包裹一次：

```tsx
import { FeedbackProvider } from "@/components/feedback/feedback-provider";

export default function RootLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <html lang="zh-CN">
      <body>
        <Providers>
          <FeedbackProvider>
            {children}
            {/* 这里的 children 可以包含任何深层组件，它们都能调用 useFeedback */}
          </FeedbackProvider>
        </Providers>
      </body>
    </html>
  );
}
```

## 五、使用场景示例

### 场景 A：全局悬浮按钮 (无业务上下文)

```tsx
// src/components/feedback/feedback-floating-button.tsx
"use client";
import { useFeedback } from "@/components/feedback/feedback-provider";

export function FeedbackFloatingButton() {
  const { open } = useFeedback();
  return <Button onClick={() => open()}>反馈</Button>;
}
```

### 场景 B：在特定业务中触发 (带业务上下文)

例如在**收藏卡片**出错时：

```tsx
// src/components/bookmark/bookmark-card.tsx
import { useFeedback } from "@/components/feedback/feedback-provider";

export function BookmarkCard({ bookmark }) {
  const { open } = useFeedback();

  const handleReportError = () => {
    open({
      type: "bug",
      title: `收藏解析失败: ${bookmark.title}`,
      context: {
        bookmark_id: bookmark.id,
        bookmark_url: bookmark.url,
        source: "card_error_boundary",
      },
    });
  };

  return (
    // ...
    <Button variant="ghost" onClick={handleReportError}>
      报错
    </Button>
  );
}
```

## 七、前端页面设计 (补充)

除了全局弹窗外，完整的反馈系统还需要以下页面支持：

### 7.1 用户侧：我的反馈列表

- **路由**: `/settings/feedback`
- **功能**: 分页展示历史反馈、状态筛选（待处理/已回复）、删除草稿。

### 7.2 用户侧：反馈详情页 (新增)

- **路由**: `/settings/feedback/[id]`
- **功能**:
  - 查看反馈完整内容及附件
  - **查看管理员回复/解决方案** (闭环核心)
  - 进度可视化（审核 -> 处理中 -> 已解决）
  - 补充评论（在未关闭前追加信息）

### 7.3 管理侧：反馈管理后台 (新增)

- **路由**: `/admin/feedback`
- **功能**:
  - **反馈看板**: 按优先级、类型、状态筛选
  - **快速处理**: 更改状态 (Reviewing -> Resolved)
  - **回复用户**: 填写处理结果 (resolution) 和内部备注 (admin_notes)

## 十、优势总结

1. **零侵入性**：业务组件不需要引入 `<UserFeedbackDialog />`，也不需要传递一大堆 props。
2. **上下文感知**：可以从深层组件直接传递���前状态（如“该收藏解析失败”）到反馈表单，无需通过 URL 参数传递。
3. **统一管理**：所有反馈逻辑（防抖、提交、状态管理）集中在 Provider 中，易于维护。
4. **扩展性**：未来如果需要添加“截屏反馈”功能，只需在 Provider 中集成 html2canvas，所有调用处自动获得该能力。
