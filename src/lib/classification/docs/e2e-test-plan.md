## 二、核心功能测试场景

### 2.1 书签分类流程

#### TC-CLASS-001: 单个书签自动分类

**前置条件**：用户有至少 3 个包含书签的文件夹

| 步骤 | 操作                                | 预期结果               |
| ---- | ----------------------------------- | ---------------------- |
| 1    | 创建新书签（带标题和 URL）          | 书签创建成功           |
| 2    | 调用 `/api/classification/classify` | 返回分类结果           |
| 3    | 检查 `folderId`                     | 非空，指向合适的文件夹 |
| 4    | 检查 `confidence`                   | 0-1 之间的置信度       |
| 5    | 检查 `decisionPath`                 | 包含追踪信息           |

**API 调用示例**：

```bash
POST /api/classification/classify
{
  "bookmarkId": 123,
  "title": "React Hooks 最佳实践",
  "summary": "深入讲解 React Hooks 的使用技巧",
  "tags": ["react", "hooks", "前端"]
}
```

#### TC-CLASS-002: 冷启动用户分类

**前置条件**：新用户，无历史数据

| 步骤 | 操作           | 预期结果                                  |
| ---- | -------------- | ----------------------------------------- |
| 1    | 创建新用户     | 用户创建成功                              |
| 2    | 添加第一个书签 | 书签创建成功                              |
| 3    | 调用分类 API   | 返回 `action: "inbox"` 或建议创建新文件夹 |
| 4    | 检查用户阶段   | 应为 "onboarding" 或 "cold_start"         |

#### TC-CLASS-003: 低置信度处理

**前置条件**：书签内容与现有文件夹主题不匹配

| 步骤 | 操作                   | 预期结果                      |
| ---- | ---------------------- | ----------------------------- |
| 1    | 创建主题完全不同的书签 | 书签创建成功                  |
| 2    | 调用分类 API           | `confidence < 0.6`            |
| 3    | 检查 `action`          | 应为 "suggest_new" 或 "inbox" |

### 2.2 文件夹演化功能

#### TC-MERGE-001: 合并候选检测

**前置条件**：有 2 个主题相似的文件夹（如"前端"和"React"）

| 步骤 | 操作                                     | 预期结果         |
| ---- | ---------------------------------------- | ---------------- |
| 1    | 调用 `/api/classification/folder-health` | 返回健康报告     |
| 2    | 检查 `mergeCandidates`                   | 包含相似文件夹对 |
| 3    | 验证相似度分数                           | > 0.7            |

#### TC-SPLIT-001: 分拆候选检测

**前置条件**：有一个内容杂乱的大文件夹（>20 书签，内部相似度低）

| 步骤 | 操作                                     | 预期结果         |
| ---- | ---------------------------------------- | ---------------- |
| 1    | 调用 `/api/classification/folder-health` | 返回健康报告     |
| 2    | 检查 `splitCandidates`                   | 包含低内聚文件夹 |
| 3    | 验证 `internalSimilarity`                | < 0.5            |

#### TC-RENAME-001: 重命名建议

**前置条件**：文件夹名称与内容不匹配

| 步骤 | 操作                 | 预期结果           |
| ---- | -------------------- | ------------------ |
| 1    | 调用文件夹画像 API   | 返回画像信息       |
| 2    | 检查 `suggestedName` | 非空，基于内容生成 |
