## 一、现状问题诊断

### 1.1 命名规则碎片化

当前系统存在 **4 套不同的命名 prompt**，分布在以下位置：

| 来源                                                                                                    | 长度规则                 | 使用场景   | 问题             |
| ------------------------------------------------------------------------------------------------------- | ------------------------ | ---------- | ---------------- |
| [simple-classification.service.ts](../src/lib/classification/services/simple-classification.service.ts) | 2-6个中文字或英文单词    | 主流程分类 | 与其他规则不一致 |
| [folder-name-generator.ts](../src/lib/ai-generator/folder/folder-name-generator.ts)                     | 2-6个汉字，最多15字符    | 聚类流程   | 字符上限过宽     |
| [naming-prompt.ts](../src/lib/classification/prompts/naming-prompt.ts)                                  | 2-6个字/词，最长不超10字 | ���名引擎  | 与其他有冲突     |
| [inbox-organizer.service.ts](../src/lib/classification/services/inbox-organizer.service.ts)             | 无规则（词频拼接）       | 收件箱整理 | 完全缺失规范     |

**后果**：同一系统产出风格差异大，用户体验不一致。

### 1.2 Prompt 指引模糊

当前 prompt 存在以下问题：

```text
// 现有示例（naming-prompt.ts:110-114）
1. 简洁：2-6 个字/词为宜，最长不超过 10 个字
2. 准确：反映文件夹主要内容
3. 一致：与用户现有风格保持统一
4. 区分：与现有文件夹有明确区分
5. 禁忌：严禁使用"内容分类与标签管理"、"待整理"、"未命名"等泛指名称
```

**缺失的关键指引**：

- 命名颗粒度指引（何时该概括、何时该具体）
- 中英文混用规则
- 反面示例（什么是糟糕的名字）
- 结构化的命名模式

### 1.3 缺少"人类感"的命名约束

现有规则未禁止以下违反人类命名直觉的模式：

| 问题类型 | 示例                                   | 问题                 |
| -------- | -------------------------------------- | -------------------- |
| 废话后缀 | XX相关、XX资料、XX内容、XX文章、XX收藏 | 不提供额外信息       |
| 过度概括 | 技术、学习、生活、工作                 | 单独使用时等于没说   |
| 动词开头 | 学习XX、研究XX、探索XX                 | 人类不这样命名文件夹 |
| 口水描述 | 关于XX的、有关XX、各种XX               | 非名词结构           |
| 冗余修饰 | 优质、精品、推荐、好用的               | 主观判断词           |

### 1.4 回退策略不佳

```typescript
// folder-name-generator.ts:89-91
return {
  name: name || "未分类", // 回退值过于泛化
  reason: parsed.reason || "基于内容相似性自动生成",
};
```

`"未分类"` 这种回退名称对用户毫无意义，应使用更智能的回退策略。

### 1.5 黑名单不完整

当前黑名单（[simple-classification.service.ts:66-74](../src/lib/classification/services/simple-classification.service.ts#L66-L74)）：


## 二、改进方案：人类化文件夹命名规范

### 2.1 核心原则

> **"像给朋友介绍你的收藏夹一样命名"**
>
> 目标：用户看到文件夹名称时，**1 秒内能想到里面存的是什么**。

### 2.2 规则 1：命名长度

| 优先级     | 长度             | 说明                       | 示例                        |
| ---------- | ---------------- | -------------------------- | --------------------------- |
| **最佳**   | 2-4 个中文字     | 人类最常用的文件夹名称长度 | 独立开发、AI 工具、个人理财 |
| **可接受** | 5-6 个字         | 需要更多上下文时使用       | React Native、职场沟通技巧  |
| **上限**   | 8 个字（含空格） | 超过此长度必须缩短         | Rust 系统编程（极限）       |

**统一标准**：废除现有的"最多15字符"和"最多10字"等不一致规则，统一为 **2-8 个字（含空格），推荐 2-4 字**。

### 2.3 规则 2：命名结构模式

按优先级排列，AI 应按以下模式命名：

| 模式          | 结构          | 示例                           | 适用场景                   |
| ------------- | ------------- | ------------------------------ | -------------------------- |
| **专有名词**  | 直接使用      | Docker、React、Figma           | 内容围绕某个工具/技术/品牌 |
| **领域名词**  | 名词/名词短语 | 个人理财、独立开发、UI 设计    | 内容属于某个明确领域       |
| **主题概念**  | 概念词        | 一人公司、远程办公、被动收入   | 内容围绕某个热门概念/话题  |
| **领域+方向** | 名词+名词     | 前端性能、数据可视化、团队管理 | 需要区分同领域不同方向     |

**禁止的结构**：

| 类型     | 禁止示例           | 修正后 |
| -------- | ------------------ | ------ |
| 动宾结构 | ~~学习 React~~     | React  |
| 动宾结构 | ~~研究 AI~~        | AI     |
| 主谓结构 | ~~如何创业~~       | 创业   |
| 冗余修饰 | ~~关于 XX 的资料~~ | XX     |

### 2.4 规则 3：用词禁令（扩展黑名单）

#### A 类：绝对禁止（系统拦截）

```typescript
const FORBIDDEN_NAMES_A = [
  // 系统保留
  "内容分类",
  "标签管理",
  "待整理",
  "收藏夹",
  "默认",
  "其他",
  "未分类",
  "杂项",
  "新建文件夹",
  "New Folder",
  "我的收藏",
  "书签",
  "Bookmark",
  "我的书签",
  // 完全无意义
  "无标题",
  "Untitled",
  "新建",
  "New",
  "临时",
  "Temp",
];
```

#### B 类：强烈不推荐（prompt 禁止 + 后处理清洗）

```typescript
const FORBIDDEN_PATTERNS_B = {
  // 废话后缀
  suffixes: ["相关", "资料", "内容", "文章", "收藏", "合集", "精选", "汇总"],
  // 过度概括
  vague: ["技术", "学习", "工作", "生活", "文档", "知识", "资源", "工具"],
  // 动词前缀
  verbPrefixes: ["学习", "研究", "探索", "了解", "关注", "阅读", "整理"],
  // 口水词
  filler: ["关于", "有关", "各种", "一些", "部分", "相关"],
  // 冗余修饰
  modifiers: ["优质", "精品", "推荐", "好用的", "最佳", "实用"],
};
```

#### C 类：组合使用时允许，单独使用时禁止

```typescript
const CONTEXTUAL_WORDS = [
  "技术",
  "学习",
  "工具",
  "设计",
  "开发",
  "教程",
  "笔记",
  "入门",
];
// 单独使用时禁止："技术" ✗
// 组合使用时允许："前端技术" ✓、"AI 工具" ✓
```

### 2.5 规则 4：中英文处理

| 场景                 | 规则                              | 示例                                       |
| -------------------- | --------------------------------- | ------------------------------------------ |
| 专有名词             | 保留原文（英文/中文取知名度高的） | React、Docker、微信                        |
| 领域概念有通用中文名 | 使用中文                          | **人工智能** 而非 AI（除非 AI 更广泛认知） |
| 缩写已被广泛认知     | 可直接使用缩写                    | AI、UI、UX、API、SaaS                      |
| 中英混排             | 英文+中文间加空格                 | **React 学习** 而非 React学习              |
| 全英文名称           | 合法但需有意义                    | DevOps、Kubernetes                         |

### 2.6 规则 5：颗粒度指引

根据用户现有文件夹数量动态调整：

| 用户文件夹总数 | 推荐颗粒度       | 示例                              |
| -------------- | ---------------- | --------------------------------- |
| < 10           | 大类（宽泛一些） | 前端、后端、设计                  |
| 10-30          | 中类（常规）     | React、Node.js、UI 设计           |
| > 30           | 细分（精确一些） | React Hooks、CSS 动画、Figma 插件 |

**动态调整**：当用户已有同大类文件夹时，新文件夹名应自动提高颗粒度。

```
用户已有：前端
新内容：React 相关
→ 应命名为：React（而非"前端开发"）
```

### 2.7 规则 6：后处理清洗管道

在 AI 输出后执行如下清洗：

```typescript
function sanitizeFolderName(name: string, tags: string[]): string {
  let result = name;

  // 1. 去除引号：移除 ""''「」【】 等包裹字符
  result = result.replace(/["''「」【】《》]/g, "");

  // 2. 去除 B 类废话后缀
  for (const suffix of FORBIDDEN_PATTERNS_B.suffixes) {
    if (result.endsWith(suffix) && result.length > suffix.length) {
      result = result.slice(0, -suffix.length).trim();
    }
  }

  // 3. 去除动词前缀
  for (const prefix of FORBIDDEN_PATTERNS_B.verbPrefixes) {
    if (result.startsWith(prefix) && result.length > prefix.length) {
      result = result.slice(prefix.length).trim();
    }
  }

  // 4. 空格规范化：中英文间确保恰好一个空格
  result = result.replace(/([a-zA-Z])([\u4e00-\u9fff])/g, "$1 $2");
  result = result.replace(/([\u4e00-\u9fff])([a-zA-Z])/g, "$1 $2");
  result = result.replace(/\s+/g, " ").trim();

  // 5. 长度截断：超过 8 字时尝试移除修饰词缩短
  if (result.length > 8) {
    result = truncateByRemovingModifiers(result);
  }

  // 6. B 类单独使用检测
  if (FORBIDDEN_PATTERNS_B.vague.includes(result)) {
    // 回退到标签提取
    return fallbackToTags(tags);
  }

  return result || fallbackToTags(tags);
}
```

## 四、回退策略改进

### 4.1 多级回退策略

```typescript
async function generateFolderNameWithFallback(
  bookmark: BookmarkInput,
  tags: string[],
): Promise<string> {
  // 优先级 1：前 2 个最频繁标签组合
  if (tags.length >= 2) {
    const combined = `${tags[0]} ${tags[1]}`;
    if (combined.length <= 8) {
      return combined;
    }
  }

  // 优先级 2：第一个非泛化标签
  const nonVagueTag = tags.find((t) => !FORBIDDEN_PATTERNS_B.vague.includes(t));
  if (nonVagueTag) {
    return nonVagueTag;
  }

  // 优先级 3：标题关键词提取
  const keywords = extractKeywords(bookmark.title);
  if (keywords.length > 0) {
    return keywords[0];
  }

  // 优先级 4：时间戳回退（最终兜底）
  // 使用更有意义的前缀而非"分类"
  return `收藏 ${formatDate(new Date(), "MMdd")}`;
}
```

### 4.2 关键词提取函数

```typescript
function extractKeywords(title: string): string[] {
  // 移除常见停用词
  const stopWords = new Set([
    "的",
    "和",
    "与",
    "或",
    "及",
    "等",
    "了",
    "在",
    "是",
    "有",
    "如何",
    "怎么",
    "为什么",
  ]);

  // 分词（简化：按空格和标点分割）
  const words = title
    .replace(/[，。！？、；：""''【】《》\(\)\[\]]/g, " ")
    .split(/\s+/)
    .filter((w) => w.length >= 2 && w.length <= 6)
    .filter((w) => !stopWords.has(w));

  // 返回有意义的词
  return words.slice(0, 3);
}
```

## 六、测试用例

### 6.1 清洗函数测试用例

```typescript
describe("sanitizeFolderName", () => {
  // 引号去除
  it("should remove quotes", () => {
    expect(sanitizeFolderName('"React"', [])).toBe("React");
    expect(sanitizeFolderName("「前端开发」", [])).toBe("前端开发");
  });

  // 废话后缀去除
  it("should remove filler suffixes", () => {
    expect(sanitizeFolderName("React 相关", [])).toBe("React");
    expect(sanitizeFolderName("前端技术资料", [])).toBe("前端技术");
  });

  // 动词前缀去除
  it("should remove verb prefixes", () => {
    expect(sanitizeFolderName("学习 Python", [])).toBe("Python");
    expect(sanitizeFolderName("研究 AI 技术", [])).toBe("AI 技术");
  });

  // 空格规范化
  it("should normalize spaces between Chinese and English", () => {
    expect(sanitizeFolderName("React学习", [])).toBe("React 学习");
    expect(sanitizeFolderName("前端  开发", [])).toBe("前端开发");
  });

  // 长度截断
  it("should truncate long names", () => {
    expect(
      sanitizeFolderName("前端开发技术学习资料", []).length,
    ).toBeLessThanOrEqual(8);
  });

  // 单独泛化词回退
  it("should fallback to tags for vague words", () => {
    expect(sanitizeFolderName("技术", ["React", "前端"])).toBe("React 前端");
  });

  // 黑名单拦截
  it("should block forbidden names", () => {
    expect(sanitizeFolderName("待整理", ["React"])).toBe("React");
    expect(sanitizeFolderName("未分类", [])).toMatch(/收藏 \d{4}/);
  });
});
```

```typescript
    });
    expect(result1.name).toBe("前端");

    // 用户文件夹多时，生成细分名称
    const result2 = await generateFolderName({
      titles: ["React Hooks 入门"],
      tags: ["React", "Hooks"],
      folderCount: 40,
    });
    expect(result2.name).toBe("React Hooks");
  });
});
```

## 八、风险与缓解

| 风险                    | 影响 | 缓解措施                         |
