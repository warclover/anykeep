# 智能分类 V4.0 安全感与持续运营建议书

**日期**：2025-12-08
**汇报人**：技术总负责人 (CTO)
**关联文档**：[智能分类 V4.0 整体架构与演进计划](./智能分类V4.0.md)

---

## 前言

V4.0 的规划在技术架构（HNSW、Trace、DWO）上已具备较高的成熟度。作为技术负责人，我建议在实施过程中补充关注 **"安全感"**（隐私与成本）和 **"持续运营能力"**，以确保系统不仅"智能"，而且"稳健"。

以下是针对 V4.0 的五点关键补充建议：

### 1. 数据飞轮与隐私边界 (Data Flywheel & Privacy)

V4.0 强调了"自进化"，依赖用户数据来调整权重和画像。这引入了潜在的隐私风险。

- **风险点**：我们是否会将用户的书签内容（URL、Title）直接作为 Few-Shot 样本发送给公有云 LLM（DeepSeek/阿里）？对于隐私敏感型用户，这可能无法接受。
- **实施建议**：
  - **数据脱敏中间件**：在调用 LLM 前，必须经过一层 PII（个人敏感信息）过滤器，自动替换掉 URL 中的 Token、SessionID、邮箱等敏感字段。
  - **本地化兜底**：对于极其敏感的分类任务（如"财务"、"合同"），提供保留纯本地 `Tier 1` 模式的选项，或未来支持接入用户私有的本地模型（如 Ollama）。

### 2. 成本熔断机制 (Cost Circuit Breaker)

V4.0 的"整理大师主动巡检"和"实时纠错"属于计算密集型功能。

- **风险点**：遭遇恶意刷量、脚本批量导入（如单日导入 10万+ 书签），或 LLM 调用逻辑死循环，导致 Token 账单失控。
- **实施建议**：
  - **多级配额管理 (Quota System)**：为不同层级用户（免费/Pro）设置每日/每小时的 AI 调用硬上限。
  - **智能降级策略**：当全局 API 成本触及警戒线时，自动触发降级：
    1.  将 `Tier 2` 模型从 Qwen-Max 降级为 Qwen-Turbo/DeepSeek-V3。
    2.  暂停"整理大师"的主动巡检功能。
    3.  仅保留核心的"新增书签分类"服务。

### 3. "负反馈"的深度利用 (Hard Case Mining)

目前的方案侧重于正反馈（用户接受了什么），但**"用户拒绝了什么"**往往蕴含更高价值。

- **洞察**：AI 推荐了 A，用户选了 B。这不仅意味着 A 错了，B 类型的内容可能具有很强的**"反直觉性"**，是模型目前的盲区。
- **实施建议**：
  - **建立 "Hard Case" 样本库**：专门自动收集用户修改率高的书签案例。
  - **定期 Review**：研发团队每两周对 Hard Case 进行人工或 AI 离线分析，找出 Prompt 或检索逻辑的系统性盲点。这将是 V4.1、V4.2 迭代最宝贵的燃料。

### 4. 灰度与 A/B 测试 (Canary Release)

V4.0 包含激进的改动（乐观 UI、动态权重），直接全量上线风险过高。

- **风险点**：乐观 UI 预测准确率不及预期，造成用户困扰；新 Prompt 在特定场景下表现退化。
- **实施建议**：
  - **Feature Flag 驱动**：所有新特性（HNSW 索引切换、乐观 UI 开关、新 Prompt 版本）必须由 Feature Flag 控制，支持秒级回滚。
  - **白名单验证**：先对内部员工和 1% 种子用户开启 V4.0，重点观测 `Tier 1` 拦截率和用户纠正率。指标达标（如纠正率 < 5%）后再逐步扩量。

### 5. 开发者体验 (DX - Prompt Playground)

提升团队自身的迭代效率同样重要。

- **痛点**：Prompt 调整目前通常需要改代码、发版，流程冗长。
- **实施建议**：
  - **Prompt Playground**：在后台开发一个简易界面，允许产品/运营直接修改数据库中的 Prompt 模板，并实时调用"Hard Case"样本库进行回归测试（跑分）。只有跑分通过的 Prompt 才能发布上线。

---

## 总结与 Action Items

建议在 **Phase 1 (稳基座)** 开发计划中，增加以下基础设施建设任务：

1.  **[Infra]** 实现基于 Redis 的用户级/全局级 Token 消耗限流与熔断器。
2.  **[Infra]** 引入 Feature Flag 服务（或基于 DB 的简易实现）。
3.  **[Security]** 开发 PII 脱敏工具类，作为 LLM Service 的前置拦截器。

补齐这三块拼图，AnyKeep 的智能分类将真正成为一个**让用户放心、让公司省心**的成熟子系统。
