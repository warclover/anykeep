# 智能分类 V4.2 AI 动态维护方案

> **版本**：V4.2 (AI Dynamic Evolution - Extended)
> **目标**：实现文件夹结构的 AI 动态自组织（创建、分拆、合并、重命名），达到用户“0 操心”与“可掌控”的平衡
> **核心依赖**：`folder_profiles` (向量画像) + `pgvector` (向量计算) + `LLM` (语义命名)

---

## 🧠 核心理念：自组织文件夹系统

传统分类是“把东西放进盒子里”，V4.2 的理念是“**盒子随东西自动生长，但主人随时可以插手**”。

- **从无到有**：新主题出现 → 攒够一批种子 → 自动长出新文件夹
- **从有到优**：
  - 内容变杂 → 自动分拆
  - 内容重复 → 自动合并
  - 名不副实 → 自动重命名（可选）
- **透明可控**：所有动作产生日志，支持月度报告，支持全自动/半自动模式切换
- **安全可靠**：所有操作支持撤销，敏感文件夹可锁定保护

## 🏗️ 技术架构与功能扩展

### 1. 动态画像机制 (Dynamic Profiling)

文件夹不再是一个静态容器，而是一个**动态向量实体**。

#### A. 画像构成

数据库表 `folder_profiles` 需扩展：

- `profile_embedding`: 文件夹的语义中心（质心）
- `top_tags`: 文件夹的高频语义标签（**限制总数，如 Top 20**，避免边界无限扩展）
- `internal_similarity`: 内聚度分数（0-1），衡量内容的纯度
- **新增** `is_ai_renamable`: 是否允许 AI 重命名（默认 true）
- **新增** `is_system_locked`: 是否系统锁定（禁止 AI 拆分/合并，默认 false）
- **新增** `last_updated_at`: 最后更新时间（用于热度分级）

#### B. 更新策略（性能优化）

- **热度分级更新**：
  - **实时微调**：仅对**活跃文件夹**（新增内容 > 5 篇，或距离上次更新 < 24 小时）进行实时微调。
  - **惰性计算**：`internal_similarity` 不实时计算，仅在后台任务巡检或用户访问时异步计算。
  - **批量更新**：非活跃文件夹的向量更新延迟到后台任务批量处理。
- **用户创建增强**：当用户手动创建文件夹时，AI 根据文件夹名称自动生成初始 `profile_embedding` 和 `top_tags`，无需等待内容填充。

---

### 2. 智能演进流程 (Evolution Pipeline)

#### 场景一：新文件夹的诞生与缓存 (Seed & Grow with Cache)

为避免冷启动阶段创建过多碎片化文件夹：

1.  **缓存池机制**：新类型的收藏若匹配度 < 0.6，**不立即创建新文件夹**，而是打上 `pending_cluster` 标记放入“待整理”。
2.  **定期分拣**：
    - **触发条件**：每新增 N 篇（如 10 篇）或每 T 时间（如每天）。
    - **聚类分析**：对“待整理”中的 `pending_cluster` 内容进行聚类。
    - **批量创建**：若某簇数量 ≥ 3，触发新文件夹创建并批量移动。

#### 场景二：智能重命名 (Adaptive Renaming)

当文件夹内容发生漂移（如从“AI”逐渐变为专存“Midjourney”）：

1.  **触发检测**：每次周期校准时，检测 `profile_embedding` 与当前名称 Embedding 的距离。
2.  **重命名逻辑**：
    - 若距离 > 阈值，且 `is_ai_renamable = true`。
    - AI 基于当前 Top 10 内容生成新名称（如建议将“AI”改为“AI 绘画”）。
3.  **用户控制**：
    - 全自动模式：直接修改，发送通知。
    - 半自动模式：发送“建议重命名”消息，需确认。
    - 用户可锁定名称（`is_ai_renamable = false`），此时 AI 仅调整向量，不改名。

#### 场景三：臃肿文件夹的分拆 (Auto-Split)

当某个文件夹的 `internal_similarity` 持续下降（如 < 0.65），且收藏数 > 20 时：

1.  **触发诊断**：后台任务检测到“亚健康”文件夹（排除 `is_system_locked = true` 的文件夹）。
2.  **聚类分析**：对文件夹内所有收藏进行 **DBSCAN** 或 **K-Means** 聚类。
3.  **决策生成**：
    - 如果发现两个明显的簇（Cluster A, Cluster B），且簇间距离较远。
    - LLM 为 Cluster A 和 Cluster B 分别命名（例如“前端技术”拆分为“Vue 开发”和“CSS 技巧”）。
4.  **执行/建议**：
    - **全自动模式**：直接拆分，原文件夹保留或重命名。
    - **半自动模式**：生成一条“整理建议”，用户一键确认。

#### 场景四：相似文件夹的合并 (Auto-Merge)

定期扫描所有文件夹两两之间的相似度：

1.  **相似度计算**：计算 `profile_embedding` 的余弦相似度（排除 `is_system_locked = true` 的文件夹）。
2.  **合并判定**：
    - 如果 Similarity > 0.92（极度相似）。
    - 且 `top_tags` 重叠率 > 80%。
3.  **执行/建议**：根据用户托管等级，自动合并或建议合并（如“AI 工具”和“人工智能软件”合并）。

### 3. 透明度与可控性 (Transparency & Control)

#### A. 消息与日志系统

所有 AI 动作（创建、合并、拆分、重命名、移动）均生成结构化日志：

- `type`: `folder_evolution`
- `action`: `create` | `merge` | `split` | `rename`
- `details`: `{ from: "AI", to: "AI 绘画", reason: "内容漂移" }`

#### B. 进化报告

- **默认频率**：每月 1 号生成。
- **自定义**：用户可设置 `report_interval`（如 2、3 个月）。
- **内容**：
  - “本月我为您创建了 3 个新文件夹...”
  - “整理了 150 篇收藏，准确率 92%...”
  - “建议合并‘设计’和‘Design’...”

#### C. 用户掌控模式

提供全局设置 `ai_autonomy_level`：

- **Level 1 (全托管)**：AI 自动执行所有操作，仅通知。
- **Level 2 (半托管)**：自动归类，但创建/合并/拆分/重命名需弹窗确认。
- **Level 3 (辅助)**：仅提供建议，不执行任何操作。

#### D. 敏感文件夹保护

- **系统锁定**：用户可手动标记文件夹为 `is_system_locked = true`，禁止 AI 对其进行拆分或合并操作。
- **应用场景**：如“归档”、“财务”、“个人隐私”等敏感文件夹。

### 1. 智能分拣服务 (SmartSortingService)

// src/lib/classification/services/smart-sorting.service.ts

class SmartSortingService {
  // 定期任务：处理缓存池（异步队列执行）
  async processInboxCache(userId) {
    const pendingBookmarks = await getPendingBookmarks(userId);

    // 先做数学聚类，避免无效 LLM 调用
    const clusters = dbscan(pendingBookmarks.vectors, { eps: 0.2, minPts: 3 });

    if (clusters.length === 0) return; // 无有效聚类，不调用 LLM

    for (const cluster of clusters) {
      // 检查本地缓存（常见标签组合）
      const cachedName = this.getCachedFolderName(cluster.tags);
      const name = cachedName || (await llmGenerateName(cluster.contents));

      // 创建文件夹（记录操作日志用于撤销）
      const snapshot = await this.createSnapshot("create", { cluster });
      const folder = await createFolder(name, userId);

      // 批量移动
      await moveBookmarks(cluster.ids, folder.id);

      // 记录日志
      await logAction("create", {
        name,
        count: cluster.length,
        snapshot_id: snapshot.id, // 关联快照，支持撤销
      });
    }
  }

  // 本地缓存映射（减少 LLM 调用）
  private getCachedFolderName(tags: string[]): string | null {
    const tagKey = tags.sort().join(",");
    const cache = {
      "React,Vue,Frontend": "前端开发",
      "Python,AI,Machine Learning": "AI 学习",
      // ... 更多常见组合
    };
    return cache[tagKey] || null;
  }
}

### 2. 文件夹画像维护 (ProfileMaintenanceService)

```typescript
// src/lib/classification/services/profile-maintenance.service.ts

class ProfileMaintenanceService {
  // 用户创建文件夹时的增强
  async onUserCreateFolder(folderId, name) {
    // LLM 生成初始特征（异步，不阻塞用户操作）
    await this.enqueueJob("generate_profile", { folderId, name });
  }

  // 异步生成画像（Job Queue 执行）
  async generateProfile(folderId, name) {
    // 检查本地缓存
    const cached = this.getCachedProfile(name);
    if (cached) {
      await updateProfile(folderId, cached);
      return;
    }

    // LLM 生成初始特征
    const { embedding, tags } = await llmPredictProfile(name);

    await updateProfile(folderId, {
      profile_embedding: embedding,
      top_tags: tags.slice(0, 20), // 限制标签总数
      is_ai_renamable: false, // 用户创建的默认不重命名
      last_updated_at: new Date(),
    });
  }

  // 智能重命名检查（仅在周期校准时执行）
  async checkRenaming(folderId) {
    const profile = await getProfile(folderId);
    if (!profile.is_ai_renamable || profile.is_system_locked) return;

    // 惰性计算：仅在需要时计算
    const contentSummary = await this.summarizeFolderContentLazy(folderId);
    const newName = await llmSuggestName(contentSummary);

    if (isNameDifferent(profile.name, newName)) {
      // 创建快照（支持撤销）
      const snapshot = await this.createSnapshot("rename", {
        folderId,
        from: profile.name,
        to: newName,
      });

      await this.executeOrPropose("rename", {
        from: profile.name,
        to: newName,
        snapshot_id: snapshot.id,
      });
    }
  }

  // 热度分级更新：仅更新活跃文件夹
  async updateProfileIfActive(folderId, newBookmarkEmbedding) {
    const profile = await getProfile(folderId);
    const hoursSinceUpdate =
      (Date.now() - profile.last_updated_at) / (1000 * 60 * 60);

    // 仅对活跃文件夹（24小时内更新过，或新增内容>5篇）实时微调
    if (hoursSinceUpdate < 24 || profile.recent_additions > 5) {
      const alpha = 0.1;
      const newEmbedding = this.interpolate(
        profile.profile_embedding,
        newBookmarkEmbedding,
        alpha,
      );
      await updateProfile(folderId, {
        profile_embedding: newEmbedding,
        last_updated_at: new Date(),
      });
    } else {
      // 非活跃文件夹延迟到后台批量更新
      await this.enqueueJob("batch_update_profile", { folderId });
    }
  }
}
```

### 3. 操作日志与撤销机制 (Operation Log & Undo)

```typescript
// src/lib/classification/services/operation-log.service.ts

interface OperationSnapshot {
  id: string;
  user_id: string;
  action: "create" | "split" | "merge" | "rename";
  folder_id?: number;
  folder_ids?: number[]; // 用于合并/拆分
  bookmark_ids: number[];
  before_state: {
    folder_name?: string;
    folder_names?: string[];
    profile_embedding?: number[];
  };
  after_state: {
    folder_name?: string;
    folder_names?: string[];
    profile_embedding?: number[];
  };
  created_at: Date;
  expires_at: Date; // 7天后过期
}

class OperationLogService {
  // 创建操作快照（在执行任何演进操作前）
  async createSnapshot(
    action: string,
    details: any,
  ): Promise<OperationSnapshot> {
    const snapshot = {
      id: generateId(),
      user_id: details.userId,
      action,
      ...details,
      created_at: new Date(),
      expires_at: new Date(Date.now() + 7 * 24 * 60 * 60 * 1000), // 7天
    };

    await db.insert("operation_snapshots", snapshot);
    return snapshot;
  }

  // 撤销操作
  async undoOperation(snapshotId: string) {
    const snapshot = await db.get("operation_snapshots", snapshotId);
    if (!snapshot || snapshot.expires_at < new Date()) {
      throw new Error("快照已过期或不存在");
    }

    // 根据 action 类型执行回滚
    switch (snapshot.action) {
      case "create":
        // 删除文件夹，将书签移回待整理
        await this.rollbackCreate(snapshot);
        break;
      case "split":
        // 合并回原文件夹
        await this.rollbackSplit(snapshot);
        break;
      case "merge":
        // 拆分为原文件夹
        await this.rollbackMerge(snapshot);
        break;
      case "rename":
        // 恢复原名称
        await this.rollbackRename(snapshot);
        break;
    }

    // 记录撤销操作
    await logAction("undo", { snapshot_id: snapshotId });
  }
}
```

### 4. 异步任务队列 (Job Queue)

```typescript
// src/lib/classification/services/job-queue.service.ts

class JobQueueService {
  // 所有 AI 演进操作必须异步化
  async enqueueJob(type: string, payload: any) {
    await db.insert("job_queue", {
      type,
      payload,
      status: "pending",
      created_at: new Date(),
    });

    // 触发 Worker 处理（Supabase Edge Function 或独立 Worker）
    await triggerWorker();
  }

  // Worker 处理逻辑（后台执行）
  async processJob(jobId: string) {
    const job = await db.get("job_queue", jobId);

    try {
      switch (job.type) {
        case "generate_profile":
          await profileService.generateProfile(
            job.payload.folderId,
            job.payload.name,
          );
          break;
        case "batch_update_profile":
          await profileService.batchUpdateProfile(job.payload.folderId);
          break;
        case "check_renaming":
          await profileService.checkRenaming(job.payload.folderId);
          break;
        case "process_inbox_cache":
          await sortingService.processInboxCache(job.payload.userId);
          break;
      }

      await db.update("job_queue", jobId, { status: "completed" });
    } catch (error) {
      await db.update("job_queue", jobId, {
        status: "failed",
        error: error.message,
      });
    }
  }
}
```

class UXEnhancementService {
  // 为缓存池中的书签添加"AI 整理中"状态
  async markPendingBookmarks(userId: string) {
    const pendingBookmarks = await getPendingBookmarks(userId);

    return pendingBookmarks.map((bookmark) => ({
      ...bookmark,
      status: "ai_processing", // 前端显示 ✨ "AI 正在观察中..."
      pending_since: bookmark.created_at,
    }));
  }

  // 成本监控（每日报警）
  async monitorDailyCost() {
    const today = new Date().toISOString().split("T")[0];
    const cost = await db.query(
      `
      SELECT 
        COUNT(*) as llm_calls,
        SUM(token_count) as total_tokens
      FROM llm_usage_log
      WHERE DATE(created_at) = $1
    `,
      [today],
    );

    if (cost.total_tokens > DAILY_LIMIT) {
      await sendAlert("LLM 成本超限", { cost });
    }
  }
}

### Phase 1: 基础智能 + 安全机制 (Smart Core + Safety) [2-3 周]

**优先级 ⭐⭐⭐⭐⭐（必须）**

1.  **Operation Log 表设计**：
    - 创建 `operation_snapshots` 表，支持 7 天撤销窗口。
    - 实现快照创建和回滚逻辑。
2.  **异步任务队列**：
    - 集成 Job Queue（Supabase `pg_net` 或 Redis/BullMQ）。
    - 所有 AI 演进操作异步化，避免阻塞 HTTP 请求。
3.  **统一向量搜索 + 标签增强**：
    - 实现 V4.1 的核心匹配逻辑。
4.  **缓存池 + 定期分拣**：
    - 实现“待整理”缓存机制，解决冷启动碎片化。
    - 添加“AI 整理中”状态标记，提升用户体验。

### Phase 2: 动态维护 (Dynamic Maintenance) [3-4 周]

**优先级 ⭐⭐⭐⭐（重要）**

1.  **热度分级更新**：
    - 实现文件夹向量的惰性计算和批量更新。
    - 仅对活跃文件夹实时微调。
2.  **AI 智能重命名**：
    - 实现重命名检测逻辑（含用户锁定开关）。
    - 集成到周期校准任务中。
3.  **自动拆分与合并**：
    - 实现 DBSCAN/K-Means 聚类分析。
    - 实现拆分/合并的决策和执行逻辑（含系统锁定保护）。

### Phase 3: 系统透明化 (Transparency) [2-3 周]

**优先级 ⭐⭐⭐（增强）**

1.  **消息系统集成**：
    - 所有 AI 动作生成结构化日志。

2.  **月度进化报告**：
    - 开发报告生成器（支持自定义周期）。
