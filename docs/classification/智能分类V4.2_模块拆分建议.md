# 智能分类 V4.2 模块拆分建议

> **角色**：AnyKeep CTO
> **日期**：2025-12-10
> **目标**：将 V4.2 拆分为"文件夹自组织管理"和"收藏智能分类"两个独立功能模块

---

## 📊 现状分析

### 当前架构耦合点

| 耦合类型     | 具体表现                                                 | 影响               |
| ------------ | -------------------------------------------------------- | ------------------ |
| **数据耦合** | `folder_profiles` 表被两个模块共享                       | 需要明确数据所有权 |
| **流程耦合** | 分类结果触发文件夹创建                                   | 需要事件驱动解耦   |
| **服务依赖** | `SimpleClassificationService` 调用 `SmartSortingService` | 需要接口抽象       |
| **配置共享** | `ai_folder_settings` 同时控制两个功能                    | 需要拆分配置       |

### 功能边界识别

#### 模块 A：收藏智能分类 (Bookmark Classification)

**职责**：回答"这个收藏应该放到哪个文件夹？"

- ✅ `SimpleClassificationService` - 核心分类逻辑
- ✅ 向量匹配（`search_folders_unified`）
- ✅ 标签增强计算
- ✅ AI 选择题模式
- ✅ 分类结果输出（classify / suggest_create / inbox）

**输入**：书签（title, summary, tags, embedding）  
**输出**：`{ folderId, folderName, confidence, action }`

#### 模块 B：文件夹自组织管理 (Folder Auto-Organization)

**职责**：回答"文件夹结构应该如何演进？"

- ✅ `SmartSortingService` - 缓存池聚类与智能创建
- ✅ `SplitService` - 文件夹分拆
- ✅ `MergeService` - 文件夹合并
- ✅ `RenameService` - 智能重命名
- ✅ `ProfileMaintenanceService` - 画像维护（热度分级更新）
- ✅ `OperationLogService` - 操作日志与撤销
- ✅ `ReportService` - 月度报告

**输入**：文件夹状态、用户偏好  
**输出**：文件夹演进建议/操作

## 🎯 拆分方案

### 方案一：完全解耦（推荐）⭐

#### 架构设计

```
┌─────────────────────────────────────────────────────────┐
│              收藏智能分类模块                              │
│  (Bookmark Classification Module)                       │
├─────────────────────────────────────────────────────────┤
│  • SimpleClassificationService                          │
│  • 向量匹配、标签增强、AI选择题                           │
│  • 输出：分类结果 + 建议创建事件                          │
└────────────────────┬───────────────────────────────────┘
                     │ 事件：folder_create_suggested
                     ▼
┌─────────────────────────────────────────────────────────┐
│           事件总线 (Event Bus)                           │
│  • folder_create_suggested                              │
│  • folder_split_suggested                               │
│  • folder_merge_suggested                               │
│  • folder_rename_suggested                               │
└────────────────────┬───────────────────────────────────┘
                     │ 订阅事件
                     ▼
┌─────────────────────────────────────────────────────────┐
│          文件夹自组织管理模块                              │
│  (Folder Auto-Organization Module)                      │
├─────────────────────────────────────────────────────────┤
│  • SmartSortingService                                  │
│  • SplitService / MergeService / RenameService          │
│  • ProfileMaintenanceService                            │
│  • OperationLogService / ReportService                 │
└─────────────────────────────────────────────────────────┘
```

#### 核心改动

**1. 分类模块输出事件而非直接调用**

```typescript
// src/lib/classification/services/simple-classification.service.ts

export class SimpleClassificationService {
  async classify(
    userId: string,
    bookmark: SimpleBookmarkInput,
  ): Promise<SimpleClassificationResult> {
    // ... 分类逻辑 ...

    // 如果建议创建文件夹，发布事件而非直接创建
    if (result.action === "suggest_create") {
      await this.eventBus.publish("folder_create_suggested", {
        userId,
        bookmarkId: bookmark.id,
        suggestedName: result.suggestedFolderName,
        confidence: result.confidence,
        reason: result.reason,
      });
    }

    return result;
  }
}
```

**2. 自组织模块订阅事件**

```typescript
// src/lib/folder-organization/services/folder-evolution.service.ts

export class FolderEvolutionService {
  constructor() {
    // 订阅分类模块事件
    this.eventBus.subscribe("folder_create_suggested", async (event) => {
      await this.handleCreateSuggestion(event);
    });
  }

  private async handleCreateSuggestion(event: FolderCreateSuggestedEvent) {
    // 根据用户偏好决定是否创建
    const settings = await this.getUserSettings(event.userId);

    if (settings.autonomyLevel === 1) {
      // 全自动：直接创建
      await this.smartSortingService.createFolderFromSuggestion(event);
    } else if (settings.autonomyLevel === 2) {
      // 半自动：生成确认消息
      await this.messageService.sendCreateConfirmation(event);
    }
  }
}
```

**3. 数据访问层隔离**

```typescript
// src/lib/folder-organization/repositories/folder-profile.repository.ts

export class FolderProfileRepository {
  // 文件夹自组织模块拥有 folder_profiles 的写权限

    // ...
  }
}

// src/lib/classification/repositories/folder-profile-read.repository.ts

export class FolderProfileReadRepository {
  // 分类模块只有读权限

    // 只读查询
  }

```

#### 优势

✅ **职责清晰**：分类只管"匹配"，自组织只管"演进"  
✅ **独立演进**：两个模块可以独立优化和发布  
✅ **易于测试**：可以分别进行单元测试和集成测试  
✅ **用户控制**：可以分别开启/关闭功能

#### 实施成本

- **开发时间**：2-3 周（事件总线 + 接口重构）
- **风险**：中等（需要充分测试事件传递）

### 方案二：接口抽象（保守）

#### 架构设计

保持现有代码结构，但通过接口抽象实现逻辑分离：

```typescript
// src/lib/classification/interfaces/folder-organization.interface.ts

export interface IFolderOrganizationService {
  /**
   * 处理分类模块的创建建议
   */
  handleCreateSuggestion(
    userId: string,
    suggestion: FolderCreateSuggestion,
  ): Promise<FolderCreationResult>;

  /**
   * 检查文件夹是否需要分拆/合并/重命名
   */
  checkEvolutionCandidates(userId: string): Promise<EvolutionCandidates>;
}

// src/lib/classification/services/simple-classification.service.ts

export class SimpleClassificationService {
  constructor(
    private folderOrgService?: IFolderOrganizationService, // 可选依赖
  ) {}

  async classify(...) {
    // 分类逻辑

    if (result.action === 'suggest_create' && this.folderOrgService) {
      // 通过接口调用，而非直接依赖
      await this.folderOrgService.handleCreateSuggestion(userId, suggestion);
    }
  }
}
```

#### 优势

✅ **改动最小**：不需要引入事件总线  
✅ **渐进式重构**：可以逐步拆分  
✅ **向后兼容**：现有代码可以继续工作

#### 劣势

❌ **仍有耦合**：通过接口调用，但仍是同步依赖  
❌ **测试复杂**：需要 Mock 接口实现

### 方案三：配置驱动（最保守）

通过配置开关完全控制两个模块的启用：

export interface ClassificationModuleConfig {

#### 优势

✅ **零代码改动**：只需配置管理

#### 劣势

❌ **未解决架构问题**：代码耦合依然存在  
❌ **长期维护困难**：两个功能混在一起

## 💡 CTO 最终建议

### 推荐方案：方案一（完全解耦）+ 渐进式实施

#### 实施路线图

**Phase 1: 接口抽象（1周）**

- 定义 `IFolderOrganizationService` 接口
- `SimpleClassificationService` 通过接口调用自组织功能
- **目标**：逻辑分离，代码仍可运行

**Phase 2: 事件总线（1周）**

- 引入轻量级事件总线（如 `EventEmitter` 或 `@anykeep/event-bus`）
- 分类模块发布事件，自组织模块订阅
- **目标**：完全解耦，异步通信

**Phase 3: 模块重构（1周）**

- 将文件夹自组织相关服务迁移到 `src/lib/folder-organization/`
- 分类模块保留在 `src/lib/classification/`
- 统一数据访问层
- **目标**：物理分离，独立维护

#### 关键决策点

| 决策项           | 建议                                                    | 理由                       |
| ---------------- | ------------------------------------------------------- | -------------------------- |
| **事件总线选择** | 自研轻量级 EventBus                                     | 避免引入重型框架，保持简单 |
| **数据访问权限** | 分类模块只读，自组织模块读写                            | 防止数据竞争，明确所有权   |
| **配置拆分**     | `ai_classification_settings` + `ai_folder_org_settings` | 用户可分别控制             |
| **API 路由**     | `/api/classification/*` + `/api/folder-organization/*`  | 清晰的 RESTful 边界        |

## 🔄 数据流设计

### 场景：新收藏分类 → 建议创建文件夹

```
1. 用户添加收藏
   ↓
2. 分类模块：SimpleClassificationService.classify()
   - 向量匹配：无匹配（confidence < 60%）
   - 输出：action = 'suggest_create'
   ↓
3. 分类模块发布事件：folder_create_suggested
   {
     userId: "xxx",
     bookmarkId: 123,
     suggestedName: "AI 绘画",
     confidence: 55,
     reason: "无匹配文件夹，建议新建"
   }
   ↓
4. 自组织模块订阅事件：FolderEvolutionService
   - 检查用户设置：autonomyLevel = 2（半托管）
   - 生成确认消息，发送到消息中心
   ↓
5. 用户确认创建
   ↓
6. 自组织模块：SmartSortingService.createFolder()
   - 创建文件夹
   - 更新 folder_profiles
   - 移动书签
   - 记录操作快照
   ↓
7. 发布事件：folder_created
   ↓
8. 分类模块可订阅此事件，更新缓存（可选）
```

## ⚠️ 风险与应对

| 风险           | 影响                       | 应对措施                    |
| -------------- | -------------------------- | --------------------------- |
| **事件丢失**   | 用户操作无响应             | 实现事件持久化（Job Queue） |
| **数据不一致** | 分类结果与文件夹状态不同步 | 定期同步检查任务            |
| **性能下降**   | 事件传递增加延迟           | 异步处理，不阻塞主流程      |
| **测试复杂度** | 需要 Mock 事件总线         | 提供测试工具类              |
