> **版本**: v2.0 (解耦设计)
> **日期**: 2025-12-08
> **状态**: 待开发

---

## 一、功能概述

### 1.1 目标

为开发和测试人员提供一个**完全独立、可随时移除**的调试工具，用于：

- 对比 V3.0 和 V4.0 分类算法的结果差异
- 观察 V4.0 的新能力（场景权重、纠错缓存、命名引擎）
- 调试分类参数，优化算法配置
- 验证不同用户场景下的分类表现

### 1.2 核心设计原则

| 原则         | 说明                                                                           |
| ------------ | ------------------------------------------------------------------------------ |
| **完全解耦** | 所有代码集中在 `src/features/classification-debugger/`，删除该目录即可移除功能 |
| **零侵入**   | 不修改任何现有分类服务代码，不引入全局状态                                     |
| **数据隔离** | 所有测试数据不写入生产数据库，使用 Mock 上下文或 dry-run 模式                  |
| **环境控制** | 通过环境变量 `ENABLE_CLASSIFICATION_DEBUGGER` 控制功能开关                     |
| **可回滚**   | 无迁移文件、无全局依赖，可随时回滚                                             |

## 三、核心实现方案

### 3.1 V3 模拟方式

**决策**: 通过配置开关禁用 V4 新特性来模拟 V3 行为（而非维护独立代码快照）

```typescript
// V3 模拟配置 - 禁用所有 V4 新特性
const V3_SIMULATION_CONFIG: ClassificationConfig = {
  // 禁用 V4.0 新特性
  enableScenarioWeights: false, // 禁用场景权重
  enableCorrectionCache: false, // 禁用纠错缓存
  enableNamingEngine: false, // 禁用命名引擎
  enableMultiSourceFusion: false, // 禁用多源融合

  // 使用 V3 阈值
  tier1Threshold: 0.9,
  tier2Threshold: 0.6,

  // 强制 dry-run
  dryRun: true,
};
```

**优势**:

- 无需维护两套代码
- V3/V4 使用同一套核心逻辑，对比更公平
- 代码量小，易维护

### 3.2 Mock 用户场景

为测试不同用户阶段的分类效果，提供预设 Mock 场景：


### 3.3 数据隔离策略

| 操作类型   | 隔离方式            | 说明                                 |
| ---------- | ------------------- | ------------------------------------ |
| 文件夹读取 | Mock 数据或只读查询 | 使用预设 Mock 场景或只读查询真实数据 |
| 历史记录   | Mock 数据           | 完全使用预设历史数据                 |
| 分类执行   | dry-run 模式        | 强制 `dryRun: true`，不写入数据库    |
| AI 调用    | 正常执行            | AI 推理无副作用，正常调用            |
| 结果保存   | 不保存              | 仅返回给前端显示，不持久化           |

## 四、API 设计

### 4.1 对比 API

```typescript
// POST /api/dev/classification-compare
interface CompareRequest {
  // 书签数据
  bookmark: {
    url: string;
    title: string;
    description?: string;
  };

  // 场景选择
  scenario: "cold-start" | "learning" | "mature" | "real-readonly";

  // V4 配置（V3 配置自动生成）
  v4Config?: Partial<ClassificationConfig>;

  // 使用预设
  preset?: "default" | "high-precision" | "fast-mode" | "cold-start-optimized";
}

interface CompareResponse {
  success: boolean;

  v3Result: {
    suggestedFolder: FolderSuggestion | null;
    confidence: number;
    reasoning: string;
    executionTime: number;
    tier: "T1" | "T2" | "T3";
  };

  v4Result: {
    suggestedFolder: FolderSuggestion | null;
    confidence: number;
    reasoning: string;
    executionTime: number;
    tier: "T1" | "T2" | "T3";
    // V4 额外信息
    scenarioWeight?: number;
    correctionApplied?: boolean;
  };

  comparison: {
    sameFolder: boolean;
    confidenceDiff: number;
    timeDiff: number;
    v4Improvements: string[];
  };
}
```

## 八、风险与缓解

| 风险              | 影响                 | 缓解措施                                   |
| ----------------- | -------------------- | ------------------------------------------ |
| V3 模拟不够准确   | 对比结果有偏差       | 通过禁用特性而非独立代码，保证核心逻辑一致 |
| Mock 数据不够真实 | 测试场景覆盖不全     | 提供 `real-readonly` 模式使用真实数据      |
| AI 调用成本       | 频繁测试增加费用     | 每次对比需两次 AI 调用，建议控制测试频率   |
| 环境变量泄露      | 生产环境暴露调试功能 | 使用服务端环境变量双重检查                 |
