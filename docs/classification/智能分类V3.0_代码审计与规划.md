# 智能分类 V3.0 代码审计与能力提升规划

## 一、 智能分类 V3.0 代码审计评价

经过对 `src/lib/classification/v3` 及其相关模块的深度代码审查，我对当前 V3.0 版本的实现评价如下：

### 1. 总体架构评价：优秀 (S)

项目成功落地了文档中规划的 **5 层智能分类架构**，结构清晰，职责分明。

- **分层设计 (Tiered Architecture)**：`TieredClassificationService` 完美实现了 `Fast (Tier 1)` -> `AI (Tier 2)` -> `Auto-Create (Tier 3)` -> `Inbox` 的分层降级策略。这不仅大幅降低了 Token 成本（预计节省 70%），还保证了响应速度。
- **模块化 (Modularity)**：每个匹配器（`KnnDirect`, `Fingerprint`, `TagMatcher`）都实现了统一的 `IMatcher` 接口，易于扩展和测试。
- **类型安全 (Type Safety)**：全链路 TypeScript 类型定义完善，从数据库层到服务层再到 API 层，有效防止了运行时错误。

### 2. 核心功能实现情况

| 核心模块                    | 实现状态  | 评价                                                                                                                                                                                              |
| :-------------------------- | :-------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |

### 3. 潜在风险与改进建议

- **复杂性管理**：系统复杂度较高，涉及多个匹配器的权重融合。虽然逻辑正确，但在出现"分错"的情况时，排查具体是哪个环节（是向量检索偏了，还是指纹权重不够）可能较困难。**（今日新增的调试工具已部分缓解此问题）**
- **性能隐患**：`FingerprintMatcher` 在用户文件夹和书签极多时（如上万条），全量计算指纹可能会有性能抖动。目前的实例级缓存是很好的优化，但需关注内存占用。

## 二、 下一步能力提升方向 (V3.1 / V4.0 规划)

基于 V3.0 坚实的基础，建议下一阶段重点关注 **"用户感知"** 和 **"系统自进化"**。

### 方向 1：交互侧的"透明化"与"可控性" (User Perception)

目前的智能都在后端"黑盒"里，用户感知不强。

- **计划 1.1：分类理由透传**
  - 在前端展示分类结果时，显示 V3 引擎的决策理由。
  - _例如_："已自动归入「前端开发」（因为内容包含 React 标签，且与您历史收藏高度相似）"
- **计划 1.2：文件夹画像可视化**
  - 在文件夹详情页，展示 AI 对该文件夹的理解（即 `Fingerprint` 的可视化）。
  - _例如_：显示词云 "这个文件夹主要包含：Vue, 教程, 源码"。用户如果发现 AI 理解偏了，可以手动修正关键词。

### 方向 2：模型侧的"自进化" (Self-Evolution)

让系统越用越顺手，不仅是静态规则，而是动态适应。

- **计划 2.1：动态权重系统 (Dynamic Weights)**
  - 目前 `CLASSIFICATION_WEIGHTS` 是静态常数。
  - **升级**：为每个用户维护一套权重。如果该用户标签打得很准，自动提高 `TagMatcher` 权重；如果用户喜欢乱起名，降低 `VectorMatcher` 权重。
- **计划 2.2：个性化 Prompt 注入**
  - 允许用户在设置中通过自然语言告诉 AI 自己的分类习惯。
  - _例如_："把所有关于 AI 的新闻都放在「科技动态」，但具体的 AI 教程放在「Dev」"。系统将这段话动态注入到 CoT Prompt 的 System 字段中。

### 方向 3：多模态与多模型 (Multimodal & Multi-Model)

- **计划 3.1：多模型路由**
  - 简单的归类任务使用轻量级模型（如 `gpt-4o-mini` 或本地模型）降低成本。
  - 复杂的、跨领域的决策（如 `AI Librarian` 的全库重构建议）路由到深思模型（如 `o1` 或 `Claude 3.5 Sonnet`）。
- **计划 3.2：图片/视频理解**
  - 目前主要依赖文本。V4.0 可加入视觉理解，对设计类截图、视频封面进行分类。
