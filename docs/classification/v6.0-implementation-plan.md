## 1. 架构对比与演进路径

### 1.1 当前架构 (v5.x)

```
┌─────────────────────────────────────────────────────────┐
│                   Content Router                         │
│              (Fast Path vs Slow Path)                    │
└────────────────────┬────────────────────────────────────┘
                     │
         ┌───────────┴───────────┐
         │                       │
    ┌────▼────┐           ┌──────▼──────┐
    │ Fast    │           │ Slow Path   │
    │ Path    │           │ - Vector    │
    │ - Source│           │ - KNN       │
    │ - Title │           │ - AI        │
    │ - Tag   │           │ - History   │
    └─────────┘           └─────────────┘
```

**核心问题**:

- ❌ 二元分类（fast/slow），缺少中间层
- ❌ 所有请求都需要后端响应（RTT ~200ms）
- ❌ 向量检索每次都调用（成本高）
- ❌ 垃圾命名文件夹无智能治理
- ❌ **空文件夹冷启动困境** - 向量语义太弱
- ❌ **大文件夹马太效应** - 内容多的文件夹"吞噬"小文件夹

### 1.2 目标架构 (v6.0 Tri-Funnel + Hybrid Search)

## 2. 核心问题诊断

### 2.1 语义鸿沟 (Semantic Gap)

**现象**: 用户创建文件夹 `/工作/发票`，保存"滴滴行程单"时，系统把它放进了"出行"文件夹。

**根因分析**:

```
用户意图: 发票 → 报销凭证 → 财务相关
系统理解: 滴滴行程单 → 出行记录 → 交通相关

问题: "发票"的向量覆盖范围太窄，没有包含"行程单"、"报销"等语义
```

### 2.2 冷启动困境 (Cold Start Problem)

**现象**: 新建空文件夹的分类命中率极低（< 30%），老文件夹命中率高（> 85%）。

**数据分布**:
| 文件夹书签数 | 命中率 | 占比 |
|-------------|--------|------|
| 0 条 | 15% | 12% |
| 1-5 条 | 45% | 23% |
| 6-20 条 | 72% | 35% |
| > 20 条 | 89% | 30% |

**根因**: 空文件夹只有名称向量，语义覆盖面极窄。

### 2.3 马太效应 (Matthew Effect)

**现象**: 大文件夹（如"前端技术"有 200+ 书签）会"吞噬"小文件夹（如"CSS 技巧"只有 5 条）。

**根因分析**:

```
大文件夹向量 = 200 个书签的质心 → 向量球体巨大，覆盖范围广
小文件夹向量 = 5 个书签的质心 → 向量球体很小，容易被包围

结果: 任何与"前端"沾边的内容，都会被"前端技术"文件夹吸走
```

## 3. 四大核心修复方案

### 3.1 方案一：合成锚点 (Synthetic Semantic Anchors)

**核心思想**: 不等用户存东西，系统先"伪造"语义数据撑起文件夹骨架。

**实现流程**:

```
用户创建文件夹 "发票"
          │
          ▼
┌─────────────────────────────────────┐
│  触发 LLM 扩展                       │
│  Prompt: "文件夹『发票』可能包含     │
│  的网页标题关键词、同义词、相关概念"  │
└─────────────────────────────────────┘
          │
          ▼
┌─────────────────────────────��───────┐
│  LLM 输出:                          │
│  电子发票, 增值税, 报销流程,         │
│  税务局, 滴滴行程单, 酒店水单,       │
│  财务系统, 发票验真, 开票申请...     │
└─────────────────────────────────────┘
          │
          ▼
┌─────────────────────────────────────┐
│  生成合成质心向量 (Synthetic Centroid)│
│  embedding = embed(扩展词包.join(' '))│
│  存入 folders.synthetic_embedding   │
└─────────────────────────────────────┘
```

**效果预估**:
| 指标 | 修复前 | 修复后 |
|------|--------|--------|
| 空文件夹命中率 | 15% | 65% |
| 语义覆盖词数 | 2-3 | 20-30 |

### 3.2 方案二：动态混合分数 (Dynamic α(n) Weighting)

**核心思想**: 根据文件夹内容数量，动态调整"名称权重"和"内容权重"的比例。

**权重公式**:

```
α(n) = max(0.4, 1 - 0.06 * n)

其中:
- n = 文件夹内书签数量
- α(n) = 文件夹名称向量的权重
- 1 - α(n) = 内容质心向量的权重
```

**分段行为**:
| 书签数 n | α(n) | 名称权重 | 内容权重 | 策��描述 |
|----------|------|----------|----------|----------|
| 0 | 1.0 | 100% | 0% | 完全信任名称 + 合成锚点 |
| 1-5 | 0.7-0.94 | 70-94% | 6-30% | 名称主导，内容辅助 |
| 6-10 | 0.4-0.64 | 40-64% | 36-60% | 过渡阶段，双轨并行 |
| > 10 | 0.4 | 40% | 60% | 内容主导，名称兜底 |

**代码实现**:

```typescript
function calculateAlpha(bookmarkCount: number): number {
  return Math.max(0.4, 1 - 0.06 * bookmarkCount);
}

function computeFolderScore(
  queryEmbedding: number[],
  folder: FolderWithEmbeddings,
): number {
  const alpha = calculateAlpha(folder.bookmark_count);

  const nameScore = cosineSimilarity(queryEmbedding, folder.name_embedding);
  const contentScore = folder.content_centroid
    ? cosineSimilarity(queryEmbedding, folder.content_centroid)
    : 0;
  const syntheticScore = folder.synthetic_embedding
    ? cosineSimilarity(queryEmbedding, folder.synthetic_embedding)
    : 0;

  // 空文件夹使用合成锚点
  if (folder.bookmark_count === 0) {
    return alpha * nameScore + (1 - alpha) * syntheticScore;
  }

  return alpha * nameScore + (1 - alpha) * contentScore;
}
```

### 3.3 方案三：反马太效应惩罚 (Anti-Matthew Penalty)

**核心思想**: 对大文件夹进行"引力惩罚"，避免其吞噬小文件夹。

**惩罚公式**:

```
penalty(n) = log(1 + n) / 10

final_score = raw_score - penalty(n)
```

**惩罚系数表**:
| 书签数 n | penalty | 效果描述 |
|----------|---------|----------|
| 0 | 0.000 | 无惩罚（冷启动保护） |
| 10 | 0.104 | 轻微惩罚 |
| 50 | 0.171 | 中度惩罚 |
| 100 | 0.201 | 较重惩罚 |
| 500 | 0.270 | 重度惩罚 |

**代码实现**:

```typescript
function applyAntiMatthewPenalty(
  rawScore: number,
  bookmarkCount: number,
): number {
  const penalty = Math.log(1 + bookmarkCount) / 10;
  return rawScore - penalty;
}
```

**效果**: 大文件夹必须匹配度**极高**才能胜出；小文件夹只要匹配度尚可，就能冒头。

### 3.4 方案四：关键词硬匹配 (BM25 Keyword Hard Match)

**核心思想**: 在向量语义之外，叠加传统 BM25 关键词匹配，解决"精准定位"问题。

**混合检索公式**:

```
final_score = 0.6 * vector_score + 0.3 * keyword_score + 0.1 * recency_boost
```

**关键词匹配逻辑**:

```sql
-- PostgreSQL 全文检索 + 向量检索混合查询
SELECT
  folder_id,
  -- 向量相似度 (语义匹配)
  1 - (content_centroid <=> $query_vector) AS vector_score,
  -- 关键词匹配度 (字面匹配)
  ts_rank(
    to_tsvector('chinese', folder_name || ' ' || COALESCE(synthetic_keywords, '')),
    plainto_tsquery('chinese', $query_title)
  ) AS keyword_score,
  -- 最近使用加成
  CASE WHEN last_used_at > NOW() - INTERVAL '7 days' THEN 0.1 ELSE 0 END AS recency_boost
FROM folders
WHERE user_id = $user_id
ORDER BY (0.6 * vector_score + 0.3 * keyword_score + recency_boost) DESC
LIMIT 5;
```

**效果**: 标题包含文件夹名的书签，`keyword_score` 会瞬间拉满，直接命中目标文件夹。

## 4. 技术实现方案

### 4.1 L1: Edge 极速层实现

#### 4.1.1 贝叶斯索引生成器 (Server-Side)

**位置**: `src/lib/classification/v6/bayesian-index-builder.service.ts`

```typescript
import type { SupabaseClient } from "@supabase/supabase-js";
import { logger } from "@/lib/logger";

/**
 * 贝叶斯索引构建器
 * 在服务端定期（每小时/每天）构建索引，推送到 CDN
 */
export class BayesianIndexBuilder {
  constructor(private supabase: SupabaseClient) {}

  /**
   * 为单个用户构建索引
   */
  async buildUserIndex(userId: string): Promise<BayesianIndex> {
    // 1. 获取用户所有书签
    const { data: bookmarks } = await this.supabase
      .from("bookmarks")
      .select("id, title, content, folder_id")
      .eq("user_id", userId)
      .not("folder_id", "is", null);

    // 2. 获取所有文件夹（包括空文件夹）
    const { data: folders } = await this.supabase
      .from("folders")
      .select("id, name, synthetic_keywords")
      .eq("user_id", userId);

    if (!folders || folders.length === 0) {
      return this.createEmptyIndex();
    }

    // 3. 统计文件夹书签数量
    const folderCounts = new Map<number, number>();
    const totalDocs = bookmarks?.length || 0;

    for (const bm of bookmarks || []) {
      const count = folderCounts.get(bm.folder_id) || 0;
      folderCounts.set(bm.folder_id, count + 1);
    }

    // 4. 构建索引
    const index: BayesianIndex = {
      version: Date.now(),
      total_docs: totalDocs,
      folders: {},
      tokens: {},
    };

    // 5. 处理每个文件夹（包括空文件夹）
    for (const folder of folders) {
      const count = folderCounts.get(folder.id) || 0;
      const alpha = this.calculateAlpha(count);

      // 文件夹基础信息
      index.folders[`f_${folder.id}`] = {
        base_prob: count > 0 ? count / Math.max(totalDocs, 1) : 0.1, // 空文件夹给默认概率
        name: folder.name,
        bookmark_count: count,
        alpha: alpha,
        // 🆕 合成关键词（用于客户端贝叶斯匹配）
        synthetic_keywords: folder.synthetic_keywords || [],
      };

      // 🆕 将合成关键词也加入 Token 索引
      if (folder.synthetic_keywords) {
        for (const keyword of folder.synthetic_keywords) {
          const tokens = this.tokenize(keyword);
          for (const token of tokens) {
            if (!index.tokens[token]) {
              index.tokens[token] = {};
            }
            // 合成关键词给予较高概率（0.8）
            index.tokens[token][`f_${folder.id}`] = 0.8;
          }
        }
      }
    }

    // 6. 处理实际书签内容的 Token
    const tokenFolderCounts = new Map<string, Map<number, number>>();
    for (const bm of bookmarks || []) {
      const tokens = this.tokenize(bm.title + " " + (bm.content || ""));
      for (const token of tokens) {
        if (!tokenFolderCounts.has(token)) {
          tokenFolderCounts.set(token, new Map());
        }
        const folderMap = tokenFolderCounts.get(token)!;
        const count = folderMap.get(bm.folder_id) || 0;
        folderMap.set(bm.folder_id, count + 1);
      }
    }

    // 7. 计算条件概率（与合成关键词合并，取较大值）
    const vocabularySize = tokenFolderCounts.size;
    for (const [token, folderMap] of tokenFolderCounts) {
      for (const [folderId, tokenCount] of folderMap) {
        const folderTotal = folderCounts.get(folderId) || 0;
        const prob = (tokenCount + 1) / (folderTotal + vocabularySize);

        if (!index.tokens[token]) {
          index.tokens[token] = {};
        }
        // 取实际概率和合成概率的较大值
        const existingProb = index.tokens[token][`f_${folderId}`] || 0;
        if (prob > existingProb) {
          index.tokens[token][`f_${folderId}`] = prob;
        }
      }
    }

    // 8. 清理低概率条目
    for (const token of Object.keys(index.tokens)) {
      const probs = index.tokens[token];
      const filtered = Object.fromEntries(
        Object.entries(probs).filter(([_, p]) => p > 0.01),
      );
      if (Object.keys(filtered).length > 0) {
        index.tokens[token] = filtered;
      } else {
        delete index.tokens[token];
      }
    }

    logger.info(
      {
        userId,
        totalDocs,
        folders: Object.keys(index.folders).length,
        tokens: Object.keys(index.tokens).length,
        sizeKB: JSON.stringify(index).length / 1024,
      },
      "V6: Bayesian index built with synthetic anchors",
    );

    return index;
  }

  /**
   * 动态权重计算 α(n)
   */
  private calculateAlpha(bookmarkCount: number): number {
    return Math.max(0.4, 1 - 0.06 * bookmarkCount);
  }

  /**
   * 简单分词器
   */
  private tokenize(text: string): Set<string> {
    const tokens = new Set<string>();
    const lower = text.toLowerCase();

    // 英文分词
    const words = lower.match(/[a-z0-9]+/g) || [];
    words.forEach((w) => tokens.add(w));

    // 中文按字/双字分词
    const chinese = lower.match(/[\u4e00-\u9fa5]/g) || [];
    chinese.forEach((c) => tokens.add(c));
    for (let i = 0; i < chinese.length - 1; i++) {
      tokens.add(chinese[i] + chinese[i + 1]);
    }

    return tokens;
  }

  private createEmptyIndex(): BayesianIndex {
    return {
      version: Date.now(),
      total_docs: 0,
      folders: {},
      tokens: {},
    };
  }
}

/**
 * 贝叶斯索引数据结构 (v6.0 增强版)
 */
export interface BayesianIndex {
  version: number;
  total_docs: number;
  folders: {
    [folderKey: string]: {
      base_prob: number;
      name: string;
      bookmark_count: number; // 🆕 书签数量
      alpha: number; // 🆕 动态权重
      synthetic_keywords: string[]; // 🆕 合成关键词
    };
  };
  tokens: {
    [token: string]: {
      [folderKey: string]: number;
    };
  };
}
```

#### 4.1.2 客户端贝叶斯推理引擎 (增强版)

**位置**: `src/lib/classification/v6/client/bayesian-engine.ts`

```typescript
import type { BayesianIndex } from "../bayesian-index-builder.service";

/**
 * 客户端贝叶斯推理引擎 (v6.0 增强版)
 * 支持动态权重和反马太效应
 */
export class ClientBayesianEngine {
  private index: BayesianIndex | null = null;
  private lastVersion: number = 0;

  async loadIndex(userId: string): Promise<void> {
    try {
      const cached = localStorage.getItem(`bayesian_index_${userId}`);
      if (cached) {
        this.index = JSON.parse(cached);
        this.lastVersion = this.index!.version;
        return;
      }
      await this.fetchIndex(userId);
    } catch (error) {
      console.error("[V6] Failed to load Bayesian index:", error);
      this.index = null;
    }
  }

  async fetchIndex(userId: string): Promise<void> {
    const response = await fetch(`/api/classification/v6/index/${userId}`);
    if (!response.ok) throw new Error("Failed to fetch index");

    const index: BayesianIndex = await response.json();
    this.index = index;
    this.lastVersion = index.version;
    localStorage.setItem(`bayesian_index_${userId}`, JSON.stringify(index));
  }

  /**
   * 预测书签应该放入哪个文件夹 (v6.0 增强版)
   */
  predict(title: string, content?: string): L1PredictionResult {
    if (!this.index || Object.keys(this.index.folders).length === 0) {
      return {
        success: false,
        confidence: 0,
        reason: "No index available or no folders",
      };
    }

    const startTime = performance.now();
    const tokens = this.tokenize(title + " " + (content || ""));

    if (tokens.size === 0) {
      return {
        success: false,
        confidence: 0,
        reason: "No tokens extracted",
      };
    }

    // 计算每个文件夹的得分
    const scores = new Map<string, number>();

    for (const [folderKey, folderData] of Object.entries(this.index.folders)) {
      let logProb = Math.log(folderData.base_prob || 0.01);
      const alpha = folderData.alpha;

      // 🆕 关键词硬匹配加成
      let keywordBonus = 0;
      const folderNameTokens = this.tokenize(folderData.name);
      for (const token of tokens) {
        if (folderNameTokens.has(token)) {
          keywordBonus += 0.5; // 每个匹配的关键词加 0.5
        }
        // 合成关键词匹配
        if (
          folderData.synthetic_keywords?.some(
            (k) =>
              k.toLowerCase().includes(token) ||
              token.includes(k.toLowerCase()),
          )
        ) {
          keywordBonus += 0.3;
        }
      }

      // Token 概率计算
      for (const token of tokens) {
        const tokenProbs = this.index.tokens[token];
        if (tokenProbs && tokenProbs[folderKey]) {
          logProb += Math.log(tokenProbs[folderKey]);
        } else {
          logProb += Math.log(1e-6);
        }
      }

      // 🆕 应用动态权重 α(n) 调整
      logProb = logProb * alpha + keywordBonus * (1 - alpha);

      // 🆕 反马太效应惩罚
      const penalty = Math.log(1 + folderData.bookmark_count) / 10;
      logProb -= penalty;

      scores.set(folderKey, logProb);
    }

    // 找出最高分
    let maxScore = -Infinity;
    let maxFolder = "";
    for (const [folderKey, score] of scores) {
      if (score > maxScore) {
        maxScore = score;
        maxFolder = folderKey;
      }
    }

    // 计算置信度（Softmax 归一化）
    const expScores = Array.from(scores.values()).map((s) =>
      Math.exp(s - maxScore),
    );
    const sumExp = expScores.reduce((a, b) => a + b, 0);
    const confidence = 1 / sumExp; // 相当于 exp(maxScore) / sum(exp(scores))

    const latency = performance.now() - startTime;

    // 判断是否足够自信（阈值 92%）
    if (confidence >= 0.92) {
      const folderId = parseInt(maxFolder.replace("f_", ""));
      return {
        success: true,
        folderId,
        folderName: this.index.folders[maxFolder].name,
        confidence,
        strategy: "L1_LOCAL",
        latencyMs: latency,
      };
    }

    return {
      success: false,
      confidence,
      reason: `Confidence ${(confidence * 100).toFixed(1)}% < 92%`,
      topCandidates: Array.from(scores.entries())
        .sort((a, b) => b[1] - a[1])
        .slice(0, 3)
        .map(([key, score]) => ({
          folderId: parseInt(key.replace("f_", "")),
          folderName: this.index!.folders[key].name,
          score: Math.exp(score - maxScore) / sumExp,
        })),
    };
  }

  private tokenize(text: string): Set<string> {
    const tokens = new Set<string>();
    const lower = text.toLowerCase();

    const words = lower.match(/[a-z0-9]+/g) || [];
    words.forEach((w) => tokens.add(w));

    const chinese = lower.match(/[\u4e00-\u9fa5]/g) || [];
    chinese.forEach((c) => tokens.add(c));
    for (let i = 0; i < chinese.length - 1; i++) {
      tokens.add(chinese[i] + chinese[i + 1]);
    }

    return tokens;
  }
}

  latencyMs?: number;
  reason?: string;
  topCandidates?: Array<{
    folderId: number;
    folderName: string;
    score: number;
  }>;

      }
```

```typescript
/**
 * 垃圾命名检测器 (v6.0 增强版)
 * 识别无意义的文件夹名称
 */
export class GenericNameDetector {
  private static readonly PATTERNS = [
    // 中文垃圾命名
    /^新建文件夹\d*$/i,
    /^未命名\d*$/i,
    /^临时\d*$/i,
    /^测试\d*$/i,
    /^文件夹\d*$/i,
    /^收藏\d*$/i,
    /^待整理\d*$/i,
    /^其他\d*$/i,
    /^杂项\d*$/i,
    /^随便\d*$/i,

    // 英文垃圾命名
    /^New Folder\d*$/i,
    /^Untitled\d*$/i,
    /^Temp\d*$/i,
    /^Test\d*$/i,
    /^Folder\d*$/i,
    /^Misc\d*$/i,
    /^Todo\d*$/i,
    /^Stuff\d*$/i,
    /^Random\d*$/i,

    // 纯数字/日��
    /^\d{4,}$/, // 纯数字（4位以上）
    /^\d{4}-\d{2}-\d{2}$/, // 日期格式
    /^\d{8}$/, // 8位日期 20250121

    // 单字符/双字符
    /^.{1,2}$/, // 1-2个字符太短
  ];

  /**
   * 检测文件夹名是否为垃圾命名
   */
  static isGenericName(folderName: string): boolean {
    const trimmed = folderName.trim();
    return this.PATTERNS.some((pattern) => pattern.test(trimmed));
  }

  /**
   * 获取垃圾命名的类型
   */
  static getGenericType(folderName: string): GenericNameType | null {
    const trimmed = folderName.trim();

    if (/^(新建文件夹|New Folder|Untitled|未命名)\d*$/i.test(trimmed)) {
      return "default_name";
    }
    if (/^(临时|Temp|测试|Test)\d*$/i.test(trimmed)) {
      return "temporary";
    }
    if (/^(其他|杂项|Misc|Stuff|Random)\d*$/i.test(trimmed)) {
      return "vague";
    }
    if (/^\d{4,}$/.test(trimmed) || /^\d{4}-\d{2}-\d{2}$/.test(trimmed)) {
      return "date_only";
    }
    if (/^.{1,2}$/.test(trimmed)) {
      return "too_short";
    }

    return null;
  }

  /**
   * 批量检测
   */
  static filterGenericFolders(
    folders: Array<{ id: number; name: string }>,
  ): Array<{ id: number; name: string; type: GenericNameType }> {
    return folders
      .filter((f) => this.isGenericName(f.name))
      .map((f) => ({
        ...f,
        type: this.getGenericType(f.name)!,
      }));
  }
}

export type GenericNameType =
  | "default_name" // 默认名称
  | "temporary" // 临时命名
  | "vague" // 模糊命名
  | "date_only" // 纯日期
  | "too_short"; // 过短
```

```sql
-- v6.0 混合检索核心函数
CREATE OR REPLACE FUNCTION hybrid_folder_search_v6(
  p_user_id UUID,
  p_query_embedding vector(1536),
  p_query_text TEXT,
  p_limit INT DEFAULT 5
)
RETURNS TABLE (
  folder_id BIGINT,
  folder_name TEXT,
  vector_score FLOAT,
  keyword_score FLOAT,
  alpha_weight FLOAT,
  matthew_penalty FLOAT,
  final_score FLOAT
) AS $$
BEGIN
  RETURN QUERY
  WITH folder_stats AS (
    SELECT
      f.id,
      f.name,
      f.bookmark_count,
      f.content_centroid,
      f.synthetic_embedding,
      f.synthetic_keywords,
      -- 动态权重 α(n) = max(0.4, 1 - 0.06 * n)
      GREATEST(0.4, 1 - 0.06 * COALESCE(f.bookmark_count, 0)) AS alpha
    FROM folders f
    WHERE f.user_id = p_user_id
      AND f.is_deleted = FALSE
  ),
  scored_folders AS (
    SELECT
      fs.id,
      fs.name,
      fs.bookmark_count,
      fs.alpha,

      -- 向量相似度（综合名称向量、内容质心、合成向量）
      CASE
        WHEN fs.bookmark_count = 0 AND fs.synthetic_embedding IS NOT NULL THEN
          -- 空文件夹：使用合成向量
          1 - (fs.synthetic_embedding <=> p_query_embedding)
        WHEN fs.content_centroid IS NOT NULL THEN
          -- 有内容：加权混合
          fs.alpha * (1 - (name_embedding <=> p_query_embedding)) +
          (1 - fs.alpha) * (1 - (fs.content_centroid <=> p_query_embedding))
        ELSE
          -- 兜底：仅名称
          1 - (name_embedding <=> p_query_embedding)
      END AS v_score,

      -- 关键词匹配分数
      COALESCE(
        ts_rank(
          to_tsvector('chinese',
            fs.name || ' ' || COALESCE(array_to_string(fs.synthetic_keywords, ' '), '')
          ),
          plainto_tsquery('chinese', p_query_text)
        ),
        0
      ) AS k_score,

      -- 反马太效应惩罚
      ln(1 + COALESCE(fs.bookmark_count, 0)) / 10.0 AS m_penalty

    FROM folder_stats fs
    LEFT JOIN folder_embeddings fe ON fe.folder_id = fs.id
  )
  SELECT
    sf.id AS folder_id,
    sf.name AS folder_name,
    sf.v_score AS vector_score,
    sf.k_score AS keyword_score,
    sf.alpha AS alpha_weight,
    sf.m_penalty AS matthew_penalty,
    -- 最终分数 = 0.6 * 向量 + 0.3 * 关键词 - 马太惩罚
    (0.6 * sf.v_score + 0.3 * LEAST(sf.k_score, 1.0) - sf.m_penalty) AS final_score
  FROM scored_folders sf
  ORDER BY final_score DESC
  LIMIT p_limit;
END;
$$ LANGUAGE plpgsql STABLE;
```

2. **向后兼容**：保持 API v5 端点运行至少 2 个版本
3. **数据完整性**：迁移前后数据一致性校验
4. **可回滚**：每个阶段支持快速回滚

```sql
-- V6 迁移脚本 001: 基础表创建与数据迁移
-- =====================================================

-- 1. 创建 V6 文件夹画像表
CREATE TABLE IF NOT EXISTS classification_folder_profiles_v6 (
    id BIGSERIAL PRIMARY KEY,
    folder_id BIGINT NOT NULL REFERENCES folders(id) ON DELETE CASCADE,
    user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,

    -- 向量字段
    name_embedding VECTOR(1024),
    content_centroid VECTOR(1024),
    synthetic_embedding VECTOR(1024),

    -- BM25 索引（计算字段）
    folder_name TEXT,
    synthetic_keywords TEXT,

    -- V6 特有字段
    bookmark_count INTEGER DEFAULT 0,
    alpha_weight FLOAT DEFAULT 1.0,
    matthew_penalty FLOAT DEFAULT 0.0,
    semantic_coverage FLOAT DEFAULT 0.0,
    cold_start_solved BOOLEAN DEFAULT FALSE,

    -- 元数据
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW(),
    profile_version INTEGER DEFAULT 6,

    UNIQUE(folder_id)
);

-- 2. 创建索引
CREATE INDEX IF NOT EXISTS idx_v6_profiles_user
    ON classification_folder_profiles_v6(user_id);
CREATE INDEX IF NOT EXISTS idx_v6_profiles_folder
    ON classification_folder_profiles_v6(folder_id);

-- 向量索引（HNSW）
CREATE INDEX IF NOT EXISTS idx_v6_name_embedding
    ON classification_folder_profiles_v6
    USING hnsw (name_embedding vector_cosine_ops);
CREATE INDEX IF NOT EXISTS idx_v6_content_centroid
    ON classification_folder_profiles_v6
    USING hnsw (content_centroid vector_cosine_ops);
CREATE INDEX IF NOT EXISTS idx_v6_synthetic_embedding
    ON classification_folder_profiles_v6
    USING hnsw (synthetic_embedding vector_cosine_ops);

-- 3. 数据迁移：V5 → V6
INSERT INTO classification_folder_profiles_v6 (
    folder_id, user_id, name_embedding, content_centroid,
    bookmark_count, folder_name, created_at, updated_at
)
SELECT
    v5.folder_id,
    v5.user_id,
    v5.name_embedding,
    v5.content_centroid,
    COALESCE((
        SELECT COUNT(*) FROM bookmarks b
        WHERE b.folder_id = v5.folder_id AND b.deleted_at IS NULL
    ), 0),
    f.name,
    v5.created_at,
    NOW()
FROM classification_folder_profiles_v5 v5
JOIN folders f ON f.id = v5.folder_id
ON CONFLICT (folder_id) DO NOTHING;

-- 4. 创建兼容视图（让旧代码继续工作）
CREATE OR REPLACE VIEW classification_folder_profiles_v5_compat AS
SELECT
    id,
    folder_id,
    user_id,
    name_embedding,
    content_centroid,
    bookmark_count,
    created_at,
    updated_at
FROM classification_folder_profiles_v6;
```

```typescript
import type { FolderProfileV5 } from "../v5/types";
import type { FolderProfileV6 } from "./types";

/**
 * V5 → V6 适配器
 * 让 V5 代码可以透明使用 V6 数据
 */
export function adaptV6ToV5(v6Profile: FolderProfileV6): FolderProfileV5 {
  return {
    id: v6Profile.id,
    folder_id: v6Profile.folder_id,
    user_id: v6Profile.user_id,
    name_embedding: v6Profile.name_embedding,
    content_centroid: v6Profile.content_centroid,
    created_at: v6Profile.created_at,
    updated_at: v6Profile.updated_at,
  };
}

/**
 * 统一 Profile 获取接口
 * 优先使用 V6，降级到 V5
 */
export async function getFolderProfile(
  folderId: bigint,
  options: { preferV6?: boolean } = { preferV6: true },
): Promise<FolderProfileV6 | FolderProfileV5 | null> {
  if (options.preferV6 && FeatureFlags.ENABLE_CLASSIFICATION_V6) {
    const v6 = await getV6Profile(folderId);
    if (v6) return v6;
  }

  // 降级到 V5
  return getV5Profile(folderId);
}
```

### 7.5.11 高风险操作注意事项

1. **删除文件夹时的影响**：
   - CASCADE 会删除 `folder_profiles` 和 `classification_folder_profiles_v5/v6`
   - SET NULL 会使多个分类记录的 folder_id 变为 NULL
   - 可能影响分类准确率统计和历史回溯

2. **建议采用软删除**：
   - 使用 `deleted_at` 标记而非硬删除
   - 保留历史数据用于分析和回溯

3. **V5 表保留策略**：
   - V6 上线后保留 V5 表 **90 天**
   - 便于问题排查和数据恢复
   - 90 天后评估是否可安全删除

## 12. 总结与建议

### 12.1 核心亮点

1. **极致体验**: 70% 请求在客户端 10ms 完成，零网络延迟
2. **成本优化**: API 调用减少 70%，LLM 调用减少 85%
3. **智能治理**: 主动发现并修复垃圾命名，提升长期数据质量
4. **渐进增强**: L1 → L2 → L3 分层降级，保证鲁棒性
5. **🆕 冷启动解决**: 合成锚点撑起空文件夹语义空间，命中率 15% → 70%
6. **🆕 马太效应抑制**: 大文件夹引力惩罚，吞噬率 30% → 5%

```typescript
 * 实现去文件夹化的自组织分类

export class CrystalGrowthService {
  // 结晶��值：至少 3 个书签聚集
  private readonly NUCLEATION_THRESHOLD = 3;
  // 命中现有文件夹的距离阈值
  private readonly HIT_DISTANCE = 0.15;
  // 晶核形成的邻居半径
  private readonly NUCLEUS_RADIUS = 0.2;
  // 语义防撞阈值
  private readonly COLLISION_THRESHOLD = 0.85;

  constructor(private supabase: SupabaseClient) {}

  /**
   * 处理新书签 - 晶体生长主入口
   */
  async processNewBookmark(
    userId: string,
    bookmark: {
      id: number;
      title: string;
      content?: string;
      embedding: number[];
    },
  ): Promise<CrystalGrowthResult> {
    const startTime = performance.now();

    // Step 1: 尝试命中现有文件夹
    const hitResult = await this.tryHitExistingFolder(
      userId,
      bookmark.embedding,
    );
    if (hitResult) {
      await this.assignToFolder(bookmark.id, hitResult.folderId);
      return {
        action: "HIT_EXISTING",
        folderId: hitResult.folderId,
        folderName: hitResult.folderName,
        confidence: hitResult.similarity,
        latencyMs: performance.now() - startTime,
      };
    }

    // Step 2: 尝试在混沌池中形成晶核
    const nucleationResult = await this.tryNucleation(userId, bookmark);
    if (nucleationResult) {
      return {
        action: "CRYSTALLIZED",
        folderId: nucleationResult.folderId,
        folderName: nucleationResult.folderName,
        clusterSize: nucleationResult.clusterSize,
        latencyMs: performance.now() - startTime,
      };
    }

    // Step 3: 留在混沌池
    await this.addToChaosPool(userId, bookmark);
    return {
      action: "POOLED",
      message: "书签已保存，等待相关内容聚集后自动分类",
      latencyMs: performance.now() - startTime,
    };
  }

  /**
   * 尝试命中现有文件夹
   */
  private async tryHitExistingFolder(
    userId: string,
    embedding: number[],
  ): Promise<{
    folderId: number;
    folderName: string;
    similarity: number;
  } | null> {
    const { data: folders } = await this.supabase.rpc("find_nearest_folder", {
      p_user_id: userId,
      p_embedding: embedding,
      p_limit: 1,
    });

    if (folders && folders.length > 0) {
      const nearest = folders[0];
      const distance = 1 - nearest.similarity;
      if (distance < this.HIT_DISTANCE) {
        return {
          folderId: nearest.folder_id,
          folderName: nearest.folder_name,
          similarity: nearest.similarity,
        };
      }
    }
    return null;
  }

  /**
   * 尝试在混沌池中形成晶核
   */
  private async tryNucleation(
    userId: string,
    bookmark: {
      id: number;
      title: string;
      content?: string;
      embedding: number[];
    },
  ): Promise<{
    folderId: number;
    folderName: string;
    clusterSize: number;
  } | null> {
    // 查找混沌池中的邻居
    const { data: neighbors } = await this.supabase.rpc(
      "find_chaos_pool_neighbors",
      {
        p_user_id: userId,
        p_embedding: bookmark.embedding,
        p_radius: this.NUCLEUS_RADIUS,
        p_limit: 10,
      },
    );

    if (!neighbors || neighbors.length < this.NUCLEATION_THRESHOLD - 1) {
      return null; // 邻居不够，无法结晶
    }

    // 形成晶核簇
    const cluster = [
      bookmark,
      ...neighbors.slice(0, this.NUCLEATION_THRESHOLD - 1),
    ];

    // 获取现有文件夹名称（用于 MECE 保证）
    const { data: existingFolders } = await this.supabase
      .from("folders")
      .select("id, name")
      .eq("user_id", userId)
      .eq("is_deleted", false);

    // 生成 MECE 文件夹名称
    const folderName = await this.generateMECEFolderName(
      cluster.map((b) => b.title),
      existingFolders?.map((f) => f.name) || [],
    );

    // 检查语义防撞
    const collision = await this.checkSemanticCollision(
      userId,
      folderName,
      existingFolders || [],
    );

    if (collision) {
      // 合并到已有文件夹，而不是新建
      const mergedName = await this.generateMergedName(
        collision.existingName,
        folderName,
        cluster.map((b) => b.title),
      );

      // 更新现有文件夹名称
      await this.supabase
        .from("folders")
        .update({ name: mergedName })
        .eq("id", collision.existingId);

      // 移动书签到现有文件夹
      for (const b of cluster) {
        await this.assignToFolder(b.id, collision.existingId);
        await this.removeFromChaosPool(userId, b.id);
      }

      logger.info(
        {
          userId,
          action: "MERGE_COLLISION",
          oldName: collision.existingName,
          newName: mergedName,
          clusterSize: cluster.length,
        },
        "V6.5: Semantic collision resolved by merge",
      );

      return {
        folderId: collision.existingId,
        folderName: mergedName,
        clusterSize: cluster.length,
      };
    }

    // 创建新文件夹
    const { data: newFolder } = await this.supabase
      .from("folders")
      .insert({
        user_id: userId,
        name: folderName,
        is_ai_generated: true,
        crystal_birth_time: new Date().toISOString(),
      })
      .select("id")
      .single();

    if (!newFolder) throw new Error("Failed to create folder");

    // 移动书签到新文件夹
    for (const b of cluster) {
      await this.assignToFolder(b.id, newFolder.id);
      await this.removeFromChaosPool(userId, b.id);
    }

    // 生成合成锚点
    await this.generateSyntheticAnchor(userId, newFolder.id, folderName);

    logger.info(
      {
        userId,
        folderId: newFolder.id,
        folderName,
        clusterSize: cluster.length,
      },
      "V6.5: New crystal formed",
    );

    return {
      folderId: newFolder.id,
      folderName,
      clusterSize: cluster.length,
    };
  }

  // 辅助方法...
  private cosineSimilarity(a: number[], b: number[]): number {
    let dot = 0,
      normA = 0,
      normB = 0;
    for (let i = 0; i < a.length; i++) {
      dot += a[i] * b[i];
      normA += a[i] * a[i];
      normB += b[i] * b[i];
```

### 11.4 动态重结晶 (Dynamic Recrystallization)

文件夹不是静态的，随着内容增长，需要**分裂**或**合并**。

#### 11.4.1 分裂条件 (Folder Splitting)

当文件夹内书签数量 > 50 且**内部方差过大**时触发分裂：

```sql
-- 检测需要分裂的文件夹
SELECT folder_id, folder_name, bookmark_count, internal_variance
FROM (
  SELECT
    f.id AS folder_id,
    f.name AS folder_name,
    COUNT(b.id) AS bookmark_count,
    -- 计算内部方差（书签向量到质心的平均距离）
    AVG(1 - (b.embedding <=> f.content_centroid)) AS internal_variance
  FROM folders f
  JOIN bookmarks b ON b.folder_id = f.id
  WHERE f.user_id = $user_id
  GROUP BY f.id, f.name, f.content_centroid
) stats
WHERE bookmark_count > 50 AND internal_variance < 0.75;
```

**分裂流程**:

1. 对文件夹内书签进行 K-Means 聚类（K=2 或 3）
2. 为每个子簇生成新名称
3. 创建子文件夹，迁移书签
4. 保留父文件夹作为"虚拟分组"

#### 11.4.2 合并条件 (Folder Merging)

当两个文件夹**语义距离过近**且**��签数都较少**时触发合并：

```sql
-- 检测需要合并的文件夹对
SELECT
  f1.id AS folder1_id, f1.name AS folder1_name, f1.bookmark_count AS count1,
  f2.id AS folder2_id, f2.name AS folder2_name, f2.bookmark_count AS count2,
  1 - (f1.content_centroid <=> f2.content_centroid) AS similarity
FROM folders f1
JOIN folders f2 ON f1.user_id = f2.user_id AND f1.id < f2.id
WHERE f1.user_id = $user_id
  AND f1.is_deleted = FALSE AND f2.is_deleted = FALSE
  AND f1.bookmark_count < 20 AND f2.bookmark_count < 20
  AND 1 - (f1.content_centroid <=> f2.content_centroid) > 0.80;
```

#### 11.6.3 核心 RPC 函数

```sql
-- 查找混沌池中的邻居
CREATE OR REPLACE FUNCTION find_chaos_pool_neighbors(
  p_user_id UUID,
  p_embedding vector(1536),
  p_radius FLOAT DEFAULT 0.20,
  p_limit INT DEFAULT 10
)
RETURNS TABLE (
  bookmark_id BIGINT,
  title TEXT,
  distance FLOAT
) AS $$
BEGIN
  RETURN QUERY
  SELECT
    cp.bookmark_id,
    b.title,
    (1 - (cp.embedding <=> p_embedding)) AS distance
  FROM chaos_pool cp
  JOIN bookmarks b ON b.id = cp.bookmark_id
  WHERE cp.user_id = p_user_id
    AND (1 - (cp.embedding <=> p_embedding)) > (1 - p_radius)
  ORDER BY distance DESC
  LIMIT p_limit;
END;
$$ LANGUAGE plpgsql STABLE;
```

### 11.9 核心理念总结

> **"废除空文件夹"**：系统里不允许存在空文件夹。文件夹是内容的**涌现 (Emergence)**，而不是容器。
>
> **"延迟满足"**：单篇书签允许暂时"无家可归"。只有积累了足够的**语义质量 (Semantic Mass)**，才允许坍缩成文件夹。
>
> **"动态重构"**：文件夹的名字不是永恒的。随着内容增加，AI 会自动把"前端"分裂成"React"和"Vue"，或者把"川菜"和"粤菜"合并成"中式烹饪"。

**这种设计将彻底消除"马太效应"和"命名模糊"问题，因为每一个文件夹都是由其内容本身"定义"的，而不是由用户拍脑袋决定的。**

#### 12.5.1 分类 API 路由增强

**文件**: `src/app/api/classification/classify/route.ts`

```typescript
import { FEATURE_FLAGS } from "@/lib/classification/config/feature-flags";
import { ClassificationContainer } from "@/lib/classification/container";

export async function POST(request: Request) {
  const supabase = await createClient();
  const container = ClassificationContainer.initialize(supabase);

  // 解析请求
  const body = await request.json();
  const { userId, bookmark, l1Result } = body;

  // 🆕 V6 路由判断
  if (FEATURE_FLAGS.enableV6TriFunnel) {
    const v6Orchestrator = container.getV6Orchestrator();

    // 如果客户端已经通过 L1 分类成功，直接使用
    if (
      l1Result?.success &&
      l1Result.confidence >= FEATURE_FLAGS.v6L1ConfidenceThreshold
    ) {
      return NextResponse.json({
        folderId: l1Result.folderId,
        folderName: l1Result.folderName,
        confidence: l1Result.confidence,
        strategy: "L1_LOCAL",
        latencyMs: 0,
      });
    }

    // 进入 L2/L3 处理
    const result = await v6Orchestrator.classify(userId, bookmark, l1Result);
    return NextResponse.json(result);
  }

  // 🆕 V6.5 ���体生长模式
  if (FEATURE_FLAGS.enableV6CrystalGrowth) {
    const crystalGrowthService = container.getCrystalGrowthService();
    const result = await crystalGrowthService.processNewBookmark(
      userId,
      bookmark,
    );
    return NextResponse.json(result);
  }

  // 降级到现有 V4.2 逻辑
  const classificationService = container.getClassificationService();
  const result = await classificationService.classify(userId, bookmark);
  return NextResponse.json(result);
}
```

#### 12.7.2 React Hook 集成

**新增文件**: `src/hooks/classification/use-v6-classification.ts`

```typescript
import { useState, useEffect, useCallback } from "react";
import {
  ClientBayesianEngine,
  L1PredictionResult,
} from "@/lib/classification/v6/l1-edge/client-bayesian-engine";

export function useV6Classification(userId: string | undefined) {
  const [engine, setEngine] = useState<ClientBayesianEngine | null>(null);
  const [isReady, setIsReady] = useState(false);
  const [indexVersion, setIndexVersion] = useState<number>(0);

  // 初始化引擎
  useEffect(() => {
    if (!userId) return;

    const bayesianEngine = new ClientBayesianEngine();
    bayesianEngine.loadIndex(userId).then(() => {
      setEngine(bayesianEngine);
      setIsReady(true);
      setIndexVersion(bayesianEngine.getVersion());
    });
  }, [userId]);

  // L1 本地预测
  const predictLocal = useCallback(
    (title: string, content?: string): L1PredictionResult | null => {
      if (!engine || !isReady) return null;
      return engine.predict(title, content);
    },
    [engine, isReady],
  );

  // L2/L3 服务端分类
  const classifyRemote = useCallback(
    async (
      bookmark: { title: string; url: string; content?: string },
      l1Result?: L1PredictionResult,
    ) => {
      const response = await fetch("/api/classification/v6/classify", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ userId, bookmark, l1Result }),
      });
      return response.json();
    },
    [userId],
  );

  // 智能分类（L1 → L2 → L3 自动降级）
  const classify = useCallback(
    async (bookmark: { title: string; url: string; content?: string }) => {
      // 先尝试 L1 本地分类
      const l1Result = predictLocal(bookmark.title, bookmark.content);

      if (l1Result?.success) {
        return {
          ...l1Result,
          strategy: "L1_LOCAL" as const,
        };
      }

      // L1 失败，转 L2/L3
      return classifyRemote(bookmark, l1Result || undefined);
    },
    [predictLocal, classifyRemote],
  );

  return {
    isReady,
    indexVersion,
    predictLocal,
    classifyRemote,
    classify,
    refreshIndex: () => engine?.fetchIndex(userId!),
  };
}
```

```typescript
// src/lib/classification/v6/config/rollout.ts
export function isUserInV6Rollout(userId: string): boolean {
  const rolloutPercentage = parseInt(process.env.V6_ROLLOUT_PERCENTAGE || "0");
  if (rolloutPercentage === 0) return false;
  if (rolloutPercentage >= 100) return true;

  // 使用用户 ID 的哈希值确定是否在灰度范围内
  const hash = hashCode(userId);
  return hash % 100 < rolloutPercentage;
}

function hashCode(str: string): number {
  let hash = 0;
  for (let i = 0; i < str.length; i++) {
    hash = (hash << 5) - hash + str.charCodeAt(i);
    hash |= 0;
  }
  return Math.abs(hash);
}
```
