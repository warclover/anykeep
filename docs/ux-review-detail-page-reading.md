# 详情页阅读体验优化方案

> 审核人：UX Chief Officer | 日期：2026-03-15
> 范围：`bookmark/[id]` 详情页的阅读体验
> 优先级标注：P0 = 必须做 | P1 = 强烈建议 | P2 = 锦上添花

---

## 一、现状问题诊断

### 1.1 排版层面

| 问题                    | 严重度 | 现状                       | 说明                                      |
| ----------------------- | ------ | -------------------------- | ----------------------------------------- |
| **内容区 padding 极小** | P0     | `px-1 md:px-2`（4px/8px）  | 文字贴着屏幕边缘，缺乏呼吸感              |
| **快照正文字号偏小**    | P0     | `prose-sm`（14px 基准）    | 长文阅读 14px 太小，业界标准 16-18px      |
| **行高未显式优化**      | P0     | 依赖 Tailwind prose 默认值 | 中文最佳阅读行高 1.75-1.85，当前约 1.5    |
| **段间距不足**          | P1     | `space-y-3`（12px）        | 内容区段落间呼吸感差                      |
| **内容宽度无约束**      | P1     | `max-w-none`（撑满容器）   | 每行字数过多（可达 80+ 中文字），阅读疲劳 |

### 1.2 布局层面

| 问题                    | 严重度 | 现状                                    | 说明                                         |
| ----------------------- | ------ | --------------------------------------- | -------------------------------------------- |
| **所有内容塞进单 Card** | P0     | 摘要/标签/备注/快照/推荐全在一个 Card   | 信息密度过高，无法区分主次                   |
| **标题区信息过载**      | P1     | 3 行紧凑布局（标题+元数据+标签+操作栏） | CardHeader 区域 ≥5 种元信息平铺              |
| **Separator 过多**      | P1     | 6+ 条分割线穿插内容区                   | 视觉噪音，反而模糊了层次                     |
| **快照区默认收起**      | P2     | `defaultExpanded={false}`               | 用户进入详情页大概率想阅读正文，却需手动展开 |

### 1.3 阅读体验层面

| 问题                           | 严重度 | 现状                                 | 说明                           |
| ------------------------------ | ------ | ------------------------------------ | ------------------------------ |
| **无沉浸阅读模式**             | P1     | 快照/文章内容与元数据、操作栏共存    | 无法专注阅读                   |
| **快照在 ScrollArea 内嵌滚动** | P1     | `maxHeight="600px"` 硬编码           | 阅读长文时频繁在内嵌滚动区操作 |
| **代码块无语法高亮**           | P1     | 快照内容用 `dangerouslySetInnerHTML` | 技术文章代码块观感差           |
| **暗色模式对比度**             | P2     | `dark:prose-invert` 直接反色         | 部分文本对比度不足             |

## 二、优化方案

### 2.1 [P0] 排版基线重建 — "让文字可以呼吸"

**目标**：建立符合中文长文阅读的排版基线。

```
改动文件：
- src/components/bookmark/bookmark-detail-client.tsx
- src/components/snapshot/snapshot-viewer.tsx
- src/app/globals.css（新增 .reading-prose 类）
```

**具体方案**：

#### A. 新增 `.reading-prose` 阅读排版类

```css
/* globals.css */
.reading-prose {
  /* 基准字号 */
  font-size: 1rem; /* 16px */

  /* 中文最佳行高 */
  line-height: 1.8;

  /* 最佳阅读宽度：65-75 中文字符 */
  max-width: 72ch;
  margin-left: auto;
  margin-right: auto;

  /* 段落间距 */
  & p {
    margin-block: 1.25em;
  }

  /* 标题层级间距 */
  & h1,
  & h2,
  & h3 {
    margin-top: 2em;
    margin-bottom: 0.75em;
  }

  /* 列表呼吸感 */
  & li {
    margin-block: 0.4em;
  }

  /* 引用块 */
  & blockquote {
    border-left: 3px solid var(--accent);
    padding: 0.75em 1em;
    margin-block: 1.5em;
    background: var(--muted);
    border-radius: 0 0.5rem 0.5rem 0;
  }

  /* 图片居中 + 圆角 */
  & img {
    margin-inline: auto;
    border-radius: 0.5rem;
    max-width: 100%;
  }
}
```

#### B. 调整容器 padding

```diff
- <div className="flex-1 overflow-auto px-1 md:px-2 pt-1 pb-4">
+ <div className="flex-1 overflow-auto px-4 md:px-8 pt-4 pb-8">
```

#### C. 快照内容升级为标准排版

```diff
- <article className="prose prose-sm dark:prose-invert max-w-none break-words">
+ <article className="prose dark:prose-invert reading-prose break-words">
```

### 2.2 [P0] 内容分区重组 — "从一张大卡变为清晰分区"

**目标**：将单一臃肿 Card 拆分为逻辑区块，用留白而非分割线建立层次。

**新布局结构**（自上而下）：

```
┌─────────────────────────────────────────────────┐
│  区块1：元信息区（标题、平台、时间、标签、操作）     │
│  ─ 紧凑设计，信息密度高但视觉整洁                   │
└─────────────────────────────────────────────────┘
         ↓ 24px 留白（非分割线）
┌─────────────────────────────────────────────────┐
│  区块2：AI 摘要区                                  │
│  ─ 独立卡片，渐变背景，视觉突出                     │
└─────────────────────────────────────────────────┘
         ↓ 24px 留白
┌─────────────────────────────────────────────────┐
│  区块3：正文阅读区（快照/微信文章）                  │
│  ─ 最大面积、最佳排版，阅读核心                     │
│  ─ 独立 Card，内含沉浸阅读按钮                     │
│  ─ 取消 ScrollArea 内嵌滚动，用自然文档流            │
└─────────────────────────────────────────────────┘
         ↓ 24px 留白
┌─────────────────────────────────────────────────┐
│  区块4：补充区（备注 + 标签编辑 + 知识关联）         │
│  ─ 折叠式展示，不干扰阅读主线                      │
└─────────────────────────────────────────────────┘
```

**关键改动**：

1. 移除单一 `<Card>` 包裹，改为 `space-y-6` 的区块布局
2. 移除大部分 `<Separator />`，用 `margin/gap` 建立层次
3. AI 摘要区保留渐变卡片样式（已有）
4. 正文阅读区默认展开（改 `defaultExpanded={true}`）

---

### 2.3 [P1] 元信息区精简 — "Less is More"

**目标**：减少 CardHeader 信息噪音，只保留最关键信息。

**优化策略**：

| 元素                  | 当前                   | 优化后                          |
| --------------------- | ---------------------- | ------------------------------- |
| 标题                  | `text-lg md:text-xl`   | `text-xl md:text-2xl`，适度放大 |
| 平台徽章              | 标题右侧               | 标题下方，与时间同行            |
| 收藏属性标签          | 固定显示"收藏属性"四字 | 移除，它没有信息量              |
| 文件夹/来源/作者/时间 | 一行排列用 `·` 分隔    | 保留，但间距优化                |
| 评级/锁定             | 右侧                   | 合入操作栏，减少视觉元素        |
| 用途标签              | 独立行                 | 合入操作栏下方或折叠显示        |

**标题区优化后**：

```
┌─────────────────────────────────────────────┐
│ 文章标题（大号字体，粗体）                        │
│                                              │
│ 📱 微信公众号 · 作者名 · 3天前发表 · 收藏于1天前  │
│                                              │
│ [返回] [编辑] [移到] [AI] [分享] [删除]  ⭐⭐⭐ │
│                                              │
│ #标签1  #标签2  #用途-学习                      │
└─────────────────────────────────────────────┘
```

### 2.4 [P1] 快照正文去除内嵌滚动 — "自然文档流"

**目标**：让快照/文章正文融入页面自然滚动，而非困在 600px 高的滚动容器中。

```diff
// snapshot-viewer.tsx
- <ScrollArea style={{ maxHeight }} className="pr-4">
-   <article className="prose prose-sm ...">
- </ScrollArea>
+ <article className="prose dark:prose-invert reading-prose">
+   {/* 使用自然文档流，不限制高度 */}
+ </article>
```

**为什么**：

- 内嵌滚动违反用户心智模型（"我在哪？"困惑）
- 触屏设备上嵌套滚动体验极差
- 长文阅读需要整页滚动的沉浸感

---

### 2.5 [P1] 沉浸阅读模式（可选增强）

**目标**：提供"聚焦阅读"按钮，点击后隐藏元信息和操作栏，仅保留正文。

**交互设计**：

- 正文区右上角添加 `<Maximize2 />` 图标按钮
- 点击后：
  - 元信息区 + 摘要区 + 补充区滑出隐藏
  - 正文区居中占满，增大字号到 18px
  - 顶部浮动一个 mini 工具栏（关闭沉浸模式 + 字号调节）
- 按 `Esc` 或点击关闭按钮退出

**实现复杂度**：中等（状态管理 + CSS transition）

---

### 2.6 [P2] 暗色模式阅读优化

**目标**：暗色模式下提供更舒适的阅读对比度。

```css
.reading-prose {
  /* 暗色模式特别调优 */
  @media (prefers-color-scheme: dark) {
    color: hsl(210 20% 88%); /* 柔和的浅灰文字，非纯白 */
    & h1,
    & h2,
    & h3 {
      color: hsl(210 20% 95%);
    }
    & blockquote {
      border-color: hsl(217 50% 45%);
      background: hsl(217 30% 15%);
    }
  }
}
```

## 三、业界对标参考

| 产品                | 核心体验                          | 可借鉴点           |
| ------------------- | --------------------------------- | ------------------ |
| **Readwise Reader** | 极致阅读排版，65ch 宽度，1.8 行高 | 排版基线、高亮标注 |
| **Notion**          | 清爽留白，模块化区块              | 区块间距、内容分区 |
| **微信读书**        | 沉浸阅读模式，字号/行距/背景可调  | 沉浸模式设计       |
| **Instapaper**      | 去噪阅读，正文优先                | 元信息最小化       |
| **Raindrop.io**     | 书签详情 + 快照阅读一体           | 快照与元数据的平衡 |

**核心启示**：所有优秀阅读产品都遵循 **"正文至上"** 原则 —— 元信息/操作/标签都是辅助，正文内容的排版才是核心竞争力。

## 四、实施优先级建议

### Phase 1：排版基线（1-2天）—— 投入少，收益大

- [x] 新增 `.reading-prose` CSS 类（字号、行高、段距、宽度）
- [x] 调整外层 padding（`px-1` → `px-4 md:px-8`）
- [x] 快照内容从 `prose-sm` 升级到 `prose` + `reading-prose`
- [x] 去除快照 ScrollArea 嵌套滚动

### Phase 2：布局重组（2-3天）—— 核心体验升级

- [x] Card 拆分为 4 个独立区块
- [x] 用 `space-y-6` 留白替代 `<Separator />`
- [x] 元信息区精简
- [x] 正文区默认展开

### Phase 3：锦上添花（2-3天）—— 差异化体验

- [x] 沉浸阅读模式
- [x] 暗色模式对比度调优
- [x] 字号调节控件（承袭 md-renderer 的 small/medium/large）

---

## 五、关键约束

1. **不改变数据模型和 API**：纯前端排版优化
2. **向后兼容**：不影响 AI 摘要渲染逻辑（SummaryRenderer 保持不变）
3. **渐进增强**：Phase 1 可独立交付，Phase 2/3 按需推进
4. **移动端优先**：所有排版参数移动端适配（字号不小于 16px）
5. **已有 md-renderer 排版系统可复用**：`typography.ts` 中的 `TYPOGRAPHY_BASE`、`FONT_STACKS` 直接引用

---

> **一句话总结**：当前详情页最大的阅读体验问题是 **"把阅读页做成了信息仪表盘"**。
> 优化的核心思路是 **"让正文回归主角，让元信息退为配角"**。
