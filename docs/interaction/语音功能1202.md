## AnyKeep 语音功能设计与 `/api/voice/intents` 接口规范（2025-12-02）

**目标**：在现有 AnyKeep 架构基础上，引入「语音 + AI」能力，支持语音搜索、语音指令和语音备注，并通过统一的 `/api/voice/intents` 接口向前端和其他内部服务暴露**结构化意图结果**。  
**现有技术栈前提**：

- 语义理解 / 对话：阿里 **百炼云** 大模型
- 摘要生成：**DeepSeek**（用于 AI 摘要/聚合总结）
- 计划 ASR：阿里云 **智能语音交互（NLS）**

---

## 一、语音功能整体设计回顾

### 1.1 设计目标

面向「中文互联网重度用户 + 知识工作者」，语音功能主要解决：

- **手忙眼忙时的操作成本**：说两句就能「搜东西」「记一句」「加备注」；
- 适配用户**碎片时间**和「听」信息的习惯；
- 在微信/B 站/小红书等中文生态中，让收藏和找回更顺手。

### 1.2 优先落地的语音能力（阶段排序）

**P0（最高优先级）**

- 语音搜索：按住说话 → 自动转成搜索词和筛选条件（平台/时间）。
- 语音指令：支持自然语言指令自动解析为结构化搜索/操作（如「帮我找上周收藏的微信文章，关于 React 性能优化的」）。

**P0.5**

- 语音朗读（TTS）：朗读单条收藏的 **标题 + AI 摘要**，或「今日新收藏摘要列表」。

**P1**

- 语音备注：在收藏详情页录一段 10–60 秒语音，自动转写为文本备注，可选再用 DeepSeek 生成精简要点。
- 语音临时收藏：不依赖网页，仅用语音快速记事，转成一条特殊类型的「语音收藏卡片」。

**后续进阶（P2+）**

- 语音对话式检索：如「总结一下我收藏的关于 React 性能优化的文章」。
- 与 Video X-Ray 结合的语音标记：边看 B 站视频边说「刚才这段帮我打个标记」。

### 1.3 技术路线（“声 → 文 → 语义”）

统一采用 **两段式**：

1. **语音识别（ASR） → 文本**
   - 厂商：阿里云智能语音交互（NLS）
   - 模式：优先短语音/一句话识别（3–20 秒）
2. **文本 → 语义意图解析**
   - 厂商：阿里百炼云大模型
   - 输出：统一的 JSON 指令（action + 参数）
3. **（可选）文本 → 摘要/聚合总结**
   - 厂商：DeepSeek，用于摘要和多条内容的聚合总结

## 二、统一接口设计：`POST /api/voice/intents`

### 2.1 功能定位

`/api/voice/intents` 是**唯一**对外暴露的语音解析服务接口，负责：

1. 接收前端上传的语音（或语音 URL）；
2. 调用阿里云 ASR 将语音转成中文文本；
3. 调用百炼云大模型，将文本解析为 **结构化意图 JSON**；
4. 返回统一格式的响应，供 Web 前端 / 浏览器扩展 / 移动端 / 其他内部服务复用。

### 2.2 请求规格

#### 2.2.1 URL & 方法

- **URL**：`POST /api/voice/intents`
- **Method**：`POST`

#### 2.2.2 鉴权

- 与现有 API 保持一致（如 Supabase Auth / JWT / Cookie），此处不赘述。

#### 2.2.3 支持的请求格式

接口支持两种方式之一：

1. **`multipart/form-data`**：前端直接上传音频二进制
2. **`application/json`**：仅传音频 URL，由后端自行抓取（适合已存储在 Supabase Storage 的场景）

##### A. `multipart/form-data` 请求体字段

| 字段名     | 类型     | 必填 | 说明                                                                   |
| ---------- | -------- | ---- | ---------------------------------------------------------------------- |
| `file`     | `binary` | 是   | 语音文件二进制，建议 `audio/webm` / `audio/mpeg` / `audio/wav` 等      |
| `mode`     | `string` | 否   | 语音用途提示：`"search" \| "command" \| "note"`，仅作为提示给 LLM 使用 |
| `language` | `string` | 否   | 默认 `"zh-CN"`，可预留英文/中英混合                                    |
| `userId`   | `string` | 否   | 当前登录用户 ID（用于日志/个性化，可从会话自动注入）                   |
| `deviceId` | `string` | 否   | 设备标识（便于排查某些设备上的录音问题）                               |
| `client`   | `string` | 否   | 客户端来源：`"web" \| "pwa" \| "extension" \| "mobile"`                |
| `traceId`  | `string` | 否   | 链路追踪 ID，便于日志聚合                                              |
| `extra`    | `string` | 否   | 可选 JSON 字符串扩展字段（如当前所在页面、是否在详情页等）             |

> 推荐做法：前端统一走 `multipart/form-data`，JSON URL 方式留给内部服务或后续扩展。

##### B. `application/json` 请求体字段（可选方案）

```jsonc
{
  "audioUrl": "https://xxx.supabase.co/storage/v1/object/public/voice/xxx.webm",
  "mode": "search", // 可选: "search" | "command" | "note"
  "language": "zh-CN",
  "userId": "uuid-xxx",
  "client": "web",
  "deviceId": "device-xxx",
  "traceId": "trace-xxx",
  "extra": {
    "page": "/home",
    "context": {
      "currentPlatformFilter": "wechat",
    },
  },
}
```

### 2.3 统一意图 JSON 结构定义

#### 2.3.1 顶层响应结构（成功）

```jsonc
{
  "success": true,
  "intent": {
    "action": "search",
    "action_confidence": 0.94,
    "keywords": ["React", "性能优化"],
    "platform": "wechat",
    "time_range": "last_week",
    "note": null,
    "note_type": null,
    "output_mode": "list",
    "extra": {},
  },
  "raw_text": "帮我找上周收藏的微信文章，关于 React 性能优化的",
  "normalized_text": "帮我找上周收藏的和 React 性能优化有关的微信文章",
  "asr_meta": {
    "engine": "aliyun-nls",
    "request_id": "asr-xxx",
    "duration_ms": 5200,
    "confidence": 0.93,
    "language": "zh-CN",
  },
  "llm_meta": {
    "provider": "bailian",
    "model": "qwen-max", // 示例
    "request_id": "llm-xxx",
    "prompt_tokens": 800,
    "completion_tokens": 120,
    "total_tokens": 920,
  },
}
```

#### 2.3.2 意图对象 `intent` 字段说明

| 字段名              | 类型       | 说明                                                                                           |
| ------------------- | ---------- | ---------------------------------------------------------------------------------------------- |
| `action`            | `string`   | 动作类型，详见「Action 枚举」。                                                                |
| `action_confidence` | `number`   | 0–1 置信度，来源于 LLM 主观判断。                                                              |
| `keywords`          | `string[]` | 与本次语音相关的核心关键词数组（用于搜索/打标签）。                                            |
| `platform`          | `string`   | 平台过滤条件，枚举：`"wechat" \| "bilibili" \| "xiaohongshu" \| "browser" \| "any"`            |
| `time_range`        | `string`   | 时间范围，枚举：`"today" \| "yesterday" \| "last_week" \| "last_month" \| "all" \| "custom"`   |
| `note`              | `string?`  | 语音备注转写/归一后的文本内容（仅在 `action` 为 `create_voice_note` / `append_note` 时使用）。 |
| `note_type`         | `string?`  | 备注类型：`"quick_thought" \| "todo" \| "context"` 等，可扩展。                                |
| `output_mode`       | `string`   | 期望的输出形态：`"list" \| "detail" \| "summary" \| "unknown"`。                               |
| `extra`             | `object`   | 预留扩展字段，如 `{ "target_bookmark_id": 123 }`。                                             |

#### 2.3.3 Action 枚举建议（首批）

1. **`search`**
   - 说明：语音搜索收藏内容。
   - 典型语句：
     - 「帮我找上周收藏的微信文章，关于 React 性能优化」
     - 「搜一下 B 站上关于 Rust 的视频」
   - 关键字段：`keywords`、`platform`、`time_range`、`output_mode="list"`

2. **`open_bookmark`**
   - 说明：打开某条收藏（通常基于最近操作上下文）。
   - 典型语句：
     - 「打开刚才说的那篇文章」
   - 关键字段：`extra.target_bookmark_id`（由调用方根据上下文补全）

3. **`create_voice_note`**
   - 说明：创建独立语音笔记/语音收藏。
   - 典型语句：
     - 「记一下：下周要看那个 React Server Components 的视频」
   - 关键字段：`note`（文本）、`note_type`（如 `"todo"`）、`keywords`

4. **`append_note`**
   - 说明：给当前收藏追加一条备注。
   - 典型语句：
     - 「这一段适合下次团队分享，重点讲性能那部分」
   - 关键字段：`note`、`note_type`，以及 `extra.target_bookmark_id`

5. **`summarize_recent`**
   - 说明：对最近一段时间里某平台/主题的收藏做总结（通常后续会用 DeepSeek）。
   - 典型语句：
     - 「总结一下我最近一周收藏的 B 站前端视频」
   - 关键字段：`platform`、`time_range`、`keywords`（如「前端」）、`output_mode="summary"`

6. **`unknown`**
   - 说明：无法可靠判断用户意图。
   - 典型语句：
     - 环境噪音/无效语音等。
   - 要求：`action_confidence` 较低（如 < 0.5），调用方可给用户「没听清」提示。

> 后续可扩展 `delete`, `pin`, `share`, `change_rating` 等动作，但首发阶段建议控制在上面的 5–6 个。

### 2.4 错误响应格式

#### 2.4.1 通用错误结构

```jsonc
{
  "success": false,
  "error": {
    "code": "ASR_TIMEOUT", // 例如: "INVALID_INPUT" | "ASR_ERROR" | "LLM_ERROR" | "INTERNAL_ERROR"
    "message": "阿里云语音识别超时",
    "details": null,
  },
  "raw_text": null,
  "intent": null,
}
```

#### 2.4.2 建议的错误码枚举

- `INVALID_INPUT`：缺少音频/格式不支持等。
- `ASR_ERROR`：阿里云 ASR 接口报错。
- `ASR_TIMEOUT`：ASR 调用超时。
- `ASR_EMPTY_RESULT`：未识别出有效文本（静音/噪声）。
- `LLM_ERROR`：百炼云调用失败。
- `LLM_PARSE_ERROR`：百炼云返回文本无法解析为合法 JSON。
- `INTERNAL_ERROR`：其他未知错误。

## 三、服务端内部处理流程（伪代码级设计）

### 3.1 流程步骤

1. **参数校验**
   - 检查是否上传了音频文件或提供了 `audioUrl`。
   - 检查音频大小/时长不超过限制（如 60 秒）。
2. **调用阿里云 ASR**
   - 选择短语音/一句话识别接口。
   - 设置合理超时时间（如 5–8 秒）。
   - 获取转写结果与置信度。
3. **文本基础清洗**
   - 去除前后空格、多余标点。
   - 若文本过短或为空，返回 `ASR_EMPTY_RESULT`。
4. **调用百炼云意图解析**
   - 构造 Prompt（见下一节），传入：文本 + mode + client/extra 等上下文。
   - 要求模型**严格返回 JSON**。
   - 解析 JSON，为防止异常，应有兜底（如癞痢头 JSON 修复）。
5. **构造统一响应**
   - 将解析后的意图结构填充到 `intent` 字段；
   - 同时返回 `raw_text`/`normalized_text`、`asr_meta`、`llm_meta`。
6. **日志与监控**
   - 记录 ASR/LLM 请求耗时及错误率；
   - 为未来优化 ASR 热词、LLM Prompt 留数据基础。

### 3.2 伪代码示例（简要）

> 此处仅为思路示意，实际实现按项目栈（Next.js API Route 等）编写。

```ts
async function handleVoiceIntents(req: Request): Promise<Response> {
  const { audioBuffer, mode, userId, client, extra } = await parseRequest(req);

  // 1. 调阿里云 ASR
  const asrResult = await callAliyunASR(audioBuffer);
  if (!asrResult.text) {
    return error("ASR_EMPTY_RESULT", "未识别到有效语音内容");
  }

  // 2. 调百炼云意图解析
  const llmInput = {
    text: asrResult.text,
    mode,
    userId,
    client,
    extra,
  };
  const llmRaw = await callBailianIntentModel(llmInput);
  const intent = safeParseIntentJSON(llmRaw); // 做 JSON 解析 + 校验

  // 3. 返回统一结构
  return json({
    success: true,
    intent,
    raw_text: asrResult.text,
    normalized_text: intent.normalized_text ?? asrResult.text,
    asr_meta: asrResult.meta,
    llm_meta: intent.llm_meta,
  });
}
```

## 四、百炼云意图解析 Prompt 模板

### 4.1 设计原则

- **只做「文本 → 结构化意图」**，不负责执行具体业务逻辑；
- 明确限制输出为 **合法 JSON**，不允许输出自然语言；
- 通过枚举方式减少“自由发挥”，提高输出稳定性；
- 预留 `extra` 字段，用于未来平滑扩展。

### 4.2 System Prompt 示例（中文）

> 可根据百炼云实际模型特性微调。

```text
你是 AnyKeep 应用的“语音意图解析引擎”。

输入是用户刚刚说出的中文句子（已经过语音识别转成文本），
你的任务是将这句话解析成一个结构化的 JSON 指令，方便后端程序执行。

严格遵守以下规则：

1. 只输出 JSON，不能输出任何解释、自然语言或其他内容。
2. JSON 顶层必须是一个对象，包含以下字段：
   - action: string
   - action_confidence: number (0-1 之间的小数)
   - keywords: string[] （长度可以为 0）
   - platform: "wechat" | "bilibili" | "xiaohongshu" | "browser" | "any"
   - time_range: "today" | "yesterday" | "last_week" | "last_month" | "all" | "custom"
   - note: string | null
   - note_type: string | null
   - output_mode: "list" | "detail" | "summary" | "unknown"
   - extra: object
   - normalized_text: string （对原始语句的轻微规范化版本，可以与原文相同）

3. action 只能从以下枚举中选择：
   - "search"            : 用户想查找之前收藏的内容
   - "open_bookmark"     : 用户想打开某条收藏（通常结合上下文）
   - "create_voice_note" : 用户想创建一条新的语音笔记/语音收藏
   - "append_note"       : 用户想给当前收藏追加备注
   - "summarize_recent"  : 用户想总结最近一段时间的收藏
   - "unknown"           : 无法判断或不确定用户意图

4. 字段含义提示：
   - keywords: 从用户语句中抽取的主题词、人物、产品名等，用于搜索或打标签。
   - platform:
       如果语句中提到 微信/公众号 → "wechat"
       B站/b站/bilibili → "bilibili"
       小红书/红书 → "xiaohongshu"
       浏览器书签/网页 → "browser"
       没有明显平台则为 "any"
   - time_range:
       今天 → "today"
       昨天 → "yesterday"
       上周/上个星期 → "last_week"
       上个月 → "last_month"
       很久以前/所有 → "all"
       其他无法归类的时间表达 → "custom"

5. 对于 search 场景：
   - keywords 尽量包含 1-5 个高价值词。
   - output_mode 通常为 "list"。

6. 对于 summarize_recent 场景：
   - output_mode 通常为 "summary"。

7. 对于 create_voice_note / append_note 场景：
   - note 字段要填入完整的用户意图文本（可做适度润色）。
   - note_type 可以是 "todo"（待办）、"quick_thought"（随想）、"context"（上下文说明）等。

8. 如果非常不确定用户想要做什么，请将 action 设为 "unknown"，并给出较低的 action_confidence（如 0.3）。

务必返回合法 JSON，且不能包含注释。
```

### 4.3 User Prompt 模板示例

> 其中 `{speech_text}` 替换为 ASR 返回的文本，`{mode}` 等为可选上下文。

```text
用户刚刚通过语音说了一句话，已经被识别为以下文本：

"{speech_text}"

补充上下文信息（JSON 格式，可能为空对象）：
{context_json}

其中 context_json 可能包含：
- mode: "search" | "command" | "note"
- client: "web" | "pwa" | "extension" | "mobile"
- current_page: 当前页面路径，例如 "/home" | "/search" | "/bookmark/123"
- current_platform_filter: 当前筛选的平台，例如 "wechat" | "bilibili"

请根据上面的 System 指令，将这句话解析成一个 JSON 指令并返回。
```

> 服务端实际调用百炼云时，可将 `speech_text`、`mode`、`client` 等字段包装为一个 `context_json`，然后拼接 System + User Prompt。

## 五、与现有功能集成与后续扩展

### 5.1 与现有搜索/收藏流程集成

- `action = "search"`  
  → 调用现有搜索 API（全文搜索 + 未来语义搜索），前端只需按 `keywords + platform + time_range` 构造查询。

- `action = "create_voice_note"`  
  → 将 `note` 作为内容创建一条特殊类型的 bookmark（`content_type = VOICE_NOTE`），并可选调用 DeepSeek 做短摘要。

- `action = "append_note"`  
  → 在当前选中/上下文中的 bookmark 下追加备注记录（可作为 `notes` 子表）。

- `action = "summarize_recent"`  
  → 根据 `platform + time_range + keywords` 拉取一批 bookmark，拼成上下文，调用 DeepSeek 输出最终总结内容，再返回前端。

### 5.2 安全、限流与成本控制

- 限制单次语音时长（如 ≤ 60 秒）与最大文件尺寸；
- 为每个用户设置每日/每月免费语音次数，超过后可提示升级 Pro（未来可用作商业化点）；
- 对 ASR/LLM 设定合理超时与熔断策略，避免下游服务问题放大到整站。

## 六、小结

- 语音功能的核心价值在于：**降低操作门槛 + 释放碎片时间**，而不是炫技式助手。
- 技术上采用「阿里云 ASR + 百炼云意图解析 + DeepSeek 摘要」的**分层架构**，既灵活又有利于成本控制。
- `/api/voice/intents` 通过统一 JSON 协议，将语音能力**抽象成标准意图接口**，前端和其他服务只需关心 `action + 参数`，不必了解 ASR/LLM 细节。
