# DeepSeek 模型版本切换方案

## 1. 背景说明

目前 DeepSeek 官方 API 并没有发布名为 `v3.2` 的特定版本号。DeepSeek 采取的是 **"Always Green" (常青)** 策略，即 `deepseek-chat` 这个模型 ID 始终指向最新稳定版（当前就是 V3）。

但是，为了应对未来可能出现的特定版本（例如 `deepseek-chat-v3.2` 或测试版），以及方便你在不同模型间（如 `deepseek-coder` vs `deepseek-chat`）快速切换，我建议采用 **"环境变量配置化"** 的方案。

这样，一旦官方发布了新版本号，你只需要在后台改一个环境变量，无需修改代码并重新部署。

## 2. 核心目标

将硬编码的 `model: "deepseek-chat"` 解耦，改为从环境变量读取，实现"配置即生效"的无缝切换。

## 3. 方案详情

### A. 环境变量变更 (.env.local / 生产环境配置)

新增一个环境变量来控制模型版本。

```bash
# 默认使用 deepseek-chat (指向最新 V3)
# 未来如果发布了 v3.2，只需改为: deepseek-chat-v3.2 (假设名称)
DEEPSEEK_MODEL=deepseek-chat
```

### B. 代码重构建议

修改 `src/lib/utils/ai-generator.ts`，引入默认值逻辑。

```typescript
// src/lib/utils/ai-generator.ts

// ...

// 定义默认模型，防止环境变量缺失导致崩溃
const DEFAULT_DEEPSEEK_MODEL = "deepseek-chat";

// ...

async function callDeepSeekAPI(...) {
  const apiKey = process.env.DEEPSEEK_API_KEY;
  // 获取模型版本，优先使用环境变量
  const modelVersion = process.env.DEEPSEEK_MODEL || DEFAULT_DEEPSEEK_MODEL;

  // ...

  const response = await fetch("https://api.deepseek.com/v1/chat/completions", {
    // ...
    body: JSON.stringify({
      model: modelVersion, // 使用动态配置的模型
      messages: [ ... ],
      // ...
    }),
  });

  // 添加日志，方便调试当前实际使用的模型
  logger.info({ model: modelVersion }, "Calling DeepSeek API");

  // ...
}

// 同样的逻辑也应用在 recommendFolder 函数中
```

## 4. 方案优势

1. **零代码变更升级**：未来出 `deepseek-chat-v4` 或 `v3.5-turbo` 时，直接在 Vercel/Supabase 后台改变量即可。
2. **A/B 测试能力**：你可以在测试环境设置 `DEEPSEEK_MODEL=deepseek-coder` 来对比摘要效果，而不影响生产环境。
3. **安全性**：即使环境变量被误删，代码也有 `deepseek-chat` 作为兜底，保证服务不挂。

## 5. 实施步骤（待审核通过后执行）

1. 在 `.env.local` 中添加 `DEEPSEEK_MODEL=deepseek-chat`
2. 修改 `src/lib/utils/ai-generator.ts` 中的两处 API 调用：
   - `callDeepSeekAPI` 函数
   - `recommendFolder` 函数
3. 添加日志记录，方便追踪实际使用的模型版本
4. 更新生产环境（Vercel/Supabase）的环境变量配置

## 6. 注意事项

- 如果 DeepSeek 官方未来发布了明确的版本号（如 `deepseek-chat-v3.2`），只需更新环境变量即可
- 建议在测试环境先验证新模型的效果，再切换到生产环境
- 保留默认值 `deepseek-chat` 作为兜底方案，确保服务稳定性
