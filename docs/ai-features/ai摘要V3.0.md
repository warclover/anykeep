## 一、 核心愿景

如果说 V2.1 是解决了"从无到有"和"结构化输出"的问题，那么 V3.0 的核心目标是 **"深度阅读与精准理解"**。

我们致力于打造一个 **"智能阅读替身"**，它不仅能概括内容，还能：

1.  **清洗噪音**：通过 Jina Reader 精准提取正文，去除广告和干扰。
2.  **深度阅读**：对于长文自动使用长上下文模型，不再简单截断，确保"读完"再"总结"。
3.  **自我修正**：根据用户反馈和质量评估指标，自动优化 Prompt，拒绝"废话摘要"。
4.  **极速响应**：通过模型路由与流式处理，让用户更快看到核心信息。

## 三、 技术架构演进 (Layer 0 - Layer 3)

V3.0 将引入分层架构，解耦提取、生成和评估逻辑。

```mermaid
graph TD
    Input[URL/Content] --> Layer0[Layer 0: 智能提取层]
    Layer0 --> |Jina/Puppeteer| CleanContent[纯净 Markdown]

    CleanContent --> Layer1[Layer 1: 策略路由层]
    Layer1 --> |Short (<10k)| ModelA[DeepSeek-V3]
    Layer1 --> |Long (>10k)| ModelB[Qwen-Long]
    Layer1 --> |Complex| ModelC[DeepSeek-R1]

    ModelA & ModelB & ModelC --> Layer2[Layer 2: 生成与结构化层]
    Layer2 --> JSON[结构化摘要 JSON]

    JSON --> Layer3[Layer 3: 质量评估层 (Guardrails)]
    Layer3 --> |Pass| DB[存储数据库]
    Layer3 --> |Fail| Retry[触发重试/降级]
```

### 3.1 Layer 0: 智能提取层 (Jina Integration)

- **痛点**：当前 regex/cheerio 提取经常包含导航栏、广告，导致 Token 浪费且干扰 AI。
- **方案**：全面集成 **Jina Reader API**。
  - **策略**：`Jina First` 策略。优先尝试 Jina 提取 Markdown。
  - **降级**：Jina 超时或失败时，回退到 `Mozilla Readability` (本地库) + `Turndown` (HTML转Markdown)。

### 3.2 Layer 1: 策略路由层 (Model Router)

- **痛点**：用同一个模型处理 500 字新闻和 5 万字论文，要么浪费 Token，要么能力不足。
- **方案**：
  - **Tokenizer 预检**：计算内容 Token 数。
  - **路由规则**：
    - `< 10k tokens` & `普通难度`: **DeepSeek-V3** (性价比之王，主力模型)
    - `> 10k tokens`: **Qwen-Long** (阿里百炼，支持超长上下文，确保不截断)
    - `复杂逻辑/学术论文`: **DeepSeek-R1** (深度推理，提取深层洞察)

### 3.3 Layer 3: 质量评估层 (Quality Guard)

- **痛点**：AI 有时会"偷懒"，输出"本文介绍了..."这种废话，或者 JSON 格式错误。
- **方案**：引入轻量级评估器（基于规则）。
  - **规则检查**：
    - `tldr` 长度 < 10 字？ -> 判定为"敷衍"
    - `key_points` 包含 "如上所述" 等无意义词？ -> 判定为"复读"
  - **动作**：评分低于 60 分 -> 自动重试（温度降低 0.1，切换到更强模型）。

## 四、 实施路线图 (Roadmap)

我们将 V3.0 的研发分为三个阶段，每阶段 2 周。

### Phase 1: 基础设施与提取升级 (Infrastructure & Extraction)

**目标**：解决"输入质量"问题，确保 AI 读到干净的内容。

1.  **[Backend]** 集成 Jina Reader API，实现 `SmartContentFetcher` 服务。
2.  **[Backend]** 完善 JSON 输出的灰度发布，全量推行结构化摘要 V2.1。
3.  **[Infra]** 建立 Token 消耗与 Jina 成功率监控面板。

### Phase 2: 智能路由与长文突破 (Routing & Long Context)

**目标**：解决"长文截断"痛点，实现成本最优。

1.  **[AI]** 实现 `ModelRouter` 类，接入 Qwen-Long 和 DeepSeek-R1 API。
2.  **[Backend]** 开发"长文模式"逻辑：检测到 Token 超限自动切换模型，不再截断。
3.  **[Frontend]** 优化长文摘要的加载状态提示（"正在深度阅读 5万字长文..."）。

### Phase 3: 质量闭环与性能优化 (Quality & Performance)

**目标**：建立"自我进化"能力，提升响应速度。

1.  **[AI]** 开发 `SummaryEvaluator`，实现规则级评分与自动重试。
2.  **[Perf]** 探索后端流式输出 (Streaming Response) 到前端，降低首字延迟。
3.  **[Data]** 收集用户对摘要的反馈数据，为 V3.5 的个性化做准备。

## 六、 风险评估

1.  **Jina API 稳定性**：第三方服务可能宕机或限流。
    - _对策_：保留现有的 `Mozilla Readability` 本地提取作为**高可用热备**。实现自动熔断切换。
2.  **Qwen-Long 延迟**：处理超长文本可能需要 10s+。
    - _对策_：前端 UI 需提供明确的进度反馈（如"正在阅读第 50 页..."），避免用户以为卡死。
3.  **JSON 格式不稳定**：DeepSeek-R1 等新模型可能偶尔不遵循 JSON 约束。
    - _对策_：强化 `OutputParser` 的容错修补能力（已在 V2.1 部分实现，需增强）。
