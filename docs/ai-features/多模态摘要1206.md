# 多模态摘要（图片内容提取）功能设计与实现方案

**文档版本**：v1.0
**日期**：2025-12-06
**目标**：引入视觉大模型（Qwen-VL），实现对收藏内容的深度视觉理解（Image Captioning, OCR, Visual Reasoning），并作为独立的可选增强功能模块。

---

## 1. 核心设计理念

### 1.1 独立与解耦 (Decoupled)

本功能不替代现有的文本摘要（DeepSeek），而是作为**"增强包" (Add-on)**。

- **独立服务**：新建 `ImageAnalysisService`，与 `AIGenerator` 并行工作。
- **独立存储**：分析结果存入独立的 `ai_vision_data` 字段（JSONB），不污染基础书签数据。
- **独立触发**：仅在用户明确勾选或特定策略下触发。

### 1.2 用户主权 (User Control)

由于视觉模型成本较高（Qwen-VL-Max 约文本模型的 3-5 倍）且耗时较长，必须将选择权交给用户。

- **UI 入口**：在“添加收藏”对话框中增加【🔍 深度视觉分析】开关。
- **默认策略**：默认关闭，或仅对“图片/设计”类目默认开启。

### 1.3 商业化预留 (Monetization Ready)

本功能天然适合作为 **Pro 会员** 的权益点。

- **架构预留**：设计配额检查 (Quota Check) 接口。
- **用量统计**：记录每次调用的 Token 消耗，便于未来计费。

---

## 2. 业务流程设计

### 2.1 用户侧流程

1.  **添加收藏**：用户输入 URL 或上传图片。
2.  **选择增强**：在对话框底部，用户看到【🔍 深度视觉分析】开关（提示：提取图片文字、分析图表逻辑、生成视觉标签）。
3.  **触发分析**：
    - 如果开关**关闭**：仅执行常规文本摘要（DeepSeek）。
    - 如果开关**开启**：后台异步触发 Qwen-VL 任务。
4.  **结果展示**：
    - 分析完成后，详情页会出现【视觉洞察】板块。
    - AI 摘要中会引用图片内容（例如："📊 架构图显示..."）。

### 2.2 系统侧流程

```mermaid
graph TD
    A[用户开启开关] --> B{配额检查}
    B -- 通过 --> C[ImageAnalysisService]
    B -- 拒绝 --> D[提示升级 Pro]
    C --> E[提取关键图片]
    E --> F[调用 Qwen-VL-Max]
    F --> G[生成结构化视觉数据]
    G --> H[存入 DB (ai_vision_data)]
    G --> I[触发文本摘要更新 (可选)]
```

## 3. 技术架构方案

### 3.1 服务层：`src/lib/utils/image-analyzer.ts`

**接口定义**：

```typescript

  // 整体描述 (Caption)

  // 提取的文字 (OCR)

  visualTags: string[]; // e.g. ["极简风格", "数据架构图", "红色调"]
  // 内容类型判断
  imageType: "chart" | "screenshot" | "photo" | "design";
  // 消耗 Token (用于计费)
  usage: { total_tokens: number };
}

export async function analyzeImage(
  imageUrl: string,
  prompt?: string,

  // ... 调用 Qwen-VL
}
```

在 `bookmarks` 表中新增 `ai_vision_data` 字段，使用 JSONB 格式，保持灵活。

## 4. Prompt 工程 (Qwen-VL 专用)

为了获得结构化输出，我们需要设计精准的 System Prompt：

```markdown
你是一个视觉内容分析专家。请分析这张图片，并输出 JSON 格式结果。

任务要求：

1. **判断类型**：是图表(chart)、截图(screenshot)、设计图(design)还是普通照片(photo)？
2. **深度描述**：
   - 如果是图表，解释其核心逻辑和结论。
   - 如果是截图，提取关键文字信息。
   - 如果是设计图，描述风格、配色和布局。
3. **视觉标签**：生成 3-5 个描述视觉特征的标签。

输出格式：
{
"imageType": "...",
"description": "...",
"ocrText": "...",
"visualTags": [...]
}
```

## 6. 成本与性能考量

- **成本**：Qwen-VL-Max 单次调用约 0.05 - 0.1 元。建议初期对所有用户免费开放少量额度（如每天 5 张），超出提示升级。
- **性能**：视觉模型响应较慢（5-10秒）。必须**异步处理**，不能阻塞用户保存收藏的操作。前端 UI 应显示“视觉分析中...”的状态。

---

## 7. 结论

本方案通过**独立服务 + 异步处理 + 用户授权**的方式，成功将重型 AI 功能引入项目，既保证了核心体验的轻快，又为未来留出了巨大的商业化想象空间。建议优先实施 Phase 1 和 Phase 2。
