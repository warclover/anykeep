## 核心问题

### 问题 1: 搜索结果不精准

**现象**: 搜索"上周的AI文章"返回无关结果

**根因分析**:

- 缺少时间范围解析
- 关键词提取不够智能
- 结果排序算法简单

### 问题 2: 整理操作无闭环

**现象**: 整理操作后用户不知道发生了什么，无法撤销

**根因分析**:

- 缺少方案预览和确认
- 无执行进度反馈
- 无撤销机制

## Batch 3: 搜索体验 (28h)

### 3.1 查询理解增强 (10h)

**目标**: 从自然语言中提取搜索意图

| 子任务         | 工时 | 关键点                     |
| -------------- | ---- | -------------------------- |
| QueryParser 类 | 2h   | 时间范围、平台、关键词提取 |
| 时间解析器     | 2h   | "上周"/"最近3天" 解析      |
| 模糊匹配       | 2h   | "那篇讲AI的" 模糊搜索      |
| 测试用例       | 4h   | 覆盖各种查询表达           |

**最佳实践方向**:

- Elasticsearch Query DSL 的查询解析
- 日期表达式解析库 (chrono-node)

### 3.2 结果相关度排序 (6h)

**目标**: 多维度排序算法

| 维度       | 权重 | 说明           |
| ---------- | ---- | -------------- |
| 向量相似度 | 35%  | 语义匹配       |
| 标题匹配   | 30%  | 精确/模糊/部分 |
| 时间相关   | 20%  | 越新越高       |
| 用户行为   | 15%  | 访问/收藏次数  |

**最佳实践方向**:

- BM25 + 语义混合排序
- Learning to Rank 简化版

## Batch 4: 整理体验 (34h)

### 4.1 整理工作流设计 (10h)

**目标**: 分析 → 方案 → 确认 → 执行 闭环

```
┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐
│ 分析    │ → │ 方案    │ → │ 确认    │ → │ 执行    │ → │ 报告    │
│ analyze │    │ plan    │    │ confirm │    │ execute │    │ report  │
└─────────┘    └─────────┘    └─────────┘    └─────────┘    └─────────┘
```

**最佳实践方向**:

- Saga Pattern（事务补偿）
- 操作快照用于撤销

### 4.2 方案执行引擎 (8h)

**目标**: 安全执行整理操作

| 操作类型   | 实现要点           |
| ---------- | ------------------ |
| 文件夹创建 | 检查重复、命名冲突 |
| 书签移动   | 批量移动、回滚支持 |
| 去重       | 保留最新/最完整    |
