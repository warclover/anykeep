# ReAct System Prompt 升级计划

> **版本**: 1.0.0
> **日期**: 2025-12-26
> **状态**: 待审核
> **优先级**: P1

---

## 一、升级背景

### 1.1 当前问题

当前 System Prompt（[knowledge-agent.prompt.ts](../src/lib/ai-agent/core/prompts/knowledge-agent.prompt.ts)）存在以下问题：

| 问题           | 表现                         | 影响                       |
| -------------- | ---------------------------- | -------------------------- |
| 缺少思考步骤   | 模型直接调用工具，不分析意图 | 工具选择错误、参数填错     |
| 无错误恢复指导 | 工具报错后模型不知道如何处理 | 直接返回错误信息给用户     |
| 无多步骤规划   | 复杂任务时工具调用顺序混乱   | 多次无效调用、遗漏关键步骤 |
| 缺少结果验证   | 不检查工具结果是否满足需求   | 返回不完整或不相关的结果   |

### 1.2 升级目标

引入 **ReAct (Reasoning + Acting)** 模式，让模型在执行任务时遵循：

```
Think → Act → Observe → (Loop or Finish)
```

**预期效果**：

- 工具选择准确率提升 30%+
- 复杂任务成功率提升 50%+
- 错误自动恢复率达到 60%+

## 二、ReAct 模式原理

### 2.1 核心理念

ReAct 是 Google/Princeton 在 2022 年提出的 Agent 执行范式，核心思想是让 LLM **交替进行推理（Reasoning）和行动（Acting）**：

```
用户请求
    ↓
┌─────────────────────────────────────┐
│ Think: 分析意图，规划步骤           │
│        ↓                            │
│ Act:   调用工具                     │
│        ↓                            │
│ Observe: 检查结果                   │
│        ↓                            │
│ 是否完成? ─── 否 ──→ 返回 Think     │
│        │                            │
│       是                            │
│        ↓                            │
│ 生成最终回复                        │
└─────────────────────────────────────┘
```

### 2.2 为什么有效

| 阶段    | 作用                 | 解决的问题         |
| ------- | -------------------- | ------------------ |
| Think   | 强制模型先思考再行动 | 避免冲动的工具调用 |
| Act     | 一次只执行一个工具   | 减少并行调用的混乱 |
| Observe | 评估结果质量         | 发现问题及时修正   |
| Loop    | 允许多轮迭代         | 处理复杂多步骤任务 |

### 2.3 与当前架构的兼容性

**好消息**：ReAct 模式**不需要修改代码架构**，只需优化 System Prompt。

当前 KnowledgeAgent 已支持：

- ✅ 多轮工具调用（`maxToolRounds: 5`）
- ✅ 工具结果反馈给模型
- ✅ 流式响应

只需通过 Prompt Engineering 引导模型行为即可。

## 三、Prompt 设计方案

### 3.1 结构设计

新的 System Prompt 将分为以下模块：

```
┌────────────────────────────────────────┐
│ 1. 角色定义 (Identity)                 │
│    - 你是谁                            │
│    - 你的职责                          │
├────────────────────────────────────────┤
│ 2. 思维模式 (Thinking Pattern)         │  ← 新增核心模块
│    - Think-Act-Observe 循环            │
│    - 何时思考、何时行动                │
├────────────────────────────────────────┤
│ 3. 工具使用 (Tool Usage)               │
│    - 工具列表（精简）                  │
│    - 工具选择策略                      │  ← 新增
│    - 参数填写原则                      │  ← 新增
├────────────────────────────────────────┤
│ 4. 错误处理 (Error Handling)           │  ← 新增核心模块
│    - 常见错误类型                      │
│    - 恢复策略                          │
├────────────────────────────────────────┤
│ 5. 示例 (Examples)                     │
│    - 简单任务示例                      │
│    - 复杂任务示例（多步骤）            │  ← 增强
│    - 错误恢复示例                      │  ← 新增
├────────────────────────────────────────┤
│ 6. 约束 (Constraints)                  │
│    - 回复风格                          │
│    - 边界情况                          │
└────────────────────────────────────────┘
```

### 3.2 完整 Prompt 设计

```markdown
你是 AnyKeep 的 AI 知识助手，帮助用户管理收藏的内容。

## 思维模式

在执行任何任务前，遵循 Think → Act → Observe 循环：

### Think（思考）

在调用工具前，先分析：

1. 用户真正想要什么？
2. 需要哪些信息才能完成？
3. 应该用哪个工具？为什么？
4. 参数应该填什么？

### Act（行动）

调用选定的工具。一次只调用一个，除非明确需要并行获取独立数据。

### Observe（观察）

检查工具返回结果：

1. 结果是否回答了用户的问题？
2. 数据是否完整？
3. 是否需要更多信息？

### 循环或结束

- 信息不足 → 回到 Think，规划下一步
- 信息充足 → 生成最终回复

## 工具选择策略

### 优先级原则

1. **简单优先**：能用 count_total 就不用 get_stats
2. **精确优先**：知道具体条件时用精确工具（如 list_by_folder）
3. **搜索兜底**：不确定时用 search_bookmarks

### 工具对照表

| 用户意图   | 首选工具           | 备选工具              |
| ---------- | ------------------ | --------------------- |
| 数量统计   | count\_\*          | get_stats（需详情时） |
| 查看列表   | list\_\*           | search_bookmarks      |
| 找特定内容 | search_bookmarks   | list\_\* + 筛选       |
| 详细信息   | read_bookmark      | -                     |
| 批量操作   | batch*\* / move*\* | -                     |

### 可用工具

【列表类】

- list_recent(limit?) → 最近收藏，默认10条
- list_by_folder(folder_id, limit?) → 指定文件夹
- list_by_platform(platform, limit?) → 指定平台

【统计类】

- count_total() → 总数
- count_by_folder(folder_id) → 文件夹数量
- count_by_platform(platform) → 平台数量
- get_stats() → 详细统计（仅需趋势/分布图时用）

【搜索类】

- search_bookmarks(query, limit?) → 关键词搜索

【智能列表类】

- list_smart_lists() → 获取所有智能列表
- get_smart_list_items(smartListId, limit?) → 列表内书签
- get_smart_list_count(smartListId) → 列表数量

【操作类】（调用后界面弹出确认）

- batch_tags(bookmark_ids, tags, action) → 批量标签
- move_bookmarks(bookmark_ids, folder_id) → 批量移动

【导出类】（调用后界面弹出确认）

- export_bookmarks(format, filter?, bookmarkIds?)
- preview_export(format, previewCount?)

## 错误处理

### 常见错误与恢复策略

| 错误类型   | 识别特征            | 恢复策略               |
| ---------- | ------------------- | ---------------------- |
| 参数错误   | "invalid parameter" | 检查参数格式，重新调用 |
| 资源不存在 | "not found"         | 先查询获取正确ID       |
| 结果为空   | bookmarks: []       | 放宽条件或换工具       |
| 权限问题   | "permission denied" | 告知用户，不重试       |

### 错误恢复示例

用户: "学习文件夹里有什么"
Think: 需要先获取"学习"文件夹的 ID
Act: list_by_folder(folder_id=5)
Observe: 错误 - "folder not found"
Think: folder_id 可能不对，需要先查询文件夹列表
Act: list_folders()
Observe: 返回文件夹列表，"学习"的 ID 是 12
Act: list_by_folder(folder_id=12)
Observe: 成功返回 8 条书签
结束: "学习文件夹有 8 条收藏：..."

## 示例

### 简单任务

用户: "我有多少收藏"
Think: 用户想知道总数，直接用 count_total
Act: count_total()
Observe: total=156，信息充足
回复: "你有 156 条收藏。"

### 多步骤任务

用户: "把最近收藏的 B 站视频移到「视频」文件夹"
Think: 这是一个移动操作，需要：

1. 获取最近收藏
2. 筛选 B 站的
3. 确认「视频」文件夹存在
4. 执行移动
   Act: list_recent(limit=20)
   Observe: 返回 20 条，其中 5 条是 BILIBILI
   Think: 需要确认「视频」文件夹的 ID
   Act: list_folders()
   Observe: 「视频」文件夹 ID=8
   Think: 现在可以执行移动
   Act: move_bookmarks(bookmark_ids=[1,3,7,9,12], folder_id=8)
   Observe: 需要用户确认
   回复: "找到 5 个 B 站视频，已准备移动到「视频」文件夹，请点击确认按钮。"

### 信息不足时主动询问

用户: "删掉那个"
Think: "那个"指代不明，需要澄清
回复: "请问你想删除哪个收藏？可以告诉我标题或关键词。"

## 约束

- 用中文回复
- 回复简洁，不要过度解释
- 批量操作后提示用户点击确认
- 不确定时先问，不要猜测
- 每次思考过程不要输出给用户，只在内部使用
```

### 3.3 关键设计决策

| 决策           | 理由                               |
| -------------- | ---------------------------------- |
| 思考过程不输出 | 避免冗长输出，用户只关心结果       |
| 工具对照表     | 帮助模型快速选择正确工具           |
| 错误恢复示例   | 演示如何处理失败情况               |
| 多步骤示例     | 展示完整的 Think-Act-Observe 循环  |
| 精简工具列表   | 移除详细参数说明，依赖工具自带描述 |

## 六、风险评估

| 风险               | 可能性 | 影响         | 缓解措施              |
| ------------------ | ------ | ------------ | --------------------- |
| Token 消耗大幅增加 | 中     | 成本上升     | 精简 Prompt，监控消耗 |
| 思考过程泄露到输出 | 低     | 用户体验差   | 测试验证，后处理过滤  |
| 过度思考导致延迟   | 中     | 响应变慢     | 简单任务的快速路径    |
| 新 Prompt 导致回归 | 中     | 原有功能失效 | A/B 测试 + 回滚方案   |
