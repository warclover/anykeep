# 主页顶部「三点」下拉菜单 → 一行工具栏 可行性分析

## 一、现状

- **位置**：`app-header.tsx` 第一行右侧，在「通知」与「用户头像」之间，通过 `HeaderMenu` 渲染。
- **触发**：`MoreHorizontal` 图标按钮，点击后展开下拉（`DropdownMenu`）。
- **内容**（来自 `header-menu.tsx`）：

| 分组     | 项                                        | 显示条件                       |
| -------- | ----------------------------------------- | ------------------------------ |
| 视图模式 | 瀑布流 / 列表 / 紧凑                      | 首页且非浏览器书签             |
| 布局模式 | 自动 / 行优先 / 列优先                    | 首页 + 卡片视图 + 非浏览器书签 |
| 排序     | 最新收藏 / 最早收藏 / 标题 A-Z / 标题 Z-A | 首页                           |
| 操作     | 新建收藏、数据导入、导出、批量选择        | 首页                           |
| 设置     | 设置                                      | 始终                           |

当前仅在 `sm+` 显示该按钮；移动端由底部导航等承担类似能力。

---

## 二、可行性结论

**可行。** 将「三点」改为一行工具栏在技术上没有障碍，主要约束是**空间**和**响应式**，需要做取舍和分层。

- 逻辑与状态已在 `HeaderMenu` 和 `HomePageContext` 中，可复用。
- 视图/布局/排序/对话框/路由等能力都通过现有 handler 和 Context 暴露，工具栏只需改为「图标/按钮 + 同一套回调」。
- 条件显示（首页/平台/视图模式）已存在，工具栏按相同条件显示/隐藏即可。

---

## 三、方案对比

### 方案 A：完全用一行图标替代三点

- **做法**：第一行右侧用图标按钮替代「三点」：视图切换（3）、布局（3 或 1+下拉）、排序（1+下拉）、新建、导入、导出、批量、设置。
- **优点**：所有操作一步到位，无需点开菜单。
- **缺点**：约 8+ 个入口，第一行在中小屏会非常挤，与 Logo、平台筛选、主题/搜索/通知/用户争空间。
- **适用**：仅建议在**大屏（如 lg+）**且**仅首页**时考虑，或只放 3–4 个最高频项。

### 方案 B：混合——高频入口工具栏 + 三点收尾（推荐）

- **做法**：
  - **首页**：在「通知」和「用户」之间增加一行小工具栏，只放**最高频**项，例如：
    - **视图**：瀑布流 / 列表 / 紧凑 三选一（Segmented 或 ToggleGroup，当前已有 3 个选项）。
    - **排序**：一个「排序」图标，点击为 Popover/Dropdown（4 个选项），避免 4 个按钮占位。
    - **主操作**：「新建收藏」用突出按钮或图标（与第二行「手动创建」二选一或统一为一个入口）。
  - **三点菜单保留**，内容收缩为：布局模式、数据导入、导出、批量选择、设置（以及非首页时仅「设置」）。
- **优点**：视图和排序使用频率高，外露后减少一步点击；其余仍收在三点内，第一行不会过载。
- **缺点**：仍保留一个「更多」入口，需要约定好「工具栏 vs 三点」的职责边界。

### 方案 C：与第二行合并为「首页工具栏」

- **做法**：首页已有第二行（快速添加 + 手动创建 + 用途筛选 + AI 助理）。将「视图 / 布局 / 排序」移到第二行左侧或右侧，形成「首页专用工具栏」；第一行三点只保留：设置，以及非首页时的必要项。
- **优点**：第一行不变，不增加拥挤感；视图/布局/排序和「创建/筛选/AI」都在同一行，语义清晰。
- **缺点**：第二行内容增多，需要布局调整（如折叠、溢出收起到「更多」等）。

---

## 四、建议

- **优先推荐方案 B（混合）**
  - 在**首页**且**非移动端**时，于第一行增加「视图切换 + 排序下拉 + 新建收藏」三个（或 2 个）入口，其余仍保留在三点内。
  - 实现成本低：从 `HeaderMenu` 抽离「视图/排序/新建」为独立按钮或小组件，仍在同一行、同一 Context 上工作；三点菜单改为只渲染「布局模式、导入、导出、批量、设置」。

- **若希望第一行尽量少动**，可采用**方案 C**：把视图/布局/排序放到第二行，与快速添加区同排，第一行三点仅保留设置等少量项。

- **不推荐在首行做方案 A 的完整 8+ 图标**，除非仅针对 lg+ 且仅首页，并做好「更多」收纳与响应式折叠。

---

## 五、实现要点（若采纳方案 B）

1. **组件**
   - 新建 `HeaderToolbar`（或扩展现有 `HeaderMenu`）：在首页时渲染「视图 ToggleGroup + 排序 Dropdown + 新建按钮」。
   - `HeaderMenu` 只保留三点 + 收缩后的菜单项（布局、导入、导出、批量、设置）。

2. **显示条件**
   - 与 `HeaderMenu` 一致：`pathname === "/home"` 且 `sm+` 时显示工具栏；视图/布局根据 `isBrowserPlatform`、`viewMode` 决定是否展示。

3. **样式**
   - 工具栏使用 `flex items-center gap-1`，按钮与现有 header 的 `size="icon"` 或小号按钮一致，避免与两侧主题/搜索/通知/用户视觉脱节。

4. **无障碍**
   - 图标按钮保留 `aria-label`（如「视图模式」「排序」「新建收藏」），排序下拉保持键盘可聚焦。

5. **国际化**
   - 若项目已有 i18n，工具栏文案与现有 `header-menu` 的「视图模式」「排序」等共用同一 key。

---

## 六、小结

| 项目     | 结论                                                               |
| -------- | ------------------------------------------------------------------ |
| 可行性   | ✅ 可行，无技术障碍                                                |
| 推荐方向 | 方案 B：首页第一行增加「视图 + 排序 + 新建」小工具栏，三点保留收尾 |
| 风险     | 首行空间紧张，需严格控制工具栏项数量与响应式断点                   |
| 后续     | 若需再减一步点击，可考虑方案 C 将视图/布局/排序迁到第二行          |
