# 图片内容提取功能：竞品对比与 AnyKeep 落地建议

## 1. 背景与目标

在 AnyKeep 的“零整理”愿景中，图片不仅仅是装饰，更是核心信息载体。用户收藏的内容中，往往包含：

- **设计灵感**（配色、构图）
- **技术图表**（架构图、流程图）
- **电商商品**（款式、参数表）
- **社交媒体截图**（对话记录、证据）

目前 AnyKeep 的摘要仅基于文本。增加“图片内容提取”将极大提升非纯文本内容的召回率和可读性。

## 2. 同类型产品竞品分析

选取四个代表性产品进行对比：**MyMind** (视觉灵感)、**Eagle** (素材管理)、**Pinterest** (图片搜索)、**Raindrop** (传统书签)。

| 维度              | **MyMind** (标杆)              | **Eagle**                 | **Pinterest**          | **Raindrop.io** | **AnyKeep (现状)** |
| :---------------- | :----------------------------- | :------------------------ | :--------------------- | :-------------- | :----------------- |
| **图片识别能力**  | ⭐⭐⭐⭐⭐ (极强)              | ⭐⭐⭐⭐ (强)             | ⭐⭐⭐⭐⭐ (极强)      | ⭐ (弱)         | ⭐ (仅封面图)      |
| **OCR 文字提取**  | 支持，且自动索引               | 支持 (本地)               | 支持                   | 不支持          | 不支持             |
| **色彩分析**      | 自动提取色盘                   | 自动提取色盘              | 支持                   | 不支持          | 不支持             |
| **物体/场景识别** | 自动打标 (e.g. "沙发", "极简") | 需插件/手动               | 极强 (以图搜图)        | 不支持          | 不支持             |
| **技术实现猜测**  | AWS Rekognition + 自研视觉模型 | 本地库 (OpenCV/Tesseract) | 深度学习计算机视觉集群 | 仅元数据提取    | 无                 |
| **用户体验**      | **"It just knows"** (完全无感) | 筛选器强大                | 推荐流强大             | 列表展示        | 列表/卡片          |

### 核心竞品深度解析

- **MyMind**：它是 AnyKeep 最值得学习的对象。当你保存一张红色的椅子图片，哪怕标题没写“红色”和“椅子”，你搜“红色”或“家具”都能找到它。它不仅做 OCR，还做**语义理解**（"This looks like a vintage chair"）。
- **Eagle**：侧重于**素材属性**（尺寸、颜色、格式）。对于设计师很有用，但对于普通知识管理（如保存一篇带图表的技术文章），它的帮助有限。

## 3. 技术方案对比

在 2025 年，我们不需要像 Pinterest 那样自建庞大的 CV 团队，可以直接利用 **多模态大模型 (Multimodal LLM)**。

| 方案         | **方案 A: Jina Reader + 纯文本 LLM** (当前路径) | **方案 B: 专用 OCR 服务** (传统路径)             | **方案 C: 多模态大模型 (VL-LLM)** (推荐路径)       |
| :----------- | :---------------------------------------------- | :----------------------------------------------- | :------------------------------------------------- |
| **核心逻辑** | 依赖 Jina 提取 Markdown 中的 `![alt]` 属性      | 调用 AWS/Google/百度 OCR 接口提取文字            | 直接把图片"看"一遍，生成描述                       |
| **技术栈**   | Jina Reader + DeepSeek V3                       | Tesseract / Baidu OCR API                        | **Qwen-VL / GPT-4o / Gemini-Pro-Vision**           |
| **优点**     | 成本极低，速度快，无需新接入模型                | 文字提取极其精准                                 | **理解力最强**。能看懂图表逻辑、幽默梗图、设计风格 |
| **缺点**     | 依赖原网页的 `alt` 标签（通常质量很差）         | 无法理解图片含义（只认字，不懂"这是一张架构图"） | 成本相对较高，推理速度慢于纯文本                   |
| **适用场景** | 新闻、博客（有良好 alt 规范）                   | 票据、文档截图、长图文                           | **复杂图表、设计灵感、社交媒体截图**               |

## 4. AnyKeep 落地建议

结合 AnyKeep "低成本、高效率" 的特点，建议采用 **"混合策略"**：

### 4.1 策略核心：分级处理

不要对所有图片都上昂贵的多模态模型。

1.  **L1 级（基础）：Jina Reader 增强**
    - 继续使用 Jina Reader，但要求其返回更详细的图片上下文。
    - 如果原网页有 `alt` 或 `caption`，直接使用。这是零成本的。

2.  **L2 级（进阶）：关键图片筛选 (Smart Selection)**
    - 一篇文章可能有 20 张图（包含广告、头像）。
    - 设计算法筛选出 **"高价值图片"**：
      - 尺寸 > 300x300
      - 宽高比正常（非长条广告）
      - 出现在正文核心区域
    - 每篇文章只对 Top 3 图片进行深度分析。

3.  **L3 级（智能）：多模态理解 (The "Magic")**
    - 接入 **阿里云 Qwen-VL-Max** (通义千问视觉版) 或 **DeepSeek-VL** (如果发布)。
    - **Prompt 示例**：
      > "请分析这张图片。如果是图表，请总结其核心逻辑；如果是设计图，请提取风格和配色关键词；如果是截图，请提取关键文字信息。输出不超过 100 字。"

### 4.2 功能设计建议

#### A. "图表透视" (Chart Insight)

- **场景**：用户收藏了一篇通过复杂架构图讲解系统的技术文章。
- **功能**：AI 识别出这是“架构图”，自动生成一段解释：“这张图展示了系统分为接入层、服务层和存储层，使用了 Redis 做缓存。”
- **UI 表现**：在 AI 摘要的 `key_points` 中，增加一条带图片的引用：
  > 📊 架构图显示系统采用了三层设计... [查看原图]

#### B. "视觉标签" (Visual Tags)

- **场景**：用户收藏了 Dribbble 上的设计图。
- **功能**：自动打上视觉标签：`#极简主义` `#赛博朋克` `#紫色调` `#3D渲染`。
- **UI 表现**：这些标签自动加入搜索索引。用户搜“紫色 界面”，能召回这张图。

#### C. "截图搜文字" (OCR Search)

- **场景**：用户在小红书/推特看到一段话，截图保存。
- **功能**：OCR 提取文字，存入 `content` 字段。
- **UI 表现**：用户搜截图里的文字，能直接搜到。

### 4.3 技术实施路线图

1.  **阶段一：基础元数据提取 (Now)**
    - 优化 Jina Reader 调用参数，确保 Markdown 中保留图片链接和 `alt` 文本。
    - 在生成 Text Summary 时，把 `alt` 文本喂给 DeepSeek。

2.  **阶段二：引入 Qwen-VL (Next Month)**
    - 针对 **"图片"类型**（如 Pinterest/Dribbble 来源）或 **"小红书"类型**（重图文），自动触发 VL 模型。
    - 将生成的 Image Caption 存入 `ai_summary` 结构中。

3.  **阶段三：视觉搜索 (Future)**
    - 计算图片的 Embedding (CLIP 模型)，存入 `pgvector`。
    - 实现“以图搜图”或“文字搜图”。

## 5. 总结

AnyKeep 不需要做一个全功能的 OCR 工具，也不需要做一个专业的素材管理器。

**AnyKeep 的图片提取应该服务于“理解”。**

建议优先做 **"关键图片的内容解释"**（辅助阅读）和 **"视觉标签自动补全"**（辅助搜索）。这能以最低的成本，显著提升用户“找回内容”的成功率，对标 MyMind 的核心体验。
