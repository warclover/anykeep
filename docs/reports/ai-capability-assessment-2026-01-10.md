# AnyKeep AI 能力综合评估报告

> **评估日期**: 2026-01-10
> **评估版本**: v2.8.2
> **评估范围**: AI Skills 系统、意图分类、工作流集成、用户体验
> **评估方法**: 代码探索 + 基线测试 + 架构分析

---

## 执行摘要

### 总体评分

| 维度           | 评分           | 说明                                         |
| -------------- | -------------- | -------------------------------------------- |
| **架构设计**   | ⭐⭐⭐⭐ (4/5) | 架构清晰，模块化良好，但存在耦合问题         |
| **意图分类**   | ⭐⭐⭐⭐ (4/5) | 规则覆盖全面，但口语化表达和工作流触发需加强 |
| **Skill 执行** | ⭐⭐⭐ (3/5)   | 24 个 Skill 已实现，但链路脆弱点较多         |
| **工作流集成** | ⭐⭐⭐ (3/5)   | 已集成但规则覆盖有限，边界判断待优化         |
| **用户体验**   | ⭐⭐⭐ (3/5)   | 流式输出完整，但交互流畅度和反馈质量需改进   |

### 核心发现

✅ **优势**:

- 意图分类测试通过率 100%（79/79 用例）
- 30 个 AI Skills 已实现并注册
- 流式响应协议完整（SSE + 统一块格式）
- 风险操作确认机制完善

⚠️ **关键问题**:

- **链路脆弱**: 意图→Skill→执行 的完整链路存在 7 个脆弱点
- **体验不佳**: 大交付物阻塞、进度卡顿、智能默认值无法修改
- **覆盖不足**: 工作流触发规则仅 7 条，口语化表达覆盖有限

## 一、架构评估

### 1.1 核心执行链路

```
用户输入
    ↓
┌─────────────────────────────────────────────────────────────┐
│ UnifiedEngine (统一入口)                                      │
│   ├─ InputPreprocessor (指代词解析)                           │
│   ├─ WorkflowModeExecutor (工作流检测) ← 🟡 规则覆盖有限      │
│   ├─ IntentRouter (意图路由)                                  │
│   │   ├─ IntentClassifier (规则+LLM混合) ← 🟡 权重冲突风险    │
│   │   ├─ ComplexityEvaluator (复杂度评估)                     │
│   │   └─ ModeSelector (模式选择)                              │
│   ├─ IntentDisambiguator (消歧) ← 🟡 选项过多时体验差          │
│   ├─ ExecutionCoordinator (执行协调)                          │
│   │   ├─ AtomicExecutor (KnowledgeAgent) ← 🔴 耦合度高        │
│   │   └─ OrchestrationEngine (编排引擎)                       │
│   └─ OutputEnhancer (输出增强) ← 🟡 可能阻塞流                 │
└─────────────────────────────────────────────────────────────┘
    ↓
SSE 流式响应
```

### 1.2 识别的 7 个架构脆弱点

| ID     | 问题                      | 严重度 | 位置                                  | 影响                          |
| ------ | ------------------------- | ------ | ------------------------------------- | ----------------------------- |
| **P4** | 原子执行器耦合            | 🔴 高  | `register.ts:228-229`                 | KnowledgeAgent 失败则系统瘫痪 |
| **P1** | 规则权重冲突              | 🟡 中  | `intent-classifier.ts:53-1418`        | 200+ 规则可能误匹配           |
| **P2** | Slow Track 超时回退       | 🟡 中  | `hybrid-intent-classifier.ts:300-368` | 回退时质量下降                |
| **P3** | 消歧/确认串行等待         | 🟡 中  | `unified-engine.ts:476-606`           | 用户交互流程冗长              |
| **P5** | 参数解析不统一            | 🟡 中  | `orchestration-engine.ts:177-178`     | 各 Skill 策略不一致           |
| **P6** | Feature Flag 与规则不同步 | 🟡 中  | `register.ts:233-293`                 | 禁用 Skill 仍可能触发         |
| **P7** | 输出增强阻塞流            | 🟢 低  | `unified-engine.ts:873-885`           | 网络延迟时阻塞                |

- 总规则数: 200+
- 权重范围: 60-100
- 分层设计:
  - 95-100: 精准意图（synthesis, active_recall, digest）
  - 85-94: 明确意图（organize 专项）
  - 75-84: 标准操作
  - 60-74: 通用查询

3. 工作流规则 (7条) 与标准规则 (200+条) 分离管理

## 七、优化路线图

### Phase 1: 快速修复 (1-2 周)

**目标**: 解决最影响用户体验的问题

| 任务               | 问题 ID | 工作量 | 产出                |
| ------------------ | ------- | ------ | ------------------- |
| 大交付物分块传输   | P0-1    | 3d     | 前端不再卡顿        |
| 进度心跳机制       | P1-1    | 1d     | 用户知道系统在运行  |

| 扩展工作流触发规则 | P1-2    | 2d     | +14 条规则          |

**验收标准**:

- [ ] 生成报告时无明显卡顿（<500ms 间隔）

- [ ] 删除操作显示受影响书签标题
- [ ] 工作流触发测试通过率 ≥90%

### Phase 2: 架构加固 (2-3 周)

**目标**: 解决架构脆弱点，提高系统稳定性

| 任务                  | 问题 ID | 工作量 | 产出                  |
| --------------------- | ------- | ------ | --------------------- |
| 原子执行器 fallback   | P0-2    | 2d     | 系统不再单点故障      |

| 统一槽位提取框架      | P5      | 5d     | 参数解析一致          |
| 意图→Skill 映射日志   | -       | 1d     | 便于调试              |

**验收标准**:

- [ ] KnowledgeAgent 失败时有 fallback 响应
- [ ] 禁用 Skill 后相关意图规则自动禁用
- [ ] 所有 Skill 使用统一的 SlotExtractor
- [ ] 调试日志显示完整的路由决策过程

### Phase 3: 体验优化 (3-4 周)

**目标**: 提升整体用户体验

| 任务               | 问题 ID | 工作量 | 产出               |
