# AnyKeep AI 摘要技术方案调研与落地建议

## 1. 调研背景与目标

**AnyKeep** 作为一个“零整理”书签管理工具，其核心价值在于帮助用户快速“消化”信息。AI 摘要需要解决以下核心痛点：

- **多模态输入**：包括公众号长文、小红书短图文、B站视频（字幕）、技术文档。
- **信息密度控制**：用户既需要一句话 "TL;DR"，也需要关键点列表。
- **成本敏感**：作为高频触发的功能，单次调用成本必须极低。
- **响应速度**：用户收藏后希望尽快看到摘要。

## 2. 市场主流技术方案对比

针对 AnyKeep 的中文互联网场景，我们选取了四个最具竞争力的模型进行对比：

| 维度             | **DeepSeek-V3** (推荐)         | **阿里云 Qwen-Turbo/Plus**            | **Moonshot (Kimi)**         | **OpenAI GPT-4o-mini** |
| :--------------- | :----------------------------- | :------------------------------------ | :-------------------------- | :--------------------- |
| **中文理解**     | ⭐⭐⭐⭐⭐ (极佳)              | ⭐⭐⭐⭐⭐ (极佳)                     | ⭐⭐⭐⭐⭐ (极佳)           | ⭐⭐⭐⭐ (良好)        |
| **长文本能力**   | 64K context (足够绝大多数文章) | **200K+ context** (适合超长论文/书籍) | **200K context** (长文标杆) | 128K context           |
| **成本 (API)**   | **极低** (输入1元/百万token)   | 低 (输入2元/百万token)                | 中 (输入12元/百万token)     | 低                     |
| **响应速度**     | 快 (推理速度优化极好)          | 快                                    | 中                          | 极快                   |
| **视频字幕处理** | 优秀                           | **极强** (由于长窗口优势)             | **极强**                    | 优秀                   |
| **国内接入**     | 原生支持，无网络障碍           | 原生支持 (百炼云)                     | 原生支持                    | 需代理，不稳定         |

### 详细分析

1.  **DeepSeek (当前使用)**
    - **优势**：目前的“性价比之王”。V3 版本在编码和中文逻辑上表现惊人，且价格只有 GPT-4 的几十分之一。对于 AnyKeep 这种可能面临大量用户收藏请求的应用，成本控制非常友好。
    - **劣势**：API 偶尔会有并发限制或波动（需关注官方稳定性更新）。

2.  **阿里云 Qwen (通义千问)**
    - **优势**：你已经在用百炼云，接入成本为零。Qwen-Turbo 速度快且便宜，Qwen-Long 专门针对超长文本（如 2小时以上的视频字幕）有优化。
    - **劣势**：通用逻辑能力略逊于 DeepSeek V3（但在摘要任务上差异不明显）。

3.  **Moonshot (Kimi)**
    - **优势**：长文本无损压缩能力最强，如果 AnyKeep 主打“万字长文精准分析”，Kimi 是首选。
    - **劣势**：价格相对较高，作为默认的通用摘要引擎略显昂贵。

## 3. 内容提取技术（Pre-processing）

AI 摘要的前提是“喂”给 AI 干净的文本。直接把 HTML 丢给 AI 会浪费 Token 且干扰效果。

**推荐方案：Jina Reader API / Firecrawl**

- **Jina Reader (`r.jina.ai`)**:
  - **原理**：专门为 LLM 设计的网页转 Markdown 工具。
  - **用法**：`https://r.jina.ai/https://your-url.com`
  - **优势**：免费额度大，自动去除广告、侧边栏，输出干净的 Markdown，对 AI 非常友好。
- **Firecrawl**:
  - **优势**：不仅能抓取，还能处理动态渲染的页面（SPA），适合复杂网站。

## 4. 推荐落地方案 (The "AnyKeep Strategy")

建议采用 **“分级处理 + 混合模型”** 策略：

### 4.1 架构设计

1.  **文本清洗层**：使用 `Jina Reader` 或自建 `Puppeteer + Readability.js` 服务，将 URL 转换为 Markdown 文本。
2.  **视频处理层**：针对 B站/YouTube，不下载视频，而是提取 **CC 字幕 (Subtitle)**。将字幕文本作为输入。
3.  **模型路由层 (Model Router)**：
    - **默认通道 (DeepSeek-V3)**：处理 90% 的常规文章、新闻、短视频摘要。成本最低。
    - **长文通道 (Aliyun Qwen-Long)**：当检测到文本长度超过 30k tokens (约 4-5万中文字) 时，自动切换到 Qwen 或 Kimi，避免截断。

### 4.2 提示词工程 (Prompt Engineering) 建议

不要只让 AI "总结这篇文章"。AnyKeep 应该输出结构化的摘要。

**推荐的 System Prompt 结构：**

```markdown
你是一个专业的知识管理助手。请阅读以下内容，并按 JSON 格式输出摘要信息。

输入内容类型：{{type}} (文章/视频字幕/社交媒体帖子)

请输出以下字段：

1. "summary": 一句话总结 (TL;DR)，不超过 50 字，直击痛点。
2. "key_points": 关键点列表 (Array)，3-5 个要点，每个要点包含 emoji 前缀。
3. "keywords": 5 个核心标签/关键词。
4. "sentiment": 情感倾向 (积极/中性/消极)。
5. "reading_time": 预计阅读时间。
6. "action_items": 如果文章包含教程或建议，列出可执行的行动项；否则为空。

注意：

- 忽略广告和推广信息。
- 保持客观中立。
- 如果是视频字幕，请忽略口语化的语气词。
```

### 4.3 针对“卡片翻转”特效的优化

为了配合首页的卡片翻转效果，摘要生成需要分两步或输出特定字段：

- **背面展示**：仅显示 `summary` (TL;DR) 和 `keywords`。
- **详情页展示**：显示完整的 `key_points` 和 `action_items`。

## 5. 实施路线图

1.  **第一周：清洗服务搭建**
    - 完善后端 `Crawler Service`，集成 Jina Reader 或优化现有的提取逻辑。
    - 重点攻克：微信公众号（防爬）、B站字幕提取接口。

2.  **第二周：Prompt 调优与模型接入**
    - 在后端实现 `SummarizationService`。
    - 接入 DeepSeek API。
    - 调试 Prompt，确保 JSON 输出稳定（这对前端渲染至关重要）。

3.  **第三周：Video X-Ray (视频透视)**
    - 实现字幕提取。
    - 实现“带时间戳的摘要”（例如：`02:30 - 介绍了核心算法`），这在长视频中非常有价值。

## 6. 结论

**AnyKeep 应继续深化使用 DeepSeek 作为主力摘要引擎。**

- **技术栈**：Next.js (前端展示) + Python/Node (后端清洗与调用) + DeepSeek V3 (核心大脑)。
- **差异化竞争点**：重点打磨 **"视频 X-Ray"** (视频转文字摘要) 和 **"小红书/推特 情绪提取"**，这两个场景目前竞品做得还不够好。
