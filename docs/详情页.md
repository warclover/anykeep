# 书签详情页内容分析增强方案

## Context

当前 AnyKeep 的内容分析功能（对比分析、主题综述）独立在 `/content-analysis` 页面，用户需要离开详情页去另一个页面重新选择内容才能使用。这打断了用户在详情页的阅读与分析流程。

**目标**：将内容分析核心能力以「上下文触发卡片」形式集成到书签详情页，功能在满足条件时自动出现，无需设置开关。

## 架构决策

1. **新组件目录**：`src/components/bookmark/detail-insights/`
2. **懒加载**：单个 `DetailInsightsLazy` 容器 + IntersectionObserver（复用 `related-bookmarks-lazy.tsx` 模式）
3. **Feature Flag**：在 `src/lib/feature-flags.ts` 新增 `detail_insights`，默认 `true`
4. **数据复用**：通过 TanStack Query 的 queryKey 去重机制，共享 `knowledgeLinkKeys.related` 数据
5. **文本常量**：集中在 `detail-insights/constants.ts`

### 2. 快速对比卡片 (`quick-compare-card.tsx`)

**触发条件**：RelatedBookmarks 数据中 `strength > 0.7` 的项 >= 2

**数据来源**：复用 `knowledgeLinkKeys.related(bookmarkId, { limit: 5, minStrength: 0.5 })`

- TanStack Query 自动去重，与 RelatedBookmarksV2 共享同一请求
- 从结果中筛选 `strength > 0.7` 的前 2 项

**交互流程**：

1. 默认展示两个高相似度书签卡片 + 相似度分数
2. **按需恢复**：展开卡片后请求 `GET /api/synthesis/match-selection?bookmarkIds=`（三篇 ID 排序后匹配）；若存在已完成的同组对比（`selection` + `quick` + `comparison`），直接展示 `overview` / `divergence`，标题栏显示「已保存」
3. 点击「一键对比」/「重新生成」→ `POST /api/synthesis`（同上参数）→ `useSynthesisStream` SSE；完成后 `invalidateQueries(detailInsightsKeys.quickCompareMatch)`
4. 渲染 `OverviewSection` + `DivergenceSection`（懒加载）；可链至 `/synthesis/{id}` 查看完整综述

### 3. 综述入口卡片 (`synthesis-entry-card.tsx`)

**触发条件**（满足任一）：

- 书签有 `folderId` 且该文件夹内 >= 3 篇书签
- 书签有标签且同标签内容 >= 3 篇

**数据来源**：`GET /api/synthesis/preview`（常量 `API_SYNTHESIS.preview`）

**Hook**：`use-synthesis-context.ts`

- 先查文件夹维度：`?sourceType=folder&sourceId={folderId}&pageSize=1` → 检查 `contentStats.totalCount`
- 不满足则查标签维度：`?sourceType=tag&sourceId={tag}&pageSize=1`
- `staleTime: 10min`
- `enabled: !!(folderId || userTags?.length || aiTags?.length)`

**交互**：点击按钮跳转 `/synthesis/new?sourceType=folder&sourceId={folderId}`（复用已有综述创建流程，无需在详情页内嵌完整创建界面）

**UI 设计**：

```

│ 🏷️ 标签「大模型」匹配 8 篇      [生成综合报告]   │

```

## 性能要点

1. 单个 IntersectionObserver，四个子卡片共享一个视口触发点
2. TanStack Query 去重：QuickCompareCard 与 RelatedBookmarksV2 共用 `knowledgeLinkKeys.related` queryKey
3. 所有 useQuery 的 `enabled` 严格受控，条件不满足时不发请求
4. 每个子卡片用 SilentErrorBoundary 隔离，单个失败不影响整体
5. 四个卡片全部不满足触发条件时，容器 return null，零 DOM 开销

## 验证方式

### Phase 1 验证

1. 打开一个已分类书签详情页 → 滚动到 insights 区域 → 应显示分类解释折叠行
2. 点击展开 → 应显示完整分类理由、匹配方式、候选文件夹
3. 打开一个未分类书签 → insights 区域不应出现分类解释
4. 设置 `NEXT_PUBLIC_FEATURE_DETAIL_INSIGHTS=false` → 整个区域不渲染
5. `npm run type-check` 通过
6. `npm run lint` 通过

### Phase 2 验证

1. 打开一个有 2+ 高相似度相关书签的详情页 → 应显示快速对比卡片
2. 点击「一键对比」→ 应内联展示对比结果（OverviewSection + DivergenceSection）
3. 打开一个属于 3+ 篇文件夹的书签 → 应显示综述入口
4. 点击综述入口按钮 → 应跳转到 `/synthesis/new` 并预填参数
5. 打开一个无相关书签、无文件夹的书签 → insights 区域为空（零 DOM）

### Phase 3 验证

1. 打开一个已完成主题聚类分析的书签 → 应显示知识定位卡片
2. 卡片应展示所属主题簇名称、同簇内容数量
3. 相关主题列表应正确展示邻近聚类
4. 未运行聚类分析的书签 → 知识定位卡片不渲染
5. `npm run type-check` 通过
6. `npm run lint` 通过
