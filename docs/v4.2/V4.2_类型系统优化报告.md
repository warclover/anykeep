## 推荐解决方案

### 方案 A：重新生成类型（推荐）

**前提条件**: Docker Desktop 运行中

```bash
# 1. 启动本地 Supabase
npm run supabase:start

# 2. 应用所有迁移
npm run supabase:db:push

# 3. 重新生成类型
npm run supabase:gen:types
```

**优点**:

- 类型与数据库完全同步
- 无需手动维护类型定义
- 零类型断言

**缺点**:

- 需要 Docker
- 可能需要调整现有代码以匹配新类型

### 方案 B：手动扩展 Database 类型

在 `src/types/supabase.ts` 的 `Database.public.Tables` 中添加：

- `folder_profiles`
- `job_queue`
- `operation_snapshots`
- `classification_trace`
- `classification_metrics`
- 等

**注意**: 尝试过此方案，但由于类型引用顺序问题导致了 700+ 错误。需要确保所有被引用的类型在 Database 定义之前声明。

### 方案 C：使用类型断言（快速修复）

对于 V4.2 新增的表访问，使用类型断言：

```typescript
// 示例：访问 folder_profiles 表
const { data } = await supabase
  .from("folder_profiles" as any)
  .select("*")
  .eq("user_id", userId);
```

**优点**:

- 快速修复
- 不影响现有类型定义

**缺点**:

- 失去类型安全
- 需要在多处添加断言
- 技术债务
