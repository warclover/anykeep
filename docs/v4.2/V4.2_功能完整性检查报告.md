## 三、Job Queue 机制

### 3.1 数据库表 (`job_queue`)

| 字段       | 说明                                                          |
| ---------- | ------------------------------------------------------------- |
| type       | 7 种任务类型                                                  |
| status     | 6 种状态 (pending/claimed/running/completed/failed/cancelled) |
| priority   | 优先级（越大越优先）                                          |
| lock_until | 防止重复执行的锁                                              |

### 3.2 RPC 函数

| 函数              | 功能                 | 实现                      |
| ----------------- | -------------------- | ------------------------- |
| `claim_next_job`  | 原子领取任务         | ✅ FOR UPDATE SKIP LOCKED |
| `complete_job`    | 标记完成             | ✅                        |
| `fail_job`        | 标记失败（支持重试） | ✅ 指数退避               |
| `enqueue_job`     | 便捷入队             | ✅                        |
| `has_pending_job` | 防重复检查           | ✅                        |

### 3.3 任务类型

- `process_inbox_cache` - 处理待整理缓存池
- `check_rename_candidates` - 检查重命名候选
- `check_split_candidates` - 检查分拆候选
- `check_merge_candidates` - 检查合并候选
- `generate_monthly_report` - 生成月度报告
- `update_folder_profiles` - 更新文件夹画像
- `cleanup_expired_data` - 清理过期数据

### 3.4 ⚠️ 待完善

1. **pg_cron 清理任务**：迁移文件中被注释，需要在生产环境启用

   ```sql
   -- 每天凌晨 4 点清理 7 天前的任务
   SELECT cron.schedule('cleanup-old-jobs', '0 4 * * *', ...)

   -- 每 15 分钟重置卡住的任务
   SELECT cron.schedule('reset-stuck-jobs', '*/15 * * * *', ...)
   ```

2. **Worker 进程**：Job Queue 需要 Worker 来处理任务
   - 当前依赖 Cron 端点被动触发
   - 建议：添加 `/api/cron/process-job-queue` 端点
