## 二、核心架构

### 2.1 Scorer + CascadeRanker 模型

```
classify(request)
  │
  ├─ 1. 构建上下文
  │     BookmarkContext ← 标准化输入
  │     FolderContext[] ← 用户文件夹（含画像、样本）
  │     UserContext     ← 用户权重偏好
  │
  ├─ 2. CascadeRanker 执行
  │     ┌─ Tier: instant (<10ms) ─────────────────┐
  │     │  RuleScorer     → Map<folderId, Score>   │
  │     │  AiTagScorer    → Map<folderId, Score>   │
  │     └──────────────────────────────────────────┘
  │            ↓ 加权融合 → Top1 置信度 ≥ 0.90? → 终止 ✓
  │     ┌─ Tier: fast (<200ms) ───────────────────┐
  │     │  VectorScorer   → Map<folderId, Score>   │
  │     │  HistoryScorer  → Map<folderId, Score>   │
  │     └──────────────────────────────────────────┘
  │            ↓ 加权融合 → Top1 置信度 ≥ 0.75? → 终止 ✓
  │     ┌─ Tier: slow (<3s) ──────────────────────┐
  │     │  LlmScorer      → Map<folderId, Score>   │
  │     │    （携带前序 Scorer 结果作为上下文）      │
  │     └──────────────────────────────────────────┘
  │            ↓ 最终融合
  │
  └─ 3. 输出 RankResult[]（Top-K 文件夹 + 置信度 + 理由）
```

```typescript
export interface Scorer {
  readonly name: string;
  readonly tier: "instant" | "fast" | "slow";
  readonly defaultWeight: number;

  /**
   * 为每个候选文件夹打分
   * 同 tier 内的 Scorer 并行执行
   */
  score(
    bookmark: BookmarkContext,
    candidates: FolderContext[],
    userCtx: UserContext,
    /** 前序 tier 的融合结果（供 slow tier 参考） */
    priorResults?: Map<number, MergedScore>,
  ): Promise<Map<number, Score>>;

  /** 是否应该执行（动态跳过） */
  shouldRun?(bookmark: BookmarkContext, userCtx: UserContext): boolean;
}

export interface Score {
  value: number; // 0-1 归一化
  confidence: number; // Scorer 对自身结果的置信度
  reason: string; // 可读理由
  signals: Signal[]; // 匹配信号明细
}

export interface Signal {
  type:
    | "url_pattern"
    | "keyword"
    | "tag_exact"
    | "tag_partial"
    | "vector_sim"
    | "history"
    | "llm_semantic";
  detail: string;
  strength: number; // 0-1
}
```

## 四、算法迁移要点

### 4.1 从旧系统迁移的核心算法

以下算法从旧系统提炼，在新架构中以 Scorer 形式实现：

| 旧实现                               | 新 Scorer       | 关键算法保留                                   |
| ------------------------------------ | --------------- | ---------------------------------------------- |
| L0RuleMatcher Phase 1                | `RuleScorer`    | URL 域名匹配 + 标题关键词 + 标签匹配           |
| L0RuleMatcher Phase 0 + AiTagMatcher | `AiTagScorer`   | 5 层策略（精确→别名→部分→核心→相关）           |
| HybridRetriever + VectorMatcher      | `VectorScorer`  | pgvector 搜索 + 关键词增强 + 名称护栏          |
| HistoryMatcher                       | `HistoryScorer` | 用户历史分类模式匹配                           |
| T0Generator + T1Corrector            | `LlmScorer`     | LLM 分类 + 文件夹上下文注入 + Chain-of-Thought |

### 4.3 Prompt 注入防护（完整迁移）

从旧系统 `sanitize-input.ts` 完整迁移以下防护逻辑到 `infra/llm.ts`：

- 移除模板注入模式（`{{}}`、`{%%}`、`<%=%>`）
- 移除 SQL 关键词、角色前缀
- 移除 XML/HTML 标签、Base64 数据
- 输入长度截断

### 4.4 LlmScorer 的 Chain-of-Thought 增强

旧系统 T0 和 T1 是独立 LLM 调用。新系统合并为单次调用，但注入前序 Scorer 结果：

```typescript
// llm.scorer.ts 中的 prompt 构建

const prompt = `你是智能书签分类助手。

## 待分类书签
- 标题: "${bookmark.title}"
- 摘要: "${bookmark.summary}"
- URL: "${bookmark.url}"
- 标签: ${bookmark.tags.join(", ")}

## 前序匹配结果（供参考）
${priorResults.map((r) => `- ${r.folderName}: ${r.scorer}评分 ${r.score}，理由: ${r.reason}`).join("\n")}

## 候选文件夹（含上下文）
${candidates
  .map(
    (c, i) => `${i + 1}. **${c.name}**
   已有内容: ${c.sampleTitles.map((t) => `「${t}」`).join("、")}
   关键词: ${c.keywords.join(", ")}`,
  )
  .join("\n")}

## 要求
1. 综合书签内容和前序匹配结果做判断
2. 如果前序结果一致且合理，直接确认
3. 如果前序结果矛盾或不合理，给出你的独立判断
4. 返回 JSON: { "folderId": number, "confidence": 0.0-1.0, "reasoning": "..." }
`;
```

**好处**：LLM 可以看到 VectorScorer 和 HistoryScorer 的初步结论，减少独立判断的随机性，相当于内置的 T1 纠正效果。

```typescript
// compat/facade-adapter.ts
// 适配 40+ 个 API 路由的 getClassificationFacade().classify() 调用

import { classify } from "../classify";
import type { ClassifyRequest, ClassifyResult } from "../types";
import { mapToLegacyResult } from "./type-mapping";

export class ClassificationFacade {
  async classify(
    request: LegacyClassificationRequest,
  ): Promise<LegacyClassificationResult> {
    // 1. 旧请求 → 新请求
    const newRequest = mapRequest(request);
    // 2. 调用新系统
    const result = await classify(newRequest);
    // 3. 新结果 → 旧结果格式
    return mapToLegacyResult(result);
  }

  async classifyBatch(
    requests: LegacyClassificationRequest[],
  ): Promise<LegacyClassificationResult[]> {
    const { batchClassify } = await import("../batch/batch-classify");
    return batchClassify(requests.map(mapRequest)).then((rs) =>
      rs.map(mapToLegacyResult),
    );
  }
}

let _facade: ClassificationFacade | null = null;

export function getClassificationFacade(): ClassificationFacade {
  if (!_facade) _facade = new ClassificationFacade();
  return _facade;
}

export function createClassificationFacade(): ClassificationFacade {
  return new ClassificationFacade();
}
```
