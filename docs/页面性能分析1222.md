## 二、性能问题详解

### 2.1 双重轮询系统冲突（最影响体验）

**位置**：

- `src/hooks/ui/use-processing-poller.ts:28` - 每 **3 秒**轮询
- `src/hooks/ui/use-classification-polling.ts:35` - 每 **0.5 秒**轮询

**问题**：

```
用户创建 1 个书签后：
├── useClassificationPolling: 0.5s 间隔 × 120 次 = 60 秒内 120 次查询
├── useProcessingPoller: 3s 间隔 = 60 秒内 20 次查询
└── 总计：140 次数据库查询/分钟/书签
```

**用户感知**：新建书签后页面持续闪烁、数据反复刷新

---

### 2.2 useEffect 链式触发

**位置**：`src/components/home/home-page-client.tsx` 共 **7 个 useEffect**

**依赖链**：

```
URL 变化 → Effect#1 同步 Context
        → Effect#3 响应 Context 变化
        → setBookmarks
        → Effect#4 性能追踪
        → 触发重渲染
```

**用户感知**：切换筛选条件时明显卡顿（3-4 次连锁渲染）

---

### 2.3 API 返回数据过大

**位置**：`src/app/api/bookmarks/route.ts:1041-1065`

**问题**：

- 返回 **23 个字段**（包括 `ai_summary` 大字段）
- 关系查询 `folders(name)` 每行额外 JOIN
- `count: "exact"` 全表扫描

**数据量**：50 条书签 ≈ 100-200KB 传输

---

### 2.4 OR 条件导致索引失效

**位置**：`src/app/api/bookmarks/route.ts:1100-1110`

```typescript
query.or("is_in_trash.eq.false,is_in_trash.is.null");
```

**问题**：PostgreSQL 对 OR + NULL 条件难以使用索引，可能全表扫描

---

### 2.5 虚拟滚动可能失效

**位置**：`src/components/home/home-page-client.tsx:173-177`

```typescript
useLayoutEffect(() => {
  if (scrollContainerRef.current) {
    setScrollContainer(scrollContainerRef.current);
  }
}, []); // 空依赖，ref 可能还未 attach
```

**问题**：初始化时机不对，可能退化为全量渲染 500+ 条书签

## 四、功能风险评估

### 4.1 P0-1：统一轮询机制

#### 原设计意图

| Hook                       | 职责                                      | 轮询间隔 | 触发条件                                                   |
| -------------------------- | ----------------------------------------- | -------- | ---------------------------------------------------------- |
| `useProcessingPoller`      | 更新**标题抓取**和**封面加载**进度        | 3秒      | `status === "PROCESSING"` 或 `title === "正在获取标题..."` |
| `useClassificationPolling` | 获取 **AI 分类结果**并**显示 Toast 通知** | 0.5秒    | 手动调用 `trackBookmark(id)`                               |

#### 🔴 合并风险：高

```
两个轮询系统有不同的设计目标：

1. useProcessingPoller：
   - 被动监听：自动检测 bookmarks 数组中的 PROCESSING 状态
   - 无通知：静默更新卡片数据
   - 更新方式：直接调用 onUpdate 回调

2. useClassificationPolling：
   - 主动追踪：需要显式调用 trackBookmark(id)
   - 有通知：显示 Toast（"已自动归类到..."、"AI 建议创建..."）
   - 更新方式：调用 router.refresh() 刷新整个页面数据
   - 特殊逻辑：区分 classified/suggested/inbox 三种状态
```

**合并后可能丢失的功能**：

| 功能                    | 风险  | 影响                                |
| ----------------------- | ----- | ----------------------------------- |
| **分类完成 Toast 通知** | 🔴 高 | 用户看不到"已自动归类到 XXX"提示    |
| **建议创建文件夹提示**  | 🔴 高 | 用户看不到"AI 建议创建新文件夹"提示 |
| **分类超时警告**        | 🟠 中 | 用户不知道分类是否失败              |
| **页面数据刷新**        | 🟠 中 | `router.refresh()` 不会被调用       |

#### ✅ 安全优化建议

**不合并，而是优化各自的实现**：

```typescript
// useClassificationPolling 优化
const POLLING_INTERVAL = 1500; // 0.5s → 1.5s（仍保持较快响应）

// useProcessingPoller 优化
const POLL_INTERVAL = 5000; // 3s → 5s（标题抓取不需要太快）
```

### 4.2 P0-2/3：轮询间隔和数据比较

#### 原设计意图

```typescript
// use-processing-poller.ts:98-100
// V4.2.25: 无论是否完成，都更新数据（修复中间状态卡片不更新问题）
// 这样标题抓取完成后，卡片会立即显示新标题和封面
onUpdate(updated);
```

#### 🟠 数据比较风险：中

**如果添加数据比较逻辑**：

```typescript
// 危险的优化方案
if (JSON.stringify(newData) !== JSON.stringify(prevData)) {
  onUpdate(updated);
}
```

**可能丢失的功能**：

| 场景              | 风险  | 说明                                         |
| ----------------- | ----- | -------------------------------------------- |
| **中间状态更新**  | 🔴 高 | 标题从"正在获取..."→实际标题的过渡可能被跳过 |
| **封面 URL 更新** | 🟠 中 | 封面抓取完成后卡片不显示                     |
| **AI 摘要更新**   | 🟠 中 | AI 处理完成后摘要不显示                      |

**代码注释明确说明**（V4.2.25 修复）：

> "无论是否完成，都更新数据（修复中间状态卡片不更新问题）"

#### ✅ 安全优化建议

**保持每次都更新，但优化渲染**：

```typescript
// 在 onUpdate 回调中使用浅比较
onUpdate: useCallback(
  (updatedBookmark) => {
    setBookmarks((prev) =>
      prev.map((b) => {
        if (b.id !== updatedBookmark.id) return b;
        // 浅比较关键字段，避免不必要的对象创建
        if (
          b.title === updatedBookmark.title &&
          b.status === updatedBookmark.status &&
          b.cover_url === updatedBookmark.cover_url
        ) {
          return b; // 返回原对象，不触发重渲染
        }
        return updatedBookmark;
      }),
    );
  },
  [setBookmarks],
);
```

### 4.3 P1-4：合并 useEffect

#### 原设计意图

7 个 useEffect 各司其职：

| useEffect | 行号 | 职责                       | 依赖项                                           |
| --------- | ---- | -------------------------- | ------------------------------------------------ |
| #1        | 123  | URL → Context 同步（首次） | `[]`                                             |
| #2        | 145  | 预加载自定义用途标签       | `[]`                                             |
| #3        | 182  | Context → 本地状态同步     | `[homeContext.filter.*]`                         |
| #4        | 282  | 性能追踪                   | `[bookmarks]`                                    |
| #5        | 296  | 新建收藏事件监听           | `[currentPlatform, currentFolder, setBookmarks]` |
| #6        | 374  | 对话框请求响应             | `[homeContext.dialog, ...]`                      |
| #7        | 468  | SSR 数据同步               | `[initialBookmarks]`                             |

#### 🔴 合并风险：高

**设计精髓**：使用 `ref` 控制首次 vs 后续行为

```typescript
// Effect #1：hasSyncedRef 确保只同步一次
const hasSyncedRef = useRef(false);
useEffect(() => {
  if (hasSyncedRef.current) return;
  hasSyncedRef.current = true;
  // ...
}, []);

// Effect #3：isFirstRenderRef 跳过首次渲染
const isFirstRenderRef = useRef(true);
useEffect(() => {
  if (isFirstRenderRef.current) {
    isFirstRenderRef.current = false;
    return;
  }
  // ...
}, [homeContext.filter.*]);
```

**合并后可能丢失的功能**：

| 功能                        | 风险  | 说明                                     |
| --------------------------- | ----- | ---------------------------------------- |
| **URL ↔ Context 双向同步** | 🔴 高 | 首次从 URL 初始化，后续响应 Context 变化 |
| **避免双重数据获取**        | 🔴 高 | 首次使用 SSR 数据，后续使用 SWR 刷新     |
| **新建收藏乐观更新**        | 🟠 中 | 新书签可能不会立即显示在列表头部         |
| **跨组件对话框协调**        | 🟠 中 | 侧边栏触发的对话框可能无法打开           |

#### ✅ 安全优化建议

**不合并，但可以优化 Effect #4（性能追踪）**：

```typescript
// 原代码：每次 bookmarks 变化都执行
useEffect(() => {
  if (bookmarks.length > 0 && !hasTrackedFirstRenderRef.current) {
    // ...
    setTimeout(() => {
      /* 100ms 延迟 */
    }, 100);
  }
}, [bookmarks]);

// 优化：移到 useBookmarksSWR 内部，减少主组件依赖
```
