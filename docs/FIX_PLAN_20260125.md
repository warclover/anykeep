## 根因分析

### 1. 数据库迁移未同步

本地有 150+ 个迁移文件，但远程数据库未执行。这些迁移通过 SQL Editor 手动执行，而非 `supabase db push`。

**影响**：

- 表和 RPC 函数在远程不存在
- 重新生成的类型不包含这些定义
- 代码引用不存在的数据库对象

### 2. 类型系统分裂

项目中存在多个类型定义位置：

| 位置                              | 用途     | 问题                 |
| --------------------------------- | -------- | -------------------- |
| `src/types/supabase.generated.ts` | 自动生成 | 依赖远程数据库状态   |
| `src/types/supabase.ts`           | 手动扩展 | 可能与生成类型冲突   |
| `src/types/domain/*.ts`           | 领域类型 | 可选字段 vs 可空字段 |

### 3. Feature 模块依赖

部分 AI Skills 功能依赖未创建的数据库表：

```
content-change-monitor → page_monitors, monitor_check_logs
semantic-cache → intent_cache_semantic 相关 RPC
similarity-finder → match_bookmarks RPC
```

## 修复方案

### 方案 A: 执行缺失的数据库迁移（推荐）

在 Supabase SQL Editor 中按顺序执行以下迁移：

```sql
-- 1. Monitor 相关
-- supabase/migrations/20251228000201_add_page_monitors.sql
-- supabase/migrations/20251228000003_add_monitor_check_logs.sql
-- supabase/migrations/20251228000004_add_monitor_rpc_functions.sql

-- 2. Intent Cache 相关
-- supabase/migrations/20260112000001_add_intent_cache_vector.sql

-- 3. Rate Limit 相关
-- supabase/migrations/20260110000010_add_rate_limit_function.sql

-- 执行后重新生成类型
npm run supabase:gen:types
```

### 方案 B: 禁用未完成功能

如果某些功能暂时不需要，可以通过 Feature Flags 禁用：

```bash
# .env.local
ENABLE_CONTENT_CHANGE_MONITOR=false
ENABLE_SEMANTIC_CACHE=false
```

### 方案 C: 添加手动类型声明

创建 `src/types/supabase-extensions.d.ts`：

```typescript
import { Database } from "./supabase.generated";

// 扩展数据库类型
declare module "./supabase.generated" {
  interface Database {
    public: {
      Tables: Database["public"]["Tables"] & {
        page_monitors: {
          Row: {
            /* ... */
          };
          Insert: {
            /* ... */
          };
          Update: {
            /* ... */
          };
        };
        // ...
      };
      Functions: Database["public"]["Functions"] & {
        match_intent_cache_semantic: {
          /* ... */
        };
        // ...
      };
    };
  }
}
```
