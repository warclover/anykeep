# 数据页面一致性修复方案

> 📅 创建日期：2024-12-19
> 🎯 目标：从架构层面保障数据统计的准确性和一致性

---

## 一、问题诊断

### 1.1 现状分析

通过全局代码分析，发现项目中有 **94 个文件** 查询 `bookmarks` 表，使用了以下核心过滤条件：

| 过滤条件              | 说明       | 当前使用情况        |
| --------------------- | ---------- | ------------------- |
| `deleted_at IS NULL`  | 软删除过滤 | ✅ 所有读操作都包含 |
| `is_in_trash = false` | 排除垃圾箱 | ⚠️ 部分查询缺失     |
| `is_invalid`          | 链接有效性 | ⚠️ 仅部分场景使用   |

### 1.2 根本原因

**查询条件分散定义，缺乏统一管理**：

```
┌─────────────────────────────────────────────────────────────────┐
│                    当前架构（问题）                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   首页 API          分析服务           搜索 API         ...     │
│   ┌─────────┐      ┌─────────┐       ┌─────────┐              │
│   │ WHERE   │      │ WHERE   │       │ WHERE   │              │
│   │ deleted │      │ deleted │       │ deleted │              │
│   │ trash=F │      │ (缺失!) │       │ trash=F │              │
│   └─────────┘      └─────────┘       └─────────┘              │
│        │                │                 │                    │
│        └────────────────┼─────────────────┘                    │
│                         ↓                                      │
│                   ┌──────────┐                                 │
│                   │ bookmarks│                                 │
│                   │   表     │                                 │
│                   └──────────┘                                 │
└─────────────────────────────────────────────────────────────────┘

问题：每个模块独立定义过滤条件 → 容易遗漏 → 数据不一致
```

### 1.3 影响范围

| 模块             | 问题                    | 影响               |
| ---------------- | ----------------------- | ------------------ |
| AnalyticsService | 缺少 `is_in_trash` 过滤 | 统计包含垃圾箱数据 |
| 导出功能         | 可能包含垃圾箱数据      | 导出数据偏多       |
| 未来新功能       | 没有统一标准            | 容易重复犯错       |

## 二、解决方案设计

### 2.1 架构目标

```
┌─────────────────────────────────────────────────────────────────┐
│                    目标架构（统一管理）                          │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   首页 API          分析服务           搜索 API         ...     │
│   ┌─────────┐      ┌─────────┐       ┌─────────┐              │
│   │ 调用    │      │ 调用    │       │ 调用    │              │
│   └────┬────┘      └────┬────┘       └────┬────┘              │
│        │                │                 │                    │
│        └────────────────┼─────────────────┘                    │
│                         ↓                                      │
│              ┌──────────────────────┐                          │
│              │ BookmarkQueryBuilder │  ← 单一事实来源          │
│              │ (统一查询条件)        │                          │
│              └──────────┬───────────┘                          │
│                         ↓                                      │
│              ┌──────────────────────┐                          │
│              │  v_active_bookmarks  │  ← 数据库视图保障         │
│              │  (PostgreSQL View)   │                          │
│              └──────────┬───────────┘                          │
│                         ↓                                      │
│                   ┌──────────┐                                 │
│                   │ bookmarks│                                 │
│                   │   表     │                                 │
│                   └──────────┘                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 分层防护策略

| 层级             | 措施                 | 作用                                   |
| ---------------- | -------------------- | -------------------------------------- |
| **L1: 数据库层** | PostgreSQL 视图      | 底层保障，即使代码出错也不会查到脏数据 |
| **L2: 代码层**   | BookmarkQueryBuilder | 统一封装，减少重复代码                 |
| **L3: 测试层**   | 一致性测试           | 自动检测条件遗漏                       |
| **L4: 文档层**   | 开发规范             | 预防新代码引入问题                     |

### Phase 2: 数据库视图（短期）

**目标**：在数据库层建立防护

#### 2.1 创建活跃书签视图

```sql
-- supabase/migrations/YYYYMMDD_create_active_bookmarks_view.sql

-- 创建活跃书签视图（排除软删除和垃圾箱）
CREATE OR REPLACE VIEW v_active_bookmarks AS
SELECT *
FROM bookmarks
WHERE deleted_at IS NULL
  AND is_in_trash = FALSE;

-- 添加注释
COMMENT ON VIEW v_active_bookmarks IS
  '活跃书签视图：自动排除软删除(deleted_at)和垃圾箱(is_in_trash)的书签。
   用于统计、分析、搜索等需要准确数据的场景。';

-- 创建带垃圾箱的视图（用于垃圾箱管理）
CREATE OR REPLACE VIEW v_trashed_bookmarks AS
SELECT *
FROM bookmarks
WHERE deleted_at IS NULL
  AND is_in_trash = TRUE;

COMMENT ON VIEW v_trashed_bookmarks IS
  '垃圾箱书签视图：仅包含垃圾箱中的书签（未永久删除）。';

-- 创建已失效书签视图
CREATE OR REPLACE VIEW v_invalid_bookmarks AS
SELECT *
FROM bookmarks
WHERE deleted_at IS NULL
  AND is_in_trash = FALSE
  AND is_invalid = TRUE;

COMMENT ON VIEW v_invalid_bookmarks IS
  '已失效书签视图：活跃书签中链接已失效的部分。';
```

#### 2.2 使用视图的场景

| 视图                  | 使用场景                       |
| --------------------- | ------------------------------ |
| `v_active_bookmarks`  | 统计分析、搜索、列表展示、导出 |
| `v_trashed_bookmarks` | 垃圾箱列表、恢复操作           |
| `v_invalid_bookmarks` | 失效链接管理、批量清理         |

### Phase 3: 统一查询构建器（中期）

**目标**：代码层统一管理查询条件

#### 3.1 创建 BookmarkQueryBuilder

````typescript
// src/lib/repositories/bookmark-query-builder.ts

import type { SupabaseClient } from "@supabase/supabase-js";
import type { Platform } from "@/types/supabase";
import { BROWSER_PLATFORMS } from "@/lib/analytics/types";

/**
 * 书签查询范围
 */
export type BookmarkScope =
  | "active" // 活跃书签（默认：排除垃圾箱和软删除）
  | "trashed" // 垃圾箱书签
  | "invalid" // 已失效书签
  | "all"; // 所有书签（仅排除软删除）

/**
 * 书签查询选项
 */
export interface BookmarkQueryOptions {
  /** 查询范围，默认 "active" */
  scope?: BookmarkScope;
  /** 平台筛选 */
  platform?: string;
  /** 排除浏览器书签 */
  excludeBrowser?: boolean;
  /** 文件夹 ID */
  folderId?: number;
  /** 用途标签 */
  usageTags?: string[];
  /** 排序字段 */
  sortBy?: "created_at" | "updated_at" | "title";
  /** 排序方向 */
  sortOrder?: "asc" | "desc";
  /** 限制数量 */
  limit?: number;
  /** 游标（分页） */
  cursor?: number;
}

/**
 * 统一的书签查询构建器
 *
 * 设计原则：
 * 1. 单一事实来源 - 所有过滤条件在此定义
 * 2. 类型安全 - 完整的 TypeScript 类型支持
 * 3. 可组合 - 支持链式调用
 *
 * @example
 * ```typescript
 * const builder = new BookmarkQueryBuilder(supabase, userId);
 *
 * // 获取活跃书签（默认排除垃圾箱）
 * const activeBookmarks = await builder.getAll();
 *
 * // 获取垃圾箱书签
 * const trashedBookmarks = await builder.getAll({ scope: "trashed" });
 *
 * // 带筛选条件
 * const filteredBookmarks = await builder.getAll({
 *   platform: "WECHAT",
 *   excludeBrowser: true,
 *   sortBy: "created_at",
 *   sortOrder: "desc",
 *   limit: 20,
 * });
 * ```
 */
export class BookmarkQueryBuilder {
  constructor(
    private supabase: SupabaseClient,
    private userId: string,
  ) {}

  /**
   * 获取所有书签
   */
  async getAll(options: BookmarkQueryOptions = {}): Promise<Bookmark[]> {
    const query = this.buildQuery(options);
    const { data, error } = await query;

    if (error) {
      throw new Error(`Failed to fetch bookmarks: ${error.message}`);
    }

    return data || [];
  }

  /**
   * 获取书签数量
   */
  async count(options: BookmarkQueryOptions = {}): Promise<number> {
    const { scope = "active" } = options;

    let query = this.supabase
      .from("bookmarks")
      .select("id", { count: "exact", head: true })
      .eq("user_id", this.userId)
      .is("deleted_at", null);

    // 应用范围过滤
    query = this.applyScope(query, scope);

    const { count, error } = await query;

    if (error) {
      throw new Error(`Failed to count bookmarks: ${error.message}`);
    }

    return count || 0;
  }

  /**
   * 构建查询
   */
  private buildQuery(options: BookmarkQueryOptions) {
    const {
      scope = "active",
      platform,
      excludeBrowser,
      folderId,
      usageTags,
      sortBy = "created_at",
      sortOrder = "desc",
      limit,
      cursor,
    } = options;

    let query = this.supabase
      .from("bookmarks")
      .select("*")
      .eq("user_id", this.userId)
      .is("deleted_at", null); // 始终排除软删除

    // 1. 应用范围过滤（最重要）
    query = this.applyScope(query, scope);

    // 2. 平台筛选
    if (platform === "browser") {
      query = query.in("platform", BROWSER_PLATFORMS);
    } else if (platform) {
      query = query.eq("platform", platform);
    } else if (excludeBrowser) {
      query = query.not(
        "platform",
        "in",
        `("${BROWSER_PLATFORMS.join('","')}")`,
      );
    }

    // 3. 文件夹筛选
    if (folderId !== undefined) {
      query = query.eq("folder_id", folderId);
    }

    // 4. 用途标签筛选
    if (usageTags && usageTags.length > 0) {
      query = query.overlaps("user_tags", usageTags);
    }

    // 5. 排序
    query = query.order(sortBy, { ascending: sortOrder === "asc" });

    // 6. 分页
    if (cursor) {
      query = query.lt("id", cursor);
    }
    if (limit) {
      query = query.limit(limit);
    }

    return query;
  }

  /**
   * 应用查询范围
   * 这是保证数据一致性的核心方法
   */
  private applyScope(query: any, scope: BookmarkScope) {
    switch (scope) {
      case "active":
        // 活跃书签：排除垃圾箱
        return query.eq("is_in_trash", false);

      case "trashed":
        // 垃圾箱书签
        return query.eq("is_in_trash", true);

      case "invalid":
        // 已失效书签：活跃 + 失效标记
        return query.eq("is_in_trash", false).eq("is_invalid", true);

      case "all":
        // 所有书签（仅排除软删除，已在外层处理）
        return query;

      default:
        return query.eq("is_in_trash", false);
    }
  }
}

/**
 * 工厂函数：创建书签查询构建器
 */
export function createBookmarkQuery(
  supabase: SupabaseClient,
  userId: string,
): BookmarkQueryBuilder {
  return new BookmarkQueryBuilder(supabase, userId);
}
````

#### 3.2 重构 AnalyticsService 使用 QueryBuilder

```typescript
// src/lib/analytics/analytics.service.ts

import { createBookmarkQuery } from "@/lib/repositories/bookmark-query-builder";

export class AnalyticsService {
  private queryBuilder: BookmarkQueryBuilder;

  constructor(
    supabase: SupabaseClient,
    userId: string,
    config: Partial<AnalyticsConfig> = {},
  ) {
    this.supabase = supabase;
    this.userId = userId;
    this.config = { ...DEFAULT_ANALYTICS_CONFIG, ...config };
    this.queryBuilder = createBookmarkQuery(supabase, userId);
  }

  private async fetchAllBookmarks(): Promise<Bookmark[]> {
    // 使用统一的查询构建器，自动应用正确的过滤条件
    return this.queryBuilder.getAll({
      scope: "active", // 明确指定：活跃书签（排除垃圾箱）
    });
  }

  // 如果需要统计垃圾箱数据，可以这样：
  private async fetchTrashedBookmarks(): Promise<Bookmark[]> {
    return this.queryBuilder.getAll({
      scope: "trashed",
    });
  }
}
```

// src/lib/analytics/__tests__/data-consistency.test.ts

describe("数据一致性测试", () => {
  describe("统计数据与列表数据一致性", () => {
    it("totalBookmarks 应等于首页 API 返回的 total", async () => {
      // 获取统计数据
      const analytics = await analyticsService.getFullAnalytics();

      // 获取列表 API 的 total
      const listResponse = await fetch("/api/bookmarks?limit=1");
      const listData = await listResponse.json();

      expect(analytics.stats.totalBookmarks).toBe(
        listData.data.pagination.total,
      );
    });

    it("垃圾箱书签不应计入 totalBookmarks", async () => {
      // 创建一个书签并移入垃圾箱
      const bookmark = await createBookmark();
      await moveToTrash(bookmark.id);

      const analytics = await analyticsService.getFullAnalytics();

      // 总数不应包含垃圾箱书签
      expect(analytics.stats.totalBookmarks).not.toContain(bookmark);
    });

    it("各平台数量之和应等于 totalBookmarks", async () => {
      const analytics = await analyticsService.getFullAnalytics();

      const platformSum = analytics.platformData.reduce(
        (sum, p) => sum + p.value,
        0,
      );

      expect(platformSum).toBe(analytics.stats.totalBookmarks);
    });
  });
});
```
