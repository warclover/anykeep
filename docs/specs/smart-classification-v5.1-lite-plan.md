# AnyKeep 智能分类 v5.1 轻量化升级方案

> **版本**: 5.1.0 (Lite)  
> **日期**: 2026-01-19  
> **作者**: AnyKeep 架构团队  
> **状态**: 设计阶段  
> **目标**: 解决大文件夹马太效应，轻量化实现

---

## 一、问题诊断

### 1.1 核心问题：大文件夹引力坍塌（马太效应）

**现象**：

- "PPT 教程"被错误归入"Claude 学习"（大文件夹）
- 成熟大文件夹（>100 条）错误吸收新语义内容
- 小文件夹（<10 条）分类准确率低

**根本原因**：

1. **固定权重策略**：v5.0 对成熟文件夹 α=0.2（80% 内容），大文件夹质心向量覆盖范围过广
2. **缺少名称护栏**：没有名称相似度的强制约束机制
3. **质心污染**：个别"放错位置"的书签污染整个文件夹画像
4. **规模不敏感**：相似度计算未考虑文件夹规模差异

### 2.2 设计原则

1. **"名字即正义"**：在数据不足时，无条件信任用户命名意图
2. **"规模感知"**：大文件夹需要更强的名称约束，防止边界无限扩展
3. **"轻量优先"**：优先使用数学优化，避免引入复杂 RAG/LLM 调用
4. **"向后兼容"**：不破坏 v5.0 现有架构，增量升级

## 三、核心算法升级

### 3.1 动态弹性权重（Elastic Weighting）

**目标**：根据文件夹内容量 $N$ 动态调整名称/内容权重

**公式**：

$$
\alpha(N) = \begin{cases}
0.8 & N < 10 \text{ (冷启动/小文件夹)} \\
0.8 - 0.3 \times \frac{N-10}{90} & 10 \leq N < 100 \text{ (成长期)} \\
0.5 & N \geq 100 \text{ (成熟大文件夹，保留50%名称权重)}
\end{cases}
$$

**实现位置**：

- `src/lib/classification/v5/folder-profiler/alpha-calculator.ts`
- 新增 `calculateElasticAlpha(folderStats: FolderStats): number` 方法

**关键逻辑**：

```typescript
// 小文件夹（<10）：80% 名称，20% 内容
// 中文件夹（10-100）：线性递减，从 80% → 50%
// 大文件夹（≥100）：50% 名称，50% 内容（防止质心过度主导）
```

---

### 3.2 语义护栏（Name-First Guardrail）

**目标**：在 Rerank 阶段增加名称相似度分数，强制提升匹配度

**实现位置**：

- `src/lib/classification/v5/classification-pipeline/hybrid-retriever.ts`
- 新增 `calculateNameSimilarityScore()` 方法

**算法**：

```typescript
// 名称相似度分数（0-1）
nameSimilarityScore = cosineSimilarity(embed(bookmarkTitle), embed(folderName));

// 融合分数调整
finalScore = 0.7 * vectorSimilarity + 0.3 * nameSimilarityScore;

// 如果名称相似度 > 0.85，强制提升排名（+0.15 加成）
if (nameSimilarityScore > 0.85) {
  finalScore += 0.15;
}
```

**触发条件**：

- 仅在 T0 阶段应用（快速路径）
- 如果名称匹配度极高，直接跳过 T1 纠正

---

### 3.3 文件夹画像去噪（Profile De-noising）

**目标**：剔除文件夹中 5% 偏离质心最远的书签，防止污染

**实现位置**：

- `src/lib/classification/v5/folder-profiler/dual-source-builder.ts`
- 新增 `removeOutliers(bookmarks: BookmarkData[]): BookmarkData[]` 方法

**算法**：

```typescript
// 1. 计算所有书签与质心的距离
const distances = bookmarks.map((b) => ({
  bookmark: b,
  distance: cosineDistance(b.embedding, centroid),
}));

// 2. 排序，取后 5% 作为离群值
const outlierCount = Math.max(1, Math.floor(bookmarks.length * 0.05));
const outliers = distances
  .sort((a, b) => b.distance - a.distance)
  .slice(0, outlierCount);

// 3. 从计算中排除离群值
const cleanedBookmarks = bookmarks.filter(
  (b) => !outliers.some((o) => o.bookmark.id === b.id),
);
```

**触发条件**：

- 仅对成熟文件夹（≥10 条）应用
- 在构建 Stage C 质心时执行

---

### 3.4 时间衰减质心（Temporal Centroid）

**目标**：近期的内容对文件夹画像贡献度更高

**实现位置**：

- `src/lib/classification/v5/folder-profiler/dual-source-builder.ts`
- 修改 `buildStageCEmbedding()` 方法

**公式**：

$$w_i = e^{-\lambda \cdot t_i}$$

其中：

- $\lambda = 0.1$（半衰期约 7 天）
- $t_i$ = 距离当前时间的天数

**实现**：

```typescript
// 计算时间权重
const now = Date.now();
const weights = bookmarks.map((b) => {
  const daysAgo = (now - b.createdAt.getTime()) / (1000 * 60 * 60 * 24);
  return Math.exp(-0.1 * daysAgo); // 3个月前权重 ≈ 0.05，3个月内权重 > 0.3
});

// 加权平均向量
const weightedCentroid = weightedAverage(bookmarks, weights);
```

## 八、总结

### 8.1 方案特点

1. **轻量化**：仅修改 4 个核心算法，不引入新依赖
2. **高效果**：预期解决 80%+ 的马太效应问题
3. **低风险**：向后兼容，支持灰度发布和回滚
4. **快实施**：3-4 天完成开发+测试+发布

### 8.2 核心价值

- ✅ **"名字即正义"**：小文件夹和名称匹配场景准确率大幅提升
- ✅ **"规模感知"**：大文件夹不再无限扩展边界
- ✅ **"质心纯净"**：去噪机制保证文件夹画像质量
- ✅ **"时间敏感"**：近期内容权重更高，适应变化
