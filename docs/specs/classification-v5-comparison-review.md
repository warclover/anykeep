## 二、BMAD 文档的亮点（值得借鉴）

### 2.1 技术实现深度 ⭐⭐⭐⭐⭐

#### ✅ 动态 α 系数算法（Decision 1）

**亮点**:
- 基于文件夹状态（空文件夹、杂物堆、成熟稳定）动态调整 α
- 引入**内聚性 (Internal Similarity)** 概念，用 pairwise cosine similarity 计算
- 代码实现清晰，有具体场景判断逻辑

**我的文档**: 只提到 α = 0.3 固定值，**需要补充动态算法**

```typescript
// BMAD 的算法更智能
const computeDynamicAlpha = (folder, bookmarks) => {
  if (bookmarkCount === 0) return 1.0;        // 空文件夹
  if (folder.isGeneric) return 0.8;            // 杂物堆
  if (internalSimilarity < 0.5) return 0.6;   // 内容分散
  if (bookmarkCount >= 10 && similarity >= 0.7) return 0.2; // 成熟稳定
  return 0.3;  // 默认
};
```

#### ✅ 条件 LLM 调用策略（Decision 2）

**亮点**:
- **高置信度 (≥85%)**: 直接分类，跳过 LLM → **节省 60%+ 成本**
- **分数接近 (Top1-Top2 差距 <10%)**: 才调用 LLM 裁决
- 有明确的阈值配置和决策路由

**我的文档**: 提到 LLM 裁决，但**缺少条件判断逻辑**

```typescript
// BMAD 的策略更务实
if (top1.hybridScore >= 0.85) {
  return { action: 'classify' };  // 跳过 LLM
}
if ((top1.score - top2.score) < 0.10) {
  return await llmArbitrate();    // 仅分数接近时调用
}
```

#### ✅ 自适应 Gardener 阈值（Decision 3）

**亮点**:
- 根据用户文件夹数量动态调整阈值
- 新用户 (0.55) → 普通用户 (0.70) → 整理狂人 (0.80)
- 避免新用户过度创建文件夹

**我的文档**: 提到新建文件夹，但**缺少自适应机制**

### 2.2 性能优化策略 ⭐⭐⭐⭐⭐

#### ✅ 惰性更新机制

**亮点**:
- Dirty Flag + 变动计数器 (`change_count`)
- 触发条件: 变动 ≥5 次 OR 距离上次更新 ≥1 小时
- 后台 Job 批量处理，避免阻塞主线程

**我的文档**: 提到惰性更新，但**缺少具体的触发条件和实现细节**

#### ✅ 反馈闭环机制

**亮点**:
- **增量更新**: 使用指数移动平均 (EMA) 更新文件夹向量
- **学习率**: 0.1，渐进式学习
- **分类失败日志**: `classification_logs` 表，用于后续分析

**我的文档**: 提到反馈学习，但**缺少具体的算法实现**

```typescript
// BMAD 的增量更新算法
const LEARNING_RATE = 0.1;
await supabase.rpc('update_folder_profile_incremental', {
  p_folder_id: folderId,
  p_new_embedding: bookmark.embedding,
  p_learning_rate: LEARNING_RATE
});
```
