## 🐛 问题描述

### 原始错误

```
ERROR: 42501: must be owner of relation users
```

### 原因分析

在 Supabase 环境中，`auth.users` 是受保护的系统表，普通用户（包括项目管理员）无法直接：

- 删除触发器（`DROP TRIGGER`）
- 创建触发器（`CREATE TRIGGER`）

原始脚本尝试删除并重新创建触发器，导致权限错误。

---

## ✅ 修复内容

### 修改 1：移除触发器删除操作

**修复前：**

```sql
-- 3.1 删除旧的触发器（准备替换）
DROP TRIGGER IF EXISTS on_auth_user_created ON auth.users;
```

**修复后：**

```sql
-- 3.1 创建改进的用户注册处理函数（使用 CREATE OR REPLACE 覆盖原函数）
-- 注意：不直接删除触发器，因为 auth.users 表在 Supabase 中受保护
```

### 修改 2：智能触发器处理

**修复前：**

```sql
-- 3.3 重新创建触发器
CREATE TRIGGER on_auth_user_created
    AFTER INSERT ON auth.users
    FOR EACH ROW
    EXECUTE FUNCTION handle_new_user();
```

**修复后：**

```sql
-- 3.2 处理触发器（安全方式，避免权限错误）
DO $$
BEGIN
    -- 检查触发器是否存在
    IF NOT EXISTS (
        SELECT 1 FROM pg_trigger
        WHERE tgname = 'on_auth_user_created'
          AND tgrelid = 'auth.users'::regclass
    ) THEN
        -- 触发器不存在，尝试创建
        BEGIN
            CREATE TRIGGER on_auth_user_created
                AFTER INSERT ON auth.users
                FOR EACH ROW
                EXECUTE FUNCTION handle_new_user();

            RAISE NOTICE '✓ Created trigger on_auth_user_created';
        EXCEPTION
            WHEN insufficient_privilege THEN
                RAISE NOTICE '⚠ Trigger creation skipped: insufficient privileges';
                RAISE NOTICE '  The trigger likely already exists or needs to be created by Supabase';
            WHEN OTHERS THEN
                RAISE NOTICE '⚠ Trigger creation failed: % (%)', SQLERRM, SQLSTATE;
        END;
    ELSE
        RAISE NOTICE '✓ Trigger on_auth_user_created already exists (function updated)';
    END IF;
END $$;
```

---

## 🔑 修复的关键点

1. **不尝试删除触发器**：避免触发权限错误
2. **检查触发器是否存在**：智能判断是否需要创建
3. **异常捕获**：优雅处理权限不足的情况
4. **友好提示**：告知用户触发器的状态

### 工作原理

- 如果触发器**已存在**：使用 `CREATE OR REPLACE FUNCTION` 更新函数即可，触发器会自动使用新函数
- 如果触发器**不存在**：尝试创建，失败则给出提示
- 如果**权限不足**：捕获异常并给出说明，不中断整个迁移
