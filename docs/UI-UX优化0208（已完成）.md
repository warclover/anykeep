## 二、P0 — 关键问题（影响核心体验）

### P0-1：硬编码中文文本违反项目规范

**问题描述**

CLAUDE.md 明确规定 "UI 文本使用常量/配置文件，不要硬编码在 JSX 中"，但经审查发现 **620+ 个文件** 存在中文硬编码，覆盖以下类型：

| 硬编码类型         | 估计数量 | 典型示例                                   |
| ------------------ | -------- | ------------------------------------------ |
| JSX 显示文本       | 500+ 处  | `"还没有收藏"`、`"欢迎回来"`、`"手动创建"` |
| `placeholder` 属性 | 30+ 处   | `placeholder="请输入邮箱地址"`             |
| `aria-label` 属性  | 10+ 处   | `aria-label="发送消息"`                    |
| 错误消息/Toast     | 50+ 处   | `toast.error("登录失败")`                  |

**涉及关键文件**（按影响面排序）

| 文件                                                 | 硬编码数量 | 说明                           |
| ---------------------------------------------------- | ---------- | ------------------------------ |
| `src/app/(auth)/login/page.tsx`                      | 30+ 处     | 整个登录页未使用 i18n          |
| `src/components/layout/mobile-bottom-nav.tsx`        | 5 处       | 导航文本全部硬编码             |
| `src/components/bookmark/empty-state.tsx`            | 2 处       | 空状态文本硬编码               |
| `src/components/layout/app-header.tsx`               | 3 处       | "手动创建"/"用途筛选"/"AI助理" |
| `src/components/layout/app-sidebar.tsx`              | 2 处       | "AnyKeep"/"智能收藏管理"       |
| `src/app/(auth)/register/page.tsx`                   | 20+ 处     | 注册页未使用 i18n              |
| `src/components/bookmark/bookmark-detail-client.tsx` | 15+ 处     | 详情页部分硬编码               |
| `src/components/synthesis/*.tsx`                     | 40+ 处     | 合成模块大量硬编码             |

**现状分析**

项目已建立 `useUiText()` Hook 和 i18n 基础设施（`src/lib/i18n/`），侧边栏 `app-sidebar.tsx` 和汉堡菜单 `mobile-menu.tsx` 已完成迁移，但其余 90%+ 的组件仍在硬编码。

**优化方案**

```
阶段 1（核心页面）：迁移登录/注册/首页/搜索页
阶段 2（布局组件）：迁移 mobile-bottom-nav、app-header、empty-state
阶段 3（业务组件）：按模块逐步迁移 bookmark、synthesis、ai 等
阶段 4（全覆盖）：placeholder、aria-label、错误消息统一迁移
```

**具体执行步骤**

1. 确认 `src/lib/messages/zh-CN.json` 和 `en-US.json` 语言文件已创建并包含完整翻译键
2. 为每个阶段建立翻译键命名规范：
   ```
   {模块}.{组件/页面}.{用途}
   例：auth.login.title → "欢迎回来"
        layout.bottomNav.bookmarks → "收藏"
        bookmark.emptyState.title → "还没有收藏"
   ```
3. 使用 `grep -r` 或 ESLint 自定义规则检测残留硬编码
4. 每阶段完成后运行回归测试确保文本正确渲染

**验收标准**

- [ ] 所有 JSX 显示文本通过 `useUiText()` 或 `t.xxx` 获取
- [ ] 所有 `placeholder` 和 `aria-label` 使用翻译键
- [ ] 切换 `en-US` 后界面无中文残留（阶段性验证）

### P0-2：导航信息架构过载

**问题描述**

侧边栏包含 **5 个分组、20+ 导航项**，对于内容收藏工具来说认知负担过重。

**当前导航结构分析**

```
内容中心 (5)    ← 合理，核心功能
├── 我的收藏
├── 我的搜索
├── 我的分类
├── 我的笔记 [Pro]
└── 我的音频

整理工具 (5)    ← "整理大师"和"收件箱"功能交叉
├── 整理中心
├── 收件箱
├── 数据中心
├── 批量操作
└── 健康检查

学习中心 (3)    ← "知识萃取"和"知识工坊"区分不清
├── 学习中心
├── 知识萃取
└── 知识工坊 [Pro]

洞察中心 (5)    ← "标签管理"放在这里不直觉
├── AI 中心
├── 数据分析
├── 标签管理      ← 应归入"内容中心"
├── 活动日志
└── 消息通知

系统 (3+子菜单)  ← 开发者工具不应暴露给普通用户
├── 设置
├── 分类管理
└── 开发者工具 (3)  ← RAG仪表盘、文件夹健康、AI调试
```

**核心问题**

1. **功能交叉**：整理中心 vs 收件箱、学习中心 vs 知识萃取 职责边界模糊
2. **分类错误**："标签管理"属于内容管理，却放在"洞察中心"
3. **开发工具泄漏**：RAG 仪表盘、AI 调试、分类追踪等开发工具对普通用户可见
4. **分组过多**：5 个分组导致视觉层级过多

**优化方案**

```
方案 A（推荐）：精简为 3+1 分组

我的内容 (6)         ← 合并"内容中心"+"标签管理"
├── 我的收藏
├── 我的搜索
├── 我的分类
├── 我的标签          ← 从"洞察中心"移入
├── 我的笔记 [Pro]
└── 我的音频

智能工具 (6)         ← 合并"整理工具"+"学习中心"
├── 收件箱
├── 整理中心
├── 知识萃取
├── 知识工坊 [Pro]
├── 批量操作
└── 数据中心

洞察与通知 (4)       ← 精简"洞察中心"
├── AI 中心
├── 数据分析
├── 活动日志
└── 消息通知

系统 (2)             ← 隐藏开发工具
├── 设置
└── 垃圾箱

开发者工具           ← 仅在 settings 中设置开启后显示
├── 分类管理
├── RAG 仪表盘
├── 文件夹健康
└── AI 调试
```

**具体执行步骤**

1. 在用户设置中添加"开发者模式"开关（`settings.developer_mode: boolean`）
2. 调整 `app-sidebar.tsx` 中的 `contentCenterItems`，将 Tags 从 `insightCenterItems` 移入
3. 合并"整理工具"和"学习中心"为"智能工具"
4. 从 `insightCenterItems` 移除"健康检查"入口
5. 开发者工具根据 `developer_mode` 条件渲染
6. 同步更新 `mobile-menu.tsx` 的 `navigationGroups`

**验收标准**

- [ ] 侧边栏导航分组 ≤ 4 个
- [ ] 开发者工具默认不可见
- [ ] 功能归类符合用户心智模型（可通过 3 人小规模可用性测试验证）

### P0-3：移动端底部导航功能严重缺失

**问题描述**

底部导航仅有 5 个入口（收藏、搜索、分类、数据、设置），而桌面端侧边栏有 20+ 入口。以下功能在移动端**完全没有直接入口**：

- 收件箱（待分类内容）
- 学习中心 / 知识萃取 / 知识工坊
- 合成功能
- AI Hub
- 消息通知（含未读徽章）
- 批量操作
- 数据导入/导出
- 健康检查

**影响**：移动端用户无法发现和使用大部分功能，而 AnyKeep 定位为"跨平台"工具。

**优化方案**

```
方案：底部导航 4 + 更多

固定 Tab (4):
├── 收藏 (BookOpen)     ← /home
├── 搜索 (Search)       ← /search
├── 收件箱 (Inbox)      ← /inbox（新增，高频操作）
└── 更多 (MoreHorizontal) ← 展开完整菜单 Sheet

"更多" Sheet 内容：
├── 我的分类 → /folders
├── 我的标签 → /tags
├── 智能工具（整理中心、知识萃取、批量操作...）
├── 洞察（数据分析、活动日志）
├── 消息通知（显示未读徽章）
├── 设置
└── 垃圾箱
```

**具体执行步骤**

1. 修改 `mobile-bottom-nav.tsx`：
   - 将 5 个 Tab 精简为 4 个：收藏、搜索、收件箱、更多
   - "更多" Tab 点击展开 Sheet（复用 `mobile-menu.tsx` 的分组结构）
2. 在"更多" Sheet 顶部添加快捷操作区（AI 助理、手动创建）
3. 消息通知在"更多" Tab 上显示未读红点
4. 确保"更多"菜单的分组结构与 P0-2 优化后的侧边栏一致

**涉及文件**

- `src/components/layout/mobile-bottom-nav.tsx` — 重构
- `src/components/layout/mobile-menu.tsx` — 可复用其 navigationGroups 配置

**验收标准**

- [ ] 移动端可访问桌面端 100% 的功能
- [ ] "更多"菜单展开流畅，无卡顿
- [ ] 未读消息在"更多" Tab 上有红点提示

## 三、P1 — 重要问题（影响用户效率）

### P1-1：Header 双行布局占用过多垂直空间

**���题描述**

`app-header.tsx` 使用两行布局：第一行 Logo + 操作区（h-14 = 56px），第二行快速添加区（h-11 = 44px），总计 **100px**。

加上侧边栏 `top-[6.25rem]`（100px）和移动端底部导航（h-16 = 64px），在移动端：

- **固定元素占据**：100px (header) + 64px (底部导航) = **164px**
- 以 iPhone SE（667px 高度）为例，可用内容区仅 **503px（75%）**
- 以 iPhone 15 Pro（852px 高度）为例，可用内容区仅 **688px（81%）**

**优化方案**

```
方案：快速添加区域改为可收起模式

1. 移动端：
   - 移除第二行，将"快速添加"整合为 FAB（已有 FloatingActionMenu 组件）
   - Header 高度从 100px → 56px
   - 节省 44px 垂直空间

2. 桌面端：
   - 保留第二行，但增加收起/展开切换
   - 向下滚动时自动收起第二行（scroll-aware header）
   - 或：将快速添加整合到侧边栏顶部区域
```

**具体执行步骤**

1. `app-header.tsx` 中 `showQuickAdd` 条件增加设备判断：
   ```tsx
   // 移动端不显示第二行
   const showQuickAdd = isHomePage && !isTrashFolder && !isMobile;
   ```
2. 移动端的"手动创建"和"AI助理"按钮整合到已有的 `FloatingActionMenu` 组件中
3. 桌面端可选实现 `scroll-aware` 效果（监听滚动方向，向下滚动时收起第二行）

**涉及文件**

- `src/components/layout/app-header.tsx` — 条件渲染第二行
- `src/components/fab/index.tsx` — 整合移动端快捷操作

**验收标准**

- [ ] 移动端 Header 高度 ≤ 56px
- [ ] 移动端仍可通过 FAB 快速添加收藏
- [ ] 桌面端快速添加区域保持可用

### P1-3：BookmarkCard 内联组件导致不必要的重挂载

**问题描述**

`src/components/bookmark/bookmark-card.tsx:275-387` 在组件函数体内定义了 `ActionMenu` 和 `SelectionCheckbox` 两个组件：

```tsx
// 当前：每次渲染创建新的组件引用
export const BookmarkCard = memo(function BookmarkCard(props) {
  const ActionMenu = ({ className, variant }) => ( ... );      // ← 内联定义
  const SelectionCheckbox = ({ className }) => ( ... );        // ← 内联定义
  // ...
}, arePropsEqual);
```

这导致即使外层使用了 `React.memo + arePropsEqual`，内部子组件仍会在每次渲染时重新创建引用，触发卸载/重挂载，浪费性能。

**优化方案**

将 `ActionMenu` 和 `SelectionCheckbox` 提取为外部独立组件：

```tsx
// 提取到文件外部或独立文件
const ActionMenu = memo(function ActionMenu({
  className,
  variant,
  bookmark,
  handlers,
  t,
  isSnapshotEnabled,
}: ActionMenuProps) {
  // ...
});

const SelectionCheckbox = memo(function SelectionCheckbox({
  className,
  isSelected,
}: SelectionCheckboxProps) {
  // ...
});
```

**具体执行步骤**

1. 提取 `ActionMenu` 为独立 memo 组件，将所需的 `bookmark`、回调函数、`t` 通过 props 传入
2. 提取 `SelectionCheckbox` 为独立 memo 组件
3. 验证 `arePropsEqual` 比较函数是否需要更新
4. 运行性能 profiling 确认优化效果

**涉及文件**

- `src/components/bookmark/bookmark-card.tsx` — 重构组件结构

**验收标准**

- [ ] `ActionMenu` 和 `SelectionCheckbox` 为外部 memo 组件
- [ ] 不触发不必要的卸载/重挂载（React DevTools Profiler 验证）
- [ ] 功能行为不变

## 四、P2 — 改进建议（提升体验质感）

### P2-1：侧边栏糖果色过于繁杂

**问题描述**

`app-sidebar.tsx` 为 5 个分组定义了 5 种不同的糖果色（粉红、天蓝、紫色、玫瑰、石板灰）：

- **粉红**（content）和**玫瑰**（insight）色调过于接近，难以区分
- 5 种颜色同时出现导致视觉信息过载
- 整体观感不够专业

**优化方案**

```
方案 A（推荐）：品牌色 + 中性色双色方案

1. 激活状态统一使用品牌紫色：
   active: "bg-purple-100 text-purple-700 dark:bg-purple-900/30 dark:text-purple-300"
   icon: "text-purple-500 dark:text-purple-400"

2. 分组标题使用灰度区分（通过字号/粗细而非颜色）

3. Hover 统一使用中性灰：
   hover: "hover:bg-gray-100 dark:hover:bg-gray-800"

方案 B：精简为 3 色方案
- 内容类（收藏/搜索/分类）：品牌紫
- 工具类（整理/学习/AI）：青蓝
- 系统类（设置/垃圾箱）：石板灰
```

**涉及文件**

- `src/components/layout/app-sidebar.tsx` — `groupCandyColors` 配置

**验收标准**

- [ ] 色彩方案不超过 3 种
- [ ] 粉红和玫瑰不同时存在
- [ ] 暗色模式下色彩同样清晰可辨

### P2-2：登录页 Slogan 视觉复杂度过高

**问题描述**

`login/page.tsx:161-222` 的 "Keep Smart. Read Anytime." slogan 存在以下问题：

**优化方案**

```
简化为干净的品牌展示：

<div className="text-center mb-8">
  <h1 className="text-3xl font-bold bg-gradient-to-r from-violet-600 to-cyan-500
                  bg-clip-text text-transparent">
    AnyKeep
```

### P2-3：关键 Suspense fallback 使用 null

**问题描述**

`src/app/(main)/layout.tsx` 中多个 Suspense 边界使用 `fallback={null}`：

```tsx
<Suspense fallback={null}>
  <MainContentWrapper>
    <MainContent>{children}</MainContent>
  </MainContentWrapper>
</Suspense>
```

虽然避免了 CLS（布局偏移），但首次加载时用户看到完全空白，无任何反馈。

**优化方案**

```
分级 fallback 策略：

1. 主内容区（关键路径）：使用轻量骨架屏
   <Suspense fallback={<MainContentSkeleton />}>

2. AI 面板（非关键路径）：保持 null（可接受）

3. FAB（装饰性）：保持 null（可接受）

MainContentSkeleton 设计：
- 仅渲染灰色条纹块（模拟标题+卡片网格）
- 使用 CSS animation，无 JS 依赖
- 高度匹配实际内容区，避免 CLS
```

**涉及文件**

- `src/app/(main)/layout.tsx` — 主内容区 fallback
- 新建 `src/components/layout/main-content-skeleton.tsx`

**验收标准**

- [ ] 主内容区加载时显示骨架屏
- [ ] 骨架屏不引入额外 CLS
- [ ] 骨架屏无 JS 依赖（纯 CSS 动画）

### P2-4：BookmarkCard 使用 `role="link"` ���义问题

**问题描述**

`bookmark-card.tsx:789` 使用 `<div role="link" tabIndex={0}>` 模拟链接行为，但缺少 `href` 属性。ARIA 规范要求 `role="link"` 元素应有明确的 URL 目标。

此外 `onKeyDown` 中的类型断言 `as unknown as React.MouseEvent` 不类型安全。

**优化方案**

```tsx
// 方案 A（推荐）：使用语义化 <a> 标签
<a
  href={`/bookmark/${bookmark.id}`}
  onClick={(e) => {
    // 阻止默认导航，使用 router.push
    if (!isSelectionMode) {
      e.preventDefault();
      router.push(`/bookmark/${bookmark.id}`);
    }
  }}
  className="block h-full cursor-pointer"
>
  <Card>...</Card>
</a>

// 方案 B：移除 role="link"，改用 role="button"（如果选择模式优先）
<div
  role="button"
  tabIndex={0}
  aria-label={`打开收藏: ${bookmark.title}`}
  onClick={handleItemClick}
  onKeyDown={(e) => {
    if (e.key === "Enter" || e.key === " ") {
      e.preventDefault();
      handleItemClick(e);  // 需要重构为不依赖 MouseEvent
    }
  }}
>
```

**涉及文件**

- `src/components/bookmark/bookmark-card.tsx` — 三种视图的外层容器

**验收标准**

- [ ] 屏幕阅读器可正确识别元素类型
- [ ] 键盘交互无类型断言
- [ ] Enter/Space 键可触发导航

### P3-3：BookmarkCard 使用 `<img>` 而非 Next.js `<Image>`

**问题描述**

`bookmark-card.tsx` 使用原生 `<img>` 标签加载封面图，虽然有 `eslint-disable` 注释说明是因为动态外部 URL，但仍缺少：

- 自动 WebP/AVIF 格式转换
- 尺寸优化（根据设备分辨率提供不同尺寸）
- 模糊占位符（blur placeholder）

**优化方案**

```tsx
// 考虑到外部 URL 的不可控性，保留 <img> 但增加优化：
// 1. 添加 width/height 属性避免 CLS
<img
  src={coverImage}
  alt={bookmark.title ?? ""}
  width={400}
  height={170} // 2.35:1 比例
  className="w-full h-full object-cover"
  loading="lazy"
  decoding="async"
  onError={handleImageError}
/>;

// 2. 如果使用 Next.js Image，需配置 remotePatterns：
// next.config.ts
images: {
  remotePatterns: [{ protocol: "https", hostname: "**" }];
}
```

**评估**：由于项目大量使用外部封面图且已有代理方案（`getProxiedImageUrl`），当前 `<img>` + `lazy` + `decoding="async"` + `onError` 的方案是合理的折中。此项优先级较低。

**验收标准**

- [ ] 图片元素包含 `width` 和 `height` 属性
- [ ] 加载失败时正确回退到占位图
