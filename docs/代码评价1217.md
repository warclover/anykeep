## 四、问题与建议 ⚠️

### 4.1 高优先级问题 🔴

#### 1. 大型文件需拆分

| 文件                                                       | 行数  | 建议                                    |
| ---------------------------------------------------------- | ----- | --------------------------------------- |
| `src/components/home/home-page-client.tsx`                 | 1,787 | 拆分为 header/sidebar/bookmarks/filters |
| `src/lib/classification/integration.ts`                    | 986   | 拆分为 executor/handler/updater         |
| `src/lib/classification/services/smart-sorting.service.ts` | 944   | 拆分为 strategies/clustering/scoring    |
| `src/types/supabase.ts`                                    | 4,029 | 自动生成，注意不要手动编辑              |

**拆分建议**：

```
home-page-client.tsx 拆分方案：
├── home-page-header.tsx
├── home-page-sidebar.tsx
├── home-page-bookmarks-section.tsx
└── home-page-filters.tsx

integration.ts 拆分方案：
├── classification-executor.ts (分类逻辑)
├── confirmation-handler.ts (确认消息)
└── profile-updater.ts (画像更新)
```

#### 2. Hydration 错误

```
TypeError: Cannot read properties of undefined (reading 'call')
```

**原因分析**：

- 与 `@sentry/nextjs` 集成有关
- webpack 模块加载顺序问题
- OpenTelemetry 依赖警告

**建议**：

- 检查 Sentry 配置
- 升级 `@sentry/nextjs` 依赖
- 或临时禁用 Sentry 进行排查

### 4.2 中优先级问题 🟡

#### 3. 缓存策略不统一

现有多套缓存实现：

- IndexedDB (`browser-bookmark/import-cache.ts`)
- SWR (`use-bookmarks-swr.ts`)
- React Query
- Server Components 缓存

**建议**：建立缓存分层策略文档

```
L1: 内存缓存（React State）     - 毫秒级
L2: 组件缓存（SWR/React Query） - 秒级
L3: IndexedDB（客户端持久化）   - 分钟级
L4: Server Cache               - 请求级
```

#### 4. 测试覆盖率未明确

#### 5. 缺少断路器模式

`fetch-with-retry.ts` 有重试机制，但缺少：

- ❌ 断路器（Circuit Breaker）

- ❌ 熔断时长计算

**建议**：实现 `CircuitBreaker` 类

```typescript
class CircuitBreaker {
  private state: "CLOSED" | "OPEN" | "HALF_OPEN" = "CLOSED";
  private failureCount = 0;
  private lastFailureTime?: number;

  async execute<T>(fn: () => Promise<T>): Promise<T> {
    // 实现断路器逻辑
  }
}
```
