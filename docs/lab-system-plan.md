# 电子元器件大型实验室智能软件系统规划方案

> 版本：v0.4（联邦式 LIMS 架构版）| 日期：2026-03-10 | 状态：待审核
>
> **v0.4 变更**：LIMS 从单体重构为联邦式微服务架构，按 17025"人机料法环"拆分为 6 个独立服务模块 + 共享数据层
>
> **v0.3 变更**：根据半导体可靠性/失效分析业务特性，新增 TDM/YMS、FAMS、SECS/GEM、CFR 21 Part 11（共 18 个子系统）
>
> **v0.2 变更**：确认硬性约束（AI 全私有化、LIMS 自研、纯内网、零基础），新增 7 个补充子系统

## 一、项目概述

### 1.1 硬性约束

| 约束项           | 要求                                       | 影响                                           |
| ---------------- | ------------------------------------------ | ---------------------------------------------- |
| **AI 全私有化**  | 所有 AI 模型必须内网私有化部署，数据不出域 | 需自建 GPU 集群，排除所有公有云 AI API 调用    |
| **LIMS 自研**    | LIMS 系统完全自研，不采购商业产品          | 研发周期长但灵活度高，需组建专业 LIMS 开发团队 |
| **纯内网环境**   | 系统运行在隔离内网，无公网访问             | 私有云部署、内网 CA、离线更新机制、内网 NTP    |
| **零信息化基础** | 现有无任何信息化系统，从零开始建设         | 需同步建设 IT 基础设施，分期建设降低风险       |

### 1.2 项目背景

电子元器件实验室承担器件可靠性测试、失效分析、环境试验、电气参数测量等关键任务，涉及 CNAS 认可体系、IEC/GB 检测标准。传统实验室面临以下痛点：

- 设备数据孤岛，人工抄录效率低、易出错
- 检测流程依赖纸质记录，追溯困难
- 专家经验隐性化，人员流动造成知识断层
- 设备利用率不透明，排期冲突频发
- 安全管理被动响应，缺乏预警机制

### 1.3 建设目标

| 维度         | 目标                                       |
| ------------ | ------------------------------------------ |
| **数据贯通** | 打通"样品→检测→报告→归档"全链路数据流      |
| **智能决策** | AI 辅助检测方案推荐、异常判定、趋势预警    |
| **合规保障** | 满足 CNAS-CL01、等保三级、电子签章法律效力 |
| **效率提升** | 检测周期缩短 30%+，报告生成效率提升 50%+   |
| **知识沉淀** | 建立可检索、可推理的实验室专家知识体系     |

### 2.1 实验室物联网系统 (IoT)

**定位**：实验室数据采集与设备互联的基础底座，为上层系统提供实时数据源。

#### 核心功能

| 模块               | 功能说明                                                                                                                          |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| **设备接入网关**   | 支持 GPIB、RS232/485、SCPI、Modbus、OPC-UA、MQTT 等通用仪器协议                                                                   |
| **半导体设备集成** | **SECS/GEM (SEMI E5/E30/E37)**：ATE 测试机、温箱、分选机等半导体设备标准通信协议；支持 Recipe 远程下发、设备状态机管理、HSMS 通信 |
| **ATE 数据采集**   | 对接主流 ATE 平台（Teradyne/Advantest/Cohu），实时采集测试数据流，支持 STDF 格式原始数据透传至 TDM 系统                           |
| **数据采集引擎**   | 高频采集（万次/秒级），支持触发采集、定时采集、事件驱动采集三种模式                                                               |
| **边缘计算节点**   | 本地数据预处理（滤波、降噪、特征提取），断网续传，减轻中心负载                                                                    |
| **协议适配层**     | 统一数据模型转换，屏蔽底层协议差异，新设备接入仅需配置驱动                                                                        |
| **设备影子**       | 维护设备最新状态快照，支持离线状态同步、指令下发队列                                                                              |
| **环境监测**       | 温湿度、洁净度、振动、电磁场、辐射剂量等参数实时采集与告警                                                                        |

#### 半导体设备接入矩阵

| 设备类型   | 典型设备                              | 接入协议               | 采集数据                      |
| ---------- | ------------------------------------- | ---------------------- | ----------------------------- |
| ATE 测试机 | Teradyne UltraFLEX / Advantest V93000 | SECS/GEM + STDF 数据流 | 测试结果、Binning、参数测量值 |
| 温度循环箱 | Thermotron / ESPEC                    | Modbus / SECS/GEM      | 温度曲线、循环计数、箱体状态  |
| 高温老化炉 | Delta Design / Aehr                   | RS485 / OPC-UA         | HTOL 温度、电压、电流、时间   |
| 振动台     | LDS / IMV                             | GPIB / RS232           | 振动频谱、加速度、位移        |
| X-ray/CT   | Nordson DAGE / YXLON                  | DICOM / 私有协议       | 图像文件、检测参数            |
| SEM/FIB    | FEI / JEOL / Hitachi                  | 私有协议 / 文件监控    | 高分辨率图像、EDS 能谱        |
| 曲线追踪仪 | Keysight / Keithley                   | SCPI / GPIB            | I-V 曲线、参数值              |
| ESD 测试仪 | Thermo Fisher / ESDEMC                | RS232 / USB            | 放电波形、阈值电压            |

#### 关键技术选型

| 技术领域        | 推荐方案                            | 理由                                            |
| --------------- | ----------------------------------- | ----------------------------------------------- |
| IoT 平台        | EMQ X + 自研设备管理                | EMQ X 高并发 MQTT，国产可控                     |
| SECS/GEM 中间件 | Cimetrix CIMConnect / 自研 GEM Host | 半导体行业标准，支持 E5/E30/E37/E87/E90         |
| 边缘计算        | EdgeX Foundry / KubeEdge            | 开源成熟，支持异构设备                          |
| 时序数据库      | TDengine                            | 国产、高压缩比，适合海量传感数据和 ATE 参数数据 |
| 仪器驱动        | IVI-COM / NI-VISA 封装层            | 电子测量仪器标准驱动接口                        |

#### AI 落地场景

| 场景                | 技术                                   | 具体应用                                                                  |
| ------------------- | -------------------------------------- | ------------------------------------------------------------------------- |
| **设备预测性维护**  | 时序异常检测 (Isolation Forest / LSTM) | 分析温箱温度均匀性漂移、ATE 测试头接触电阻变化，提前 2 周预警需维护的设备 |
| **环境异常预警**    | 多变量时序预测                         | 温湿度联合建模，预测恒温恒湿箱性能衰退，避免 HTOL/THB 试验样品失效        |
| **智能采集策略**    | 强化学习                               | 根据测试阶段自动调整采样频率（稳态降频、瞬态升频），节省存储 30%+         |
| **ATE Recipe 优化** | 统计分析 + ML                          | 分析历史测试数据，推荐测试项排序和限值优化，减少测试时间                  |

### 2.2 实验室门口屏系统

**定位**：实验室各房间入口的信息展示与交互终端，实现"到门即知"的信息透明化。

#### 核心功能

| 模块               | 功能说明                                                                      |
| ------------------ | ----------------------------------------------------------------------------- |
| **实验室状态看板** | 实时显示：当前检测任务、设备状态（运行/空闲/故障）、环境参数（温湿度/洁净度） |
| **排期日历**       | 按天/周展示设备预约情况，支持刷卡/扫码现场预约                                |
| **人员签到**       | 人脸识别 + 工卡双因子签到，记录进出时间                                       |
| **安全提示**       | 动态安全告警（高压、辐射、化学品）、应急疏散路线                              |
| **通知公告**       | 检测标准更新、设备维护通知、培训安排推送                                      |
| **访客登记**       | 访客扫码登记、NDA 电子签署、临时权限授予                                      |

#### 关键技术选型

| 技术领域 | 推荐方案                                             |
| -------- | ---------------------------------------------------- |
| 硬件     | 10.1-15.6 寸工业级触摸屏（Android/Linux），IP65 防护 |
| 前端框架 | Flutter（跨平台）或 Android 原生 + WebView 混合      |
| 人脸识别 | 虹软 / 百度离线 SDK（内网部署，数据不出域）          |
| 数据同步 | WebSocket 实时推送 + 本地缓存（断网可用）            |

#### AI 落地场景

| 场景                 | 具体应用                                                         |
| -------------------- | ---------------------------------------------------------------- |
| **智能排期推荐**     | 基于历史使用数据，推荐最优检测时段（避开高峰、串联关联试验）     |
| **人脸门禁联动**     | 识别人员资质是否匹配当前实验室（如：未持有高压操作证的人员告警） |
| **异常状态语音播报** | 环境超标时 TTS 自动播报告警，无需人工查看                        |

### 2.3 实验室数字孪生系统

**定位**：构建实验室物理空间、设备、流程的 1:1 数字镜像，实现"可视、可控、可预测"。

#### 核心功能

| 模块             | 功能说明                                                       |
| ---------------- | -------------------------------------------------------------- |
| **3D 场景建模**  | 实验室空间、设备、管线、走线的三维建模，支持 BIM 数据导入      |
| **实时数据映射** | IoT 数据驱动 3D 模型状态（设备运行动画、环境热力图、人员定位） |
| **设备交互**     | 点击 3D 设备模型，查看实时参数、历史曲线、维保记录、操作手册   |
| **空间热力分析** | 温度场、电磁场、洁净度的空间分布可视化                         |
| **流程仿真**     | 检测流程动画回放，瓶颈环节高亮标注                             |
| **远程巡检**     | VR/AR 辅助远程巡检，专家远程指导现场操作                       |

#### 关键技术选型

| 技术领域 | 推荐方案                                   | 理由                                     |
| -------- | ------------------------------------------ | ---------------------------------------- |
| 3D 引擎  | Unity / Unreal Engine / Three.js（Web 端） | Unity 生态成熟，Web 端用 Three.js 轻量化 |
| BIM 集成 | Autodesk Forge / IFC 解析                  | 对接建筑设计数据                         |
| 定位技术 | UWB 室内定位（厘米级）                     | 人员/移动设备精准定位                    |
| 数据驱动 | WebSocket + 数据插值                       | 实时驱动 3D 模型状态变化                 |

#### AI 落地场景

| 场景             | 技术                | 具体应用                                                           |
| ---------------- | ------------------- | ------------------------------------------------------------------ |
| **空间优化建议** | 路径规划 + 约束优化 | 分析设备布局与使用频率，推荐实验室空间调整方案（减少人员动线交叉） |
| **能耗预测**     | 时序预测模型        | 基于设备运行计划预测未来 24h 用电/制冷负荷，优化能源调度           |
| **故障根因定位** | 因果推理            | 设备故障时，在 3D 场景中高亮关联设备/环境因素，辅助排查            |

### 2.4 实验室终端服务系统

**定位**：检测人员的日常工作统一入口，整合各子系统功能到工位终端。

#### 核心功能

| 模块           | 功能说明                                                  |
| -------------- | --------------------------------------------------------- |
| **统一工作台** | 单点登录(SSO)，角色化首页（检测员/审核员/管理员视图不同） |
| **任务中心**   | 待办任务、检测排期、审核流程、消息通知的统一收件箱        |
| **快捷操作**   | 一键启动数据采集、扫码关联样品、语音录入检测备注          |
| **报告工作台** | 模板选择→数据自动填充→在线编辑→审核流转→签章出具          |
| **个人仪表盘** | 个人工作量统计、技能矩阵、培训进度、绩效看板              |
| **离线模式**   | 核心功能离线可用（数据采集、报告编辑），联网后自动同步    |

#### 关键技术选型

| 技术领域 | 推荐方案                                                          |
| -------- | ----------------------------------------------------------------- |
| 架构     | 微前端（qiankun / Module Federation），各子系统独立开发、统一集成 |
| 前端     | React / Vue 3 + TypeScript                                        |
| 离线     | Service Worker + IndexedDB                                        |
| 桌面端   | Electron / Tauri（需要本地仪器驱动交互时）                        |

#### AI 落地场景

| 场景             | 具体应用                                                                          |
| ---------------- | --------------------------------------------------------------------------------- |
| **智能任务分配** | 根据检测员技能等级、当前负载、设备可用性，自动推荐最优任务分配方案                |
| **报告智能填充** | LLM 根据采集数据自动生成检测结论段落，检测员只需审核确认                          |
| **语音助手**     | 检测过程中语音指令控制（"开始采集"、"标记异常点"、"记录备注：第 3 引脚焊接异常"） |
| **操作引导**     | 新员工执行复杂测试时，AI 逐步引导操作流程，实时校验操作是否正确                   |

### 2.5 实验室 LIMS 系统（联邦式架构）

**定位**：实验室业务核心系统，管理"样品-检测-数据-报告"的完整生命周期。

**架构决策**：采用**联邦式 LIMS** 架构——按 ISO/IEC 17025 的"人、机、料、法、环"五要素拆分为独立微服务模块，共享数据层，统一 API 网关对外。外部看是一个系统，内部各模块可独立开发、测试、部署、升级。

#### 联邦式架构总览

```
┌───────────────────── LIMS Platform ──────────────────────┐
│                                                          │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌────────────┐  │
│  │  样品服务  │ │  方法标准  │ │  数据校验  │ │ 报告+签章   │  │
│  │  (料)     │ │  服务     │ │  服务     │ │ 服务       │  │
│  │          │ │  (法)     │ │          │ │            │  │
│  └────┬─────┘ └────┬─────┘ └────┬─────┘ └─────┬──────┘  │
│       │            │            │              │         │
│  ┌────▼────────────▼────────────▼──────────────▼──────┐  │
│  │         检测流程编排引擎 (Workflow Orchestrator)      │  │
│  │   动态流转 │ 并行路由 │ 条件分支 │ 长周期试验管理       │  │
│  └────────────────────┬──────────────────────────────┘  │
│                       │                                  │
│  ┌────────────────────▼──────────────────────────────┐  │
│  │            FAMS 失效分析引擎                         │  │
│  │   FA 工作流 │ 病历卡 │ 图像管理 │ 8D/FMEA/FTA       │  │
│  └───────────────────────────────────────────────────┘  │
│                       │                                  │
│  ┌────────────────────▼──────────────────────────────┐  │
│  │            共享数据层 (PostgreSQL + MinIO)            │  │
│  │   样品库 │ 方法库 │ 检测数据 │ 报告库 │ FA 图像库      │  │
│  └───────────────────────────────────────────────────┘  │
├──────────────────────┬───────────────────────────────────┤
│     统一 API 网关     │        事件总线 (MQ)              │
└──────────────────────┴───────────────────────────────────┘
         │                          │
    ┌────┴────┬──────┬─────┐   异步事件通知
    ▼         ▼      ▼     ▼   (设备状态/环境告警/人员签到)
  IAM(人)  EAM(机)  IoT  QMS     ▼
  TMS(人)          (环)         Safety(环)
```

#### 17025 五要素与服务模块映射

| 17025 要素           | 服务模块     | 归属                        | 说明                                                     |
| -------------------- | ------------ | --------------------------- | -------------------------------------------------------- |
| **人 (Personnel)**   | 人员资质服务 | → 外部系统 **IAM + TMS**    | 人员能力确认、授权范围、培训记录，LIMS 通过 API 调用校验 |
| **机 (Equipment)**   | 设备状态服务 | → 外部系统 **EAM + IoT**    | 设备校准状态、可用性、实时数据，LIMS 通过 API 查询/订阅  |
| **料 (Sample)**      | 样品管理服务 | → LIMS 内部模块             | 样品接收、标识、流转、存储、留样、到期处置               |
| **法 (Method)**      | 方法标准服务 | → LIMS 内部模块             | 检测方法、标准条款、参数模板、版本管理、验证记录         |
| **环 (Environment)** | 环境监控服务 | → 外部系统 **IoT + Safety** | 温湿度、洁净度、振动等，LIMS 通过事件总线接收告警        |

#### 核心服务模块详细设计

##### 模块 1：样品管理服务（料）

| 功能             | 说明                                                             |
| ---------------- | ---------------------------------------------------------------- |
| **样品接收登记** | 条码/RFID 标识生成、客户信息关联、样品照片采集                   |
| **流转追踪**     | 样品位置实时追踪（接收→分样→上机→检测→留样→退样），全程扫码记录  |
| **存储管理**     | 库位管理（温控/常温/防潮柜）、到期提醒、留样管理                 |
| **批次追溯**     | Wafer Lot → 封装批次 → 检测数据 → 供应商 → 应用产品 的全链路追溯 |
| **分样/合样**    | 同一批次拆分多组进行不同试验，试验后结果合并汇总                 |

##### 模块 2：方法标准服务（法）

| 功能             | 说明                                                                         |
| ---------------- | ---------------------------------------------------------------------------- |
| **标准条款库**   | JEDEC (JESD22/JESD47)、AEC-Q100/Q101/Q200、MIL-STD-883 等标准的结构化存储    |
| **检测方法管理** | 方法验证/确认记录、测量不确定度评定、方法偏离控制                            |
| **参数模板引擎** | 每个标准试验条件的完整参数模板（温度、电压、时间、判定准则），一键关联到任务 |
| **版本管理**     | 标准更新时自动比对差异，标记受影响的检测方法和在执行任务                     |
| **限值/公式库**  | 可配置的数据校验规则、计算公式、合格判定逻辑                                 |

##### 模块 3：检测流程编排引擎（核心协调器）

| 功能           | 说明                                                                                            |
| -------------- | ----------------------------------------------------------------------------------------------- |
| **动态流转**   | 同一批次芯片支持并行路由（如同时进行电气特性确认 + 环境应力测试）                               |
| **条件分支**   | 测试结果触发不同后续流程（如：ESD 未通过 → 自动触发 FA 流程）                                   |
| **任务调度**   | 任务创建→分配→执行→复核→审批 五级流程，自动匹配人员资质（调用 IAM/TMS）和设备可用性（调用 EAM） |
| **长周期试验** | HTOL/TC/THB/HAST 等持续数百小时的试验管理，自动计算累计应力时长，中间读数点管理                 |
| **委外管理**   | 部分测试项委托外部实验室时的样品寄送、进度跟踪、结果回传、数据合并                              |
| **ATE 对接**   | 自动接收 IoT 层透传的 ATE 测试结果，关联样品批次，Bin 分类自动汇总                              |

##### 模块 4：数据校验服务

| 功能             | 说明                                                               |
| ---------------- | ------------------------------------------------------------------ |
| **数据接入**     | IoT 自动采集 + 手工录入双通道，支持离线数据导入                    |
| **校验规则引擎** | 范围检查、逻辑检查、趋势检查、跨参数关联检查，规则可配置无需改代码 |
| **质控图**       | X-R / Xbar-S / CUSUM 控制图，自动判断 OOC（失控）和趋势            |
| **不确定度计算** | 基于方法标准服务提供的评定模型，自动计算扩展不确定度               |
| **数据锁定**     | 原始数据一旦录入不可修改，修改需走偏离流程并保留完整修改痕迹       |

##### 模块 5：报告服务

| 功能             | 说明                                                   |
| ---------------- | ------------------------------------------------------ |
| **模板引擎**     | 支持 Word/PDF/Excel 多格式，CNAS/CMA 认可标识自动嵌入  |
| **数据自动填充** | 从数据校验服务拉取检测结果，自动填充到报告模板对应位置 |
| **多级审核**     | 编制→校核→审批→签发 的审核链，关联电子签章系统         |
| **版本追溯**     | 报告修改历史完整留存，支持任意版本回溯和差异对比       |
| **批量出具**     | 同类检测批量生成报告，支持报告合并/拆分                |

##### 模块 6：FAMS 失效分析引擎

> **设计决策**：FAMS 作为 LIMS 平台内的独立服务模块，与其他模块共享数据层，避免数据割裂。但其内部按独立子系统级别设计，拥有独立的 FA 工作流引擎。

| 功能                 | 说明                                                                                    |
| -------------------- | --------------------------------------------------------------------------------------- |
| **FA 工作流引擎**    | 非线性、探索性流程：初步检查→外观→X-ray/CT→开封→SEM/FIB→EDS/EBSD，任意环节可回退或分支  |
| **病历卡式缺陷追踪** | 每个失效样品一张"病历卡"，记录完整分析路径、每步发现、关联图片、中间结论                |
| **高分辨率图像管理** | X-ray/CT 三维数据、SEM 高倍图像的结构化归档（MinIO 对象存储），支持标注、对比、版本管理 |
| **失效机理分类**     | 预置半导体失效模式：EM/HCI/NBTI/TDDB/EOS/ESD/焊点疲劳/键合失效/封装分层等               |
| **8D/FMEA/FTA 工具** | 内置 8D 报告模板、FMEA 分析表、FTA 故障树编辑器                                         |
| **案例沉淀**         | FA 完成后自动生成结构化案例（现象→路径→根因→纠正），推送至专家知识库                    |

#### 联邦式架构的关键约束

| 约束              | 说明                                                                                                               |
| ----------------- | ------------------------------------------------------------------------------------------------------------------ |
| **共享数据层**    | 所有模块共享同一 PostgreSQL 集群，Schema 按模块隔离（sample_schema / method_schema / ...），外键关联保证数据一致性 |
| **统一 API 网关** | 对外暴露统一的 LIMS API，内部路由到各服务模块；外部系统（EAM/TMS/IoT）只需对接一个入口                             |
| **事件驱动协同**  | 模块间通过事件总线（RabbitMQ）异步通信，如"样品到达"事件触发任务自动创建                                           |
| **独立部署**      | 每个模块可独立打包为 Docker 镜像，独立升级不影响其他模块（灰度发布）                                               |
| **事务边界**      | 跨模块操作使用 Saga 模式保证最终一致性，单模块内使用本地事务                                                       |

#### 关键技术选型

| 技术领域   | 推荐方案                               | 理由                                         |
| ---------- | -------------------------------------- | -------------------------------------------- |
| 后端框架   | Java (Spring Boot 3 + Spring Cloud)    | 微服务成熟生态，企业级稳定性                 |
| 服务通信   | gRPC（内部同步）+ RabbitMQ（异步事件） | 高性能 + 解耦                                |
| 工作流引擎 | Camunda 8                              | BPMN 2.0，支持复杂流程编排，含 FA 非线性流程 |
| 报告引擎   | Aspose（离线版）+ 自研模板引擎         | 复杂报告排版，内网无需 License 联网验证      |
| 数据校验   | Drools 规则引擎                        | 可配置规则，非开发人员可维护                 |
| 图像存储   | MinIO（S3 兼容对象存储）               | FA 高分辨率图像 TB 级存储需求                |
| 数据库     | PostgreSQL 15+ (Schema 隔离)           | 单库多 Schema，保持外键完整性                |

#### AI 落地场景

| 场景                 | 技术                    | 具体应用                                                              |
| -------------------- | ----------------------- | --------------------------------------------------------------------- |
| **检测方案智能推荐** | RAG + LLM               | 根据样品类型、客户要求、历史数据，自动推荐检测项目组合和方法标准      |
| **数据异常智能判定** | 统计过程控制 + 异常检测 | 自动识别离群值，区分"真异常"与"测量波动"，给出判定建议                |
| **报告自动生成**     | LLM + 模板引擎          | 根据检测数据自动撰写结论段落，生成初稿报告（人工审核修改）            |
| **标准合规检查**     | NLP + 知识图谱          | 自动比对检测方法与最新标准版本，提醒变更影响                          |
| **预测性质量控制**   | 时序预测                | 分析质控数据趋势，在 OOC 发生前 3-5 个批次预警                        |
| **FA 智能辅助**      | 多模态 AI (VLM)         | 输入失效照片+现象描述，匹配历史相似案例，推荐分析路径和可能的失效机理 |

| 模块            | 功能说明                                                            |

#### CFR 21 Part 11 合规（面向国际客户）

| 要求             | 实现方式                                                  |
| ---------------- | --------------------------------------------------------- |
| **唯一用户标识** | IAM 统一管理，禁止共享账号，离职账号即时禁用              |

| **记录保护**     | 电子记录防篡改（哈希校验），版本控制，原始数据不可覆盖    |
| **系统验证**     | 系统上线前的 IQ/OQ/PQ 验证文档，变更控制流程              |

### 2.8 实验室专家知识库系统

**定位**：将实验室隐性专家经验转化为可检索、可推理、可传承的知识资产。

#### 核心功能

| 模块         | 功能说明                                                                    |
| ------------ | --------------------------------------------------------------------------- |
| **知识采集** | 文档导入（标准/SOP/论文）、专家访谈录入、检测案例自动沉淀、失效分析报告归档 |
| **知识图谱** | 构建"元器件-失效模式-检测方法-标准条款"的关联图谱                           |
| **智能检索** | 语义搜索 + 关键词搜索混合模式，支持自然语言提问                             |
| **知识问答** | RAG 架构：用户提问→检索相关知识→LLM 生成精准回答（带引用来源）              |
| **案例库**   | 典型失效案例、疑难问题解决方案、最佳实践，支持相似案例推荐                  |
| **标准解读** | 检测标准条款的结构化解析、版本对比、影响评估                                |
| **知识审核** | 专家审核发布流程，确保知识准确性，支持纠错和更新                            |

#### 半导体失效分析专项知识体系

| 知识类别           | 示例                                                                                                     |
| ------------------ | -------------------------------------------------------------------------------------------------------- |
| **芯片级失效机理** | 电迁移(EM)、热载流子注入(HCI)、NBTI/PBTI、TDDB、软击穿、闩锁效应(Latch-up)的特征图谱、物理模型和判定依据 |
| **封装级失效模式** | 焊点疲劳、键合丝断裂(Wire Bond Failure)、封装分层(Delamination)、爆米花效应(Popcorn)、导电银胶开裂       |
| **EOS/ESD 损伤**   | 氧化层击穿特征、金属熔融特征、CDM/HBM/MM 损伤模式区分                                                    |
| **可靠性加速模型** | Arrhenius 模型、Coffin-Manson 模型、Eyring 模型、Black 方程的适用场景和参数推导                          |

### 2.11 测试数据与良率分析系统 (TDM/YMS)

**定位**：处理半导体测试海量原始数据的专业分析平台，LIMS 管流程，TDM 管数据深度分析。

#### 为什么 LIMS 无法替代 TDM

| 维度     | LIMS                    | TDM/YMS                                                      |
| -------- | ----------------------- | ------------------------------------------------------------ |
| 数据粒度 | 样品/批次级别的检测结果 | Die 级别的每个测试参数原始值（百万级数据点/批次）            |
| 数据格式 | 结构化表单              | STDF（Standard Test Data Format）、WAT、EWS 等半导体专用格式 |
| 分析维度 | 合格/不合格判定         | 参数分布、CPK、Wafer Map 空间分析、多批次趋势、相关性分析    |
| 数据量   | GB 级                   | TB 级（单台 ATE 日产数 GB 原始数据）                         |

#### 核心功能

| 模块                 | 功能说明                                                                                    |
| -------------------- | ------------------------------------------------------------------------------------------- |
| **STDF 解析引擎**    | 高性能解析 STDF V4/V4-2007 格式文件，支持主流 ATE 平台（Teradyne/Advantest/Cohu）的数据变体 |
| **Wafer Map 可视化** | Die 级别的晶圆图渲染，支持多参数叠加、缺陷聚类标注、Zone 分区统计                           |
| **参数统计分析**     | CPK/PPK 能力指数、直方图、箱线图、散点图、正态检验、参数相关性矩阵                          |
| **Bin 分析**         | 测试 Bin 分布统计、Bin Pareto 图、Soft Bin → Hard Bin 映射分析                              |
| **多批次趋势**       | 同型号跨批次的良率趋势、参数漂移追踪、SPC 控制图（X-bar/R/S）                               |
| **异常检测 (PAT)**   | Part Average Testing：Die 级别的统计异常检测，识别离群值（潜在早期失效）                    |
| **边缘应力分析**     | Guardband 分析、Margin Test 数据的参数余量评估，识别边缘 Die                                |
| **报表导出**         | 自动生成良率报告、CPK 报告、客户定制格式报告                                                |

#### 关键技术选型

| 技术领域  | 推荐方案                                 | 理由                                    |
| --------- | ---------------------------------------- | --------------------------------------- |
| STDF 解析 | 自研 Rust/C++ 解析器 + Python 分析层     | STDF 解析性能要求高（单文件可达 GB 级） |
| 数据存储  | ClickHouse / Apache Doris                | 列式存储，支持 TB 级数据毫秒级查询      |
| 可视化    | ECharts / D3.js + 自研 Wafer Map 组件    | Wafer Map 是高度定制化的可视化需求      |
| 分析引擎  | Python (NumPy/SciPy/Pandas) + 分布式计算 | 统计分析成熟生态                        |

#### AI 落地场景

| 场景               | 技术                  | 具体应用                                                                       |
| ------------------ | --------------------- | ------------------------------------------------------------------------------ |
| **良率预测**       | 时序预测 + 特征工程   | 基于前几个批次的测试参数分布预测后续批次良率，提前预警良率下滑                 |
| **根因定位**       | 多变量分析 + 因果推理 | 良率异常时自动关联 Wafer Map 空间模式、设备参数、环境数据，定位可能的根因      |
| **PAT 自适应阈值** | 无监督异常检测        | 动态计算 PAT 统计限值，替代静态限值，降低过杀（Overkill）率                    |
| **测试项优化**     | 特征选择 + 相关性分析 | 识别冗余测试项、推荐最小测试集，在不牺牲覆盖率的前提下缩短测试时间             |
| **缺陷模式识别**   | CNN 图像识别          | Wafer Map 缺陷模式自动分类（Edge/Center/Random/Scratch/Zone 等），关联工艺问题 |

### 2.13 质量管理系统 (QMS)

**定位**：覆盖 CNAS 认可体系全要素的质量管理平台，是 LIMS 的质量管控上层系统。

#### 为什么 QMS 不能由 LIMS 替代

LIMS 聚焦"样品→检测→报告"的技术流程，QMS 覆盖更广的管理体系要素：

```
QMS 覆盖范围（CNAS-CL01 全要素）
├── 管理要求（LIMS 不涉及）
│   ├── 管理评审、方针目标
│   ├── 内部审核计划与执行
│   ├── 纠正措施 / 预防措施 (CAPA)
│   ├── 投诉处理
│   └── 持续改进
├── 技术要求（与 LIMS 协同）
│   ├── 人员资质与能力确认 ← QMS 管理，LIMS 使用
│   ├── 设备与环境 ← 资产管理系统管理，QMS 监控
│   ├── 方法验证与确认 ← QMS 发起，LIMS 执行
│   └── 测量不确定度 ← QMS 评定方法，LIMS 计算
└── 文件控制（与 DMS 协同）
    ├── 体系文件版本管理
    └── 记录控制
```

#### 核心功能

| 模块             | 功能说明                                                        |
| ---------------- | --------------------------------------------------------------- |
| **体系文件管理** | 质量手册、程序文件、作业指导书的版本控制、审批发布、受控分发    |
| **内审管理**     | 年度内审计划、审核检查表、不符合项记录、整改跟踪、关闭验证      |
| **管理评审**     | 评审输入数据自动汇总（来自 LIMS/资产/培训等系统）、评审报告模板 |
| **CAPA 管理**    | 不符合→根因分析→纠正措施→效果验证 的闭环流程，支持 5Why/鱼骨图  |
| **风险管理**     | 风险识别→评估→应对→监控，风险矩阵可视化                         |
| **供应商评价**   | 关键供应商/分包方的评价、准入、定期复评                         |
| **客户投诉**     | 投诉受理→调查→处理→回复→归档的标准流程                          |
| **能力验证**     | 能力验证 / 实验室间比对的计划、参与、结果分析                   |

#### AI 落地场景

### 2.18 IT 运维监控平台

**定位**：保障所有子系统 7×24 稳定运行的技术底座，零基础建设必须同步上线。

#### 为什么零基础必须同步建设

17 个子系统同时依赖 IT 基础设施，没有运维监控等于"盲人开车"：

- 服务器宕机无人知晓 → 检测数据丢失
- 数据库满了无预警 → LIMS 全线瘫痪
- 网络故障排查无工具 → 恢复时间数倍延长

#### 核心功能

| 模块             | 功能说明                                                      |
| ---------------- | ------------------------------------------------------------- |
| **基础设施监控** | 服务器 CPU/内存/磁盘、网络交换机、存储阵列、UPS 电源          |
| **应用监控**     | 各子系统健康检查、接口响应时间、错误率、JVM/容器指标          |
| **数据库监控**   | 慢查询、连接池、主从同步延迟、表空间使用率                    |
| **GPU 集群监控** | GPU 利用率、显存、推理队列长度、模型服务状态（AI 私有化必备） |
| **日志中心**     | 全系统日志集中采集、检索、告警规则、异常日志自动标记          |
| **告警管理**     | 多级告警（邮件/短信/企微/钉钉）、告警抑制、值班排班、故障升级 |
| **自动化运维**   | 常见故障自愈（服务重启、磁盘清理）、批量操作、配置管理        |
| **备份管理**     | 自动备份策略、备份验证、恢复演练记录                          |
| **CMDB**         | 所有 IT 资产（服务器/网络设备/软件许可）的配置管理数据库      |

#### 关键技术选型

| 技术领域 | 推荐方案                                      |
| -------- | --------------------------------------------- |
| 监控     | Prometheus + Grafana + Alertmanager           |
| 日志     | ELK Stack (Elasticsearch + Logstash + Kibana) |
| 链路追踪 | SkyWalking / Jaeger                           |
| 自动化   | Ansible（批量操作）+ 自研运维脚本             |
| CMDB     | NetBox（开源）/ 自建                          |

#### AI 落地场景

| 场景             | 具体应用                                                    |
| ---------------- | ----------------------------------------------------------- |
| **智能告警降噪** | AI 关联分析告警风暴，合并同源告警，识别根因告警 vs 衍生告警 |
| **故障预测**     | 磁盘 SMART 数据 + 系统日志分析，提前预测硬件故障            |
| **容量规划**     | 基于历史趋势预测存储/算力增长需求，提前扩容规划             |
| **日志异常检测** | 无监督学习识别日志中的异常模式，发现潜在问题                |

### 3.4 数据安全红线

| 规则               | 说明                                                         |
| ------------------ | ------------------------------------------------------------ |
| **数据绝对不出域** | 所有 AI 模型内网私有化部署，禁止任何形式的外网数据传输       |
| **最小权限**       | AI 服务按角色授权，仅可访问业务必需数据                      |
| **脱敏处理**       | 模型训练/微调数据需经脱敏处理（客户信息）                    |
| **审计追溯**       | AI 推理请求全程留痕（输入/输出/模型版本/耗时），支持事后审计 |
| **人工复核**       | AI 生成的检测结论/报告必须经过人工审核确认，AI 不做最终判定  |
| **模型安全**       | 模型权重文件加密存储，仅推理进程可访问；禁止模型文件外传     |
| **离线更新**       | 模型更新通过安全审查后，以离线介质导入；禁止在线拉取         |

## 五、基础设施与安全合规

### 5.1 基础设施规划（纯内网私有云）

| 层面         | 方案                                           | 内网适配说明                        |
| ------------ | ---------------------------------------------- | ----------------------------------- |
| **部署架构** | 纯私有云（VMware vSphere / OpenStack）         | 不依赖任何公网服务，内网 DNS/NTP/CA |
| **容器化**   | Kubernetes 集群（RKE2 / Kubeadm）              | 内网镜像仓库 Harbor，离线部署       |
| **数据库**   | PostgreSQL + TDengine + Neo4j + Milvus + Redis | 全部内网部署，主从 + 定期冷备       |
| **消息队列** | RabbitMQ / Kafka                               | 内网集群，不暴露外部端口            |
| **API 网关** | APISIX（国产开源）                             | 统一认证、限流、路由，对接 IAM      |
| **监控**     | Prometheus + Grafana + ELK + SkyWalking        | 内网运维监控全栈                    |
| **备份容灾** | 本地备份 + 异地磁带/离线介质                   | 关键数据 RPO < 1h，RTO < 4h         |
| **网络架构** | 三区两域（办公区/生产区/DMZ）                  | VLAN 隔离、防火墙策略、最小开放端口 |
| **软件更新** | 离线更新机制（U盘/内网分发）                   | 安全审查后导入，禁止直连外网        |

### 5.2 零基础建设优先级

由于零信息化基础，需按以下顺序搭建：

```

├── 内网基础服务（DNS / NTP / CA / Harbor / GitLab）
├── IAM 统一认证系统（所有子系统依赖）

```

### 5.3 安全合规要求

| 标准           | 要求                 | 落地措施                                                         |
| -------------- | -------------------- | ---------------------------------------------------------------- |
