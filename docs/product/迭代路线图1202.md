## AnyKeep 迭代路线图（2025-12-02）

**目标用户**：中文互联网重度用户、知识工作者  
**核心定位**：零整理、视觉优先、深度支持微信/B站/小红书  
**文档目的**：结合目标客户习惯，明确当前功能中「该深挖」与「可暂缓」的部分，并给出未来 4–6 周的详细迭代路线图。

---

## 一、功能优先级评估：哪些要深挖，哪些先放一放

### 1.1 值得继续「深挖」的功能（优先投入）

#### A. 首页「灵感墙」（卡片/瀑布流/来源感）

- **原因**：
  - 是用户每天打开看到的第一屏，决定是否愿意留下来。
  - 目标用户习惯「刷流」而不是「翻目录」，视觉舒适 + 信息一眼可扫。
- **建议深挖方向**：
  - 卡片信息密度与层级：封面 > 平台标识 > 标题 > 摘要 > 标签 > 时间/来源。
  - 瀑布流体验：多端列数适配、图片懒加载、虚拟滚动，确保大规模数据流畅。
  - 来源强化：平台色 + 图标 + 来源账号，帮助用户按「场景记忆」快速识别内容。

#### B. 一键收藏链路（浏览器扩展 + 手机系统分享）

- **原因**：
  - 收藏入口越顺滑，留存越高。目标用户厌恶「多一步确认/多一个表单」。
- **建议深挖方向**：
  - 浏览器扩展：点击一次即收藏，默认不弹复杂表单，只给轻量反馈。
  - 移动端：从「系统分享 → AnyKeep」的路径要安装后立即可用。
  - 反馈设计：小动画 + 简短提示（标题 + 平台），强化愉悦感和信任感。

#### C. AI 自动分类 + AI 标签（零整理承诺的核心）

- **原因**：
  - 真正兑现「Don’t Organize. Just Keep.」的是自动分类，而不是摘要本身。
- **建议深挖方向**：
  - 自动分类 UI：用非阻塞 Toast/底部卡片提示「💡 觉得可以放到【XXX】」，一键同意/忽略。
  - 纠错体验：用户修改/拒绝推荐时，系统能「记住偏好」，逐步提高命中率。
  - 标签展示：控制在 3–5 个高价值标签，且语言自然干净，便于后续筛选。

#### D. 微信/B站/小红书 内容解析质量

- **原因**：
  - 这是 AnyKeep 与 Cubox 等稍后读、以及国外产品拉开差距的**护城河**。
- **建议深挖方向**：
  - 标题与封面统一清洗规则，避免出现乱码、重复来源名等问题。
  - 元数据（作者、发布时间、类型）在不同平台上的准确率和一致性。
  - 失败兜底：无法完美解析时，提供体面可用的默认卡片，避免「残废卡片」破坏观感。

#### E. 搜索 + 简单筛选体验（关键词为主，语义搜索渐进）

- **原因**：
  - 真实痛点是：「我记得之前看到过某个点，但忘了在哪。」
  - 关键词 + 平台/时间/标签的组合，能解决 80% 现实场景。
- **建议深挖方向**：
  - 搜索入口要在首页显眼（顶栏/底部 Tab）。
  - 筛选项聚焦在：平台、时间、标签，避免一上来塞大量高级条件。
  - 搜索结果卡片风格与首页统一，避免「跳到另一个产品」的割裂感。

#### F. 简单「收件箱」视图 + 轻量整理流

- **原因**：
  - 用户一边想「不要整理」，一边又会对完全堆积的收藏有轻微焦虑。
- **建议深挖方向**：
  - 提供「最近收藏 / 待整理」视图，与自动分类结合。
  - 强调「随手点两下就好」，而不是「你有 XX 条任务待处理」。

### 1.2 可以「暂缓深挖」的功能（先做到可用即可）

#### A. 高级文件夹系统（复杂层级 / 批量管理 UI）

- **原因**：
  - 真正沉迷复杂层级结构的是 Notion/Obsidian 深度用户，不是主要人群。
  - 复杂文件夹结构与「零整理」理念存在一定张力。
- **策略**：
  - 先保证：基本的创建/重命名/简单移动即可。
  - 高级特性（树形拖拽、颜色自定义、批量重排）放在后续版本。

#### B. 评分体系 & 复杂 Analytics 仪表盘

- **原因**：
  - 大多数用户不会认真给每条收藏打分，更多只是「囤着」。
  - 图表酷，但日常打开频率低，对首发体验影响有限。
- **策略**：
  - 保留一两块简单统计，如「总收藏数/按平台分布」。
  - 时序分析、行为漏斗、多维度报表后置。

#### C. 高级批量操作 & 自动化工作流

- **原因**：
  - 服务的是效率极客/重度用户，学习成本和实现成本都较高。
- **策略**：
  - 先支持多选删除、多选移动等最基础操作。
  - 规则引擎/自动归档/自动打标签，等用户规模与需求更明确后再做。

#### D. 面向维护/运营的高级工具 UI（reclassify/check 面板等）

- **原因**：
  - 价值更多在内部使用，对终端用户感知价值不高。
- **策略**：
  - 先有 API + 脚本，不急于为其设计完善的用户界面。

#### E. 深度个性化配置 & 高自由度主题系统

- **原因**：
  - 早期用户更在意「默认是否好看」，而不是「能否换十几套主题」。
- **策略**：
  - 先做浅色/深色/跟随系统三档。
  - 完整主题与自定义配色可作为未来 Pro 卖点。

#### F. 多终端 Native 打包细节（Capacitor 深挖）

- **原因**：
  - 首发阶段 Web/PWA + 浏览器扩展已足够验证核心价值。
  - APP 商店上架及原生体验打磨成本高，可后置。
- **策略**：
  - 优先保证移动端 PWA 像 App 一样好用，再渐进优化原生打包体验。

### 1.3 简化版优先级结论

- **P0（继续深挖）**：
  - 首页灵感墙（视觉 & 瀑布流）
  - 一键收藏链路（扩展 + 分享）
  - AI 自动分类 & 标签
  - 微信/B站/小红书解析质量
  - 搜索 + 筛选基础体验
  - 简单收件箱视图

- **P1（做到可用即可）**：
  - 文件夹基础管理
  - 简单统计视图
  - 多选 + 基础批量操作
  - 设置页（账号 + 主题 + 接入说明）

- **P2（暂缓深挖）**：
  - 复杂文件夹/标签管理
  - 高级 Analytics / 报表
  - 工作流/规则引擎
  - 高级主题/个性化
  - 完整 native App 打包体验

## 二、4–6 周详细迭代路线图

### 周目标总览

- **前 4 周**：打磨出「应用市场首发版可上线水准」。
- **后 2 周**：根据精力和进度，增强移动/PWA体验与数据闭环。

## 第 1 周：首页「灵感墙」与卡片基础体验

**核心目标**：用户一打开就觉得「好看、轻松」，愿意多刷几屏。

### 1. 首页结构收敛

- 保留：
  - 顶部：Logo + 搜索入口（图标）。
  - 单行平台筛选 Chip（全部/微信/B站/小红书/浏览器/其他）。
  - 瀑布流卡片区域。
- 暂不在首页露出：
  - 文件夹树、复杂分析模块、过多筛选栏。

### 2. 卡片设计落地（视觉 + 信息层级）

- 明确顺序：
  - 封面图（主视觉）。
  - 平台图标 + 色条（右上角）。
  - 标题（≤ 2 行）。
  - AI 摘要（1–2 行）。
  - 标签（≤ 3 个）。
  - 底部一行灰字：来源账号 + 收藏时间。
- 统一视觉规范（可在 Figma 中先固化）：
  - 间距、圆角、阴影、字体大小、行高、卡片宽度。

### 3. 瀑布流实现与性能优化

- 断点列数：
  - 手机：1 列。
  - 平板：2 列。
  - 桌面：3–4 列。
- 性能：
  - 图片懒加载。
  - 使用虚拟滚动（react-virtual/virtuoso 等）保证 10,000+ 条仍流畅。

### 4. 验收标准

- 首页信息仅与「刷收藏」直接相关，无明显「管理感」压力。
- 在 50+ 卡片场景下快速滚动，肉眼无明显卡顿。
- 平台识别度：用户 3 秒内能看出哪些是微信/B站/小红书。

---

## 第 2 周：一键收藏链路 & 微信/B站/小红书解析质量

**核心目标**：让目标用户「随手就能丢进来」，并保证卡片长得靠谱。

### 1. 浏览器扩展 MVP 打磨

- 行为：
  - 点击扩展图标 → 默认直接保存当前页面。
  - 成功后弹出轻量浮层：缩略封面 + 标题 + 平台 + 「已加入灵感墙」。
- 登录/认证：
  - 与 Web 登录态打通，失败时给出明确的重新登录指引。

### 2. 手机端系统分享链路检查

- Android/Chrome：
  - 路径：`分享 → AnyKeep` 是否顺滑可复现。
- 登录态：
  - 首次使用分享入口时的登录验证体验（避免循环跳转）。

### 3. 平台解析质量专项

- 微信：
  - 标题（去除冗余）、封面、公众号名称、发布时间。
- B站：
  - 标题、封面、UP 主、时长。
- 小红书：
  - 封面图、首行标题/内容片段、作者。
- 建议准备一批固定测试链接，形成解析质量回归用例。

### 4. 验收标准

- 从浏览器点击扩展到看到「已收藏」反馈 ≤ 3 秒。
- 至少在一台真实安卓手机上完成「系统分享 → AnyKeep → 成功保存」全链路。
- 解析质量：
  - 微信/B站/小红书各 10 条测试链接中，标题可读率 ≥ 95%，封面/作者/时间信息 ≥ 80% 正确。

## 第 3 周：AI 自动分类 & 标签体验

**核心目标**：让用户真实感受到「扔进去就完事了」。

### 1. AI 自动分类交互设计与实现

- 触发时机：
  - 收藏保存完成后短时间内触发，非阻塞地给出推荐。
- 展现形式：
  - 底部轻量提示卡/Toast：
    - 标题：`💡 觉得可以放这里`
    - 推荐项：`📁 前端开发（匹配 82%）`
    - 按钮：`同意` / `忽略` / `换一个…`
- 行为逻辑：
  - 同意 → 应用分类 + 记录用户行为，后续相似内容更偏向该文件夹。
  - 忽略 → 保留在收件箱，不再多打扰。

### 2. AI 标签优化

- 展示控制：
  - 标签数量在 3–5 个之间，过长/过专业的关键词做规则过滤。
- 风格：
  - 语言自然、人类可读，避免「纯技术关键词堆砌」。

### 3. 简单「收件箱」视图

- 入口形式：
  - 首页 Tab（如：`全部 | 收件箱`），或首页顶部一个简单筛选开关。
- 判定逻辑：
  - 最近收藏 + 尚未被用户确认分类的内容归为「收件箱」。

### 4. 验收标准

- 连续收藏 10 条内容时，其中 ≥ 7 条给出的文件夹推荐是「看得过去」的。
- 自动推荐提示不会遮挡主要操作区域，且用户可一键忽略。
- 就算用户完全不做分类操作，也能在「全部」视图无障碍浏览。

## 第 4 周：搜索 & 筛选体验 + 基础「我/设置」页

**核心目标**：让用户能轻松找回东西，并搭好产品的基础「外壳」。

### 1. 搜索页梳理

- 顶部搜索框：
  - 对标题 + 摘要 + 标签 + 描述做全文搜索。
- 快捷筛选：
  - 平台：微信 / B站 / 小红书 / 浏览器。
  - 时间：今天 / 本周 / 本月。
- 搜索历史：
  - 展示最近 5 条搜索记录，点击可以快速复用。

### 2. 搜索结果列表

- 使用简版卡片：
  - 小缩略图 + 标题 + 平台 + 时间 + 一行摘要。
- 点击卡片 → 跳转收藏详情页。

### 3. 「我 / 设置」基础页

- 模块建议：
  - 头像 + 昵称（可用手机号尾号） + 简单统计（已收藏 N 条）。
  - 主题切换：浅色 / 深色 / 跟随系统。
  - 「扩展 & 分享接入指南」：用图文解释如何安装浏览器扩展、如何从手机分享。
  - 基础条目：账号与安全、数据导出说明（可先做成预告）、帮助与反馈、关于。

### 4. 验收标准

- 搜索结果对开发者本人使用来说「至少不离谱」：常用关键词可以找到期望内容。
- 联合平台/时间筛选时，结果响应及时，数量合理。
- 新用户可以通过「扩展 & 分享接入指南」独立完成配置，无需额外口头指导。

> 完成前 4 周后：应具备一个可用于邀请种子用户/小范围灰度的「首发版」。

## 第 5 周（可选）：PWA/移动体验 & 初次引导打磨

**核心目标**：降低日常使用摩擦，让它更像「一个顺手的 App」。

### 1. PWA 体验专项

- 安装：
  - 图标、名称、启动画面（Splash）体验。
- 启动：
  - 冷启动时的 Skeleton/loading 状态设计。
- 离线兜底：
  - 网络错误时的提示文案与重试按钮。

### 2. 移动端交互细节

- 手势：
  - 支持 Android 常见返回手势，避免与左右滑动冲突。
- 点击区域：
  - 卡片和按钮点击目标在小屏幕上足够大，降低误触。
- 浮动按钮：
  - 检查在不同机型上的位置与遮挡情况。

### 3. 初次引导（Onboarding）精简

- 建议不超过 2–3 屏：
  1. 这是一面「微信/B站/小红书 + 浏览器书签」的灵感墙。
  2. 展示「从微信/B站/浏览器一键保存」的示意图。
  3. 强调「不用整理，AI 帮你自动放好」。
- 引导结束后直接进入真实首页，而不是复杂多步骤设置。

### 4. 验收标准

- 在主流手机上，PWA 启动和切换体验接近原生 App。
- 新用户在 1 分钟内完成：登录 → 从微信或浏览器收藏第一条内容。

## 第 6 周（可选）：数据闭环与精细化打磨

**核心目标**：用数据来验证设计假设，准备 v1.1+ 的方向。

### 1. 埋点与事件定义

- 建议至少覆盖：
  - 首次启动、完成登录。
  - 完成首次收藏（区分：浏览器扩展 / 手机分享 / Web 内创建）。
  - 首页浏览深度（滚动行为、卡片曝光数）。
  - 搜索使用次数、平台筛选使用比例。
  - AI 分类推荐被接受/忽略的次数和比例。

### 2. 数据驱动的首轮优化

- 根据数据回答：
  - 哪个入口是主要收藏来源？（扩展 vs 手机分享 vs Web 内）
  - 搜索是否被经常使用？入口是否太隐蔽？
  - AI 分类被拒绝率是否过高？是否需要调整策略/文案？

### 3. Bug & 体验问题清单

- 汇总：
  - 前几周开发中的已知问题。
  - 种子用户反馈的高频问题（特别是：崩溃、白屏、严重卡顿、解析错误）。
- 优先修复 TOP 10 高影响问题。

### 4. 验收标准

- 至少有 10–20 个真实用户完整体验过「收藏 → 浏览 → 搜索」主链路。
- 能用数据回答：
  - 收藏来源分布。
  - 搜索与筛选的实际使用情况。
  - AI 分类推荐的接受率大致区间。

---

## 三、一句话总结

- **策略**：集中火力打磨「首页灵感墙 + 一键收藏链路 + AI 自动分类」，把「零整理的中文收藏墙」这条主线做到极致；
- **节奏**：4 周内打造可上线首发版，之后再用 2 周补 PWA 体验与数据闭环；
- **取舍**：复杂目录/报表/工作流/重度主题等高级功能，先做到可用或直接延期，为最核心体验让路。
