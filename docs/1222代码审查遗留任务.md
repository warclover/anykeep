## 遗留任务

### W2: 异步错误处理增强

**优先级**: ⚠️ Warning
**工作量**: 大（119 个异步函数）
**当前覆盖率**: 5.8%（119 个异步函数仅 7 处 .catch()）

**问题描述**:

- `src/lib/classification/` 模块有 119+ 个异步函数
- 大部分缺少错误捕获，可能导致未捕获的 Promise rejection
- 生产环境可能出现静默失败

**建议方案**:

1. 逐模块优化，每次 PR 处理 1-2 个文件
2. 优先处理关键路径：
   - `integration.ts` - 核心分类入口
   - `smart-sorting.service.ts` - 智能分拣
   - `folder-health.service.ts` - 文件夹健康
3. 使用统一的错误处理模式：
   ```typescript
   try {
     // 业务逻辑
   } catch (error) {
     logger.error({ error, context }, "Operation failed");
     throw error; // 或返回错误结果
   }
   ```

**涉及文件**:

- `src/lib/classification/services/*.ts`
- `src/lib/classification/learning/*.ts`
- `src/lib/classification/router/*.ts`

---

### W3: integration.ts 拆分

**优先级**: ⚠️ Warning
**工作量**: 中（860 行）
**风险**: 需谨慎评估依赖关系

**问题描述**:

- `src/lib/classification/integration.ts` 单文件 860+ 行
- 职责过多，违反单一职责原则
- 难以测试和维护

**建议拆分方案**:

```
integration.ts (860 行)
  ↓ 拆分为
├── classification-executor.ts    # 分类执行逻辑
├── confirmation-handler.ts       # 确认/取消处理
├── profile-updater-integration.ts # 画像更新集成
└── integration-facade.ts         # 对外统一入口（保持兼容）
```

**拆分步骤**:

1. 分析现有导出和依赖
2. 识别内聚的功能模块
3. 逐步提取到独立文件
4. 保持 `integration.ts` 作为 facade 层确保兼容
5. 添加单元测试

**注意事项**:

- 确保 API 兼容性
- 循环依赖检查
- 导出路径不变
