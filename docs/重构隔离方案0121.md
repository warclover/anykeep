## 三、推荐方案：新建 Supabase 项目（方案 A）

### 3.1 架构设计

```
┌─────────────────────────────────────────────────────────────────────┐
│                        隔离后的架构                                   │
├──────────────────────────────┬──────────────────────────────────────┤
│       主分支 (main)           │       重构分支 (phoenix)              │
├──────────────────────────────┼──────────────────────────────────────┤
│  Git: main                   │  Git: phoenix-refactor               │
│  ↓                           │  ↓                                   │
│  .env.local                  │  .env.phoenix.local                  │
│  ↓                           │  ↓                                   │
│  Supabase 项目: anykeep      │  Supabase 项目: anykeep-phoenix      │
│  (原数据库，完整保留)          │  (新数据库，独立运行)                  │
│                              │                                      │
│  URL: xxx.supabase.co        │  URL: yyy.supabase.co                │
│  数据: 生产数据               │  数据: 迁移后的空库/测试数据           │
└──────────────────────────────┴──────────────────────────────────────┘
```

### 3.2 执行步骤

#### Step 1: 创建新 Supabase ���目（5 分钟）

1. 登录 [Supabase Dashboard](https://supabase.com/dashboard)
2. 点击 **New Project**
3. 填写信息：
   - **Name**: `anykeep-phoenix`
   - **Database Password**: 生成强密码并保存
   - **Region**: 选择与原项目相同的区域
4. 等待项目创建完成（约 2 分钟）

#### Step 2: 获取新项目凭据

在新项目的 **Settings → API** 中获取：

```bash
# 新项目的环境变量
NEXT_PUBLIC_SUPABASE_URL=https://xxxxxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOiJI...
SUPABASE_SERVICE_ROLE_KEY=eyJhbGciOiJI...
```

#### Step 3: 创建重构分支

```bash
# 确保当前在 main 分支且代码是最新的
git checkout main
git pull origin main

# 创建重构分支
git checkout -b phoenix-refactor

# 推送到远程
git push -u origin phoenix-refactor
```

#### Step 4: 创建重构专用环境文件

```bash
# 复制现有环境文件作为模板
cp .env.local .env.phoenix.local
```

编辑 `.env.phoenix.local`，替换为新项目的凭据：

```bash
# .env.phoenix.local - 重构分支专用

# ========== 新 Supabase 项目 ==========
NEXT_PUBLIC_SUPABASE_URL=https://[新项目ID].supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=[新项目的 anon key]
SUPABASE_SERVICE_ROLE_KEY=[新项目的 service role key]

# ========== 其他配置保持不变 ==========
# AI Keys 等可��复用
DEEPSEEK_API_KEY=...
OPENAI_API_KEY=...
```

#### Step 5: 配置 npm scripts（可选但推荐）

在 `package.json` 中添加重构专用命令：

```json
{
  "scripts": {
    "dev": "next dev",
    "dev:phoenix": "cp .env.phoenix.local .env.local && next dev",
    "supabase:push:phoenix": "cp .env.phoenix.local .env.local && supabase db push"
  }
}
```

#### Step 6: 初始化新数据库

```bash
# 切换到重构分支
git checkout phoenix-refactor

# 链接到新 Supabase 项目
supabase link --project-ref [新项目ID]

# 推送所有迁移到新数据库
supabase db push
```

#### Step 7: （可选）导入测试数据

如果需要测试数据，可以从原数据库导出部分数据：

```bash
# 从原数据库导出（不含用户敏感数据）
pg_dump -h db.[原项目ID].supabase.co -U postgres -d postgres \
  --data-only \
  --table=public.folders \
  --table=public.bookmarks \
  > test_data.sql

# 导入到新数据库
psql -h db.[新项目ID].supabase.co -U postgres -d postgres < test_data.sql
```

## 四、日常开发工作流

### 4.1 切换到重构分支开发

```bash
# 1. 切换分支
git checkout phoenix-refactor

# 2. 使用重构环境启动（方式一：手动复制）
cp .env.phoenix.local .env.local
npm run dev

# 或（方式二：使用 npm script）
npm run dev:phoenix
```

### 4.2 切换回主分支

```bash
# 1. 恢复原环境文件
git checkout main
git checkout -- .env.local  # 恢复原环境变量

# 2. 启动开发
npm run dev
```

### 4.3 安全检查清单

每次执行数据库操作前，确认：

```bash
# 检查当前分支
git branch --show-current
# 期望输出: phoenix-refactor（如果在重构）或 main（如果在主分支）

# 检查当前连接的数据库
grep "SUPABASE_URL" .env.local
# 确认 URL 与预期一致
```

## 五、重构完成后的合并策略

### 5.1 代码合并

当重构验证通过后：

```bash
# 1. 确保重构分支是最新的
git checkout phoenix-refactor
git pull origin phoenix-refactor

# 2. 合并到 main
git checkout main
git merge phoenix-refactor

# 3. 解决冲突（如有）
# 4. 推送
git push origin main
```

### 5.2 数据库迁移合并

**⚠️ 关键步骤**：重构分支可能删除了很多表/字段，需要谨慎处理

**策略 A：全新部署（推荐用于 MVP 阶段）**

```bash
# 直接将重构后的迁移推送到原数据库
supabase link --project-ref [原项目ID]
supabase db push
```

**策略 B：增量迁移（生产环境有用户数据时）**

1. 导出原数据库的用户数据
2. 应用重构后的 Schema
3. ���换并导入数据

### 5.3 清理

重构完成并验证后：

```bash
# 删除重构分支
git branch -d phoenix-refactor
git push origin --delete phoenix-refactor

# 可选：删除或保留 anykeep-phoenix 项目
# 建议保留一段时间作为备份
```

```bash

# 本地环境变量（自动生成）
# API URL: http://127.0.0.1:54321
```

**优点**：完全离线，无需网络
**缺点**：需要 Docker，资源占用较大
