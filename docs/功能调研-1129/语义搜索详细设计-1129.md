## 1. 设计目标与定位

### 1.1 核心目标

AnyKeep 的语义搜索不是简单的「向量相似度检索」，而是围绕 **「个人知识管理 + 学习闭环」** 场景，提供更智能、更贴合用户意图的搜索体验。

**差异化定位**：

- 不只是「找到相似内容」，而是「找到对用户当前学习/工作最有价值的内容」
- 结合评级、平台、学习状态等多维度信号，让搜索结果更「有用」
- 支持长期学习场景：语义查询可保存为「智能集合」，动态更新

### 1.2 用户价值

1. **自然语言搜索**：用户可以用「如何用 Obsidian 做知识管理」这样的自然语言，而不是必须记住精确关键词
2. **跨平台内容发现**：即使内容来自不同平台（微信/B站/小红书/浏览器），也能通过语义关联找到
3. **学习价值优先**：高评级（L2/L3）内容在语义搜索结果中优先展示，帮助用户聚焦真正重要的知识
4. **长期主题追踪**：将语义查询保存为「智能集合」，自动追踪某个主题下的所有相关内容

## 2. 技术架构设计

### 2.1 向量生成与存储

#### 2.1.1 文本来源与拼接策略

**为每条收藏生成 embedding 的文本来源**：

```typescript
// 优先级顺序（从高到低）
const embeddingText = [
  bookmark.title, // 标题（最重要）
  bookmark.ai_summary || "", // AI 摘要（如果有）
  bookmark.description || "", // 原始描述
  bookmark.user_tags?.join(" ") || "", // 用户标签
  bookmark.ai_tags?.join(" ") || "", // AI 标签
  bookmark.notes || "", // 用户笔记（如果有）
]
  .filter(Boolean)
  .join("\n\n");
```

**为什么这样拼接**：

- 标题权重最高（用户最常用来识别内容）
- AI 摘要包含核心信息，比原始描述更结构化
- 标签和笔记提供额外语义信号
- 用 `\n\n` 分隔，让模型理解这是不同段落

#### 2.1.2 向量生成服务

**技术选型**：

- **主模型**：OpenAI `text-embedding-3-small`（1536 维，成本低、质量好）
- **备选模型**：DeepSeek Embedding（如果 OpenAI 不可用）
- **存储**：PostgreSQL + pgvector 扩展（已在 Supabase 中配置）

**实现位置**：

- `src/lib/utils/embedding-generator.ts`（已有基础代码，需要完善）

**生成时机**：

1. **新建收藏时**（异步）：
   - 创建收藏成功后，后台任务生成 embedding
   - 失败不影响主流程，可后续重试
2. **批量补全**（一次性任务）：
   - 为现有收藏批量生成 embedding
   - 使用队列控制并发，避免 API 限流

#### 2.1.3 数据库字段设计

```sql
-- bookmarks 表已有字段（确认）
embedding vector(1536),              -- 向量嵌入
-- 需要新增字段

embedding_model VARCHAR(50),         -- 使用的模型（'openai' / 'deepseek'）
embedding_failed_count INT DEFAULT 0, -- 失败次数（用于重试策略）
```

### 2.2 语义搜索核心算法

#### 2.2.1 基础向量搜索

**PostgreSQL 函数**（在 Supabase 中创建）：

```sql
CREATE OR REPLACE FUNCTION search_bookmarks_semantic(
  query_embedding vector(1536),
  user_id uuid,
  match_threshold float DEFAULT 0.7,
  match_count int DEFAULT 20,
  min_importance int DEFAULT 0  -- 最低评级（0=全部，2=仅高价值，3=仅深度学习）
) RETURNS TABLE (
  id bigint,
  title text,
  url text,
  platform varchar,
  importance smallint,
  similarity float,
  folder_id bigint,
  ai_summary text
) AS $$
BEGIN
  RETURN QUERY
  SELECT
    b.id,
    b.title,
    b.url,
    b.platform,
    b.importance,
    1 - (b.embedding <=> query_embedding) AS similarity,  -- 余弦相似度
    b.folder_id,
    b.ai_summary
  FROM public.bookmarks b
  WHERE
    b.user_id = search_bookmarks_semantic.user_id
    AND b.deleted_at IS NULL
    AND b.embedding IS NOT NULL
    AND b.importance >= search_bookmarks_semantic.min_importance
    AND (1 - (b.embedding <=> query_embedding)) >= match_threshold
  ORDER BY
    -- 综合排序：相似度 + 评级权重
    (1 - (b.embedding <=> query_embedding)) *
    CASE
      WHEN b.importance = 3 THEN 1.3  -- L3 深度学习内容加权
      WHEN b.importance = 2 THEN 1.15 -- L2 高价值内容加权
      ELSE 1.0
    END DESC
  LIMIT match_count;
END;
$$ LANGUAGE plpgsql;
```

**关键设计点**：

- 使用 `<=>` 操作符（pgvector 的余弦距离）
- 相似度阈值 `match_threshold` 可配置（默认 0.7，可调）
- **评级权重**：L3 内容相似度得分 × 1.3，L2 × 1.15，让高价值内容更容易出现在前面
- 支持按 `min_importance` 过滤（例如「只在高价值内容中搜索」）

#### 2.2.2 混合搜索（关键词 + 语义）

**策略**：先做关键词过滤，再做语义排序

```typescript
// 伪代码示意
async function hybridSearch(query: string, userId: string) {
  // 1. 关键词搜索（PostgreSQL 全文搜索）
  const keywordResults = await fulltextSearch(query, userId);
  const keywordIds = new Set(keywordResults.map((r) => r.id));

  // 2. 语义搜索
  const queryEmbedding = await generateEmbedding(query);
  const semanticResults = await searchBookmarksSemantic(queryEmbedding, userId);

  // 3. 合并与去重
  const combined = new Map();

  // 关键词结果：相似度 = 1.0（完全匹配）
  keywordResults.forEach((r) => {
    combined.set(r.id, { ...r, similarity: 1.0, source: "keyword" });
  });

  // 语义结果：如果不在关键词结果中，添加
  semanticResults.forEach((r) => {
    if (!combined.has(r.id)) {
      combined.set(r.id, { ...r, source: "semantic" });
    } else {
      // 如果关键词和语义都命中，提升权重
      const existing = combined.get(r.id);
      existing.similarity = Math.max(existing.similarity, r.similarity * 1.1);
      existing.source = "hybrid";
    }
  });

  // 4. 按综合得分排序
  return Array.from(combined.values())
    .sort((a, b) => b.similarity - a.similarity)
    .slice(0, 20);
}
```

**优势**：

- 精确关键词匹配的内容（如标题完全匹配）优先展示
- 语义相似但关键词不匹配的内容也能被发现
- 两者都命中的内容权重更高

## 3. 创新功能设计

### 3.1 学习价值优先排序

**功能描述**：
在语义搜索结果中，结合「评级（importance）」和「学习状态」进行智能排序。

**实现方式**：

```typescript
// 在 search_bookmarks_semantic 函数中已包含评级权重
// 前端可以进一步过滤/排序

interface SearchResult {
  id: number;
  title: string;
  similarity: number;
  importance: 0 | 1 | 2 | 3;
  last_accessed_at?: string; // 最近访问时间
  has_notes: boolean; // 是否有用户笔记
}

// 前端排序逻辑（可选）
function sortByLearningValue(results: SearchResult[]) {
  return results.sort((a, b) => {
    // 综合得分 = 相似度 × 重要性系数 × 学习状态系数
    const scoreA =
      a.similarity *
      (a.importance === 3 ? 1.3 : a.importance === 2 ? 1.15 : 1.0) *
      (a.has_notes ? 1.1 : 1.0); // 有笔记的内容略加权

    const scoreB =
      b.similarity *
      (b.importance === 3 ? 1.3 : b.importance === 2 ? 1.15 : 1.0) *
      (b.has_notes ? 1.1 : 1.0);

    return scoreB - scoreA;
  });
}
```

**UI 表现**：

- 在搜索结果卡片上，高评级（L2/L3）内容显示明显标记：
  - `🏆 高价值` / `📘 深度学习`
- 提供筛选选项：
  - 「仅显示高价值内容」（`min_importance >= 2`）
  - 「优先显示未复盘内容」（L3 且最近未访问）

### 3.2 学习意图识别（P2 功能）

**功能描述**：
根据用户查询，识别搜索意图（教程/定义/案例），并调整搜索策略。

**实现思路**（轻量版，不需要大模型）：

```typescript
// 简单的意图分类规则
function detectSearchIntent(
  query: string,
): "tutorial" | "definition" | "example" | "general" {
  const lowerQuery = query.toLowerCase();

  // 教程类关键词
  if (/\b(如何|怎么|怎样|教程|步骤|方法|指南)\b/.test(lowerQuery)) {
    return "tutorial";
  }

  // 定义类关键词
  if (/\b(什么是|定义|概念|含义|意思)\b/.test(lowerQuery)) {
    return "definition";
  }

  // 案例类关键词
  if (/\b(案例|例子|示例|参考|灵感|模板)\b/.test(lowerQuery)) {
    return "example";
  }

  return "general";
}

// 根据意图调整搜索参数
function adjustSearchByIntent(
  intent: string,
  baseParams: SearchParams,
): SearchParams {
  switch (intent) {
    case "tutorial":
      // 教程类：优先 B 站视频、长文公号
      return {
        ...baseParams,
        platform_weights: { BILIBILI: 1.2, WECHAT_OFFICIAL_ACCOUNT: 1.1 },
      };
    case "example":
      // 案例类：优先小红书、网页
      return {
        ...baseParams,
        platform_weights: { XIAOHONGSHU: 1.2, UNKNOWN: 1.1 },
      };
    default:
      return baseParams;
  }
}
```

**后续可扩展**（P3）：

- 使用小模型（如 DeepSeek）做更精确的意图分类
- 根据用户历史搜索行为，学习个性化偏好

### 3.3 语义智能集合（Smart Collections）

**功能描述**：
用户可以将一个语义查询「保存为智能集合」，系统自动追踪该主题下的所有相关内容。

**数据模型**：

```sql
CREATE TABLE smart_collections (
  id BIGSERIAL PRIMARY KEY,
  user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  name VARCHAR(200) NOT NULL,              -- 集合名称，如「AIGC 工作流」
  query_text TEXT NOT NULL,                -- 原始查询文本
  query_embedding vector(1536),            -- 查询的向量表示
  match_threshold FLOAT DEFAULT 0.7,       -- 匹配阈值
  min_importance INT DEFAULT 0,            -- 最低评级要求
  auto_update BOOLEAN DEFAULT TRUE,        -- 是否自动更新
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE smart_collection_items (
  collection_id BIGINT REFERENCES smart_collections(id) ON DELETE CASCADE,
  bookmark_id BIGINT REFERENCES bookmarks(id) ON DELETE CASCADE,
  added_at TIMESTAMP DEFAULT NOW(),
  PRIMARY KEY (collection_id, bookmark_id)
);
```

**工作流程**：

1. **创建智能集合**：
   - 用户在搜索结果页点击「保存为智能集合」
   - 系统记录查询文本和 embedding
   - 立即计算一次匹配结果，作为初始集合内容

2. **自动更新**（定时任务）：
   - 每天/每周扫描新收藏
   - 计算新收藏与集合 query_embedding 的相似度
   - 如果相似度 >= threshold，自动加入集合

3. **用户界面**：
   - 在侧边栏显示「智能集合」分组
   - 点击集合，展示所有匹配的收藏（按相似度排序）
   - 显示「最近新增 X 条」提示

**应用场景**：

- 「所有 Obsidian 相关学习资料」
- 「AIGC 工具和工作流」
- 「产品设计灵感库」

### 3.5 可解释的语义匹配

**功能描述**：
在搜索结果中，简单说明「为什么这条内容匹配你的查询」。

**实现方式**（轻量版）：

```typescript
// 分析匹配原因
function explainMatch(
  bookmark: Bookmark,
  query: string,
  similarity: number,
): string {
  const reasons: string[] = [];

  // 1. 标题匹配关键词
  const titleMatch = extractKeywords(query).filter((kw) =>
    bookmark.title.toLowerCase().includes(kw.toLowerCase()),
  );
  if (titleMatch.length > 0) {
    reasons.push(`标题包含「${titleMatch.join("、")}」`);
  }

  // 2. 标签匹配
  const tagMatch = extractKeywords(query).filter((kw) =>
    [...(bookmark.user_tags || []), ...(bookmark.ai_tags || [])].some((tag) =>
      tag.toLowerCase().includes(kw.toLowerCase()),
    ),
  );
  if (tagMatch.length > 0) {
    reasons.push(`标签匹配「${tagMatch.join("、")}」`);
  }

  // 3. 语义相似度
  if (similarity >= 0.8) {
    reasons.push("内容高度相关");
  } else if (similarity >= 0.7) {
    reasons.push("内容相关");
  }

  return reasons.join(" · ") || "语义匹配";
}
```

**UI 表现**：

- 在搜索结果卡片底部，显示一行小字：
  - `匹配原因：标题包含「Obsidian」· 标签匹配「知识管理」· 内容高度相关`
- 帮助用户理解「为什么 AI 认为这条相关」，增强信任

### 3.6 个性化搜索偏好（P3 功能）

**功能描述**：
根据用户历史行为，微调搜索排序（例如：用户更偏爱 B 站视频，或更偏爱技术类内容）。

**实现思路**（轻量版，不需要训练模型）：

```typescript
// 分析用户历史行为
interface UserSearchPreference {
  preferred_platforms: Record<Platform, number>; // 平台偏好得分
  preferred_content_types: Record<string, number>; // 内容类型偏好
  search_click_patterns: Record<string, number>; // 哪些搜索结果更常被点击
}

// 在搜索时应用偏好
function applyUserPreference(
  results: SearchResult[],
  preference: UserSearchPreference,
): SearchResult[] {
  return results
    .map((r) => ({
      ...r,
      // 根据用户偏好调整得分
      adjusted_score:
        r.similarity *
        (preference.preferred_platforms[r.platform] || 1.0) *
        (r.importance === 3 ? 1.3 : r.importance === 2 ? 1.15 : 1.0),
    }))
    .sort((a, b) => b.adjusted_score - a.adjusted_score);
}
```

**数据收集**：

- 记录用户点击的搜索结果（哪些被点开、哪些被设为高价值）
- 定期分析，生成轻量偏好模型
- 在搜索时应用（可选，用户可在设置中关闭）

## 7. 成本控制策略

### 7.1 Embedding 生成成本

**策略**：

- 新建收藏时异步生成（不阻塞主流程）
- 批量补全时使用队列控制并发（避免 API 限流）
- 失败重试机制（最多 3 次）

**成本估算**（OpenAI text-embedding-3-small）：

- 每 1M tokens ≈ $0.02
- 每条收藏平均 ~500 tokens（标题+摘要+标签）
- 1000 条收藏 ≈ $0.01（非常便宜）

### 7.2 搜索查询成本

**策略**：

- 查询 embedding 生成：每次搜索调用一次 API
- 缓存机制：相同查询文本的 embedding 可以缓存（Redis/内存）
- 用户配额限制：Free 用户每天语义搜索次数有限（如 10 次），Pro 用户更高额度

### 8.2 搜索 API 实现

**文件**：`src/app/api/search/semantic/route.ts`

```typescript
import { NextRequest, NextResponse } from "next/server";
import { createClient } from "@/lib/supabase/server";
import { generateEmbedding } from "@/lib/utils/embedding-generator";

export async function GET(request: NextRequest) {
  const searchParams = request.nextUrl.searchParams;
  const query = searchParams.get("q");
  const mode = searchParams.get("mode") || "hybrid";
  const minImportance = parseInt(searchParams.get("min_importance") || "0");

  if (!query) {
    return NextResponse.json({ error: "Query is required" }, { status: 400 });
  }

  const supabase = await createClient();
  const {
    data: { user },
  } = await supabase.auth.getUser();

  if (!user) {
    return NextResponse.json({ error: "Unauthorized" }, { status: 401 });
  }

  try {
    // 1. 生成查询向量
    const queryEmbedding = await generateEmbedding(query);

    // 2. 调用数据库函数
    const { data, error } = await supabase.rpc("search_bookmarks_semantic", {
      query_embedding: queryEmbedding,
      user_id: user.id,
      match_threshold: 0.7,
      match_count: 20,
      min_importance: minImportance,
    });

    if (error) throw error;

    // 3. 添加匹配原因（可解释性）
    const resultsWithReason = data.map((item: any) => ({
      ...item,
      match_reason: explainMatch(item, query, item.similarity),
    }));

    return NextResponse.json({
      success: true,
      data: {
        results: resultsWithReason,
        total: resultsWithReason.length,
        mode: "semantic",
        query_embedding_generated: true,
      },
    });
  } catch (error) {
    console.error("Semantic search error:", error);
    return NextResponse.json(
      {
        error: "Search failed",
        details: error instanceof Error ? error.message : "Unknown error",
      },
      { status: 500 },
    );
  }
}

function explainMatch(
  bookmark: any,
  query: string,
  similarity: number,
): string {
  const reasons: string[] = [];
  const queryKeywords = query.toLowerCase().split(/\s+/);

  // 标题匹配
  const titleMatch = queryKeywords.filter((kw) =>
    bookmark.title.toLowerCase().includes(kw),
  );
  if (titleMatch.length > 0) {
    reasons.push(`标题包含「${titleMatch.join("、")}」`);
  }

  // 相似度说明
  if (similarity >= 0.8) {
    reasons.push("内容高度相关");
  } else if (similarity >= 0.7) {
    reasons.push("内容相关");
  }

  return reasons.join(" · ") || "语义匹配";
}
```

   - 语义搜索不是万能的，某些精确查询仍需要关键词搜索
