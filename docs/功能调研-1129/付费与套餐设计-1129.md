## AnyKeep 付费与套餐设计（可配置版本）

**文档日期**：2025-11-29  
**文档版本**：V1.0

本设计文档基于当前 AnyKeep 功能与规划（语义搜索、智能分类、智能评级、失效检测、抖音模块等），给出一套 **Free / Pro** 套餐及付费机制方案。  
**重要前提**：所有与配额/限制相关的指标均需可配置，而非硬编码在代码中。

---

## 1. 套餐结构与定位

### 1.1 套餐层级

- **Free（免费版）**
  - 面向轻量个人用户，体验 AnyKeep 的核心理念与基础能力。
- **Pro（个人专业版）**
  - 面向中重度知识管理用户，解锁 AI 能力、自动化、跨平台高级导入、学习复盘等。

> 后续如需要 Team/Workspace 等团队版，可在本设计之上扩展。

### 1.2 定价建议（仅作参考，具体由商业策略决定）

- Free：永久免费。
- Pro：
  - 月付：¥18–25 / 月
  - 年付：¥168–228 / 年（约 2–2.5 折）

定价不在本设计硬编码，只在应用内文案展示时引用配置中心的价格字段。

## 2. 可配置付费参数设计

### 2.1 配置存储方案概览

所有与套餐相关的数值/开关，**统一存放在可编辑的配置源中**，建议两层结构：

1. **全局套餐配置表**（如 `billing_plans` 配置表，或 JSON 配置文件，或远程配置中心），字段示例：
   - `plan_id`：`free` / `pro`
   - `limits`：JSON（详见 2.2）
   - `features`：JSON（布尔开关类能力）
   - `pricing`：价格信息（货币、月/年价格）

2. **用户订阅状态表**（如 `user_subscriptions` 或存放在 `profiles` 中）：
   - `user_id`
   - `plan_id`（当前计划）
   - `status`：`active` / `canceled` / `expired`
   - `expires_at`

> 前端与后端均应从统一的配置接口获取套餐参数，而不是在代码各处写死数值。

### 2.2 典型可配置指标（Limits）

针对 Free/Pro 需要可调节的核心指标，可以设计如下结构（示例）：

```jsonc
{
  "plan_id": "pro",
  "limits": {
    "max_bookmarks": 20000,
    "max_folders": 1000,
    "max_tags_per_bookmark": 50,

    "ai_summary_monthly_quota": 1000,
    "ai_summary_daily_quota": 50,

    "semantic_search_daily_quota": 200,

    "batch_import_max_items_per_job": 5000,
    "batch_import_max_jobs_per_day": 10,

    "link_check_enabled": true,
    "link_check_max_bookmarks_per_run": 2000,
    "link_check_run_interval_days": 7,

    "douyin_enabled": true,

    "rating_enabled": true,
    "ai_rating_enabled": true,

    "mindmap_enabled": true,
  },
  "pricing": {
    "currency": "CNY",
    "monthly": 25,
    "yearly": 228,
  },
}
```

关键点：

- **所有数值（数量、次数、间隔等）都在 `limits` 中统一管理**。
- Free 版采用同样结构，只是数值更小/部分布尔开关为 false。

## 4. 权限与配额检查设计

### 4.1 服务端统一检查层

在后端实现一个统一的「套餐与配额」工具模块，例如：

```ts
interface PlanLimits {
  max_bookmarks: number;
  ai_summary_daily_quota: number;
  semantic_search_daily_quota: number;
  // ...
}

async function getUserPlanLimits(userId: string): Promise<PlanLimits> {
  // 1. 读取 user 的 plan_id（profiles 或 subscriptions 表）
  // 2. 从 billing_plans 表或配置服务中加载对应 plan 的 limits
}

async function assertWithinLimit(
  userId: string,
  action: "create_bookmark" | "ai_summary" | "semantic_search",
) {
  const limits = await getUserPlanLimits(userId);
  // 根据 action 类型与当前使用统计做校验
}
```

所有关键 API（如创建收藏、调用 AI、语义搜索、批量导入、失效检测）在进入业务逻辑前统一调用 `assertWithinLimit`：

- 若超过限制：
  - 返回标准化错误响应（如 402 或业务错误码），附带当前套餐信息与升级提示文案 Key。

### 4.2 使用统计存储

对于「次数/额度」型限制，需要记录使用量：

- 建议单独一张表，如 `usage_counters`：

```sql
CREATE TABLE usage_counters (
  user_id UUID NOT NULL,
  period_start DATE NOT NULL,
  metric VARCHAR(50) NOT NULL,
  value BIGINT NOT NULL DEFAULT 0,
  PRIMARY KEY (user_id, period_start, metric)
);
```

示例：

- `metric = 'ai_summary_daily'`，`period_start = 2025-11-29`。
- `metric = 'semantic_search_daily'`，`period_start` 同上。

服务端在执行成功后递增对应 `metric`，在校验时与 `limits` 中的配额比对。

> 也可以将部分统计放入缓存（如 Redis），定期回写数据库，视基础设施而定。

## 5. 付费流程与 UI 设计要点

### 5.1 升级入口与付费墙触发

**统一入口：**

- 顶部头像下拉菜单：`升级到 Pro`。
- 侧边栏底部固定按钮：`升级 Pro`。

**功能内触发：**

- 当用户触发受限行为时（超过配额或尝试使用 Pro 功能）：
  - API 返回「超限/无权限」，前端根据错误码弹出统一的升级弹窗。
  - 弹窗内容包括：
    - 当前操作对应的限制说明（如「语义搜索为 Pro 专属功能」）
    - Free vs Pro 对比表（简版）
    - 升级按钮（跳转支付页或拉起支付组件）

### 5.2 套餐对比页（/pricing 或升级弹窗）

展示内容：

- 主要功能对比表（按模块分组：收藏、搜索、AI、导入导出、自动化等）。
- 各套餐价格（从配置中读取）。
- 支付周期切换（按月/按年）。

前端从配置接口读取当前生效的套餐参数，便于后期调价无需改代码。

## 6. 降级与过期策略

### 6.1 订阅过期逻辑

当 `subscription_expires_at < now()` 或支付平台通知取消时：

- 将 `plan` 降级为 `free`，或将 `subscription_status` 标注为 `expired`。
- 不立即删除任何数据。

**超配数据处理建议：**

- 保留所有已有收藏 / 文件夹 / 标签 / AI 数据。
- 对超出免费配额的部分：
  - 允许「查看」但限制「新增」和「部分高级操作」。
  - 示例：收藏数已 1,200（免费上限 500），可以看旧的，但不能再创建新收藏，除非删到 500 以下或升级。

### 6.2 用户体验文案

- 明确告知：
  - 升级前后的权益变化；
  - 降级后不会立刻删除数据，只是新增/高级功能受限。

## 7. 与现有与规划功能的绑定清单

> 以下功能在实现时，应统一通过套餐配置与权限模块控制。

- **收藏数限制**：创建收藏 API。
- **AI 摘要/标签**：AI 调用 API/Edge Functions。
- **语义搜索/混合搜索**：搜索 API。
- **智能评级建议**：智能评级 API 调用控制（仅 Pro）。
- **浏览器书签批量导入**：批量导入 API 限制条数/次数。
- **抖音模块**：抖音收藏相关 API 仅 Pro 生效。
- **失效检测视图与设置**：失效收藏列表 API + 设置页中开关仅 Pro 可用。
- **学习/复盘视图**：相关页面/接口仅 Pro 可用。
- **思维导图/关系视图**：图谱视图接口与页面仅 Pro 可用。

## 8. 开发落地步骤建议

1. **后端**：
   - 建立 `billing_plans` 配置（可先用 JSON 配置/常量，后续迁移到 DB）。
   - 在用户 Profile 中增加 `plan_id` / `subscription_status` 等字段。
   - 实现统一的 `getUserPlanLimits` 与 `assertWithinLimit` 工具。
   - 为关键 API 加上限制校验。

2. **前端**：
   - 增加「当前套餐信息」的全局 Context 或 Hook，从后端获取。
   - 实现统一的「升级 Pro」弹窗与 `pricing` 对比页。
   - 在各功能入口处按套餐显示/禁用/触发付费墙。

3. **支付集成**：
   - 与选定支付平台打通（Stripe / Paddle / 国内支付渠道等），在支付成功回调中更新订阅状态。

4. **运营工具**：
   - 后台配置界面（中长期）：
     - 可在线编辑 `billing_plans` 中的数值与开关。
     - 支持灰度调整不同批次用户的配额（后期可选）。
