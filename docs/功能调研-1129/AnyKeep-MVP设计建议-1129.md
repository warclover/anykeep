## AnyKeep MVP 设计建议（聚焦学习闭环 & 语义搜索）

**文档日期**：2025-11-29  
**文档版本**：V1.0

本设计建议用于指导 AnyKeep 在「不急于上市、先打磨好 MVP 给朋友/同学试用」的阶段，聚焦少数关键场景，把「收藏 → 整理 → 找回 → 复盘」这条学习闭环做顺，为后续商业化与功能扩展打基础。

---

## 1. MVP 目标与验证假设

### 1.1 产品目标

- 为重度信息/学习用户（产品/运营/开发/内容从业者等）提供一个：  
  **能够跨平台收集中文内容，并通过 AI 帮助整理与搜索，最终支持复盘学习的个人知识空间。**

### 1.2 核心验证假设

1. **流程假设**：  
   用户能自然、低摩擦地完成从「看到内容」到「进入 AnyKeep 并被整理好」的流程。
2. **价值假设**：  
   在 1–2 周使用后，用户能明显感受到：
   - 「我重要的内容没有再丢」
   - 「我能找回几周前看到的东西，并且还记得要点」
3. **用户假设**：  
   以学习/内容工作者为主的细分人群，会愿意持续使用，并愿意为「更聪明的搜索与整理」付费。

---

## 2. MVP 目标用户与核心场景

### 2.1 目标用户（第一批试用者画像）

1. **学习型用户**：
   - 重度使用公众号/B 站/小红书学习技能、知识的人。
2. **内容/产品/运营从业者**：
   - 需要收集竞品、活动案例、文案/设计灵感。
3. **开发/技术人员**：
   - 收集技术文章、官方文档、教程视频等。

### 2.2 核心场景（MVP 聚焦这两条）

#### 场景 A：学习型内容整理（公号 + B 站为主）

- 用户在公众号/B 站看到一篇/一个值得学习的内容：  
  → 一键分享到 AnyKeep  
  → AI 自动生成摘要与标签  
  → 用户简单确认分类/评级  
  → 之后通过关键词/语义搜索/学习视图找回并复盘。

#### 场景 B：灵感/案例库（网页 + 小红书为辅）

- 用户看到好的落地页/活动/文案/设计：  
  → 通过浏览器扩展或粘贴链接保存  
  → 按项目/主题整理  
  → 未来通过标签/语义搜索快速找到相关案例。

## 3. MVP 范围：Must / Should / Nice to have

### 3.1 Must Have（必须完成，且体验要“不错”）

#### 3.1.1 收藏入口

- Web 端：
  - 粘贴链接 → 一键解析（标题/描述/封面 URL）。
  - 简单的「新增收藏」表单（标题可编辑、备注、文件夹、标签）。
- 浏览器扩展（Chrome/Edge）：
  - 一键保存当前页面为收藏。
  - 至少能展示标题和当前 URL，自动填充平台信息。

（如有精力，可再补 Android 系统分享 → AnyKeep 但非 MVP 必须）

#### 3.1.2 整理与结构化

- 文件夹系统 + 标签系统：
  - 支持基础的创建/重命名/移动。
- 「待整理」视图：
  - 所有新收藏默认进入「待整理」列表。
  - 支持在这里完成：
    - 选择文件夹
    - 简单评级（例如：未评级 / 一般 / 高价值 / 深度学习）
- AI 摘要与标签（基础版）：
  - 支持对网页/公号/B 站等收藏内容调用 AI 生成：
    - 1–2 段简洁摘要
    - 3–5 个标签建议
  - 有每日/每月调用限制（为后续付费模型预留）。

#### 3.1.3 搜索与筛选（含语义搜索 MVP）

- 关键词/全文搜索：
  - 支持按标题/描述检索。
  - 支持按平台/文件夹/标签筛选。
- 语义搜索 MVP：
  - 对最近一段时间/少量书签生成 embedding（如标题+摘要+标签）。
  - 允许用户在搜索框中选择「语义」模式，返回相似度排序结果。
  - 体验要求：
    - 结果相关性「大致靠谱」即可，不追求极致。
    - 失败时要有清晰 fallback（回退到关键词搜索）。

#### 3.1.4 简单学习/复盘视图

- 评级中支持一个「深度学习」级别（L3）。
- 提供一个「学习」视图：
  - 只展示所有 L3 收藏。
  - 按「最新添加」/「最近访问」排序。
- 首页给出简单提示：
  - 如「你有 X 条深度学习内容，今天还没看」。

> 不需要一开始就实现复杂的间隔重复算法，先有「看得见的学习队列」即可。

#### 3.1.5 体验基础

- 清晰的 Empty State：
  - 首页/搜索/文件夹为空时，引导用户去收藏第一条内容。
- 直观的错误提示：
  - 爬取失败/AI 失败时，给出可操作的提示（例如「试着自己写一句总结吧」）。
- 性能与稳定性：
  - 首页加载与搜索响应在可接受范围内（>90% 请求在 1s 内返回是一个目标参考）。

---

### 3.2 Should Have（尽量做，或做精简版）

#### 3.2.1 智能分类与智能评级（简化版）

- 智能分类：
  - 可以基于标题+摘要+平台，对新收藏给出一个推荐文件夹/标签。
  - UI 上展示「AI 推荐：放入 X 文件夹」，用户一键接受/忽略。
- 智能评级：
  - 在新收藏详情中，展示「AI 推荐：高价值/深度学习」，供用户参考。
  - 不必覆盖真实 `importance` 字段，仅作为建议（见智能评级设计文档）。

#### 3.2.2 浏览器书签基础导入

- 支持从 Chrome 导出的书签 HTML 中导入部分数据：
  - 解析标题/URL/基本层级结构。
  - 不需要一上来就做全量、分批、失效检测等高级能力。

#### 3.2.3 简单 Analytics

- 在一个「统计」视图中简单展示：
  - 本周新增收藏数。
  - 使用最多的平台分布。
  - 高价值（L2+/L3）收藏数量。

> 主要作用是让试用者“看见自己在用”，提高主观价值感。

---

### 3.3 Nice to Have（可视时间与精力酌情实现）

- 移动端 PWA 体验打磨（离线/图标/启动速度等）。
- 更细致的复盘节奏（如「看过一次后，3 天内提醒复盘」）。
- 与抖音收藏模块的初步集成（如果技术风险可控）。
- 思维导图/关系视图最基础版（仅可视化，不强求交互完备）。

## 4. 语义搜索的创新与 MVP 设计要点（简要）

> 详细的创新设计见独立语义搜索设计文档，这里只列出 MVP 应考虑的关键点。

### 4.1 MVP 级语义搜索功能

1. **基础向量生成**：
   - 对部分书签（例如最近 2000 条或最近 3 个月内容）生成 embedding：
     - 文本输入 = 标题 + AI 摘要 + 标签（若存在）。
2. **单轮查询**：
   - 用户输入自然语言查询（如「如何用 Obsidian 管理 PKM」），  
     → 生成 query embedding，  
     → 调用 PGVector / 向量数据库检索。
3. **结果展示**：
   - 标注为「语义搜索」，并提示可以回退为关键词搜索。
   - 支持按平台/文件夹筛选（即「在 X 范围内做语义检索」）。

### 4.2 可逐步扩展的创新方向（为后续版本预留）

在 MVP 稳定后，可在语义搜索上进一步做差异化（规划为 P1/P2）：

- **按“学习价值”排序**：
  - 将 `importance`（评级）与语义相似度结合排序，高评级内容优先出现。
- **语义智能过滤**：
  - 自动理解查询意图（如“找教程/找案例/找定义”），并在结果中提高对应内容类型权重。
- **语义 Smart Folder**：
  - 用户可以保存语义查询为「智能集合」（例如「与 AIGC 工作流相关的所有收藏」），自动实时更新。
- **与复盘/学习联动**：
  - 在语义结果中优先标出尚未复盘的 L3 内容，帮助用户做主题复习。

## 5. MVP 验收标准（可供自测与小范围测试）

1. **可用性**：
   - ≥80% 的试用用户能在 5 分钟内完成：  
     1）新增一条收藏；  
     2）在「待整理」中为其选文件夹和评级；  
     3）通过搜索找到它。

2. **学习闭环体验**：
   - 至少 50% 的重度试用者能在 1–2 周后说出：
     - “我用它找到过之前看过但记不清的内容”；
     - “我有一小部分内容会特意标记为深度学习，并在学习视图中看它们”。

3. **语义搜索感知价值**：
   - 用户在尝试语义搜索后，主观评价为「比普通搜索更好用/更聪明」的比例 ≥ 50%。

4. **稳定性与性能**：
   - 关键路径（首页加载、列表加载、搜索请求）的错误率与延迟在可接受范围内（可根据日志与主观感受综合评估）。

## 6. 开发与迭代节奏建议

### 6.1 阶段拆分（建议）

1. **Phase 1：基础可用版（1–2 周）**
   - 手动添加/粘贴链接 → 收藏创建。
   - 文件夹/标签管理 + 待整理视图。
   - 基础关键词搜索。

2. **Phase 2：AI 整理 + 语义搜索 MVP（2–3 周）**
   - AI 摘要/标签（带配额）。
   - 语义搜索 MVP（对部分书签做 embedding）。
   - 简单评级（手动），并在搜索排序中加基础支持。

3. **Phase 3：学习视图与细节打磨（1–2 周）**
   - L3 学习视图与首页提示。
   - 空状态、错误提示、反馈入口、简单埋点。

4. **Phase 4：与试用用户一起迭代**
   - 邀请 5–10 位典型朋友/同学试用。
   - 收集定性反馈与日志数据，评估哪些功能最有价值/最鸡肋。
   - 再决定下一阶段（如抖音模块、失效检测等）的优先级。
