### T1：首页分享参数消费（P0 — 当前断路修复）

**问题**：`/api/share-target` 重定向到 `/home?action=create&url=...&title=...`，但首页组件 `home-page-client-layered.tsx` 不读取这些参数，分享后用户只看到正常首页，无任何反馈。

**涉及文件**：

| 文件                                               | 变更                                                          |
| -------------------------------------------------- | ------------------------------------------------------------- |
| `src/components/home/home-page-client-layered.tsx` | 新增 `useShareParams` hook 消费                               |
| `src/hooks/domain/use-share-params.ts`             | **新建** — 解析 `action/url/title/share_url/share_title` 参数 |
| `src/components/quick-add/QuickAddBookmark.tsx`    | 支持外部传入 `initialUrl` + `initialTitle` 打开预填           |

**实现逻辑**：

```typescript
// src/hooks/domain/use-share-params.ts
export function useShareParams() {
  const searchParams = useSearchParams();
  const router = useRouter();
  const pathname = usePathname();

  useEffect(() => {
    const action = searchParams.get("action");
    const url = searchParams.get("url") || searchParams.get("share_url");
    const title = searchParams.get("title") || searchParams.get("share_title");

    if (action === "create" && url) {
      // 触发快速添加，预填 URL 和标题
      emitShareEvent({ url, title });

      // 清理 URL 参数，避免刷新重复触发
      router.replace(pathname, { scroll: false });
    }
  }, [searchParams]);
}
```

**验收标准**：

- [ ] 从其他 App 分享链接到已安装的 PWA → 自动打开快速添加弹窗，URL 已预填

- [ ] 参数消费后 URL 被清理，刷新不重复触发
- [ ] 无 URL 时重定向到首页，显示 toast 提示

```typescript
// src/hooks/domain/use-pwa-install.ts
export function usePwaInstall() {
  const [installPrompt, setInstallPrompt] =
    useState<BeforeInstallPromptEvent | null>(null);
  const [isInstalled, setIsInstalled] = useState(false);

  useEffect(() => {
    // 检测是否已安装（standalone 模式）
    const mq = window.matchMedia("(display-mode: standalone)");
    setIsInstalled(mq.matches);

    // 监听安装提示事件
    const handler = (e: Event) => {
      e.preventDefault();
      setInstallPrompt(e as BeforeInstallPromptEvent);
    };
    window.addEventListener("beforeinstallprompt", handler);
    return () => window.removeEventListener("beforeinstallprompt", handler);
  }, []);

  const install = async () => {
    if (!installPrompt) return false;
    installPrompt.prompt();
    const { outcome } = await installPrompt.userChoice;
    setInstallPrompt(null);
    return outcome === "accepted";
  };

  return { canInstall: !!installPrompt, isInstalled, install };
}
```

### T5：Android Share Intent 接收

**方案选型**：Capacitor 自定义插件 vs 原生 Activity + JS Bridge

推荐 **原生 Activity + 重定向到 WebView** 方案，复用已有的 `share-target` 端点逻辑：

**涉及文件**：

| 文件                                                     | 说明                             |
| -------------------------------------------------------- | -------------------------------- |
| `android/app/src/main/java/.../ShareReceiverActivity.kt` | **新建** — 接收 Intent，提取 URL |
| `android/app/src/main/AndroidManifest.xml`               | 注册 Activity + Intent Filter    |
| `capacitor.config.ts`                                    | 配置 share intent 处理           |

**实现逻辑**：

```kotlin
// android/app/src/.../ShareReceiverActivity.kt
class ShareReceiverActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        val sharedUrl = when (intent?.action) {
            Intent.ACTION_SEND -> {
                val text = intent.getStringExtra(Intent.EXTRA_TEXT) ?: ""
                // 从文本中提取 URL
                val urlPattern = Regex("https?://[^\\s]+")
                urlPattern.find(text)?.value ?: text
            }
            Intent.ACTION_VIEW -> intent.dataString
            else -> null
        }

        val title = intent.getStringExtra(Intent.EXTRA_SUBJECT) ?: ""

        if (!sharedUrl.isNullOrBlank()) {
            // 方式一：重定向到 WebView 主 Activity
            val mainIntent = Intent(this, MainActivity::class.java).apply {
                putExtra("share_url", sharedUrl)
                putExtra("share_title", title)
                addFlags(Intent.FLAG_ACTIVITY_CLEAR_TOP)
            }
            startActivity(mainIntent)
        }

        finish()
    }
}
```

**MainActivity 侧处理**：

```kotlin
// 在 MainActivity.kt 的 onCreate 中
override fun onCreate(savedInstanceState: Bundle?) {
    super.onCreate(savedInstanceState)

    // 检查是否来自分享
    val shareUrl = intent.getStringExtra("share_url")
    val shareTitle = intent.getStringExtra("share_title")
    if (!shareUrl.isNullOrBlank()) {
        // 构建带参数的 URL，WebView 加载后前端消费
        val encoded = URLEncoder.encode(shareUrl, "UTF-8")
        val titleEncoded = URLEncoder.encode(shareTitle ?: "", "UTF-8")
        // 利用 Capacitor 的 server URL 机制注入参数
        bridge.webView.evaluateJavascript(
            "window.__SHARE_DATA__ = { url: '$shareUrl', title: '${shareTitle ?: ""}' }",
            null
        )
    }
}
```

**前端对接**（与 T1 联动）：

```typescript
// src/hooks/domain/use-share-params.ts 追加 Capacitor 路径
useEffect(() => {
  // 路径 1: URL 参数（PWA Share Target）
  // ...已有逻辑...

  if (Capacitor.isNativePlatform()) {

    emitShareEvent(data);
    delete (window as any).__SHARE_DATA__;
  }
}, []);
```

### T8：iOS Share Extension 实现

iOS Share Extension 是**独立的 App Extension target**，与主 App 通过 App Group 共享数据。

**技术要点**：

| 项目                        | 说明                                                     |
| --------------------------- | -------------------------------------------------------- |
| 新建 Share Extension Target | Xcode → File → New Target → Share Extension              |
| App Group 配置              | 主 App 和 Extension 共享 `group.com.anykeep.app`         |
| 数据传递方式                | UserDefaults(suiteName: group) 或 文件共享               |
| UI                          | 系统默认 SLComposeServiceViewController 或自定义 SwiftUI |
| URL Scheme                  | `anykeep://share?url=...&title=...` 唤起主 App           |

**实现流程**：

```
用户在 Safari/微信 点击分享 → 选择 AnyKeep
  → iOS Share Extension 打开（轻量 UI）
  → 提取 URL + 标题
  → 写入 App Group UserDefaults
  → 打开主 App（URL Scheme）
  → 主 App 读取 UserDefaults，打开快速添加
  → 清空 UserDefaults
```

**验收标准**：

- [ ] iOS 系统分享菜单出现 AnyKeep 图标
- [ ] 分享后主 App 自动打开并预填 URL
- [ ] Extension 内存限制 120MB 以内
- [ ] 无网络时数据暂存，下次打开 App 时处理

**工作量**：5-8 天（含审核适配）

**核心流程**：

```
微信服务器 POST /api/wechat/callback
  → 验签（signature + timestamp + nonce + token）
  → 解密消息体（AES-256-CBC，EncodingAESKey）
  → 解析 XML → 提取消息类型
  → 路由处理：
     ├─ 文本消息（含 URL）→ 提取 URL → 创建书签
     ├─ 链接消息（MsgType=link）→ 直接获取 url + title
     ├─ 事件消息（关注/取关）→ 更新绑定状态
     └─ 其他 → 回复帮助文本
  → 构造 XML 响应 → 加密 → 返回
```

```typescript
export async function handleWechatMessage(msg: WechatMessage): Promise<string> {
  switch (msg.MsgType) {
    case "text": {
      const url = extractUrl(msg.Content);

        msg.Url,
        msg.Title,

      );
    case "event":

        return WELCOME_TEXT;
      }
      break;
  }
  return DEFAULT_REPLY;
}
```

### T10：用户绑定机制

**绑定方案**：用户在 AnyKeep Web 端生成绑定二维码 → 微信扫码关注 → 自动绑定

**涉及文件**：

| 文件                                        | 说明                         |
| ------------------------------------------- | ---------------------------- |
| `src/app/api/wechat/bindng/route.ts`        | **新建** — 生成绑定 token    |
| `src/lib/wechat/bindng.service.ts`          | **新建** — 绑定逻辑          |
| `src/components/settings/wechat-bindng.tsx` | **新建** — 设置页绑定入口 UI |
| `supabase/migrations/xxx_wechat_bindng.sql` | **新建** — 绑定关系表        |

**数据模型**：

```sql
CREATE TABLE wechat_bindings (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  openid TEXT NOT NULL UNIQUE,
  unionid TEXT,
  nickname TEXT,
  status TEXT NOT NULL DEFAULT 'active'  -- active | unbound
  bound_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE(user_id)  -- 一个用户只绑一个微信
);

-- RLS
ALTER TABLE wechat_bindings ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Users manage own binding"
  ON wechat_bindings FOR ALL
  USING (auth.uid() = user_id);
```

**绑定流程**：

```
Web 端：设置 → 微信绑定 → 生成带 state 的临时二维码 URL
  → 用户微信扫码 → 关注公众号（带 scene 参数）
  → 微信推送 subscribe 事件（带 EventKey = binding_token）
  → 后端校验 token → 创建 wechat_bindings 记录
  → Web 端轮询绑定状态 → 显示绑定成功
```

**可预开发内容**：

- 绑定服务逻辑（token 生成、校验、绑定、解绑）
- 设置页 UI 组件

**验收标准**：

- [ ] 生成绑定 token 并持久化（TTL 5 分钟）

## 八、技术风险与缓解

| 风险                                 | 影响                 | 缓解措施                                            |
| ------------------------------------ | -------------------- | --------------------------------------------------- |
| Android WebView 兼容性               | JS Bridge 通信异常   | 使用 Capacitor 官方 Bridge，覆盖 Android 8+         |
| iOS Share Extension 内存限制 (120MB) | Extension 被系统杀死 | 仅做 URL 提取 + UserDefaults 写入，不加载 WebView   |
| 微信消息 5 秒超时                    | 爬取内容耗时导致超时 | 先回复「收藏中...」，异步处理后推送客服消息通知结果 |
| Chrome Web Store 审核拒绝            | 上架延迟             | 提前准备完整的隐私政策、权限说明                    |
| PWA `beforeinstallprompt` iOS 不支持 | iOS 用户无法自动安装 | 手动引导截图：Safari → 分享 → 添加到主屏幕          |
