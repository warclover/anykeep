## 1. 摘要与战略目标 (Executive Summary & Strategy)

### 1.1 产品愿景 (Vision)

成为用户管理碎片化、跨平台信息的首选**外部记忆索引 (External Memory Index)**。

### 1.2 核心价值主张 (Value Proposition)

**"无摩擦收集，意图式检索。"** (Frictionless Capture, Intent-Based Retrieval)
我们解决的核心痛点是：信息高度分散、收藏后不可检索、链接及图片失效。

### 1.3 成功标准 (Success Metrics / KPIs)

| 类别          | 指标 (KPI)                              | 目标值 (Target) | 衡量标准                                                             |
| :------------ | :-------------------------------------- | :-------------- | :------------------------------------------------------------------- |
| **效率/使用** | **Aha Moment (首次收藏)**               | 90%             | 用户首次分享链接到 AnyKeep，2 秒内收到"已保存"通知。                 |
| **核心价值**  | **有效搜索率 (Retrieval Success Rate)** | > 85%           | 用户的语义搜索在结果页前 5 位命中目标内容的比例。                    |
| **留存/粘性** | **D7 留存率**                           | > 35%           | 用户使用 App 超过 7 天后，平均每周的搜索次数 (Search Queries/Week)。 |
| **性能**      | **搜索平均延迟 (Latency)**              | < 500ms         | 从用户输入搜索词到结果加载完成的平均时间。                           |

### 1.4 产品定位语 (Positioning Statement)

> **对于** 每天接触大量碎片化信息的知识工作者和深度学习者，
> **AnyKeep** 是一款智能内容聚合工具，
> **它能够** 零摩擦收集跨平台内容，并通过AI语义检索快速找回记忆，
> **不同于** 传统书签工具和稍后阅读应用，
> **我们的产品** 提供跨平台内容治理、AI驱动的意图式检索，以及永久有效的链接持久化。

## 2. 用户实际需求深度分析 (In-Depth User Needs Analysis) ⭐

### 2.1 问题本质：信息过载时代的记忆外包困境

#### 2.1.1 现象级痛点观察

**定量数据支撑：**

- 📊 **信息爆炸：** 普通用户每天接触信息量约 34GB（相当于10万个单词），但大脑只能有效处理其中的 0.004%
- 📱 **平台碎片化：** 中国互联网用户平均安装 **43个App**，内容分散在微信、小红书、B站、知乎、抖音等封闭生态
- 🔖 **收藏黑洞：** 调研显示，78% 的用户承认"收藏了大量内容但从未回看"，微信收藏平均使用率仅 **12%**
- ⏱️ **搜索成本：** 用户回忆并找到"一个月前看过的某个视频"平均需要 **15-20分钟**，成功率不足 40%

#### 2.1.2 用户痛点分层模型（Kano模型分析）

```
       用户满意度
          ↑
兴奋型需求 │ • AI对话式检索（"帮我找上周那个教做咖啡的视频"）
(Delight) │ • 公开收藏夹社区
          │ • 智能内容推荐
      ────┼──────────────────────────────────
期望型需求 │ • 混合语义检索（向量+关键词）
(Expected)│ • 视频时间戳提取
          │ • 跨平台Deep Link
          │
基本型需求 │ • 一键收藏（系统分享）
(Basic)   │ • 图片/链接持久化
          │ • 基础关键词搜索
          └──────────────────────────────→ 功能完善度
```

**决策依据：**

- **MVP阶段：** 必须100%满足"基本型需求"，否则产品无法成立
- **Beta阶段：** 至少实现80%的"期望型需求"，形成差异化竞争力
- **成熟期：** 通过"兴奋型需求"建立护城河，提升用户LTV

- **< 10分：** 放入Backlog，根据用户反馈再决定

### 2.4 用户需求验证清单（Product-Market Fit Checklist）

**在开始开发前，必须验证的5个关键假设：**

- [ ] **假设1：用户真的会"收藏后不回看"吗？**
  - **验证方法：** 问卷调查100人 + 访谈10人
  - **成功标准：** >70% 承认收藏利用率 <20%

- [ ] **假设2：语义检索比关键词搜索更有效？**
  - **验证方法：** A/B测试（提供20个场景，让用户分别用两种方式找内容）
  - **成功标准：** 语义检索成功率高出20%以上

- [ ] **假设3：用户愿意为AI检索付费？**
  - **验证方法：** Fake Door Test（展示付费页面但不收费，观察点击率）
  - **成功标准：** 点击率 >8%

- [ ] **假设4：链接失效是真实痛点？**
  - **验证方法：** 分析用户微信收藏的100条链接，统计失效率
  - **成功标准：** 失效率 >30%

- [ ] **假设5：跨平台聚合有真实需求？**
  - **验证方法：** 调研用户日常收藏内容分布在几个平台
  - **成功标准：** 平均使用 ≥3个平台进行内容收藏

## 3. 商业化前景分析 (Business Opportunity Analysis) ⭐

### 3.1 市场规模估算 (TAM-SAM-SOM Model)

#### 3.1.1 市场层级拆解

```
┌────────────────────────────────────────────────────────────┐
│ TAM (Total Addressable Market) - 总可达市场                │
│ 中国互联网用户 × 有内容收藏习惯的比例                        │
│ = 10.5亿 × 60% = 6.3亿人                                   │
│ 市场价值：6.3亿 × ¥60/年 = ¥378亿/年                       │
└────────────────────────────────────────────────────────────┘
                          ↓
┌────────────────────────────────────────────────────────────┐
│ SAM (Serviceable Addressable Market) - 可服务市场           │
│ 一线/新一线城市 + 知识工作者 + 深度学习者                     │
│ = 6.3亿 × 25% = 1.58亿人                                   │
│ 市场价值：1.58亿 × ¥120/年 = ¥189亿/年                     │
└────────────────────────────────────────────────────────────┘
                          ↓
┌────────────────────────────────────────────────────────────┐
│ SOM (Serviceable Obtainable Market) - 可获得市场            │
│ 前3年可触达的早期采用者（创作者+职场学习者）                  │
│ = 1.58亿 × 2% = 316万人                                    │
│ 市场价值：316万 × ¥150/年 = ¥4.74亿/年                     │
└────────────────────────────────────────────────────────────┘
```

#### 3.1.2 市场规模对标

| 参照产品           | 类型     | 全球付费用户                      | ARPU     | 年收入  | 中国市场潜力                  |

**结论：** AnyKeep切入的是 **¥3-5亿/年** 的细分市场，处于Pocket和Notion之间的"智能收藏"赛道。

### 12.2 关键流程时序图

#### 12.2.1 收集流程 (Capture Flow)

```
用户 -> UniApp: 分享链接
UniApp -> API Gateway: POST /api/capture {"url": "..."}
API Gateway -> Capture-API: 验证用户
Capture-API -> Redis: 快速入队
Capture-API --> UniApp: 200 OK "已保存" (< 200ms)
Redis -> RabbitMQ: 异步任务
RabbitMQ -> AI-Worker: 拉取任务
AI-Worker -> 爬虫池: 获取内容
爬虫池 --> AI-Worker: HTML/视频信息
AI-Worker -> 通义千问: 生成摘要+标签
AI-Worker -> OSS: 上传封面图
AI-Worker -> PostgreSQL: 保存完整数据+向量
AI-Worker -> WebSocket: 推送"处理完成"通知
WebSocket --> UniApp: 实时更新卡片
```

#### 12.2.2 检索流程 (Search Flow)

```
用户 -> UniApp: 输入搜索词 "如何做面包"
UniApp -> Search-API: GET /api/search?q=如何做面包
Search-API -> Redis: 检查缓存
[Cache Miss]
Search-API -> AI-Worker: 将查询向量化
AI-Worker --> Search-API: embedding_vector
Search-API -> PostgreSQL: 混合查询
  - 向量相似度 (cosine_similarity)
  - 关键词匹配 (full-text search)
  - 时间衰减 (recency boost)
PostgreSQL --> Search-API: 结果集 (Top 20)
Search-API -> Redis: 缓存结果 (5分钟)
Search-API --> UniApp: JSON响应
UniApp: 渲染结果列表
```

### 12.3 数据库索引策略

```sql
-- 核心表结构优化
CREATE TABLE bookmarks (
    id BIGSERIAL PRIMARY KEY,
    user_id BIGINT NOT NULL,
    original_url TEXT NOT NULL,
    platform VARCHAR(50),
    title TEXT,
    ai_summary TEXT,
    ai_timeline JSONB,  -- 视频时间戳
    embedding_vector vector(1536),  -- OpenAI/通义向量维度
    oss_cover_key VARCHAR(255),
    tags JSONB,
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW(),

    -- 性能关键索引
    INDEX idx_user_created (user_id, created_at DESC),
    INDEX idx_platform (platform),
    INDEX idx_vector USING ivfflat (embedding_vector vector_cosine_ops) WITH (lists = 100),
    INDEX idx_fulltext USING GIN (to_tsvector('chinese', title || ' ' || COALESCE(ai_summary, '')))
);
```
