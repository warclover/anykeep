## 二、速率限制审计

### 🔴 高优先级问题

#### 2.1 高风险操作缺乏显式速率限制

| 操作         | 端点                                 | 当前状态     | 建议限制             |
| ------------ | ------------------------------------ | ------------ | -------------------- |
| 账户删除     | `DELETE /api/user/delete`            | 仅全局中间件 | 2 次/小时 + 邮箱验证 |
| 用户数据导出 | `POST /api/user/export`              | 仅全局中间件 | 5 次/天              |
| 批量删除     | `DELETE /api/bookmarks/batch-delete` | 仅全局中间件 | 10 次/分钟           |

**修复方案：**

```typescript
// src/app/api/user/delete/route.ts
import { checkRateLimit } from "@/lib/utils/rate-limiter";

export async function DELETE(request: Request) {
  const rateLimitResult = checkRateLimit(user.id, "/api/user/delete");
  if (!rateLimitResult.allowed) {
    return Response.json({ error: "请求过于频繁" }, { status: 429 });
  }
  // ... 删除逻辑
}
```

#### 2.2 生产环境使用内存存储

- **当前状态**：速率限制数据存储在内存中
- **问题**：多进程/多服务器环境无法共享限制状态
- **建议**：生产环境迁移到 Redis

#### 4.1 embedding 字段类型错误

| 层级       | 类型定义                  | 正确类型           |
| ---------- | ------------------------- | ------------------ |
| 数据库     | `vector(1536)` (pgvector) | -                  |
| TypeScript | `string \| null`          | `number[] \| null` |

**影响**：语义搜索功能可能受影响

**修复位置**：`src/types/supabase.ts` → bookmarks.embedding

#### 4.2 RLS 策略不一致

```sql
-- 当前 UPDATE 策略（缺少 deleted_at 检查）
FOR UPDATE USING (auth.uid() = user_id);

-- 建议修改为
FOR UPDATE USING (auth.uid() = user_id AND deleted_at IS NULL);
```

**风险**：可能允许更新已软删除的记录
