## 五、SOLID 原则违反分析

### 5.1 Single Responsibility Principle (SRP) 违反

**违反实例**：

1. **home-page-client.tsx** - 承担 6 个职责：
   - 列表数据管理
   - 平台筛选逻辑
   - 排序逻辑
   - 选择模式管理
   - 导入对话框管理
   - 批量操作处理

2. **bookmark-card.tsx** - 承担 4 个职责：
   - 收藏卡片渲染
   - 评分显示
   - 内容类型徽章
   - 交互处理

### 5.2 Dependency Inversion Principle (DIP) 违反

**违反实例**：

- 所有 Repository 直接依赖 SupabaseClient（具体实现）
- Services 构造函数硬依赖 Repositories（具体实现）

**当前做法**：

```typescript
// ❌ 依赖具体实现
export class BookmarkRepository {
  constructor(private supabase: SupabaseClient) {}

  async findById(bookmarkId: number) {
    const { data, error } = await this.supabase
      .from("bookmarks")
      .select(...)
      .single();
  }
}
```

### 5.3 Interface Segregation Principle (ISP) 违反

**违反实例**：

- Repository 层暴露整个 SupabaseClient 接口
- useImportSession 导出 9 个方法的复杂接口

## 六、对未来迭代的影响评估

### 6.1 有利因素

1. **分层清晰**：组件 → Hooks → Lib 的依赖方向正确，无越层调用
2. **无循环依赖**：扫描未发现直接循环依赖

## 七、改进建议

### 7.1 第一优先级：数据访问层抽象（预计 2-3 天）

**目标**：解除 Classification 模块与 Supabase 的紧耦合

```typescript
// 新增接口定义
// src/lib/classification/interfaces/data-source.interface.ts

interface IDataSource {
  select<T>(table: string, fields: string[], filters?: Filter[]): Promise<T[]>;
  insert<T>(table: string, data: T): Promise<T>;
  update<T>(table: string, id: string, data: Partial<T>): Promise<T>;
  delete(table: string, id: string): Promise<void>;
}

// Repository 改造
export class BookmarkRepository {
  constructor(private dataSource: IDataSource) {} // 依赖抽象

  async findById(id: number) {
    return this.dataSource.select(
      "bookmarks",
      ["*"],
      [{ field: "id", value: id }],
    );
  }
}
```

- 可轻松切换数据源（Supabase → PostgreSQL → Mock）

### 8.4 渐进式迁移策略

#### 适配器模式（零风险切换）

```typescript
// src/lib/classification/adapters/supabase-adapter.ts

// 步骤 1：定义抽象接口
interface IDataSource {
  select<T>(table: string, query: QueryOptions): Promise<T[]>;
  insert<T>(table: string, data: T): Promise<T>;
  update<T>(table: string, id: string, data: Partial<T>): Promise<T>;
}

// 步骤 2：为现有 Supabase 创建适配器
class SupabaseDataSourceAdapter implements IDataSource {
  constructor(private supabase: SupabaseClient) {}

  async select<T>(table: string, query: QueryOptions): Promise<T[]> {
    let q = this.supabase.from(table).select(query.fields.join(","));

    if (query.filters) {
      for (const filter of query.filters) {
        q = q.eq(filter.field, filter.value);
      }
    }

    const { data, error } = await q;
    if (error) throw error;
    return data as T[];
  }
}

// 步骤 3：Repository 使用接口
class BookmarkRepository {
  constructor(private dataSource: IDataSource) {}

  async findById(id: number) {
    const [bookmark] = await this.dataSource.select("bookmarks", {
      fields: ["*"],
      filters: [{ field: "id", value: id }],
    });
    return bookmark;
```

```typescript
// src/lib/features/auto-rollback.ts

class FeatureFlagController {
  private errorCounts = new Map<string, number>();
  private readonly ERROR_THRESHOLD = 10;
  private readonly TIME_WINDOW_MS = 60000;

  async executeWithRollback<T>(
    featureFlag: string,
    newImplementation: () => Promise<T>,
    fallbackImplementation: () => Promise<T>,
  ): Promise<T> {
    if (!FEATURE_FLAGS[featureFlag]) {
      return fallbackImplementation();
    }

    try {
      const result = await newImplementation();
      this.resetErrorCount(featureFlag);
      return result;
    } catch (error) {
      this.incrementErrorCount(featureFlag);

      if (this.shouldRollback(featureFlag)) {
        console.error(`Auto-rollback triggered for ${featureFlag}`);
        await this.disableFeature(featureFlag);
        await this.notifyTeam(featureFlag, error);
      }

      return fallbackImplementation();
    }
  }
}
```
