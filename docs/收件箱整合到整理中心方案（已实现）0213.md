# 收件箱整合到整理中心可行性方案

> **文档版本**: 1.0
> **创建日期**: 2026-02-13
> **状态**: 待审核

---

## 一、背景与目标

### 1.1 现状

当前存在两个独立页面：

| 页面         | 路由        | 定位               | 移动端入口   |
| ------------ | ----------- | ------------------ | ------------ |
| **收件箱**   | `/inbox`    | 待处理内容聚合中心 | 底部固定 Tab |
| **整理中心** | `/organize` | AI 智能整理控制台  | "更多" Sheet |

### 1.2 问题

1. **功能重叠**：两者都提供"智能整理"能力
2. **用户认知负担**：需要理解两个入口的区别
3. **导航冗余**：整理中心的 `ClusterPendingCard` 点击后跳转到收件箱
4. **移动端体验割裂**：收件箱在底部 Tab，整理中心在 Sheet 中

### 1.3 目标

将收件箱整合到整理中心，形成**统一的整理入口**：

- 减少用户认知负担
- 简化导航结构
- 提升功能内聚性

## 三、整合方案

### 3.1 方案概述

**推荐方案：Tab 统合 + 分层布局**

将整理中心重构为**多 Tab 架构**，收件箱作为其中一个 Tab 存在：

```
┌─────────────────────────────────────────────────────────┐
│  [待处理] [未读] [高价值] [已失效][最近]  [健康诊断]      │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  当前选中 Tab 的内容区域                                 │
│                                                         │
│  - 待处理: 聚类建议 + 书签列表 + 整理建议                │
│  - 未读/高价值/已失效/最近: 书签列表                     │
│  - 健康诊断: 文件夹健康 + 内容健康                       │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 3.2 路由设计

#### 方案 A: 单一路由（推荐）

```
/organize           → 默认显示 "待处理" Tab
/organize?tab=unread
/organize?tab=high-value
/organize?tab=broken
/organize?tab=recent
/organize?tab=health
```

- ✅ 优点：URL 简洁，统一入口
- ❌ 缺点：需要迁移 `/inbox` 的所有功能

#### 方案 B: 保留双路由

```
/inbox              → 收件箱功能（保持不变）
/organize           → 整理中心（移除聚类卡片，添加跳转链接）
```

- ✅ 优点：改动最小
- ❌ 缺点：仍然是两个入口，问题未解决

### 3.3 移动端适配

**底部 Tab 调整**：

```
当前: [收藏] [搜索] [收件箱] [更多]

调整后: [收藏] [搜索] [整理] [更多]
                    ↓
              /organize (待处理 Tab)
```

- 将 "收件箱" 改名为 "整理"
- 路由从 `/inbox` 改为 `/organize`

## 四、详细实现计划

### 4.1 Phase 1: 基础整合（预估 2-3 天）

#### 任务清单

1. **创建新的 Tab 配置**
   - 文件: `src/lib/constants/organize-tabs.ts`
   - 内容: 定义 6 个 Tab 的 ID、标签、图标

2. **重构 `OrganizePageClient`**
   - 添加顶层层 Tab 切换器
   - 保留现有的快速操作网格和健康诊断面板
   - 新增书签列表展示区域

3. **迁移收件箱组件**
   - 复用 `InboxTabs` 组件逻辑
   - 复用 `BookmarkListCard` 组件
   - 复用 `ClusterSuggestionsPanel` 和 `OrganizationSuggestionsPanel`

### 4.2 Phase 2: 导航调整（预估 1 天）

#### 任务清单

1. **更新 `nav-config.ts`**
   - 收件箱路由改为 `/organize`
   - 整理中心改为移动端可见

2. **更新 `mobile-bottom-nav.tsx`**
   - 将 "收件箱" Tab 改名为 "整理"
   - 调整路由和图标

3. **添加路由重定向**
   - `/inbox` → `/organize` (带 toast 提示)

### 4.3 Phase 3: 清理与优化（预估 1 天）

#### 任务清单

1. **移除冗余代码**
   - 删除 `ClusterPendingCard` 组件（功能已整合）
   - 清理收件箱相关的独立路由（保留重定向）

2. **性能优化**
   - Tab 切换时保留数据缓存
   - 懒加载各 Tab 内容

3. **测试验证**
   - E2E 测试覆盖新路由
   - 移动端回归测试

## 六、备选方案

### 6.1 方案 B: 最小改动

仅调整导航入口，不整合页面：

1. 移动端底部 Tab 从 "收件箱" 改为 "整理"
2. 整理中心添加"待处理书签"快速入口卡片
3. 保持两个页面独立

**优点**: 改动最小，风险最低
**缺点**: 功能仍然分散

### 6.2 方案 C: 抽屉模式

保持收件箱为独立页面，整理中心的"聚类待处理"改为**侧边抽屉**：

1. 点击卡片打开右侧抽屉
2. 抽屉内显示简化版收件箱功能
3. 完整功能仍需进入 `/inbox`

**优点**: 快速访问，不离开当前页
**缺点**: 实现复杂，维护成本高

---

## 七、推荐方案

**推荐采用方案 A（单一路由 + Tab 统合）**，理由：

1. **用户体验最佳**: 单一入口，逻辑清晰
2. **功能内聚**: 所有整理相关功能集中管理
3. **维护成本低**: 减少重复代码和联动逻辑
4. **扩展性好**: 未来可方便添加新 Tab

### 实施优先级

1. 🔴 **P0**: Phase 1 基础整合（核心功能迁移）
2. 🟡 **P1**: Phase 2 导航调整（移动端适配）
3. 🟢 **P2**: Phase 3 清理优化（代码质量）
