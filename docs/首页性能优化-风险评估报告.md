## 二、优化项风险评估矩阵

### 2.1 风险等级定义

| 等级        | 定义                   | 回滚难度          | 影响范围     |
| ----------- | ---------------------- | ----------------- | ------------ |
| 🔴 **高危** | 可能导致核心功能失效   | 难，需重新发布    | 多个功能模块 |
| 🟠 **中危** | 可能导致部分功能异常   | 中等，git revert  | 单个功能模块 |
| 🟡 **低危** | 仅影响性能，不影响功能 | 易，hotfix 可修复 | 渲染表现     |
| 🟢 **安全** | 几乎无风险             | 无需回滚          | 无           |

### 2.2 各优化项风险评估

#### P0-1: RSC 并行请求优化

| 维度         | 评估                                         |
| ------------ | -------------------------------------------- |
| **风险等级** | 🟢 **安全**                                  |
| **改动范围** | 仅 `page.tsx` 中的 `HomePageWithData` 函数   |
| **影响功能** | 首屏数据加载                                 |
| **失败表现** | 并行请求失败 → 数据不显示 → 用户看到错误提示 |
| **回归风险** | 极低 - 逻辑简单，`Promise.all` 是标准模式    |
| **测试要点** | 首屏正常渲染、数据正确性、错误处理           |

**详细分析**：

- 现有代码已有完整的错误处理机制
- `Promise.all` 失败时行为与串行一致（进入 catch）
- 不改变数据结构，仅改变执行顺序

**结论**：✅ 可直接实施，风险极低

---

#### P0-2: HomeView Context 订阅拆分

| 维度         | 评估                                                 |
| ------------ | ---------------------------------------------------- |
| **风险等级** | 🔴 **高危**                                          |
| **改动范围** | `HomeView` + 所有子组件的 Context 使用方式           |
| **影响功能** | 筛选、排序、选择、对话框、AI 面板等全部功能          |
| **失败表现** | 状态不同步、操作无响应、对话框无法打开、选择功能失效 |
| **回归风险** | 高 - 需修改 15+ 文件的 Context 调用方式              |
| **测试要点** | 所有交互功能需完整回归测试                           |

**详细风险点**：

1. **Context 兼容层风险** ⚠️

   ```tsx
   // 现有代码使用聚合 Context
   const homeContext = useHomePageContext();
   const platform = homeContext.filter.platform;

   // 改为细粒度订阅
   const { platform } = useFilter();
   ```

   - 风险：若某个组件遗漏修改，会导致运行时错误
   - 缓解：编译时 TypeScript 会捕获部分错误

2. **Context 嵌套顺序风险** ⚠️

   ```tsx
   // 当前嵌套顺序（已在 combined-provider.tsx 定义）
   <ViewModeProvider>
     <FilterProvider>
       <DialogProvider>
         <SelectionProvider>
           <AIPanelProvider>
   ```

   - 风险：若组件在错误层级调用 Context，会得到 undefined
   - 缓解：现有架构已正确嵌套，保持不变

3. **useMemo 依赖风险** ⚠️

   ```tsx
   // home-view.tsx 第 91 行
   const homeContext = useHomePageContext();
   // ...
   const toolbarProps = useMemo(() => ({...}), [homeContext.filter, ...]);
   ```

   - 风险：改为细粒度订阅后，useMemo 依赖需同步更新
   - 缓解：仔细检查所有 useMemo/useCallback 依赖

4. **effect 依赖风险** ⚠️
   ```tsx
   // home-view.tsx 第 101-109 行
   useEffect(() => {
     if (urlPlatform && urlPlatform !== homeContext.filter.platform) {
       homeContext.filter.setPlatform(urlPlatform);
     }
   }, []);
   ```

   - 风险：依赖数组需同步更新，否则 effect 不执行或死循环

**缓解措施**：

1. 分批改造，每改造一个文件立即测试
2. 保留兼容层，渐进式迁移
3. 增加单元测试覆盖 Context 使用场景

**结论**：⚠️ 需谨慎实施，建议分阶段进行

#### P0-3: Virtuoso 回调稳定性优化

| 维度         | 评估                                                                 |
| ------------ | -------------------------------------------------------------------- |
| **风险等级** | 🟠 **中危**                                                          |
| **改动范围** | `virtual-bookmark-grid.tsx`、`virtual-bookmark-list.tsx` 等 3 个文件 |
| **影响功能** | 卡片点击、编辑、删除、选择、滚动加载                                 |
| **失败表现** | 点击无响应、选择失效、滚动异常                                       |
| **回归风险** | 中等 - 涉及虚拟列表核心渲染逻辑                                      |
| **测试要点** | 所有卡片交互、批量选择、滚动加载                                     |

**详细风险点**：

1. **回调引用丢失风险** ⚠️

   ```tsx
   // 改造前：直接引用
   const renderItem = useCallback((_, bookmark) => (
     <GridBookmarkItem onEdit={onEdit} ... />
   ), [onEdit, ...]);

   // 改造后：ref 间接引用
   const callbacksRef = useRef({ onEdit, ... });
   callbacksRef.current = { onEdit, ... };
   const renderItem = useCallback((_, bookmark) => (
     <GridBookmarkItem onEdit={(id) => callbacksRef.current.onEdit?.(id)} ... />
   ), []);
   ```

   - 风险：若 ref 更新时机不对，可能调用旧回调
   - 缓解：确保每次 render 都更新 ref

2. **selectedIds 同步风险** ⚠️
   - 现有代码已使用 `selectedIdsRef`（第 220-221 行）
   - 风险：改造时需保留此逻辑

3. **memo 失效风险** ⚠️
   - 若 props 比较逻辑不正确，memo 会失效
   - 缓解：使用 React DevTools Profiler 验证

**缓解措施**：

1. 保留原有回调作为 fallback
2. 分组件改造，逐一验证
3. 增加 E2E 测试覆盖关键交互

**结论**：⚠️ 可实施，需仔细测试交互功能

#### P1-1: 轮询优化

| 维度         | 评估                                                   |
| ------------ | ------------------------------------------------------ |
| **风险等级** | 🟡 **低危**                                            |
| **改动范围** | `home-data-provider.tsx` 中的 `handleProcessingUpdate` |
| **影响功能** | 新建书签后的自动更新                                   |
| **失败表现** | 新建书签后状态不更新（需手动刷新）                     |
| **回归风险** | 低 - 不影响核心 CRUD 功能                              |
| **测试要点** | 新建书签 → 等待处理完成 → 卡片状态更新                 |

**详细风险点**：

1. **updateCacheItem 实现风险**

   ```tsx
   // use-bookmarks-swr.ts 第 548-561 行
   const updateCacheItem = useCallback(
     (bookmarkId, updater) => {
       setData((prev) => {
         const newData = prev.map((b) =>
           b.id === bookmarkId ? updater(b) : b,
         );
         syncToCache(newData, hasMore);
         return newData;
       });
     },
     [hasMore, syncToCache],
   );
   ```

   - ✅ 已实现 immutable 更新，仅更新单条
   - ✅ 不会导致整数组引用变化
   - 风险：依赖 hasMore 和 syncToCache，需确保引用稳定

2. **轮询间隔延长风险**
   - 从 3s → 5s：用户体验略有下降（延迟 2s）
   - 缓解：保留首次立即轮询

**结论**：✅ 可实施，风险较低

### 4.2 保守策略（更安全）

如果担心 P0-2 风险过高，可以：

1. **跳过 P0-2**：仅实施 P0-1 + P0-3 + P1-1 + P1-2
   - 仍可获得 60-70% 的性能提升
   - 风险大幅降低

2. **P0-2 替代方案**：不拆分 Context，仅优化渲染

   ```tsx
   // 方案：使用 React.memo + useMemo 阻断重渲染
   const HomeViewMemo = memo(HomeView);

   // 在 HomeView 中使用 useMemo 缓存大对象
   const toolbarProps = useMemo(() => ({...}), [dep1, dep2]);
   const contentProps = useMemo(() => ({...}), [dep3, dep4]);
   ```

   - 优点：改动小，风险低
   - 缺点：优化效果有限（约 20-30%）
