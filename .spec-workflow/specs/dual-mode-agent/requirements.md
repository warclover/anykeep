# 双模式智能体系统 - 需求文档 (v2.1)

## 概述

### 项目背景

AnyKeep 已具备成熟的 AI 架构基础（ReAct ���环、80+ Tools、30+ Skills、零接管确认机制），需要升级为支持**流体升级 (Fluid Escalation)** 的智能体系统——用户无需手动切换模式，系统根据操作复杂度自动升级交互层级。

### 核心设计理念

> **"用户不需要知道什么是 Agent，他只知道 AnyKeep 变聪明了。"**

- 取消全局模式开关，改为基于意图的自动升级
- 传统界面具备 AI 的预测能力
- AI 界面具备传统界面的可控性

### 核心价值

| 用户类型 | 痛点                       | 解决方案                   |
| -------- | -------------------------- | -------------------------- |
| 新用户   | 不熟悉 AI 交互，担心误操作 | 默认菜单操作 + AI 智能建议 |
| 熟练用户 | 重复性操作效率低           | 预测性操作 + 自动升级      |
| 高级用户 | 希望 AI 自主完成复杂任务   | 全能指令框 + 目标驱动      |

### 与产品愿景对齐

本功能直接支持 AnyKeep "AI 智能处理" 的核心价值主张，将现有的 AI 辅助能力升级为可控的自主智能体，同时保留传统操作路径确保用户掌控感。

## 功能需求

### REQ-1: 流体升级架构 (Fluid Escalation)

**用户故事:** 作为用户，我想要系统根据操作复杂度自动调整 AI 参与程度，以便无需学习新概念即可享受智能化服务。

#### 验收标准

1. WHEN 用户执行简单操作（如删除单个书签） THEN 系统 SHALL 立即执行，无 AI 干预
2. WHEN 用户执行多步骤操作（如整理文件夹） THEN 系统 SHALL 自动浮出状态栏显示 AI 执行进度
3. WHEN 用户输入复杂目标（如"整理本周文章并写周报"） THEN 系统 SHALL 自动进入目标驱动模式
4. WHEN AI 介入执行 THEN 系统 SHALL 在状态栏显示当前步骤和进度
5. IF 用户 5 秒内无操作 AND 状态栏可见 THEN 系统 MAY 自动最小化状态栏

#### 三级升级机制

```
┌─────────────────────────────────────────────────────────────────┐
│ L1: 即时执行层                                                   │
│ ─────────────────                                               │
│ 触发: 单步操作（删除、收藏、添加标签）                             │
│ 行为: 立即执行 + Toast 通知                                      │
│ AI 角色: 无                                                     │
│ 成本: 0 能量                                                    │
└─────────────────────────────────────────────────────────────────┘
                              ↓ 自动升级
┌─────────────────────────────────────────────────────────────────┐
│ L2: 智能辅助层                                                   │
│ ─────────────────                                               │
│ 触发: 多步骤操作、批量操作、需要分析的操作                         │
│ 行为: 状态栏显示 + 关键步骤确认                                   │
│ AI 角色: 智能助手                                                │
│ 成本: 不显示（轻量级，可忽略）                                    │
│ 示例: 点击"整理" → 状态栏: [分析结构 → 建议移动 5 个 → 确认?]     │
└─────────────────────────────────────────────────────────────────┘
                              ↓ 自动升级
┌─────────────────────────────────────────────────────────────────┐
│ L3: 目标驱动层                                                   │
│ ─────────────────                                               │
│ 触发: 自然语言目标、复杂任务、明确请求 AI 帮助                     │
│ 行为: 生成计划 + 自主执行 + 检查点确认                            │
│ AI 角色: 自主执行者                                              │
│ 成本: 显示能量消耗（⚡ 预计 15 能量）                             │
│ 示例: "帮我把 AI 文章整理并写周报" → 全流程自动化                  │
└─────────────────────────────────────────────────────────────────┘
```

#### 状态栏设计

```
┌─────────────────────────────────────────────────────────────────┐
│ [🤖] 整理中: 分析结构 ✓ → 移动书签 (3/5) → 添加标签    [⏸] [✕] │
└─────────────────────────────────────────────────────────────────┘
```

- 平时隐藏，工作时自动显示
- 点击步骤可展开详情
- 支持暂停和取消

### REQ-2: 预测���操作 (Agent Bait)

**用户故事:** 作为用户，我想要在选中内容后看到 AI 推荐的智能操作，以便在最需要时获得工具支持。

#### 验收标准

1. WHEN 用户选中多个收藏 THEN 系统 SHALL 在 Action Bar 右侧显示 AI 推荐按钮（桌面端）
2. WHEN 用户在移动端选中多个收藏 THEN 系统 SHALL 将 FAB 从 "+" 变形为 "✨"
3. WHEN 推荐按钮生成 THEN 系统 SHALL 在 100ms 内完成（使用规则引擎）
4. IF 规则引擎无明确匹配 THEN 系统 MAY 在 300ms 后显示 LLM 推荐结果
5. WHEN 用户点击推荐按钮 THEN 系统 SHALL 自动升级到 L2/L3 层级执行
6. WHEN 用户连续忽略某类推荐 3 次 THEN 系统 SHALL 降低该类推荐的显示权重

#### 两级分类器架构

```typescript
// L1: 规则引擎 (本地，<10ms)
规则示例:
├── 全是 PDF → 推荐 "✨ 提取文本"
├── 全是英文 → 推荐 "✨ 翻译"
├── 来自同一来源 → 推荐 "✨ 创建合集"
├── 超过 10 个 → 推荐 "✨ 批量整理"
├── 全是技术文章 → 推荐 "✨ 生成摘要"
└── 有重复内容 → 推荐 "✨ 去重"

// L2: LLM 分类器 (仅当 L1 无明确匹配，防抖 300ms)
用于复杂场景的智能推荐
```

### REQ-3: 幽灵指针可视化 (Ghost Interactions)

**用户故事:** 作为用户，我想要看到 AI 正在操作界面的哪个部分，以便建立信任感并��解 AI 的行为。

#### 验收标准

1. WHEN Agent 执行 `select_bookmark(id)` THEN 系统 SHALL 高亮闪烁对应书签行
2. WHEN Agent 执行 `switch_folder(name)` THEN 系统 SHALL 自动滚动侧边栏并选中文件夹
3. WHEN 目标元素不在视口内 THEN 系统 SHALL 先滚动到可见区域再高亮
4. WHEN 高亮显示 THEN 系统 SHALL 持续 1.5 秒后渐隐
5. IF 用户正在手动操作同一元素 THEN 系统 SHALL 跳过该元素的高亮

#### 可视化效果

| 操作类型      | 视觉反馈                        |
| ------------- | ------------------------------- |
| 选中/操作书签 | 书签行边框高亮 + 轻微放大动画   |
| 切换文件夹    | 侧边栏滚动 + 文件夹项背景色变化 |
| 添加标签      | 标签气泡弹出动画                |
| 移动书签      | 书签行滑动到目标文件夹方向      |
| 删除书签      | 书签行淡出 + 划线效果           |

#### 分层乐观 UI 策略

**核心原则**: 不等后端成功再动 UI，而是先播放动画，失败再回滚。

```typescript
// 工具自声明乐观更新配置
interface ToolOptimisticConfig {
  enabled: boolean; // 是否启用乐观更新
  successRate: number; // 历史成功率阈值 (>0.95 才启用)
  rollbackAnimation: "shake" | "bounce" | "fade"; // 失败时回滚动画
}

// 分层策略
const optimisticPolicy = {
  // 高成功率操作 → 立即乐观更新
  highConfidence: {
    operations: ["move_bookmark", "add_tag", "remove_tag", "update_title"],
    behavior: "立即播放动画，后端失败则弹回",
    rollbackAnimation: "bounce",
  },

  // 中等风险操作 → 等待确认再动画
  mediumRisk: {
    operations: ["batch_move", "create_folder", "merge_folders"],
    behavior: "显示 Loading 状态，成功后播放动画",
    rollbackAnimation: "shake",
  },

  // 破坏性操作 → 必须等待成功
  destructive: {
    operations: ["delete_bookmark", "delete_folder", "clear_tags"],
    behavior: "等待后端确认，成功后播放淡出动画",
    rollbackAnimation: "fade",
  },
};
```

#### 乐观更新流程

```
Agent 决定移动书签
        ↓
发送 intent_event 给前端
        ↓
前端立即播放移动动画 (乐观更新)
        ↓
    ┌───────┴───────┐
    ↓               ↓
后端成功         后端失败
    ↓               ↓
动画完成         弹回原位 + 提示
```

### REQ-5: 执行监控与控制

**用户故事:** 作为用户，我想要实时了解 AI 的执行进度并能随时干预，以便保持对操作的掌控感。

#### 验收标准

1. WHEN Agent 开始 L2/L3 执行 THEN 系统 SHALL 显示状态栏/监控面板
2. WHEN 步骤状态变化 THEN 系统 SHALL 实时更新进度（100ms 刷新率）
3. WHEN 用户点击已完成步骤 THEN 系统 SHALL 展开显示详细操作日志
4. WHEN 执行遇到错误 THEN 系统 SHALL 暂停执行并显示错误详情
5. WHEN 用户点击 "暂停" THEN 系统 SHALL 立即暂停并保持状态
6. WHEN 用户点击 "手动接管" THEN 系统 SHALL 降级到 L1 并保留任务队列
7. WHEN 执行完成 THEN 系统 SHALL 显示完成通知和回滚选项
8. WHEN L3 任务执行中 THEN 系统 SHALL 在状态栏显示能量消耗

#### 监控面板状态

| 状态   | 图标 | 可用操作             |
| ------ | ---- | -------------------- |
| 规划中 | 🔄   | 取消                 |
| 执行中 | ▶️   | 暂停、取消、手动接管 |
| 检查点 | ⏸️   | 继续、跳过、取消     |
| 已暂停 | ⏸️   | 继续、取消、手动接管 |
| 已完成 | ✅   | 查看报告、撤销全部   |
| 错误   | ❌   | 重试、跳过、取消     |

#### 能量消耗显示 (仅 L3)

```
┌─────────────────────────────────────────────────────────────────┐
│ [🤖] 整理中: 移动书签 (3/5)           ⚡ 已消耗 8/15    [⏸] [✕] │
└─────────────────────────────────────────────────────────────────┘
```

### REQ-6: 混合回滚策略 (Hybrid Rollback)

**用户故事:** 作为用户，我想要在 AI 执行完成后能够一键撤销所有操作，以便放心让 AI 自主执行。

#### 验收标准

1. WHEN Agent 任务开始 THEN 系统 SHALL 根据操作类型选择回滚策略
2. WHEN 任务完成 THEN 系统 SHALL 显示 Toast "任务已完成 [撤销本次操作]"，持续 10 秒
3. WHEN 用户点击 "撤销本次操作" THEN 系统 SHALL 在 3 秒内执行回滚
4. WHEN 回滚日志超过 24 小时 THEN 系统 SHALL 自动清理
5. IF 回滚过程中检测到冲突（实体已被用户修改） THEN 系统 SHALL 提示用户选择

#### 混合回滚策略

```typescript
interface HybridRollbackStrategy {
  // 简单操作 → Undo Log (高效，毫秒级回滚)
  undoLog: {
    move_bookmark: { inverse: "move_bookmark"; params: ["originalFolderId"] };
    add_tag: { inverse: "remove_tag"; params: ["tagId"] };
    remove_tag: { inverse: "add_tag"; params: ["tagId"] };
    update_title: { inverse: "update_title"; params: ["originalTitle"] };
    update_note: { inverse: "update_note"; params: ["originalNote"] };
  };

  // 复杂操作 → 状态快照 (可靠，原子性恢复)
  snapshot: {
    batch_move: true; // 批量移动涉及多个原位置
    create_folder: true; // 创建后可能被其他操作依赖
    merge_folders: true; // 合并涉及复杂状态变化
  };

  // 破坏性操作 → 软删除 (已有能力，直接复用)
  softDelete: {
    delete_bookmark: true; // 标记 deleted_at，保留 30 天
    delete_folder: true; // 同上
  };
}
```

### REQ-7: 检查点与安全机制

**用户故事:** 作为用户，我想��在 AI 执行关键操作前获得确认机会，以便防止意外的数据损坏。

#### 验收标准

1. WHEN Agent 即将执行删除操作 THEN 系统 SHALL 强制触发检查点
2. WHEN Agent 即将批量修改 >10 个项目 THEN 系统 SHALL 触发检查点
3. WHEN 检查点触发 THEN 系统 SHALL 暂停执行并显示操作预览
4. WHEN 用户在检查点选择 "跳过" THEN 系统 SHALL 记录并继续执行
5. IF 用户在同一会话内 3 次跳过同类检查点 THEN 系统 SHALL 询问是否禁用

#### 默认检查点规则

| 触发条件        | 检查点类型 | 可配置   |
| --------------- | ---------- | -------- |
| 删除任意项目    | 强制确认   | 否       |
| 批量修改 >10 项 | 预览确认   | 阈值可调 |
| 创建/删除文件夹 | 预览确认   | 是       |
| 修改用户设置    | 强制确认   | 否       |

### REQ-8: 上下文状态桥接

**用户故事:** 作为用户，我想要 AI 操作时界面能同步更新，以便我能看到实时变化。

#### 验收标准

1. WHEN Agent 执行操作 THEN 系统 SHALL 实时更新传统 UI 的列表视图
2. WHEN Agent 完成操作 THEN 系统 SHALL 高亮显示受影响项 3 秒（幽灵指针）
3. WHEN 用户手动操作 THEN 系统 SHALL 将当前选中项同步到 Agent 上下文
4. IF 存在未完成任务 THEN 系统 SHALL 在状态栏显示任务数量

#### 同步机制

### REQ-10: 渐进式成本透明

**用户故事:** 作为用户，我想要了解 AI 功能的使用成本，以便做出明智的使用决策。

#### 验收标准

1. WHEN L1 操作执行 THEN 系统 SHALL NOT 显示任何成本信息
2. WHEN L2 操作执行 THEN 系统 SHALL 仅显示 "AI 辅助中" 徽章
3. WHEN L3 操作开始前 THEN 系统 SHALL 显示预估能量消耗
4. WHEN L3 操作执行中 THEN 系统 SHALL 实时显示已消耗/预估总量
5. WHEN 剩余能量 <20% THEN 系统 SHALL 显示低能量提醒
6. WHEN 剩余能量不足以完成任务 THEN 系统 SHALL 在执行前阻断并提示

#### 渐进式透明策略

```typescript
interface CostTransparencyStrategy {
  // L1: 即时执行 - 不显示成本（无 Token 消耗）
  L1: {
    showCost: false;
    showBadge: false;
  };

  // L2: 智能辅助 - 仅显示 AI 徽章
  L2: {
    showCost: false;
    showBadge: true; // 显示 "AI" 标识
  };

  // L3: 目标驱动 - 显示能量消耗
  L3: {
    showCost: true;
    costUnit: "能量"; // 用"能量"而非"Token"，更友好
    showEstimate: true; // 执行前显示预估
    showRealtime: true; // 执行中实时更新
  };
}
```

#### 配额策略

```typescript
interface QuotaPolicy {
  free: {
    dailyL3Tasks: 10; // 每日 10 次 L3 免费

    energyPool: 2000; // 每月 2000 能量

  // 配额不足时的处理
  onQuotaLow: {
    threshold: 0.2; // <20% 时提醒

  onQuotaExhausted: {
    action: "gentle_block"; // 温和阻断
    message: "今日能量已用完，明日 00:00 重置";
    upgradePrompt: true; // 显示升级入口
  };
}
```

## 非功能需求

### 性能要求

| 指标              | 目标值      | 测量方式       |
| ----------------- | ----------- | -------------- |
| 规则引擎推荐      | <100ms      | 选中到按钮显示 |
| LLM 推荐 (防抖后) | <500ms      | 防抖结束到显示 |
| 目标解析生成计划  | <3s         | 输入到显示计划 |
| 单步骤执行时间    | <2s（平均） | 不含网络请求   |
| 高亮动画          | 60fps       | 动画流畅度     |
| 乐观更新回滚      | <100ms      | 失败到弹回完成 |
| Undo Log 回滚     | <500ms      | 点击到恢复完成 |
| 快照回滚          | <3s         | 点击到恢复完成 |

### 安全要求

1. **操作审计**: 所有 Agent 执行的操作必须记录到审计日志
2. **权限边界**: Agent 不能执行超出用户权限范围的操作
3. **数据保护**: 删除操作必须支持软删除，保留 30 天恢复窗口
4. **Undo Log 隔离**: Undo Log 仅在当前设备存储，不跨设备同步

### 可靠性要求

1. **状态持久化**: Agent 执行状态每步骤持久化，支持异常恢复
2. **错误恢复**: 单步骤失败不影响整体任务，支持重试或跳过
3. **事务性**: 回滚操作保证原子性（Undo Log 按序执行）
4. **降级策略**: Agent 服务不可用时自动降级到 L1 层级
5. **乐观更新一致性**: 后端失败时确保 UI 状态与数据库一致

### 可用性要求

1. **零学习成本**: 流体升级对用户透明，无需学习新概念
2. **渐进式引导**: 首次触发 L2/L3 时显示简短说明
3. **快捷键**: Cmd/Ctrl + K 唤起指令框
4. **移动端适配**: 动态 FAB + Bottom Sheet 交互
5. **成本感知**: 用"能量"替代"Token"，降低技术门槛

### 代码架构要求

- **单一职责**: 每个组件/服务专注单一功能
- **模块化设计**: 升级管理、执行监控、上下文桥接、回滚策略独立模块
- **依赖管理**: 复用现有 AI 基础设施
- **UI 绑定工具**: Tool 增加 `optimistic` 和 `highlightElementId` 属性
- **成本集成**: 与 SubscriptionService 深度集成

1. 基于现有 Next.js 14 + React 架构

2. 单次目标最多支持 20 个步骤
3. Undo Log 保留时间 24 小时
4. Free 用户每日 10 次 L3 任务

### 假设

1. 用户已熟悉 AnyKeep 基本功能
2. 现有 AI 基础设施稳定可用
3. 用户网络环境稳定
4. 高成功率操作 (>95%) 适合乐观更新
