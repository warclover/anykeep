## 1. 设计目标与定位

### 1.1 核心目标

AnyKeep 的 AI 摘要不是简单的「一段话总结」，而是围绕 **「个人知识管理 + 学习闭环」** 场景，提供多层级、多场景、可交互的摘要能力。

**差异化定位**：

- 不只是「告诉用户这篇文章讲了什么」，而是「帮助用户快速决策、高效学习、真正用起来」
- 支持多粒度摘要（一句话 / 要点式 / 结构化），适配不同使用场景
- 与评级、复盘、搜索、行动项等功能深度联动，形成知识管理闭环

### 1.2 用户价值

1. **快速决策**：在列表视图看到一句话摘要，快速判断是否需要深入阅读
2. **高效学习**：在详情页看到要点式/结构化摘要，快速抓住核心内容
3. **实践导向**：生成可执行的步骤清单、行动建议，从「知道」到「做到」
4. **长期复盘**：摘要与自测题目、行动建议结合，支持学习闭环

## 2. 功能模块设计

### 2.1 多层级摘要系统

#### 2.1.1 摘要粒度定义

**三级摘要体系**：

1. **超短摘要（15–30 字）**
   - 用途：列表卡片、搜索结果预览
   - 特点：一句话概括核心，帮助快速筛选
   - 示例：`介绍用 Obsidian 搭建个人知识管理系统的方法，包括插件推荐和工作流设计。`

2. **要点式摘要（3–7 条要点）**
   - 用途：详情页默认展示、快速浏览
   - 特点：结构化要点，便于快速扫读
   - 示例：
     ```
     • 核心观点：Obsidian 适合做个人知识库，关键在于插件和工作流
     • 推荐插件：Templater、Dataview、Calendar
     • 工作流：每日笔记 → 周报 → 项目追踪
     • 适用场景：知识工作者、学生、研究者
     ```

3. **结构化摘要（完整版）**
   - 用途：深度阅读、复盘、输出准备
   - 特点：包含背景、核心观点、论据、结论、适用场景等
   - 示例：

     ```
     【背景】
     本文介绍如何用 Obsidian 搭建个人知识管理系统。

     【核心观点】
     1. Obsidian 的核心优势在于双向链接和本地存储
     2. 插件生态丰富，可根据需求定制工作流
     3. 工作流设计比工具本身更重要

     【关键论据】
     - Templater 插件可以自动化笔记模板
     - Dataview 插件可以实现数据查询和统计
     - Calendar 插件可以按时间维度组织笔记

     【适用场景】
     - 知识工作者需要管理大量文档和想法
     - 学生需要整理课程笔记和论文
     - 研究者需要追踪文献和研究进展

     【不适用场景】
     - 需要多人协作的场景（建议用 Notion）
     - 需要云端实时同步的场景（建议用 Obsidian Sync）
     ```

#### 2.1.2 数据模型

```sql
-- 在 bookmarks 表中已有 ai_summary 字段
-- 需要新增字段支持多层级摘要

ALTER TABLE bookmarks ADD COLUMN IF NOT EXISTS ai_summary_short TEXT;      -- 超短摘要（15-30字）
ALTER TABLE bookmarks ADD COLUMN IF NOT EXISTS ai_summary_points JSONB;    -- 要点式摘要（JSON数组）
ALTER TABLE bookmarks ADD COLUMN IF NOT EXISTS ai_summary_structured JSONB; -- 结构化摘要（JSON对象）
ALTER TABLE bookmarks ADD COLUMN IF NOT EXISTS ai_summary_version INT DEFAULT 1; -- 摘要版本（用于重新生成）
ALTER TABLE bookmarks ADD COLUMN IF NOT EXISTS ai_summary_confidence FLOAT; -- 摘要可信度（0-1）
```

**JSON 结构示例**：

```json
// ai_summary_points

  "核心观点：Obsidian 适合做个人知识库",
  "推荐插件：Templater、Dataview、Calendar",
  "工作流：每日笔记 → 周报 → 项目追踪"
]

// ai_summary_structured
{
  "background": "本文介绍如何用 Obsidian 搭建个人知识管理系统。",
  "core_points": [
    "Obsidian 的核心优势在于双向链接和本地存储",
    "插件生态丰富，可根据需求定制工作流"
  ],
  "key_arguments": [
    "Templater 插件可以自动化笔记模板",
    "Dataview 插件可以实现数据查询和统计"
  ],
  "applicable_scenarios": [
    "知识工作者需要管理大量文档和想法",
    "学生需要整理课程笔记和论文"
  ],
  "non_applicable_scenarios": [
    "需要多人协作的场景（建议用 Notion）"
  ]
}
```

#### 2.1.3 生成策略

**一次性生成 vs 按需生成**：

- **新建收藏时**：默认生成「超短摘要 + 要点式摘要」
- **结构化摘要**：按需生成（用户点击「查看完整摘要」时触发）
- **重新生成**：用户可以在详情页点击「重新生成摘要」，选择粒度

**成本控制**：

- 超短摘要：可以复用要点式摘要的第一条，或单独调用（成本低）
- 要点式摘要：主要摘要，每次收藏都生成
- 结构化摘要：仅在用户明确需要时生成（Pro 功能，有配额限制）

### 2.2 任务/场景导向摘要

#### 2.2.1 摘要类型定义

**三种场景模式**：

1. **学习模式**
   - 目标：帮助用户理解和记忆
   - 重点：概念、原理、关键例子、知识点
   - 输出格式：

     ```
     【核心概念】
     - 概念 1：定义 + 例子
     - 概念 2：定义 + 例子

     【关键原理】
     - 原理 1：说明
     - 原理 2：说明

     【需要记住的要点】
     1. 要点 1
     2. 要点 2
     ```

2. **实践模式**
   - 目标：帮助用户执行和操作
   - 重点：步骤、注意事项、检查清单
   - 输出格式：

     ```
     【执行步骤】
     1. Step 1：具体操作
     2. Step 2：具体操作

     【注意事项】
     - 注意点 1
     - 注意点 2

     【检查清单】
     - [ ] 检查项 1
     - [ ] 检查项 2
     ```

3. **创作模式**
   - 目标：帮助用户引用和创作
   - 重点：观点、金句、逻辑框架、可引用素材
   - 输出格式：

     ```
     【核心观点】
     - 观点 1：可引用的表述
     - 观点 2：可引用的表述

     【金句摘录】
     - "金句 1"
     - "金句 2"

     【逻辑框架】
     1. 框架结构 1
     2. 框架结构 2
     ```

#### 2.2.2 用户交互设计

**在详情页提供摘要模式切换**：


**生成时机**：

- 默认摘要：创建收藏时自动生成
- 场景摘要：用户切换模式时按需生成（可缓存，避免重复调用）

### 2.3 结构化摘要：从段落到字段

#### 2.3.1 结构化字段定义

**通用字段**（适用于所有内容类型）：

- `background`：背景/上下文
- `core_points`：核心观点（数组）
- `key_arguments`：关键论据/例子（数组）
- `conclusions`：结论/总结
- `applicable_scenarios`：适用场景（数组）
- `non_applicable_scenarios`：不适用场景（数组）

**步骤型内容字段**（适用于教程/指南）：

- `steps`：步骤列表（数组，每个步骤包含：序号、描述、注意事项）
- `prerequisites`：前置条件
- `tools_resources`：所需工具/资源

**对比型内容字段**（适用于评测/对比）：

- `comparison_items`：对比项列表
- `comparison_table`：对比表格（JSON）
- `recommendations`：推荐建议

#### 2.3.2 数据模型

```sql
-- 使用 JSONB 字段存储结构化摘要
-- ai_summary_structured 字段（已在 2.1.2 中定义）

-- 示例数据
{
  "type": "tutorial",  // 内容类型：tutorial / comparison / article
  "background": "...",
  "core_points": [...],
  "steps": [
    {
      "step": 1,
      "description": "...",
      "notes": "..."
    }
  ],
  "comparison_table": {
    "items": ["方案A", "方案B"],
    "criteria": ["价格", "功能", "易用性"],
    "scores": [[100, 80], [90, 95], [85, 90]]
  }
}
```

#### 2.3.3 UI 展示设计

**结构化摘要的渲染**：

```tsx
// 伪代码示意
<StructuredSummary data={summary}>
  {summary.background && (
    <Section title="背景">
      <p>{summary.background}</p>
    </Section>
  )}

  {summary.core_points && (
    <Section title="核心观点">
      <ul>
        {summary.core_points.map((point, i) => (
          <li key={i}>{point}</li>
        ))}
      </ul>
    </Section>
  )}

  {summary.steps && (
    <Section title="执行步骤">
      <ol>
        {summary.steps.map((step, i) => (
          <li key={i}>
            <strong>步骤 {step.step}：</strong>
            {step.description}
            {step.notes && <Note>{step.notes}</Note>}
          </li>
        ))}
      </ol>
    </Section>
  )}
</StructuredSummary>
```

**优势**：

- 结构化字段可以单独参与搜索（例如：搜索「包含步骤清单的收藏」）
- 可以导出为 Markdown/JSON，便于后续重组到思维导图/项目空间

### 2.4 与复盘/学习深度绑定

#### 2.4.1 自测题目生成

**功能描述**：
基于摘要内容，自动生成 3–5 个自测题目，帮助用户检验学习效果。

**实现方式**：

```typescript
// 调用 AI 生成自测题目
async function generateQuizQuestions(
  bookmarkId: number,
  summary: string,
): Promise<QuizQuestion[]> {
  const prompt = `
基于以下摘要，生成 3-5 个自测题目，帮助用户检验学习效果。

摘要：
${summary}

要求：
- 题目要覆盖核心知识点
- 可以是选择题、简答题、判断题
- 输出 JSON 格式
`;

  const response = await callAI(prompt);
  return parseQuizQuestions(response);
}

interface QuizQuestion {
  id: string;
  type: "multiple_choice" | "short_answer" | "true_false";
  question: string;
  options?: string[]; // 选择题选项
  correct_answer?: string; // 正确答案（可选，用于自动评分）
  explanation?: string; // 答案解析
}
```

**数据模型**：

```sql

  question_text TEXT NOT NULL,
```

### 2.5 个性化摘要

#### 2.5.1 个性化维度

**基于用户偏好**：

1. **内容风格偏好**
   - 喜欢方法论/框架的用户 → 摘要优先强调结构和步骤
   - 喜欢案例/故事的用户 → 摘要多保留例子和场景描述

2. **领域偏好**
   - 技术类用户 → 使用技术术语，强调实现细节
   - 产品类用户 → 强调用户价值、商业模式
   - 设计类用户 → 强调视觉、交互、用户体验

3. **学习习惯**
   - 喜欢深度学习的用户 → 摘要更详细，包含更多背景
   - 喜欢快速浏览的用户 → 摘要更简洁，只保留核心

#### 2.5.2 实现方式（轻量版）

**不需要训练复杂模型，使用 Prompt 模板切换**：

```typescript
interface UserPreference {
  content_style: "methodology" | "case_study" | "balanced";
  domain_focus: string[]; // 关注的领域，如 ['tech', 'product', 'design']
  learning_style: "deep" | "quick" | "balanced";
}

function getPersonalizedPrompt(
  basePrompt: string,
  userPreference: UserPreference,
): string {
  let personalizedPrompt = basePrompt;

  // 根据内容风格调整
  if (userPreference.content_style === "methodology") {
    personalizedPrompt += "\n\n重点强调：方法、框架、步骤、结构";
  } else if (userPreference.content_style === "case_study") {
    personalizedPrompt += "\n\n重点强调：案例、例子、场景、故事";
  }

  // 根据领域调整术语
  if (userPreference.domain_focus.includes("tech")) {
    personalizedPrompt += "\n\n使用技术术语，强调实现细节";
  }

  // 根据学习习惯调整详细程度
  if (userPreference.learning_style === "deep") {
    personalizedPrompt += "\n\n摘要要详细，包含背景和上下文";
  } else if (userPreference.learning_style === "quick") {
    personalizedPrompt += "\n\n摘要要简洁，只保留核心要点";
  }

  return personalizedPrompt;
}
```

**用户设置入口**：

- 在设置页增加「摘要偏好」配置
- 用户可以选择：内容风格、领域偏好、学习习惯
- 系统根据偏好调整摘要生成策略

### 2.8 多文档合并摘要

#### 2.8.1 功能描述

对同一主题的多条收藏（例如：多个「Obsidian 教程」），生成：

- **共通要点摘要**：这些内容共同在讲什么？
- **差异点摘要**：各自的独特之处/优缺点
- **综合版实践指南**：把多篇收藏合并为一篇自己的总结

#### 2.8.2 实现方式

**数据模型**：

```sql
CREATE TABLE merged_summaries (
  id BIGSERIAL PRIMARY KEY,
  user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  name VARCHAR(200) NOT NULL,  -- 合并摘要名称，如「Obsidian 教程综合指南」
  source_bookmark_ids BIGINT[] NOT NULL,  -- 来源收藏 ID 列表

  differences JSONB,    -- 差异点
  comprehensive_guide TEXT,  -- 综合版指南

);
```

**生成逻辑**：

```typescript
async function generateMergedSummary(
  bookmarkIds: number[],
  userId: string,
): Promise<MergedSummary> {
  // 1. 获取所有收藏的摘要
  const summaries = await getBookmarkSummaries(bookmarkIds);

  // 2. 生成共通要点
  const commonPointsPrompt = `
以下是多篇关于同一主题的内容摘要，请提炼共通要点。

摘要列表：
${summaries.map((s, i) => `${i + 1}. ${s}`).join("\n")}

要求：
- 找出这些内容的共同主题和观点
- 提炼核心要点（3-5 条）
- 输出 JSON 格式
`;

  // 3. 生成差异点
  const differencesPrompt = `
以下是多篇关于同一主题的内容摘要，请分析各自的独特之处。

摘要列表：
${summaries.map((s, i) => `${i + 1}. ${s}`).join("\n")}

要求：
- 找出每篇内容的独特观点/方法
- 分析各自的优缺点
- 输出 JSON 格式
`;

  // 4. 生成综合版指南
  const guidePrompt = `
基于以下多篇内容摘要，生成一份综合版实践指南。

摘要列表：
${summaries.map((s, i) => `${i + 1}. ${s}`).join("\n")}

要求：
- 整合所有内容的精华
- 形成一份可执行的实践指南
- 包含步骤、注意事项、推荐方案
- 输出 Markdown 格式
`;

  const [commonPoints, differences, guide] = await Promise.all([
    callAI(commonPointsPrompt),
    callAI(differencesPrompt),
    callAI(guidePrompt),
  ]);

  return {
    common_points: parseJSON(commonPoints),
    differences: parseJSON(differences),
    comprehensive_guide: guide,
  };
}
```

### 2.10 质量控制与可信度反馈

#### 2.10.1 摘要可信度评估

**评估维度**：

1. **原文质量**
   - 原文长度、结构完整性、抓取成功率

2. **摘要质量**
   - 摘要长度是否合理
   - 是否包含核心信息
   - 是否与原文标题/标签一致

3. **用户反馈**
   - 用户是否标记「摘要不准确」
   - 用户是否频繁编辑摘要

**实现方式**：

```typescript
interface SummaryQuality {
  source_quality: number; // 0-1，原文质量得分
  summary_quality: number; // 0-1，摘要质量得分
  user_feedback: number; // 0-1，用户反馈得分（基于编辑频率、标记等）
  overall_confidence: number; // 综合可信度
}

function calculateSummaryConfidence(bookmark: Bookmark): SummaryQuality {
  // 1. 评估原文质量
  const sourceQuality = evaluateSourceQuality(bookmark);

  // 2. 评估摘要质量
  const summaryQuality = evaluateSummaryQuality(bookmark.ai_summary);

  // 3. 评估用户反馈
  const userFeedback = evaluateUserFeedback(bookmark);

  // 4. 综合可信度
  const overallConfidence =
    sourceQuality * 0.3 + summaryQuality * 0.5 + userFeedback * 0.2;

  return {
    source_quality: sourceQuality,
    summary_quality: summaryQuality,
    user_feedback: userFeedback,
    overall_confidence: overallConfidence,
  };
}
```

**UI 展示**：

- 在摘要区域显示可信度指示器（如：`可信度：85%`）
- 低可信度摘要（< 70%）显示警告提示：「摘要可能不准确，建议查看原文」

## 4. 成本控制策略

### 4.1 摘要生成成本

**策略**：

1. **分级生成**
   - 超短摘要：可以复用要点式摘要，或单独调用（成本低）
   - 要点式摘要：主要摘要，每次收藏都生成
   - 结构化摘要：仅在用户明确需要时生成（Pro 功能，有配额限制）

2. **缓存机制**
   - 相同内容的摘要可以缓存（基于 URL + 内容 hash）
   - 场景摘要（学习/实践/创作）可以缓存，避免重复生成

3. **批量生成优化**
   - 批量导入时，可以批量调用 AI API（控制并发）
   - 使用更便宜的模型（如 DeepSeek）做批量摘要

### 4.2 成本估算

**OpenAI GPT-4o-mini**（假设）：

- 输入：~2000 tokens（标题 + 内容）
- 输出：~500 tokens（摘要）
- 成本：~$0.001 per 摘要

**DeepSeek**（更便宜）：

- 成本约为 OpenAI 的 1/10

**1000 条收藏**：

- 要点式摘要：~$1（OpenAI）或 ~$0.1（DeepSeek）
- 结构化摘要（按需）：额外成本
