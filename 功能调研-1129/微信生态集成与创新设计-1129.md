## 微信生态集成与创新设计（AnyKeep）

**文档日期**：2025-11-29  
**文档版本**：V1.0

本文件围绕微信生态（公众号 + 视频号），结合 AnyKeep 的产品定位（跨平台收藏 + AI 知识管理 + 学习复盘），整理一套可落地的集成与创新方向，用于后续功能规划与迭代参考。

---

## 1. 设计目标与整体思路

### 1.1 目标

1. 让 AnyKeep 成为「微信内容（公号 + 视频号）」的**最佳外部知识承载空间**。
2. 不只是保存链接，而是将公号长文与视频号内容**结构化、卡片化、可复盘**。
3. 与其他平台（B 站、小红书、浏览器书签等）统一到同一个知识空间和学习闭环中。

### 1.2 整体思路

- 针对 **公众号**：从「整篇文章」走向「结构化知识卡片」。
- 针对 **视频号**：围绕时间轴、要点提炼与多模态笔记做增强。
- 针对 **跨平台**：以「主题/作者/动机」为线索串联微信与外部内容。
- 同时考虑微信生态的合规与技术边界，尽量通过「分享 → 链接 → 解析」方式接入。

---

## 2. 公众号集成与创新设计

### 2.1 文章结构自动提炼与卡片化

#### 2.1.1 功能概述

在现有「AI 摘要+标签」基础上，为公众号文章提供更深入的结构化能力：

- **自动提纲**：从正文提取出 3–7 个小节标题 + 关键句。
- **知识卡片化（中长期）**：将一篇长文拆分为多张「知识卡片」，每张对应一个小节或关键观点。

#### 2.1.2 UI 表现

- 收藏详情页中，增加「文章大纲」区域：
  - 按层级展示：章节标题 + 每节一句话概括。
  - 支持点击某小节，跳转到原文对应位置（若技术可行，至少可记录小节标题以便回想）。
- 卡片化视图（后续）：
  - 在 AnyKeep 内，将长文拆成数张子卡片：
    - 每张卡片：小节标题 + 段落摘要 + 自己的笔记。
  - 用户可对单独卡片打标签/评级/加入专题。

#### 2.1.3 技术要点

- 文本来源：通过分享链接获取文章正文 HTML，再做正文抽取（现有爬虫基础上升级）。
- 结构抽取：使用规则 + LLM 混合方式：
  - 规则：根据 `<h1/h2/h3>` 标签、标点、换行等做初步分段。
  - LLM：基于分段文本生成章节标题与一句话总结。

### 2.2 高亮与摘录机制

#### 2.2.1 功能概述

帮助用户在「阅读公号」的过程中顺手完成「筛选与提炼」，而不是读完再整篇收藏：

- 在阅读页面（浏览器或小程序环境）支持文本划选 → 「保存高亮到 AnyKeep」。
- 高亮被视为「子卡片」，挂载在该文章收藏之下。

#### 2.2.2 交互流程

1. 用户在公众号文章中划选一段文字。
2. 通过浏览器扩展或小程序浮层，点击「保存到 AnyKeep」。
3. AnyKeep 记录：文章标题、链接、选中段落、时间戳（可选）、用户备注。
4. 在 AnyKeep 内，文章详情页展示「我的高亮」列表。

#### 2.2.3 高亮视图

- 提供一个「高亮/摘录」视图：
  - 以文章为分组，展示所有选中段落。
  - 支持按主题/标签聚合高亮（例如「所有关于 HTTP 状态码的摘录」）。

**价值**：帮助用户将「被动阅读」转为「主动筛选」，大幅提升内容复盘效率。

---

### 2.3 系列/专栏识别与跟踪

#### 2.3.1 功能概述

许多公众号采用系列/专栏形式（如「XX 指南（上/中/下）」），AnyKeep 可以：

- 自动识别系列文章（基于标题/目录页/作者标记等）。
- 将同一系列下的收藏归为一组，提供「系列视图」。

#### 2.3.2 UI 表现

- 在收藏详情中显示：
  - 若属于某系列，展示「系列：XXX（第 N 篇，共 M 篇）」
  - 提供「查看系列」入口，按顺序列出所有相关文章。
- 在列表中提供「系列过滤」：
  - 例如仅看某个专栏/课程的内容。

#### 2.3.3 技术思路

- 标题模式识别：
  - 正则匹配常见序号模式，如 `（一）/（二）`、`上/中/下`、`Part 1/2/3`。
- 作者+标题主题聚类：
  - 同一作者 + 相似标题关键部分 + 相近时间 → 归为一组。

## 3. 视频号集成与创新设计

### 3.1 时间轴笔记与书签

#### 3.1.1 功能概述

针对视频号教程/拆解类内容，提供「时间点/片段」级别的知识标记：

- 用户可以为某个时间点或时间段添加笔记：
  - 例如：`00:35 - 讲了 REST 的 4 个约束`、`02:10–02:40 - DEMO 演示配置过程`。
- 在 AnyKeep 内形成该视频的「时间轴视图」。

#### 3.1.2 交互设计

- 在视频详情页：
  - 显示一列时间点标记，按时间顺序排列。
  - 点击某一行 → 在原视频中跳转（若技术限制，则至少提示时间点）。
- 在编辑时：
  - 用户输入时间（手动或通过「当前时间」按钮）+ 简短笔记。

#### 3.1.3 技术边界

- 若能获取视频号的「带时间参数」链接或跳转 API，可实现深度跳转。
- 若不可，则以文本标记为主，让用户手动拖动进度条到指定时间点。

---

### 3.2 文本内容提取与摘要

#### 3.2.1 功能概述

在合规前提下，将视频内容部分文本化，以便：

- 更好地进行语义搜索与摘要
- 与文字内容统一进入知识库

#### 3.2.2 技术手段（视可行性分层）

1. **优先使用已有字幕**：
   - 若视频号存在官方字幕/文案，可在链接解析时提取。

2. **备选：语音转文字**：
   - 若允许技术上进行语音转写，可对完整或片段音频做 STT（Speech-to-Text），再进行摘要与要点提炼。

3. **极简方案**：
   - 用户手动写笔记，配合简短 AI 提示词生成要点摘要即可，不强求自动全文转写。
