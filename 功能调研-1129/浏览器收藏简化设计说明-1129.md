## 浏览器收藏简化设计说明（无图片极简卡片）

**文档日期**：2025-11-29  
**文档版本**：V1.0

本设计说明用于指导 AnyKeep「浏览器收藏」在列表中的展示形态，目标是在**不使用任何封面图片 / favicon** 的前提下，依然让用户一眼看清一条网页收藏的关键信息：

- 这是哪个网站（域名）？
- 大概是哪一类页面（路径信息）？
- 标题是什么、是否值得点开？

---

## 1. 设计目标与原则

### 1.1 设计目标

1. **信息密度高但不压迫**：主要依靠文字排版和层级，而不是图片。
2. **强调网站来源与页面标题**：方便用户快速识别与信任。
3. **URL 精确但不冗长**：在有限空间内展示关键信息，如主域名 & 主要路径。
4. **适配多平台与主题**：在浅色/深色主题下都清晰可读。

### 1.2 设计原则

- **主次分明**：标题 > 域名 > 路径 > 辅助标签/时间。
- **不显示完整 URL**，只展示主干信息 + 必要提示（例如参数数量）。
- **不使用图片**：不加载封面图、favicon，仅用 Emoji/矢量小图标表示协议/平台。

---

## 2. 信息结构与层级

浏览器收藏卡片推荐为「最多三行 + 右侧/底部辅助区域」结构：

### 2.1 第一行：域名信息（来源识别）

**展示内容：**

- 安全状态图标（协议）
  - `🔒` 表示 HTTPS
  - `⚠` 或 `http` 小字表示 HTTP（非加密，可选）
- 子域名 + 主域名 + 顶级域：
  - 子域名：浅色文字，例如 `developer.`
  - 主域名+顶级域：加粗，例如 `github.com`

**视觉示例（文字表示）：**

- `🔒  developer.`**`apple.com`**
- `🔒  docs.`**`supabase.com`**
- `🔒  www.`**`sspai.com`**

**设计要点：**

- 子域名信息保留，帮助识别站点的具体区域（如 docs/blog/dev）。
- 主域名加强对比度，使用户迅速确认来源。

### 2.2 第二行：标题（主阅读焦点）

**展示内容：**

- 收藏的页面标题（来自爬虫/元数据），可编辑。
- 文字样式：
  - 使用较大字号，半粗/粗体。
  - 单行或最多两行展示，超出部分以省略号截断。

**示例：**

- `用 Obsidian 搭建个人知识管理系统的完整指南`
- `如何使用 GitHub Actions 自动部署静态网站`

> 标题是用户判断是否点击的核心，应在视觉上优先于 URL 信息。

### 2.3 第三行：路径信息（URL 精简表示）

**展示内容：**

- 主域名之后的路径部分，以「文件路径」比喻展示：
  - 以 `~` 起始：`~/blog/2025/obsidian-pkm-intro`
  - 使用等宽字体 + 浅灰色，弱化视觉但仍易读。

**简化规则：**

- 仅展示 path 部分，不展示协议与主域名（已在第一行展示）。
- 对于多级路径：
  - 正常长度：完整展示：`~/docs/guides/local-development`
  - 过长时：保留首段和末段，中间用 `…`：
    - `~/posts/…/obsidian-pkm-intro`
- 带有复杂 query 参数时：
  - 默认省略 query，仅在末尾添加提示：
    - `~/search/results   ? 5 params`
  - 鼠标悬浮时可在 tooltip 中展示完整 URL（可选）。

### 2.4 辅助信息区（右侧或底部）

**可选展示内容：**

- 平台小标签（根据域名/平台识别）：
  - 例如：`Web` / `Doc` / `Blog` / `Dev`
  - 使用小号标签样式，不喧宾夺主。
- 收藏时间 / 最近访问时间：
  - 示例：`收藏于 2025-11-29`、`最近访问 3 天前`。
- 操作图标：
  - 打开链接 / 复制链接 / 更多菜单（三点）。

> 辅助信息不应占用主视觉区域，可放在卡片右下角或第三行右侧。

## 3. URL 解析与展示规则

### 3.1 URL 解析步骤

给定原始 URL（例如：`https://developer.apple.com/documentation/swift`）：

1. 解析协议：`https`
2. 解析主机：`developer.apple.com`
   - 子域名：`developer`
   - 主域名：`apple`
   - 顶级域：`.com`
3. 解析路径：`/documentation/swift`
4. 解析 query & fragment：如 `?q=xxx&lang=zh#section-1`（通常不展示在主视图）

### 3.2 映射到展示字段

**第一行：**

- 协议 → 安全图标：
  - `https` → `🔒`
  - `http` → `⚠` 或小写 `http` 提示
- host：
  - 子域名 → 浅色：`developer.`
  - 主域名+顶级域 → 加粗：`apple.com`

**第三行：**

- 路径：
  - 若为空（如首页）→ 显示：`~/` 或 `~`。
  - 否则使用上述 `~/...` 规则进行简化。
- query 参数：
  - 统计参数数量：`param_count = len(queryParams)`
  - 若 `param_count > 0`：追加 `? N params` 提示。

## 4. 组件结构与接口设计（前端视角）

### 4.1 React 组件接口（示例）

```ts
export interface BrowserBookmarkCardProps {
  title: string; // 页面标题（可编辑）
  url: string; // 原始 URL
  createdAt?: string; // 收藏时间
  lastVisitedAt?: string; // 最近访问时间
  platformLabel?: string; // 平台标签，例如 "Web" / "Blog"
  importance?: 0 | 1 | 2 | 3; // 评级，可选展示
  onOpen?: () => void;
  onCopyLink?: () => void;
  onMore?: () => void;
}
```

内部可拆成两个层级组件：

- `UrlMetaLine`：负责解析并渲染第一行（协议+域名）。
- `UrlPathLine`：负责渲染第三行路径信息。

### 4.2 布局结构（简化示意）

```tsx
<div className="bookmark-card">
  <div className="card-main">
    <div className="card-line-1">
      <ProtocolIcon /> {/* 🔒 / ⚠ */}
      <Subdomain />
      <Domain />
    </div>
    <div className="card-line-2">
      <Title /> {/* 可能带评级小徽标 */}
    </div>
    <div className="card-line-3">
      <Path />
      <QueryHint />
    </div>
  </div>
  <div className="card-meta">{/* 平台标签 / 时间 / 操作按钮 */}</div>
</div>
```

样式建议：

- `card-main` 占主列，`card-meta` 固定宽度靠右或折行到底部。
- 在窄屏（移动端）时，将 `card-meta` 折到标题行下方，以两行布局为主。

## 5. 交互与状态设计

### 5.1 基本交互

- 整卡点击：
  - 默认行为：打开链接（可配置为在新标签页打开）。
  - 支持键盘访问（回车触发）。
- 次级操作：
  - 复制链接按钮：复制完整 URL。
  - 更多菜单：移动到文件夹、设置标签、编辑标题等。

### 5.2 悬浮状态（Hover）

- 整卡轻微提升/阴影增强（提升可点击感）。
- 第一行/第二行文字颜色略增强，暗示可点击。
- 可选：在 hover 时显示完整 URL 的 tooltip（包含 query & fragment）。

### 5.3 不同状态提示（可选）

- 若该收藏被检测为失效（结合失效检测功能）：
  - 在第一行前或第三行右侧显示小徽标：`⚠ 已失效`。
  - 可使用浅色边框或背景以示区别。

## 6. 适配与无障碍

### 6.1 浅色 / 深色主题

- 域名行：使用主题主色或中性深色。
- 标题行：主体文字颜色（最深的黑/白）。
- 路径行：次要文字颜色（中灰 / 浅灰）。

确保在两种主题中对比度均符合 WCAG 基础要求（至少 4.5:1）。

### 6.2 无障碍与可读性

- 即使不依赖颜色（如黑白打印或色弱模式），仍旧通过：
  - 字体粗细（粗体 vs 正常）
  - 字号（标题大于路径）
  - 行距与间距  
    区分层级。
- 所有图标需有 aria-label（例如协议图标说明「使用 HTTPS 安全连接」）。

---

## 7. 与 AnyKeep 其他功能的对接点

1. **平台识别**：
   - 可以与现有 `platform` 字段结合，将域名信息与平台标签（如「微信文章」「B站视频」「通用网页」）统一展示样式。

2. **评级（importance）**：
   - 可在标题右侧增加小徽标，如：`· 高价值`、`· 深度学习`，但不影响卡片整体简洁性。

3. **搜索与筛选**：
   - 当关键词高亮命中标题或路径时，可用下划线/背景色弱高亮对应部分。
