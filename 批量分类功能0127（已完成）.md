## 一、��计理念

### 核心洞察

一次性导入 1000 个收藏与日常单个收藏的逻辑完全不同：

- **单个收藏** = "向已知的架子上摆书"
- **批量导入** = "面对一地乱书，重新设计图书馆的布局"

### 设计原则

1. **不追求即时性，追求全局视野下的合理性**
2. **先做好自动分组，起名字的事可以交给用户**
3. **渐进式信任**：沙盒预览 → 用户确认 → 批量应用
4. **功能解耦**：各模块独立运行，通过接口协作

## 三、核心流程：三步分拣法

### Phase 1: 特征批处理 (Bulk Feature Extraction)

**目标**: 将书签转化为可计算的向量表示，不做任何分类决策

#### 3.1.1 处理内容

1. 全部书签存入临时导入池，标记 `status: 'processing'`

#### 3.1.2 L1.5 标签预分组（新增）

**目标**: 在向量计算前，利用网页自带 keywords 进行预分组，减少后续计算量

```typescript
interface PreGroupingService {
  // 按关键词预分组
  async preGroupByKeywords(bookmarks: Bookmark[]): Promise<PreGroupingResult>;
}

interface PreGroupingResult {
  groups: Map<string, string[]>;  // keyword -> bookmarkIds
  ungrouped: string[];            // 无标签的书签
  superNodes: SuperNode[];        // 聚合后的超级节点
}

interface SuperNode {
  id: string;                     // group:${keyword}
  embedding: number[];            // 代表向量
  memberIds: string[];            // 成员书签 ID
  weight: number;                 // 权重 = 成员数
}
```

**实现逻辑**:

```typescript
async function preGroupByKeywords(bookmarks: Bookmark[]): Promise<PreGroupingResult> {
  const groups = new Map<string, string[]>();
  const ungrouped: string[] = [];

  for (const bookmark of bookmarks) {
    const keywords = bookmark.metadata?.keywords || [];

    if (keywords.length > 0) {
      const primaryKeyword = normalizeKeyword(keywords[0]);
      if (!groups.has(primaryKeyword)) {
        groups.set(primaryKeyword, []);
      }
      groups.get(primaryKeyword)!.push(bookmark.id);
    } else {
      ungrouped.push(bookmark.id);
    }
  }

  // 将 10+ 个同标签书签合并为"超级节点"
  // 注：核心域名白名单只需 5+ 个即可预分组
  const superNodes: SuperNode[] = [];
  for (const [keyword, ids] of groups) {
    if (ids.length >= 10) {
      const representative = await selectRepresentative(ids);
      superNodes.push({
        id: `group:${keyword}`,
        embedding: representative.embedding,
        memberIds: ids,
        weight: ids.length,
      });
    }
  }

  return { groups, ungrouped, superNodes };
}
```

### Phase 2: 无监督聚类 (Unsupervised Clustering)

**目标**: 在不看用户现有文件夹的情况下，发现书签内部的"小圈子"

#### 3.2.1 分层采样聚类算法（性能验证通过）

**问题**: DBSCAN 对 `eps` 参数极其敏感，且全量计算性能瓶颈明显
- eps 太大 → 2-3 个巨大的"杂货堆"
- eps 太小 → 几百个 1-2 篇的"碎屑"
- 全量 DBSCAN 1000 点需要 ~920ms，HDBSCAN 需要 ~6300ms

**解决方案**: 分层采样 DBSCAN（已通过性能验证）

> **性能测试结果** (2026-01-27):
> | 算法 | 100点 | 500点 | 1000点 | 2000点 |
> |-----|-------|-------|--------|--------|
> | 全量 DBSCAN | 9ms | 154ms | 919ms | 跳过 |
> | HDBSCAN | 28ms | 802ms | 6,278ms | 48,480ms |
> | **分层采样 DBSCAN** | **2ms** | **3ms** | **10ms** | **41ms** |

```typescript
interface ClusteringStrategy {
  primary: 'sampled-dbscan';      // 首选：分层采样（快 600 倍）
  fallback: 'iterative-dbscan';   // 兜底：迭代式调参

  sampledDbscanConfig: {
    sampleRatio: 0.1;             // 采样 10%
    minSampleSize: 50;            // 最少采样 50 个
    eps: 0.35;                    // 余弦距离阈值
    minPts: 3;                    // 最小簇点数
    assignmentThreshold: 0.65;    // 分配到簇的相似度阈值
  };

  iterativeDbscanConfig: {
    initialEps: 0.2;
    epsStep: 0.05;
    maxIterations: 5;
    targetClusterRatio: 0.7;      // 目标：70% 书签被成簇
  };
}
```

**分层采样聚类实现**:

```typescript
async function sampledDbscanClustering(
  bookmarks: BookmarkWithEmbedding[],
  config: SampledDbscanConfig
): Promise<ClusteringResult> {
  const n = bookmarks.length;
  const sampleSize = Math.max(config.minSampleSize, Math.floor(n * config.sampleRatio));

  // ============================================
  // 第一轮：采样 + 全量 DBSCAN
  // ============================================
  const sampleIndices = randomSample(n, sampleSize);
  const sampleBookmarks = sampleIndices.map(i => bookmarks[i]);

  const sampleLabels = dbscan(
    sampleBookmarks.map(b => b.embedding),
    config.eps,
    config.minPts
  );

  // ============================================
  // 第二轮：计算簇质心
  // ============================================
  const clusterCentroids = new Map<number, number[]>();
  const clusterMembers = new Map<number, string[]>();

  for (let i = 0; i < sampleLabels.length; i++) {
    const label = sampleLabels[i];
    if (label === -1) continue;  // 跳过噪声点

    if (!clusterCentroids.has(label)) {
      clusterCentroids.set(label, new Array(1536).fill(0));
      clusterMembers.set(label, []);
    }

    // 累加向量
    const centroid = clusterCentroids.get(label)!;
    const embedding = sampleBookmarks[i].embedding;
    for (let d = 0; d < embedding.length; d++) {
      centroid[d] += embedding[d];
    }
    clusterMembers.get(label)!.push(sampleBookmarks[i].id);
  }

  // 归一化质心
  for (const [label, centroid] of clusterCentroids) {
    const count = clusterMembers.get(label)!.length;
    for (let d = 0; d < centroid.length; d++) {
      centroid[d] /= count;
    }
  }

  // ============================================
  // 第三轮：将剩余点分配到最近簇
  // ============================================
  const labels: Map<string, number> = new Map();
  const centroids = Array.from(clusterCentroids.entries());

  for (const bookmark of bookmarks) {
    let bestLabel = -1;
    let bestSimilarity = config.assignmentThreshold;

    for (const [label, centroid] of centroids) {
      const similarity = cosineSimilarity(bookmark.embedding, centroid);
      if (similarity > bestSimilarity) {
        bestSimilarity = similarity;
        bestLabel = label;
      }
    }

    labels.set(bookmark.id, bestLabel);
  }

  return {
    labels,
    clusterCount: clusterCentroids.size,
    noiseCount: Array.from(labels.values()).filter(l => l === -1).length,
  };
}

// 迭代式 DBSCAN 兜底（当采样结果不理想时）
function iterativeDbscan(
  embeddings: number[][],
  config: IterativeConfig
): number[] {
  let eps = config.initialEps;
  let bestLabels: number[] = [];
  let bestRatio = 0;

  for (let i = 0; i < config.maxIterations; i++) {
    const labels = dbscan(embeddings, eps, 3);
    const noiseCount = labels.filter(l => l === -1).length;
    const ratio = 1 - noiseCount / embeddings.length;

    if (ratio > bestRatio) {
      bestRatio = ratio;
      bestLabels = labels;
    }

    if (ratio >= config.targetClusterRatio) {
      return labels;
    }
    eps += config.epsStep;
  }

  return bestLabels;
}
```

#### 3.2.2 时空感知聚类偏置（新增）

**深度洞察**: 用户在短时间内连续收藏的页面，即便语义上稍有偏差，极大概率也属于同一个"研究课题"或"临时项目"。

**解决方案**: 在相似度计算中加入"时间近邻权重"

```typescript
interface TemporalBiasConfig {
  /** 时间窗口配置 */
  windows: [
    { maxMinutes: 5, boost: 0.08 },   // 5分钟内：高度相关
    { maxMinutes: 30, boost: 0.05 },  // 30分钟内：中度相关
    { maxMinutes: 120, boost: 0.02 }, // 2小时内：轻微相关
  ];

  /** 是否考虑收藏顺序（连续收藏比间隔收藏更相关） */
  considerSequence: boolean;
}

function computeTemporalBoost(
  a: { createdAt: Date },
  b: { createdAt: Date }
): number {
  const diffMinutes = Math.abs(
    a.createdAt.getTime() - b.createdAt.getTime()
  ) / 60000;

  if (diffMinutes <= 5) return 0.08;
  if (diffMinutes <= 30) return 0.05;
  if (diffMinutes <= 120) return 0.02;
  return 0;
}
```

**价值**: 解决语义模型无法识别的"情境关联"，例如用户为旅行计划同时搜了酒店、机票和签证，AI 可能分到不同类，但"时间近邻"能把它们聚在一起。

#### 3.2.3 域名协同权重（新增）

**问题**: 仅依靠向量可能丢失关联信息（如 20 个 GitHub 链接逻辑上都属于"技术"）

**解决方案**: 分级域名权重

```typescript
interface DomainWeightConfig {
  // 域名类型分类
  domainCategories: {
    professional: ['github.com', 'stackoverflow.com', 'developer.mozilla.org'];
    contentPlatform: ['medium.com', 'zhihu.com', 'juejin.cn', 'bilibili.com'];
    portal: ['news.google.com', 'hao123.com'];
    shortener: ['bit.ly', 't.co', 'tinyurl.com'];
  };

  // 距离调整因子
  distanceModifiers: {
    professional: -0.15;     // 同一专业站点，距离减少 15%
    contentPlatform: -0.05;  // 内容平台，轻微减少 5%
    portal: 0;               // 门户不调整
    shortener: 0;            // 短链忽略
  };
}

function computeAdjustedDistance(
  a: Bookmark,
  b: Bookmark,
  rawDistance: number
): number {
  if (a.domain === b.domain) {
    const category = getDomainCategory(a.domain);
    const modifier = distanceModifiers[category];
    return Math.max(0, rawDistance + modifier);
  }
  return rawDistance;
}
```

### Phase 3: 映射与生长 (Mapping & Growth)

**目标**: 将聚类结果与用户现有文件夹匹配，或触发新文件夹创建

#### 3.3.1 空洞检测逻辑（新增）

**深度洞察**: 某类书签与"前端"文件夹相似度 0.6，与"后端"相似度 0.55，最终可能被分错。

**解决方案**: 增加"分类孤岛"检测，避免污染用户已整理好的高纯度文件夹

```typescript
interface VacuumDetectionConfig {
  /** 模棱两可阈值：最佳匹配与次优匹配差值 */
  ambiguityThreshold: 0.1;

  /** 最低置信度阈值：低于此值直接建议新建 */
  minConfidenceThreshold: 0.5;

  /** 目标文件夹纯度阈值：低于此值不允许合并 */
  minTargetCohesion: 0.4;
}

function shouldCreateNewFolder(
  clusterCentroid: number[],
  topMatches: FolderMatch[]
): { shouldCreate: boolean; reason?: string } {
  if (topMatches.length < 2) {
    return {
      shouldCreate: topMatches[0]?.similarity < 0.5,
      reason: 'no_good_match',
    };
  }

  const [best, second] = topMatches;

  // 1. 模棱两可检测：差值 < 0.1
  if (best.similarity - second.similarity < 0.1) {
    return {
      shouldCreate: true,
      reason: 'ambiguous_match',  // 宁可新建也不乱分
    };
  }

  // 2. 目标文件夹太乱：不往乱盒子里扔
  if (best.cohesion < 0.4) {
    return {
      shouldCreate: true,
      reason: 'target_folder_messy',
    };
  }

  // 3. 置信度过低
  if (best.similarity < 0.5) {
    return {
      shouldCreate: true,
      reason: 'low_confidence',
    };
  }

  return { shouldCreate: false };
}
```

**价值**: 避免污染用户已经整理好的、高纯度的文件夹。宁可让用户新建，也不要往干净的盒子里扔杂物。

#### 3.3.2 映射策略分级

| 匹配程度 | 条件 | 动作 |
|---------|------|------|
| 精准匹配 | 簇质心与文件夹质心相似度 > 0.75 | 直接归档 |
| 模糊匹配 | 相似度 0.5-0.75 | 列入"建议归档"，需用户确认 |
| 无匹配 | 相似度 < 0.5 | 触发晶体生长，新建文件夹 |
| 目标混乱 | 目标文件夹内聚度 < 0.4 | 建议新建而非合并 |

**核心映射逻辑**:

```typescript
async function mapClustersToExistingFolders(
  clusters: Cluster[],
  existingFolderProfiles: FolderProfile[]
): Promise<MappingResult[]> {
  const mappingResults: MappingResult[] = [];

  for (const cluster of clusters) {
    // 1. 计算簇的平均向量 (Centroid)
    const clusterCentroid = calculateMeanVector(cluster.embeddings);

    // 2. 在现有文件夹向量库中搜索
    const bestMatch = await findMostSimilarFolder(clusterCentroid, existingFolderProfiles);

    // 3. 检查目标文件夹是否混乱
    const targetCohesion = bestMatch ? await computeFolderCohesion(bestMatch.id) : 0;

    if (bestMatch && bestMatch.similarity > 0.75 && targetCohesion > 0.4) {
      // 精准匹配：直接归档
      mappingResults.push({
        clusterId: cluster.id,
        action: 'MERGE',
        targetId: bestMatch.id,
        confidence: bestMatch.similarity,
      });
    } else if (bestMatch && bestMatch.similarity > 0.5) {
      // 模糊匹配：需用户确认
      mappingResults.push({
        clusterId: cluster.id,
        action: 'SUGGEST_MERGE',
        targetId: bestMatch.id,
        confidence: bestMatch.similarity,
        warning: targetCohesion < 0.4 ? 'target_folder_messy' : undefined,
      });
    } else {
      // 无匹配：晶体生长，新建文件夹
      const suggestedName = await generateFolderNameViaLLM(cluster.sampleTitles);
      mappingResults.push({
        clusterId: cluster.id,
        action: 'CREATE',
        name: suggestedName,
        confidence: cluster.cohesion,
      });
    }
  }

  return mappingResults;
}
```

### 6.2 结构质量检测

```typescript
interface OriginalStructureAnalysis {
  /** 原始文件夹数量 */
  folderCount: number;

  /** 有效文件夹数量（包含 >= 3 个书签） */
  validFolderCount: number;

  /** 已分类书签占比 */
  classifiedRatio: number;

  /** 平均文件夹深度 */
  avgDepth: number;

  /** 结构质量评分 (0-1) */
  structureQuality: number;

  /** 推荐处理模式 */
  recommendedMode: 'preserve' | 'hybrid' | 'rebuild';
}

async function analyzeOriginalStructure(
  bookmarks: ImportedBookmark[]
): Promise<OriginalStructureAnalysis> {
  const folders = new Map<string, number>();
  let classifiedCount = 0;
  let totalDepth = 0;

  for (const bookmark of bookmarks) {
    if (bookmark.originalPath && bookmark.originalPath !== '/') {
      classifiedCount++;
      const depth = bookmark.originalPath.split('/').length;
      totalDepth += depth;

      // 统计文件夹使用频率
      const folderPath = bookmark.originalPath;
      folders.set(folderPath, (folders.get(folderPath) || 0) + 1);
    }
  }

  const validFolders = Array.from(folders.entries())
    .filter(([_, count]) => count >= 3);

  const classifiedRatio = classifiedCount / bookmarks.length;
  const avgDepth = classifiedCount > 0 ? totalDepth / classifiedCount : 0;

  // 结构质量评分
  const structureQuality = calculateStructureQuality({
    classifiedRatio,        // 权重 40%
    validFolderRatio: validFolders.length / Math.max(folders.size, 1),  // 权重 30%
    avgDepth,               // 权重 20%（1 < depth < 4 为佳）
    folderCount: folders.size,  // 权重 10%
  });

  return {
    folderCount: folders.size,
    validFolderCount: validFolders.length,
    classifiedRatio,
    avgDepth,
    structureQuality,
    recommendedMode:
      structureQuality > 0.7 ? 'preserve' :
      structureQuality > 0.3 ? 'hybrid' : 'rebuild',
  };
}
```

**质量评分指标**:

| 指标 | 计算方式 | 权重 |
|-----|---------|------|
| 分类覆盖率 | 已分类书签 / 总书签 | 40% |
| 有效文件夹率 | >= 3 个书签的文件夹 / 总文件夹 | 30% |
| 结构深度合理性 | 1 < 平均深度 < 4 | 20% |
| 命名质量 | 非默认名称的文件夹比例 | 10% |

| **先验权重** | 同一原始文件夹的书签，距离减少 10% | 域名权重扩展 |
| **簇命名参考** | 优先使用用户原有的文件夹名 | AI 命名 prompt 增强 |
| **冲突检测** | AI 建议与原始路径不同时高亮 | 冲突检测器 |

**先验权重实现**:

```typescript
function computeAdjustedDistance(
  a: BookmarkWithOriginalPath,
  b: BookmarkWithOriginalPath,
  rawDistance: number
): number {
  let adjustedDistance = rawDistance;

  // 1. 域名权重（已有）
  if (a.domain === b.domain) {
    const category = getDomainCategory(a.domain);
    adjustedDistance += distanceModifiers[category];
  }

  // 2. 原始路径先验权重（新增）
  if (a.originalPath && b.originalPath) {
    const pathSimilarity = computePathSimilarity(a.originalPath, b.originalPath);
    if (pathSimilarity > 0.8) {
      // 同一原始文件夹，距离减少 10%
      adjustedDistance *= 0.9;
    } else if (pathSimilarity > 0.5) {
      // 相邻文件夹，距离减少 5%
      adjustedDistance *= 0.95;
    }
  }

  return Math.max(0, adjustedDistance);
}

function computePathSimilarity(pathA: string, pathB: string): number {
  const partsA = pathA.split('/');
  const partsB = pathB.split('/');

  let commonParts = 0;
  for (let i = 0; i < Math.min(partsA.length, partsB.length); i++) {
    if (partsA[i] === partsB[i]) {
      commonParts++;
    } else {
      break;
    }
  }

  return commonParts / Math.max(partsA.length, partsB.length);
}
```

## 附录：关键决策记录

| 决策点 | 选项 | 决策 | 理由 |
|-------|------|------|------|
| 聚类算法 | DBSCAN vs K-Means vs HDBSCAN | **分层采样 DBSCAN** | 性能测试显示比 HDBSCAN 快 600 倍（10ms vs 6278ms） |
| eps 敏感性 | 固定值 vs 自适应 | **迭代式自适应兜底** | 采样聚类为主，迭代式作为降级方案 |
| 域名权重 | 统一权重 vs 分级权重 | **分级权重** | 专业站点 vs 内容平台差异大 |
| 降维方案 | 384 维降维 vs 分层采样 | **分层采样** | 保持精度，复杂度 O(n×k) vs O(n²) |
| 预分组 | 无 vs L1.5 标签预分组 | **标签预分组** | 节省 30%-50% 计算量 |
| 去重时机 | 分拣中 vs 分拣后 | **分拣后独立** | 不阻塞主流程 |

| 确认机制 | 自动应用 vs 用户确认 | **沙盒预览 + 确认** | 渐进式信任 |
